## 一、已经确认无误的部分

- `feat-image-4a` 作为协作目录名可以保留。
- 当前 4.3 负责模块名方向是正确的：
  - `logistics_trace_core`
  - `logistics_trace_evidence`
- 主模型名方向是正确的：
  - `logistics.trace.event`
  - `logistics.trace.evidence`

## 二、已完成的纠偏（代码已与规范对齐）

### 模块与测试

- `addons/logistics_trace_evidence/__init__.py` 已正确加载 `controllers`，模块可安装。
- 存储层测试已收口为 `tests/test_image_storage_service.py`，类名 `TestLogisticsEvidenceImageStorage`，覆盖真实落盘与 URL 构建，不再使用旧「外部 image service」语义。
- `services/image_service_client.py` 已删除；唯一实现为 `services/image_storage_service.py`（`LogisticsEvidenceImageStorage`）。

### P0 命名与状态机（留痕事件）

- 文件：`addons/logistics_trace_core/models/logistics_trace_event.py`
- 状态：`new` / `done` / `void`
- 字段：`trace_type`、`trace_source`、`biz_type`（当前取值 `batch`、`waybill`，与当前不做波次主对象的范围一致）

### P0 命名与状态机（证据）

- 文件：`addons/logistics_trace_evidence/models/logistics_trace_evidence.py`
- 状态：`new` / `ok` / `bad` / `del`
- 证据类型：`image` / `sign` / `file` / `video` / `other`
- 关联字段：`trace_id` → `logistics.trace.event`

### 设置项与存储枚举

- `res.config.settings` 使用 `logistics_trace_image_public_base_url`、`logistics_trace_image_storage_root`，对应 `ir.config_parameter`：`logistics_trace_evidence.image_public_base_url`、`logistics_trace_evidence.image_storage_root`。
- 图片引用模型上 `storage_provider`：`local` / `minio` / `s3` / `oss`；本阶段本地上传回写 `local`。

### 文档口径

- `协作边界说明.md`、`当前协作边界与验收说明.md`、`接入与验收说明.md` 已明确：`image-manager-main` 仅参照，运行时不必存在该仓库。

## 三、仍为 P1 / 待收口项

### 1. 接口路径未按三层前缀落地

- 规范要求示例：`/api/admin/logistics/...`、`/api/mini/logistics/...`、`/api/open/logistics/...`
- 当前图片访问：`/logistics_trace/evidence-images/<image_access_key>`
- 说明：功能可用；总装若强制路径规范，需在 controller 层增加或迁移路由并保持对外兼容策略。

### 2. 视图与动作命名

- 文件：`addons/logistics_trace_evidence/views/logistics_trace_evidence_views.xml` 等
- 目标：XML ID、action、菜单、界面字符串按「模块名 + 对象名 + 用途」统一收口（与总规范用词一致）。

### 3. 子模型 `logistics.trace.evidence.image`

- 当前：证据下的图片引用记录子模型。
- 待决策：是否长期保留该子层级，或收敛为更通用的证据明细结构（需与总设计一致）。

### 4. `biz_type` 扩展空间

- 规范示例值含 `wave`、`order` 等；当前仅 `batch`、`waybill`。
- 待其他功能线提供波次 / 订单主对象或挂接规则后再扩展。

### 5. 历史 change-notes

- 部分 `docs/change-notes/*.md` 仍提及已删除的 `image_service_client.py`，仅作变更历史保留，**以当前代码与本清单「二、已完成的纠偏」为准**。
