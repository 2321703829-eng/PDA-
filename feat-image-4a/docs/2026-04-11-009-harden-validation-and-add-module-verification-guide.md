# 2026-04-11-009 Harden Validation and Add Module Verification Guide

## 背景
为了让 `feat-image-4a` 后续更适合你们自己建数据库、部署到服务器并和同事模块一起总装验收，本轮重点补的是：

- 进一步减少命名残留和语义歧义
- 加强业务主体校验
- 给当前模块提供一套明确的验证方法

## 本次改动

### 1. 补充服务层规范化命名
新增：

- `services/image_storage_service.py`

并把当前模块中的实际导入统一指向这个文件，使当前“图片落服务器目录”的实现语义更准确。

保留旧的 `image_service_client.py` 仅作为兼容转发层，避免当前阶段因为文件占用或引用链问题影响模块结构稳定性。

### 2. 强化留痕主体校验
对 `logistics.trace.event` 补充了更严格的约束：

- 批次级留痕必须有批次号
- 运单级留痕必须有运单号
- 批次级留痕不能混带运单号
- 运单级留痕不能混带批次号

这样更符合“图片挂批次或挂运单，而不是混挂”的当前规范。

### 3. 新增模块有效性验证文档
新增：

- `模块有效性验证方法.md`

这份文档把当前模块应该怎么验证拆成了几层：

- 结构验证
- 规范验证
- 模块安装验证
- 后台功能验证
- 存储方式验证
- 协作验收验证

## 当前结果
本轮之后，`feat-image-4a` 更适合回答两个关键问题：

1. 这条线当前代码是不是已经基本符合要求
2. 后续在你们自己的 Odoo 环境中应该怎么验证它是否有效

下一步更值得继续补的是：
