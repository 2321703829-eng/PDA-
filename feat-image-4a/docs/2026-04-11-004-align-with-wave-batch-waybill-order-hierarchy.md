# Change Notes

## 本轮目标
把 `feat-image-4a` 的业务挂载口径进一步对齐到当前已确认的主链：

```text
波次号 -> 批次号 -> 运单号 -> 订单号
```

## 修改文件
- `feat-image-4a/docs/协作边界说明.md`
- `feat-image-4a/docs/接入与验收说明.md`

## 修改原因
- 最新沟通已经明确，业务中同时存在波次号、批次号、订单号、运单号四层对象。
- 本地当前能确认的核心设计文档是《Odoo19物流留痕系统运单主对象与留痕主流程设计》。
- 该文档已经明确：运单号是门店交付类留痕主对象，订单号不是图片归档主对象。
- 因此需要把 `feat-image-4a` 的协作和验收文档继续对齐到“波次/批次/运单/订单”这条层级主线。

## 改动摘要
- 在协作边界说明中补充了当前采用的业务主链
- 明确：
  - 波次号当前不由本功能线实现
  - 批次号用于装车前类图片
  - 运单号用于门店交付类图片
  - 订单号不是图片主挂载点
- 在接入与验收说明中补充了同样的层级说明，方便团队总装时统一口径

## 当前结论
在当前已读到的本地文档范围内，`feat-image-4a` 应继续坚持：

- 不做订单级图片挂载
- 只做批次级/运单级图片挂载
- 最终等待调度侧把波次、批次、运单正式对象补齐后再完成外键化集成
