# 2026-05-06 证据图片导出改造与联调准备报告

## 1. 背景

本轮工作聚焦在证据图片批量导出链路的两个问题：

- 图片级缺失被整批任务“伪装”为完全成功
- 导出结果页按 `Success / Failed / Skipped` 展示，不符合业务对“图片导出”的理解

同时，本轮修改要求先在本机完成并验证，再推送到 GitHub `feat-text` 分支并同步到联调服务器。

## 2. 本轮修改范围

### 后端

文件：

- `custom_addons/logistics_web/services/evidence_image_export_service.py`

完成内容：

- 证据图片导出继续以 `image` 作为导出主单位
- 当任务内存在图片级 `skipped / failed` 时，任务总状态从 `success` 收口为 `partial_failed`
- 任务结果 payload 补充图片级指标：
  - `matched_image_count`
  - `skipped_image_count`
  - `failed_image_count`
- 行级摘要文案改为按图片维度表达
- ZIP 内 `manifest.json` 的 `entry_type` 改为写任务真实入口，不再固定写死为 `from_waybill`

### 前端

文件：

- `custom_addons/logistics_web/static/src/js/actions/export_result_action.js`

完成内容：

- 导出结果页补充图片级统计卡片：
  - `命中图片`
  - `导出运单`
  - `导出证据`
  - `导出图片`
  - `未导出-数据缺失`
  - `未导出-系统异常`
- 结果页状态文案从技术口径改成业务口径：
  - `已导出`
  - `未导出-系统异常`
  - `未导出-数据缺失`
- 从证据列表发起的图片导出，结果页“返回入口”改为回到证据列表，而不是运单列表
