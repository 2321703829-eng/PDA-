## 1. 文档定位

这份文档不是实现代码，而是把两个最关键的增强区块先拆成结构草案：

- 时间线 widget
- 证据区 widget

目标是让你后面无论写 Odoo 组件、OWL 组件，还是先做降级版，都知道边界在哪里。

---

## 2. 总体设计原则

### 2.1 它们是详情页增强区，不是独立前端系统

- 时间线和证据区默认嵌在运单详情页
- 它们服务于阅读，不替代运单表单本身

### 2.2 输入要稳定，输出只负责展示和跳转

widget 不负责自己拼聚合逻辑，主要职责是：

- 接收结构化数据
- 做阅读层渲染
- 触发跳转和切换事件

### 2.3 支持降级

如果一期来不及做增强 widget，应能退回：

- 留痕：`tree/form`
- 证据：`list/kanban + 附件预览`

## 3. 时间线 widget 结构

## 3.1 推荐名称

- `TraceTimelineWidget`

## 3.2 输入 props 建议

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `waybillId` | number | 是 | 当前运单 ID |
| `items` | array | 是 | 时间线数据 |
| `loading` | boolean | 是 | 加载状态 |
| `emptyText` | string | 否 | 空态文案 |
| `readonly` | boolean | 否 | 是否只读 |

## 3.3 输出事件建议

| 事件名 | 用途 |
|---|---|
| `trace-click` | 点击某条留痕 |
| `evidence-click` | 点击该留痕关联证据 |
| `exception-click` | 点击关联异常 |
| `load-more` | 加载更多时间线 |

## 3.4 内部分区建议

```text
TraceTimelineWidget
├─ 顶部栏
│  ├─ 标题
│  ├─ 类型筛选
│  └─ 仅看有图 / 仅看异常
├─ 时间线列表
│  ├─ TimelineCard
│  │  ├─ 时间点
│  │  ├─ 类型标签
│  │  ├─ 摘要
│  │  ├─ 操作人
│  │  ├─ 图片数量
│  │  └─ 异常标识
├─ 加载更多
└─ 空态 / 错误态
```

## 3.5 单张卡片建议

每条 `TimelineCard` 推荐包含：

- 时间
- 类型标签
- 摘要文本
- 操作人
- 图片数量
- 异常标识
- 快速动作：查看证据 / 查看异常

## 3.6 视觉阅读原则

- 时间点要醒目
- 摘要优先于技术字段
- 异常节点要有明显色标
- 图片数量作为辅助信息，不喧宾夺主

## 4. 证据区 widget 结构

## 4.1 推荐名称

- `EvidenceViewerWidget`

## 4.2 输入 props 建议

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `waybillId` | number | 是 | 当前运单 ID |
| `items` | array | 是 | 证据列表 |
| `activeEvidenceId` | number | 否 | 当前选中证据 |
| `loading` | boolean | 是 | 加载状态 |
| `readonly` | boolean | 否 | 是否只读 |

## 4.3 输出事件建议

| 事件名 | 用途 |
|---|---|
| `evidence-change` | 当前图片切换 |
| `trace-click` | 跳转到所属留痕 |
| `open-full-image` | 打开原图 |
| `load-more` | 加载更多证据 |

## 4.4 内部分区建议

```text
EvidenceViewerWidget
├─ 顶部栏
│  ├─ 标题
│  ├─ 证据数量
│  └─ 筛选标签
├─ 主显示区
│  ├─ 当前图片
│  ├─ 左右切换
│  └─ 大图打开动作
├─ 图片信息侧栏
│  ├─ 所属留痕
│  ├─ 上传时间
│  ├─ 上传人
│  ├─ 备注
│  └─ 是否异常证据
├─ 缩略图带
└─ 空态 / 错误态
```

## 4.5 主交互建议

- 点缩略图切换当前图
- 点“查看所属留痕”跳到时间线对应节点
- 点“大图”打开原图
- 左右切换保持顺序稳定

## 5. 运单详情页中的布局建议

推荐布局：

```text
运单详情页
├─ 顶部摘要带
├─ 基本信息区
├─ 执行上下文区
├─ 运单下订单明细区
├─ TraceTimelineWidget
└─ EvidenceViewerWidget
```

说明：
- 时间线在前，证据在后，更符合事实阅读顺序
- 证据区默认由时间线和异常区共同驱动

---

## 6. 异常详情页中的布局建议

推荐布局：

```text
异常详情页
├─ 异常摘要区
├─ 关联对象区
├─ 关键留痕摘要
├─ TraceTimelineWidget（可收起）
└─ EvidenceViewerWidget（关键证据模式）
```

说明：
- 异常页中的两类 widget 应该更克制
- 默认只显示关键节点和关键证据，不需要把整条运单阅读链完整复制过来

---

## 7. 空态与错误态建议

## 7.1 时间线区

- 无留痕：显示“当前暂无留痕记录”
- 加载失败：显示“时间线加载失败，请稍后重试”

## 7.2 证据区

- 无证据：显示“当前暂无证据图片”
- 图片失效：显示“当前图片暂时无法读取”

---

## 8. 一期最小实现建议

如果一期要先做最小可用版，建议：

1. 时间线 widget 先只做卡片流 + 点击跳证据
2. 证据 widget 先只做缩略图 + 大图 + 基本信息
3. 暂不加入复杂批量动作和批注能力

---

## 9. 当前实现边界

这两个 widget 当前只承担：

- 阅读
- 过滤
- 跳转

暂不承担：

- 留痕编辑
- 图片上传
- 图片批注
- 复杂审核流
