- 模块落位层
- 实现对象层

## 2. 使用边界

当前这张总关系表负责回答：

- 某份专题稿大致应落在哪个模块
- 该专题更偏 Python 模型、XML 视图、前端增强还是联调 / 验收
- 后续回填时优先看哪些模型、方法、页面对象

当前不替代：

- 状态机专题里的业务规则细节
- 数据库稿里的字段、索引和约束细节
- 权限稿里的角色、动作、记录规则细节
- 单独专题里的详细章节和编号体系

### 5.2 库存专题当前更接近的真实落点

当前更推荐：

- `stock.quant`
  - 作为库存结果页主对象
  - 承接数量摘要、反查按钮、追溯入口
- `stock.location`
  - 作为货位页主对象
  - 承接位置级汇总与入口
- `stock.warehouse`
  - 作为仓级页主对象
  - 承接仓级聚合与入口

### 5.3 库存专题当前最顺的推进链

`总稿 -> 数量口径 -> 反查入口 -> 页面结构 -> 字段映射 -> XML 草稿 -> Python 映射 -> 任务拆分 -> 联调与验收`

## 7. 当前统一建议

1. 先用这张总关系表决定“该进哪份专题”，再进专题看细节。
