## 章节总览

这份稿子当前主要解决 3 个问题：

1. 库存页上的“相关主单、相关批次、相关运单、异常摘要”这些入口应该怎么排优先级
2. 库存页该通过什么入口方式把人从结果页稳定送到业务页和追溯主链
3. 动作跳转时最少要带哪些 `domain / context / search_default_*`，才能保证落地后可联调

建议阅读顺序：

1. 先看 `1` 到 `4`，明确本稿职责、范围和反查对象总表
2. 再看 `5` 到 `8`，明确主单反查、追溯反查、摘要字段和 Smart Button 设计
3. 最后看 `9` 到 `12`，明确动作规则、边界和联调验证点

## 1. 文档定位

本文件重点回答“库存页如何跳出去”，而不是“库存口径怎么定义”。

它的作用是：

- 固定库存反查的主阅读路径
- 降低库存页与业务主单页、追溯主链页之间的跳转成本
- 避免后续不同页面各自发明反查方式

当前更推荐把这份稿理解成：

`库存专题中负责“入口怎么挂、用户往哪里送、上下文怎么带”的动作规范稿。`

它不直接替代：

- 库存现状与数量口径稿
- 追溯主链正文设计稿
- 异常中心正文设计稿
- 证据查看器和留痕时间线设计稿

## 2. 范围与边界

### 2.1 当前纳入范围

- 库存页到业务主单页的反查入口
- 库存页到批次、运单、留痕、异常的反查入口
- 列表页和详情页的最小摘要字段
- Smart Button、快捷入口、链接动作的最小规范
- `act_window + domain + context + search_default_*` 的默认做法

### 2.2 当前不纳入范围

- 重做新的库存主页面
- 追溯主链正文结构
- 留痕时间线细节
- 证据组件细节
- 复杂跨系统路由体系

### 2.3 一句话边界

`本稿只解决“怎么把人从库存页稳稳送到对的地方”，不解决“目标页面里面怎么完整阅读”。`

## 3. 当前统一目标

当前更推荐通过本稿先收住下面 5 件事：

1. 让库存页成为稳定的反查入口，而不是孤立的结果页
2. 让库存页只展示足够继续下钻的摘要信息，不承接完整追溯阅读
3. 让库存侧入口与仓储管理前端接入稿保持一致，不重新发明动作方式
4. 固定库存反查链路的优先级，避免入口过多但用户不知道先点哪里
5. 为后续前端接入、动作实现、联调验证提供统一验收基线

当前更推荐的反查总原则是：

`业务主单反查看来源，批次反查看承接，运单反查看履约，留痕 / 异常反查看深读。`

## 4. 反查对象总览

### 4.1 当前推荐的主链顺序

库存页与外部对象的连接顺序，当前更推荐为：

`库存 -> 业务主单 / 批次 -> 运单 -> 留痕 / 异常`

进一步收口为：

- 业务解释优先看相关主单
- 追溯承接优先看批次
- 履约事实优先看运单
- 深读和处理再进留痕或异常页

### 4.2 当前推荐的对象总表

| 来源页 | 反查对象 | 当前入口方式 | 当前价值 |
|---|---|---|---|
| `stock.quant` 库存结果页 | 入库单 / 出库单 / 盘点单 / 移位单 | 详情页关联区、相关主单入口 | 回答当前结果是被哪些动作形成或改变的 |
| `stock.quant` 库存结果页 | 批次 | 快捷入口、Smart Button、详情字段链接 | 作为追溯主链第一承接对象 |
| `stock.quant` 库存结果页 | 运单 | 快捷入口、Smart Button、最近关联运单链接 | 作为履约阅读入口 |
| `stock.quant` 库存结果页 | 留痕 / 异常 | 摘要入口、Smart Button、标签入口 | 用于继续下钻，不作为列表页主阅读对象 |
| `stock.location` 货位页 | 批次 / 运单 / 主单 | Smart Button、详情页入口 | 回答某位置当前和最近关联了什么 |
| `stock.warehouse` 仓级页 | 批次 / 运单 / 异常 | Smart Button、汇总入口 | 回答某仓总体有哪些可继续下钻的对象 |

### 4.3 当前建议的入口优先级

当前更推荐：

1. 详情页优先挂完整入口
2. 列表页优先挂轻量快捷入口或摘要字段
3. 批次入口优先于直接异常入口
4. 运单入口优先于留痕深读入口

## 5. 库存页到入库 / 出库 / 盘点 / 移位的反查路径

### 5.1 业务主单反查的目标

库存页反查到业务主单，当前更推荐回答下面几类问题：

1. 这条库存结果主要由哪类业务动作形成
2. 最近一次改变该库存结果的主单是什么
3. 如果要继续看执行过程，应进入哪个主单页

### 5.2 从库存结果页反查主单

当前更推荐从 `stock.quant` 明细页提供“相关主单”入口，并在该入口下至少支持：

- 相关入库单
- 相关出库单
- 相关盘点单
- 相关移位单

主阅读逻辑建议为：

- 先按当前库存结果最相关的单据类型排序
- 再按最近更新时间或最近动作时间排序

### 5.3 从货位页反查主单

当前更推荐从 `stock.location` 页反查：

- 当前货位最近入库单
- 当前货位最近出库单
- 当前货位最近移位单
- 当前货位最近盘点单

它更适合回答：

- 这个位置最近发生过什么
- 这个位置为什么现在有这批库存

### 5.4 从批次库存视角反查主单

当用户已经下钻到批次库存或相关批次页时，当前更推荐把主单反查理解成：

- 该批次是由哪次入库形成
- 该批次在仓内是否经历过移位
- 该批次是否因盘点或出库发生过结果变化

### 5.5 当前推荐的主跳转与次跳转

当前更推荐：

- 主跳转：`库存明细 -> 相关主单列表 -> 主单详情`
- 次跳转：`库存列表 -> 默认筛选后的主单列表`

不建议：

- 从库存列表页直接散落多个深链接到不同主单详情
- 列表页直接堆满四类主单按钮，造成入口噪音

### 5.6 一句话收口

`主单反查优先回答来源问题，适合先从库存明细页挂入口，再进入对应主单详情页看执行过程。`

## 6. 库存页到批次 / 运单 / 留痕 / 异常的反查路径

### 6.1 到批次的反查路径

当前更推荐把批次作为库存页的第一优先追溯入口。

原因是：

- 批次最接近库存结果本身
- 批次比运单更稳定地承接库存侧查询
- 批次页天然适合继续下钻到运单、留痕和异常

当前建议：

- `库存列表页`：展示最近关联批次或批次数摘要
- `库存明细页`：提供 `相关批次` 入口
- `货位页`：提供 `相关批次` 入口
- `仓级页`：提供 `当前批次` 汇总入口

### 6.2 到运单的反查路径

当前更推荐把运单作为库存页的第二优先追溯入口。

当前建议：

- 列表页只展示最近关联运单或运单数摘要
- 详情页提供 `相关运单` Smart Button 或快捷入口
- 默认先进入运单列表页，再进入运单详情页

它更适合回答：

- 这批库存最近关联到了哪些履约对象
- 如果要看单笔事实，应往哪个运单继续下钻

### 6.3 到留痕的反查路径

当前更推荐把留痕入口收在摘要层，而不是让库存页直接承载完整留痕阅读。

当前建议：

- 列表页只展示最新留痕时间
- 详情页可提供 `查看追溯` 或 `查看留痕摘要` 入口
- 进入后优先落到批次或运单的追溯页，而不是库存专属留痕页

### 6.4 到异常的反查路径

当前更推荐把异常入口理解成“有问题再进”的处理入口，而不是库存页第一层主入口。

当前建议：

- 列表页只显示 `是否有未闭环异常` 或 `异常关注` 标记
- 详情页提供 `查看异常` 入口
- 仓级页允许提供 `当前异常` 汇总入口

### 6.5 允许直接跳异常页的场景

当前更推荐只在下面几类场景允许直接跳异常页：

1. 当前库存结果存在未闭环异常
2. 当前库存结果存在负可用量或待确认库存
3. 当前来源页本身已通过筛选条件进入“异常关注”视图

### 6.6 当前推荐的一句话链路

`库存先跳批次，再跳运单；留痕和异常更多是继续深读和处理时才进入。`

## 7. 页面摘要字段建议

### 7.1 当前建议的字段分层

当前更推荐按“列表页轻量、详情页完整”来分层：

- 列表页：只保留能决定下一步去哪看的字段
- 详情页：补齐 Smart Button、相关对象摘要和深度入口

### 7.2 当前建议的字段表

| 字段 | 当前用途 | 出现在列表页还是详情页 | 是否一期必需 |
|---|---|---|---|
| 最近关联批次 | 作为第一追溯入口摘要 | 列表页 + 详情页 | 是 |
| 最近关联运单 | 作为第二追溯入口摘要 | 列表页 + 详情页 | 是 |
| 最新留痕时间 | 判断是否值得继续看追溯 | 列表页 + 详情页 | 是 |
| 是否存在未闭环异常 | 判断是否需要进入异常处理 | 列表页 + 详情页 | 是 |
| 当前关联主单数 | 判断来源关系是否复杂 | 详情页 | 建议有 |
| 相关入库单数 | 回答当前结果来源面 | 详情页 | 建议有 |
| 相关出库单数 | 回答当前结果消耗面 | 详情页 | 建议有 |
| 相关移位单数 | 回答位置变化面 | 详情页 | 建议有 |
| 相关盘点单数 | 回答差异校正面 | 详情页 | 建议有 |

### 7.3 当前不建议上列表页的内容

当前不建议把下面内容直接堆到库存列表页：

- 完整异常明细
- 完整留痕时间线
- 四类主单逐条明细
- 图片证据缩略图墙

### 7.4 一句话收口

`库存页只放足够判断“下一步去哪看”的摘要，不把深读内容提前塞进结果页。`

## 8. Smart Button 与快捷入口建议

### 8.1 当前推荐的设计原则

当前更推荐：

- 详情页使用 Smart Button 承载主要反查入口
- 列表页使用字段链接或轻量快捷入口承载最常用反查
- 同一对象上的按钮顺序保持稳定

当前建议的按钮顺序为：

`相关批次 -> 相关运单 -> 相关主单 -> 查看追溯 -> 查看异常`

### 8.2 当前建议的按钮表

| 页面对象 | Smart Button 名称 | 跳转目标 | 当前说明 |
|---|---|---|---|
| `stock.quant` | `相关批次` | 批次列表 / 批次详情 | 第一优先追溯入口 |
| `stock.quant` | `相关运单` | 运单追溯列表 | 第二优先追溯入口 |
| `stock.quant` | `相关主单` | 入库 / 出库 / 盘点 / 移位相关主单列表 | 第一优先业务解释入口 |
| `stock.quant` | `查看追溯` | 批次或运单追溯页 | 用于继续深读 |
| `stock.quant` | `查看异常` | 当前异常列表 | 仅在有异常时突出 |
| `stock.location` | `相关批次` | 当前货位关联批次列表 | 仓内位置反查入口 |
| `stock.location` | `相关运单` | 当前货位关联运单列表 | 履约反查入口 |
| `stock.location` | `相关主单` | 当前货位关联主单列表 | 回答最近做过什么 |
| `stock.warehouse` | `当前批次` | 当前仓关联批次列表 | 仓级汇总入口 |
| `stock.warehouse` | `当前运单` | 当前仓关联运单列表 | 仓级履约入口 |
| `stock.warehouse` | `当前异常` | 当前仓异常列表 | 仓级异常汇总入口 |

### 8.3 当前更推荐的快捷入口做法

当前更推荐：

- 列表页中的 `最近关联批次`、`最近关联运单` 支持点击跳转
- `最新留痕时间` 只作为提示字段，不一定直接可点
- `未闭环异常` 标签在异常视图中可作为快速入口

### 8.4 一句话收口

`Smart Button 负责稳定主入口，列表字段负责轻量捷径；两者分工明确，不互相替代。`

## 9. 上下文传参与默认筛选规则

### 9.1 当前推荐的动作总原则

当前更推荐统一沿用：

`act_window + domain + context + search_default_*`

不建议为了库存反查额外发明复杂前端路由。

### 9.2 当前建议保留的上下文字段

当前更推荐保留下列上下文字段：

- `default_source_model`
- `default_source_id`
- `default_source_name`
- `search_default_warehouse_id`
- `search_default_location_id`
- `search_default_product_id`
- `search_default_lot_id`
- `search_default_has_open_exception`

如目标页需要面包屑或返回动作，也可补：

- `default_back_action_xmlid`
- `default_back_res_id`

### 9.3 当前建议的场景表

| 场景 | 推荐动作方式 | 推荐 domain | 推荐 context |
|---|---|---|---|
| 库存明细跳批次列表 | `act_window + domain` | 当前库存结果关联的 `lot_ids` | `default_source_model`、`default_source_id`、`search_default_warehouse_id` |
| 库存明细跳运单列表 | `act_window + domain + search_default_*` | 当前库存结果关联的运单范围 | `default_source_model`、`default_source_id`、`search_default_warehouse_id`、`search_default_lot_id` |
| 库存明细跳相关主单列表 | `act_window + domain + context` | 当前库存结果关联的入库 / 出库 / 盘点 / 移位范围 | `default_source_model`、`default_source_id`、`search_default_location_id` |
| 货位页跳批次列表 | `act_window + domain + search_default_*` | 当前货位关联批次 | `default_source_model`、`default_source_id`、`search_default_location_id` |
| 仓级页跳异常列表 | `act_window + context` | 当前仓范围内异常对象 | `default_source_model`、`default_source_id`、`search_default_warehouse_id`、`search_default_has_open_exception` |

### 9.4 默认筛选建议

当前更推荐：

- 进入批次列表时优先带出当前仓库、货位、商品上下文
- 进入运单列表时优先带出批次和仓库上下文
- 进入异常列表时优先带出 `has_open_exception`
- 进入主单列表时优先按当前库存结果关联度排序

### 9.5 空状态与权限不足处理

当前更推荐：

- 无关联对象时展示明确空状态，不弹错误
- 权限不足时显示“有相关对象但当前无权限查看”的轻量提示
- 不在库存页硬编码绕过目标页权限

### 9.6 一句话收口

`入口动作要把用户稳稳送到对的筛选结果里，而不是只把用户扔到一个空白列表页。`

## 10. 页面职责边界

### 10.1 库存页的职责

库存页当前更推荐只承担下面三件事：

1. 展示库存结果和库存摘要
2. 暴露稳定反查入口
3. 提示是否值得继续下钻

### 10.2 库存页不承担的职责

库存页当前不建议承担：

- 完整留痕时间线阅读
- 图片证据主阅读
- 异常闭环处理
- 责任裁定
- 复杂跨单据对比

### 10.3 与目标页面的边界

当前更推荐：

- 主单页负责执行过程和业务状态阅读
- 批次页负责追溯承接
- 运单页负责履约事实阅读
- 异常页负责问题处理
- 留痕页负责证据与时间线深读

### 10.4 一句话收口

`库存页是入口页，不是终点页；它最重要的价值是把人送对地方。`

## 11. 联调与验证点

### 11.1 入口可见性

需要验证：

- 列表页和详情页是否按设计暴露了入口
- 无关联对象时入口是否正确隐藏或置灰
- 有异常时 `查看异常` 是否正确突出

### 11.2 默认筛选正确性

需要验证：

- 从库存明细跳批次是否自动带出仓库 / 货位 / 商品范围
- 从库存明细跳运单是否自动带出批次或当前对象范围
- 从仓级页跳异常是否自动带出当前仓筛选

### 11.3 返回链与上下文正确性

需要验证：

- 目标页是否能识别来源对象
- 返回动作是否能回到原来源页
- 面包屑或标题是否保留来源语义

### 11.4 空状态与权限处理

需要验证：

- 无关联对象时是否显示明确空状态
- 权限不足时是否显示轻量提示而不是报错
- 记录规则是否不会导致误判“无数据”

### 11.5 一致性验证

需要验证：

- `stock.quant`、`stock.location`、`stock.warehouse` 三类入口是否遵循同一反查语言
- 按钮顺序、字段命名、默认筛选语义是否一致
- 与仓储管理前端接入稿的入口说法是否一致

### 11.6 一句话收口

`联调不是只看能不能点开，而是看点开后是不是落到了正确、有上下文、可继续阅读的页面。`
