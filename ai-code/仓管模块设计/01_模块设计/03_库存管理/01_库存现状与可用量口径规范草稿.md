## 章节总览

这份稿子当前主要解决 3 个问题：

1. 库存页、报表页、接口页里常说的“在手量、可用量、冻结量、占用量”到底分别是什么意思
2. 库存现状默认应该按什么粒度阅读，商品、货位、批次三个视角应该如何分工
3. 这些数量口径如何建立在 Odoo 原生 `stock.quant / stock.move / stock.move.line` 之上，而不是另造一套并行库存真相

建议阅读顺序：

1. 先看 `1` 到 `3`，明确本稿的职责、范围和收口目标
2. 再看 `4` 到 `7`，明确库存术语、数量关系和三类库存视角的分工
3. 最后看 `8` 到 `12`，明确状态表达、对象映射、页面联动和当前待确认项

## 1. 文档定位

本文件重点回答“库存怎么定义”，不直接回答“库存页怎么画”。

它的作用是：

- 固定库存现状的统一解释
- 避免页面、接口、报表、联调时各说各话
- 为数据库字段、查询结果、搜索筛选和报表口径提供前置约束

当前更推荐把这份稿理解成：

`库存管理专题中负责“数量词典”和“阅读粒度”的基础稿。`

它不直接替代：

- 入库、出库、盘点、移位这些业务主单专题
- 库存反查与追溯入口设计稿
- 统计与报表专题
- Odoo 原生库存事实层

## 2. 范围与边界

### 2.1 当前纳入范围

- 库存现状的统一解释
- 在手量、可用量、冻结量、占用量四个核心数量口径
- 货位库存、批次库存、商品库存三种阅读视角的分工
- 库存页最小字段、最小筛选和最小报表联动口径
- 与 Odoo 原生 `stock.quant / stock.move / stock.move.line / stock.location / stock.lot` 的映射关系

### 2.2 当前不纳入范围

- 财务价值口径
- 成本核算口径
- 补货策略、补货算法、安全库存策略
- 复杂多租户库存隔离深度方案
- 独立的库存异常处理中心设计

### 2.3 一句话边界

`本稿先解决“库存结果怎么说、怎么读、怎么统一”，不解决“库存优化怎么做满”。`

## 3. 当前统一目标

当前更推荐通过本稿先收住下面 5 件事：

1. 用最少的一组数量术语覆盖一期库存查询、库存反查和库存报表需求
2. 保持页面口径、接口口径、数据库口径、报表口径一致
3. 保持与 Odoo 原生库存事实层兼容，不另造并行库存主表
4. 固定库存现状页的默认阅读粒度，避免商品视角、货位视角、批次视角混读
5. 让库存页优先回答“现在有什么、在哪里、能不能再分配”，而不是承担复杂执行或追责功能

当前更推荐的总原则是：

`库存现状 = 当前结果视图；数量口径 = 结果解释词典；库存页 = 结果查询页与反查入口页。`

## 4. 核心术语表

| 术语 | 当前定义 | 适用对象 | 当前说明 |
|---|---|---|---|
| 库存现状 | 某一时点下库存结果在仓库、货位、商品、批次等维度上的当前分布与数量状态 | 库存页、接口、报表 | 回答“现在有什么、在哪里、数量如何” |
| 在手量 | 已实际形成并处于仓内可识别库存位置中的当前结果量 | 页面、接口、报表 | 作为库存结果的基础口径，优先映射 `stock.quant` |
| 可用量 | 当前仍可继续参与正常分配、预留或出库的数量 | 页面、接口、报表 | 一期建议作为库存页核心必显字段 |
| 占用量 | 已被业务执行链锁定、预留或分配，但尚未真正离库的数量 | 页面、接口、报表 | 一期更推荐先与 `reserved_quantity` 口径对齐 |
| 冻结量 | 因质检、异常、待确认、人工锁定或位置不可分配等原因暂不允许继续参与正常分配的数量 | 页面、接口、报表 | 一期允许先按轻量业务规则表达 |
| 可售量 | 面向销售承诺或客户可售判断的可承诺数量 | 报表、经营分析 | 当前不作为一期库存页主口径 |
| 货位库存 | 按仓内物理位置阅读的库存结果 | 库存页、仓内查询 | 更贴近仓内作业和定位问题 |
| 批次库存 | 按批次阅读的库存结果 | 反查页、追溯链路 | 更贴近追溯和质量问题 |
| 商品库存 | 按商品汇总阅读的库存结果 | 报表、汇总页 | 更贴近管理视角和汇总视角 |

### 4.1 当前不建议混用的说法

当前不建议把下面几组词混成同一个意思：

- `可用量` 和 `在手量`
- `冻结量` 和 `占用量`
- `商品库存汇总` 和 `库存事实行`
- `库存结果标签` 和 `业务主单状态`

### 4.2 一句话术语基线

`在手量看结果底盘，可用量看还能不能分，占用量看已经被谁锁住，冻结量看当前为什么不能再分。`

## 5. 库存现状统一口径

### 5.1 库存现状页回答的问题

库存现状页当前更推荐只回答下面 4 类问题：

1. 现在库存在哪个仓、哪个货位
2. 现在库存有多少在手量、多少可用量
3. 现在库存是否已被占用或被冻结
4. 如果发现问题，下一步应反查到哪个批次、主单或运单

它不直接回答：

- 这批货最终责任归谁
- 这次争议最终怎么判
- 全链路证据时间线怎么逐条阅读

### 5.2 默认展示粒度

当前一期更推荐把库存现状的默认结果粒度收口为：

`货主 + 仓库 + 货位 + 商品 + 批次（可为空）的库存结果切片`

说明：

- `仓库` 解决组织归属
- `货位` 解决实物位置
- `商品` 解决对象识别
- `批次` 解决追溯入口，但允许对未启用批次管理的商品为空

### 5.3 当前建议的主阅读轴

当前更推荐把库存现状页的主阅读轴收口为：

`货位优先，商品并读，批次下钻。`

对应理解为：

- 默认库存查询优先让人先看清“货在哪里”
- 商品用于帮助理解“这里放着什么”
- 批次更适合作为反查和追溯维度，而不是所有库存页的第一主维度

### 5.4 一期建议的页面分工

- `库存列表页`：以库存结果行为主，回答当前位置和数量状态
- `货位页`：以仓内位置为主，回答某货位上当前有什么
- `批次页`：以追溯关系为主，回答某批次当前还落在哪些位置
- `商品汇总页 / 报表页`：以聚合视角为主，回答某商品整体库存规模

### 5.5 一句话收口

`库存现状默认先按“位置上的结果”阅读，再按“商品上的汇总”理解，最后按“批次上的追溯”继续下钻。`

## 6. 在手量 / 可用量 / 冻结量 / 占用量定义

### 6.1 当前更推荐的数量关系

当前一期更推荐把四个口径理解为：

```text
在手量 = 当前已实际形成的库存结果量
可用量 = 在手量 - 占用量 - 冻结量
占用量 = 已被业务链预留或锁定、但尚未真正离库的量
冻结量 = 因规则限制暂不允许继续参与正常分配的量
```

### 6.2 在手量

在手量当前更推荐理解为：

- 已经进入库存事实层
- 已经处于某个可识别仓内位置
- 当前时点下能够被看见的结果量

它是库存结果口径的底盘，优先映射到 `stock.quant`。

### 6.3 占用量

占用量当前更推荐理解为：

- 已经被出库、拣货、分配、预留等执行链锁住
- 当前不能再被其他新单据重复分配
- 但实物尚未真正完成离库

一期更推荐优先对齐 Odoo 原生预留口径，不自行发明第二套“占用”真相。

### 6.4 冻结量

冻结量当前更推荐理解为：

- 因质检、异常、待确认、人工锁定、货位不可分配等原因
- 当前暂不参与正常分配、正常拣货或正常出库
- 它不是业务主单状态，而是库存结果上的限制量

一期更推荐把冻结量理解成“轻量业务限制口径”，可以先来自：

- 位置级限制
- 异常级限制
- 人工冻结标记
- 待确认规则

### 6.5 可用量

可用量当前更推荐理解为：

- 在正常权限和正常规则下
- 当前仍可继续参与新分配、新预留或新出库的数量

它应作为库存页、库存查询和库存汇总报表的核心口径之一。

### 6.6 异常值处理建议

当前更推荐保留事实结果，不对异常值做页面层“美化修正”。

也就是说：

- 若 `可用量 < 0`，不建议静默改成 `0`
- 应保留真实结果，并同时打上异常关注标记
- 后续由盘点、异常、数据联调去解释为什么出现负值或冲突值

### 6.7 一期建议的字段显隐基线

| 口径 | 当前定义 | 是否一期必显 | 是否参与筛选 | 数据来源方向 |
|---|---|---|---|---|
| 在手量 | 当前库存结果底盘 | 是 | 是 | `stock.quant` |
| 可用量 | 可继续分配的数量 | 是 | 是 | `stock.quant` + 业务限制规则 |
| 占用量 | 已预留但未离库的数量 | 建议显式展示 | 是 | `stock.move / stock.move.line` 预留关系 |
| 冻结量 | 因规则限制不可再分的数量 | 建议至少有摘要或标签 | 是 | 位置规则 / 异常规则 / 人工锁定 |
| 可售量 | 面向销售承诺的数量 | 否 | 否 | 后续专题再议 |

### 6.8 一句话收口

`一期先把在手量、可用量、占用量、冻结量这四个量说清，不把可售量、经营量、财务量一起拉进来。`

## 7. 货位库存、批次库存、商品库存关系

### 7.1 三种视角的角色分工

当前更推荐把三种视角理解成不同层级的阅读入口，而不是三套不同真相：

- `货位库存`：仓内作业和定位问题的第一视角
- `批次库存`：追溯链、质量链、异常链的第一视角
- `商品库存`：汇总、管理和报表的第一视角

### 7.2 当前建议的优先级

当前一期更推荐按下面顺序理解优先级：

1. 货位库存优先作为默认阅读视角
2. 批次库存优先作为反查和追溯视角
3. 商品库存优先作为汇总和管理视角

### 7.3 页面如何避免重复表达

当前更推荐通过“每个页面只承担一个主维度”来避免重复表达：

- 库存结果页主讲位置上的库存结果
- 批次页主讲某批次分布到了哪些位置
- 商品汇总页主讲整体规模，不复写每条位置明细

### 7.4 货位库存与批次库存的关系

当前更推荐把两者理解为：

- 货位库存回答“这一格里现在有什么”
- 批次库存回答“这一批现在分散在哪”

所以两者是可互相反查的，但不应强行合并成同一种首页。

### 7.5 商品库存汇总与底层事实的关系

商品库存汇总当前更推荐建立在底层库存事实行之上做聚合，而不是单独维护商品库存总账。

也就是说：

- 商品库存汇总是结果聚合视图
- `stock.quant` 仍是库存事实层
- 页面和报表都不应再维护第二份商品库存真相

### 7.6 一句话收口

`货位看位置，批次看追溯，商品看汇总；三者是同一份库存事实的不同阅读方式。`

## 8. 库存状态与异常表达

### 8.1 当前不建议建立独立复杂状态机

库存专题当前不建议另建一套复杂的“库存主状态机”。

更推荐的做法是：

- 用数量字段表达结果
- 用轻量标签表达当前限制
- 用异常摘要表达是否值得继续下钻

### 8.2 当前建议的结果标签

当前更推荐库存结果页只保留轻量标签，例如：

- `正常可用`
- `部分占用`
- `全部占用`
- `部分冻结`
- `全部冻结`
- `异常关注`

这些标签用于帮助阅读，不替代主单状态。

### 8.3 冻结、占用、待处理的表达方式

当前更推荐：

- `占用` 主要作为数量字段和结果标签表达
- `冻结` 主要作为数量字段和结果标签表达
- `待处理` 更适合作为异常摘要或待确认摘要，而不是库存主状态

### 8.4 库存异常的表达边界

当前更推荐库存页只暴露轻量异常摘要，例如：

- 是否存在未闭环异常
- 是否存在负可用量
- 是否存在待确认库存

完整异常阅读和处理仍留在异常中心或追溯主链。

### 8.5 一句话收口

`库存页展示结果标签，不承接复杂状态流转；真正的业务状态仍留在主单页。`

## 9. 与 Odoo 原生对象的映射

### 9.1 当前核心映射表

| 业务口径 | 当前原生对象 | 当前字段方向 | 当前说明 |
|---|---|---|---|
| 在手量 | `stock.quant` | `quantity` 方向 | 作为库存结果底盘 |
| 占用量 | `stock.quant / stock.move / stock.move.line` | 预留数量方向 | 一期更推荐先对齐原生预留语义 |
| 可用量 | `stock.quant` + 业务限制规则 | `quantity - reserved - frozen` 方向 | 页面统一显示口径 |
| 冻结量 | `stock.location` + 业务规则 + 异常规则 | 衍生字段方向 | 一期允许先做轻量衍生表达 |
| 货位库存 | `stock.location + stock.quant` | 位置维度聚合 | 仓内定位视角 |
| 批次库存 | `stock.lot + stock.quant` | 批次维度聚合 | 追溯视角 |
| 商品库存 | `product.product + stock.quant` | 商品维度聚合 | 汇总视角 |

### 9.2 对象分工理解

- `stock.quant`：库存事实层，优先回答当前结果
- `stock.move`：库存变动意图与预留关系来源
- `stock.move.line`：执行明细与细粒度位置、批次关系来源
- `stock.location`：物理位置和位置规则来源
- `stock.lot`：批次维度与追溯入口来源

### 9.3 当前更推荐的实现原则

当前更推荐继续沿用数据库规范中的原则：

1. 优先复用 Odoo 原生事实层
2. 允许在其上补业务语义字段和衍生摘要
3. 不另造并行库存主表、并行库存流水表、并行货位事实层

### 9.4 一句话收口

`库存口径建立在 Odoo 原生事实层之上补语义，不在 Odoo 原生事实层之外再造第二套库存真相。`

## 10. 页面字段、搜索筛选与报表口径联动

### 10.1 库存页最小字段集合

当前更推荐库存页最小字段先围绕：

- 货主
- 仓库
- 货位
- 商品
- 批次
- 在手量
- 可用量
- 占用量
- 冻结量
- 最近更新时间

如果需要和前端接入稿保持一致，库存结果页还可补充轻量摘要字段：

- 最近关联批次
- 最近关联运单
- 最近留痕时间

### 10.2 搜索筛选组织方式

当前更推荐搜索筛选按下面 4 组组织：

1. 归属组
   - 货主
   - 仓库
2. 位置组
   - 货位
3. 对象组
   - 商品
   - 批次
4. 数量状态组
   - 有库存
   - 可用量大于 0
   - 存在占用
   - 存在冻结
   - 异常关注

### 10.3 页面与报表的口径联动

当前更推荐页面和报表复用同一套数量定义：

- 页面说“在手量”，报表也说“在手量”
- 页面说“可用量”，报表也说“可用量”
- 页面说“冻结量”，报表也说“冻结量”

不建议：

- 页面叫“可用量”，报表改叫“可分配量”
- 页面按一种公式算，报表按另一种公式算

### 10.4 页面与报表的边界

当前更推荐：

- 页面优先回答当前结果和当前定位问题
- 报表优先回答汇总规模和管理汇总问题

所以两者可以用同一套数量口径，但不应做成同一类页面。

### 10.5 一句话收口

`页面和报表可以分工不同，但数量词典必须共用一套。`

## 11. 当前待确认项

当前仍建议在后续评审中继续确认：

1. 冻结量的一期来源是否只先收位置限制和异常限制，还是同步纳入人工冻结动作
2. 占用量是否在所有库存列表页都显式展示，还是先在详情页和导出中重点展示
3. 未启用批次管理的商品在库存结果页中，是否统一以空批次展示
4. 货主维度是否在所有库存页默认显式展示，还是仅在多货主场景强制显式
5. 负可用量、负库存、待确认库存的页面提示级别是否需要进一步细分
