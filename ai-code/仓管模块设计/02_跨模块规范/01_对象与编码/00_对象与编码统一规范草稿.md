## 章节总览

这份文档当前主要回答 4 个问题：

1. 仓管模块里“对象”到底分哪几层，编号前缀怎么统一
2. 主单、执行记录、任务、证据、日志各自的编码字段该怎么命名
3. 编码字段在数据库、页面、搜索、导入导出里应如何一致表达
4. 这份对象与编码规范如何与状态流程、数据库、权限三份主干规范互相对齐

建议阅读顺序：

1. 先看 `3` 到 `5`，建立对象分层、对象编号、模型命名的统一认知
2. 再看 `6` 到 `10`，掌握不同对象的编码规则和字段命名规则
3. 最后看 `13` 到 `15`，理解它与状态流程、数据库、权限三份主干规范的交叉关系

## 1. 文档定位

本文件是仓管模块的跨模块基础规范之一。

它不替代各业务主单状态机专题，也不替代数据库稿，而是专门负责统一：

- 对象命名
- 对象编号
- 编码字段
- 页面展示用名
- 与实现层的回填口径

## 2. 适用范围

当前适用于：

- 主数据对象
- 主单对象
- 明细对象
- 执行记录对象
- 任务对象
- 证据对象
- 日志对象

当前不强行纳入：

- Odoo 原生所有技术对象的完整编号重写
- 三方系统外部编码体系的全部镜像
- 图片二进制对象存储内部文件名规则

## 3. 对象分层与命名总原则

统一原则如下：

- 业务对象名称优先直白、短、稳定
- 对象编号优先表达对象类别，不优先表达业务状态
- 编码字段只表达“对象识别码”，不混入状态语义
- 页面显示名称可中文化，但模型技术名、字段名、编号前缀保持英文稳定
- 同一类对象只保留一套主编码，不并行维护多套主编号

## 4. 对象编号体系总表

当前建议的主编号前缀如下：

- `OBJ-MD-*`：主数据对象
- `OBJ-IN-*`：入库主链对象
- `OBJ-OU-*`：出库主链对象
- `OBJ-CT-*`：盘点主链对象
- `OBJ-RL-*`：移位主链对象
- `OBJ-TS-*`：任务对象
- `OBJ-EV-*`：证据对象
- `OBJ-LG-*`：日志对象

示例：

- `OBJ-IN-01 = 入库单`
- `OBJ-IN-02 = 入库单明细`
- `OBJ-IN-03 = 收货记录`
- `OBJ-OU-01 = 出库单`
- `OBJ-OU-03 = 拣货记录`
- `OBJ-TS-01 = 导入任务`
- `OBJ-EV-01 = 证据元数据`
- `OBJ-LG-01 = 操作日志`

## 5. 模型技术名与显示名称统一口径

统一建议：

- 模型技术名使用英文蛇形命名
- 页面显示名称使用中文业务名称
- 对象编号只做跨文档引用，不直接替代页面标题

示例方向：

- `logistics.wms.inbound`
  - 显示名称：`入库单`
  - 对象编号：`OBJ-IN-01`
- `logistics.wms.outbound`
  - 显示名称：`出库单`
  - 对象编号：`OBJ-OU-01`
- `logistics.wms.operation.log`
  - 显示名称：`操作日志`
  - 对象编号：`OBJ-LG-01`

## 6. 主单对象编码口径

主单对象统一保留一个主编码字段，建议命名为：

- `name`

页面含义统一理解为：

- 入库单号
- 出库单号
- 盘点单号
- 移位单号

不建议再并行维护：

- `code`
- `bill_no`
- `order_no`

等重复主编码字段作为主识别码。

## 7. 执行记录对象编码口径

执行记录对象也统一保留一个主编码字段，建议命名为：

- `name`

适用对象：

- 收货记录
- 上架记录
- 拣货记录
- 复核记录

统一理解为：

- 当前记录号是执行记录主识别码
- 通过外键关联到主单，不通过拼接多个外部字段充当主识别码

## 8. 任务对象编码口径

任务对象统一建议：

- `name`：任务号
- `external_ref`：外部请求号或三方流水号

适用对象：

- 导入任务
- 回传任务
- 重试记录

统一边界：

- `name` 是系统内主识别码
- `external_ref` 是与外部系统对账用的辅助编码

## 9. 证据与日志对象编码口径

证据与日志对象统一建议：

- 证据对象：
  - `name` 可选
  - `evidence_code` 可按需要单独保留
- 日志对象：
  - `name` 可选
  - 优先依赖对象关联与时间序列，不强制要求独立业务单号

一期更建议：

- 证据对象保留轻量编码或访问键
- 日志对象优先用 `id + 时间 + 关联对象` 组合定位

## 10. 编码字段命名规则

当前统一建议如下：

- 主识别码：`name`
- 外部参考码：`external_ref`
- 货主编码：`owner_code`
- 商品编码：`product_code`
- 条码：`barcode`
- 货位编码：`location_code`
- 仓库编码：`warehouse_code`

不建议混用：

- `code`
- `number`
- `no`
- `doc_no`

作为多个对象的主编码字段名。

## 11. 编码生成与唯一性边界

统一建议：

- 主单 `name`：模块内唯一
- 执行记录 `name`：执行记录模型内唯一
- 任务 `name`：任务模型内唯一
- `external_ref`：按外部来源 + 外部请求号做唯一性约束

不建议一期做：

- 跨全系统所有对象共用一套绝对唯一总流水号
- 把对象类别、状态、货主、日期全部编码进主识别码

## 12. 页面、搜索与导入导出中的编码展示口径

统一建议：

- 列表页优先显示主编码 `name`
- 搜索优先支持主编码、外部参考码、对象名称
- 导入导出模板优先保留：
  - 主编码
  - 外部参考码
  - 关键关联对象编码

不建议一期：

- 同一页面同时并列展示多套“主编号”
- 让页面标题、搜索字段、导出字段各自用不同编码字段

## 13. 与状态与流程统一规范之间的交叉映射

当前统一边界：

- 本文负责对象与编码
- 状态流程稿负责状态编号、异常补充状态编号、状态推进边界

两者的关系是：

- `OBJ-*` 负责“这是什么对象”
- `ST-* / EST-*` 负责“这个对象当前处于什么状态”

## 14. 与数据库设计规范之间的交叉映射

当前统一边界：

- 本文负责字段命名和对象编号口径
- 数据库稿负责字段如何落表、唯一约束、索引、模型到文件树映射

对齐重点包括：

- `name`
- `external_ref`
- 各类 `*_code`
- 对象编号 `OBJ-*`

## 15. 与权限与角色规范之间的交叉映射

当前统一边界：

- 本文负责对象标识和编码口径
- 权限稿负责谁能看、谁能改、范围如何收口

需要共同对齐的重点包括：

- 哪些编码可搜索
- 哪些编码可见
- 哪些编码可导出
- 哪些编码属于跨货主 / 跨仓库敏感识别信息

1. `OBJ-*` 与 `ST-* / EST-*` 必须分层表达，不能混为一类编号。
2. 主单对象优先映射 `ST-*`，执行记录对象优先映射 `ST-EX-*`。
3. `EST-*` 只表达异常补充状态，不替代主状态编号。
