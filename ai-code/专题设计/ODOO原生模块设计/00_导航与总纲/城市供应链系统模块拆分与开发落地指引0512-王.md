# 城市供应链全链路系统模块拆分与开发落地指引

版本：v0.1  
适用对象：内部产品、开发、运营、仓库、调度、财务协同  
日期：2026-05-12

> 本文件用于把当前杂糅在一起的功能，按 B2B、ERP、WMS、TMS、BI、系统底座六类重新归位，形成后续产品原型、数据库设计、开发排期和验收口径。

## 0\. 核心结论

这套城市供应链系统，不建议继续按“一个大工具里堆所有功能”的方式开发。建议统一拆成：

| 模块 | 一句话定位 | 核心边界 |

|---|---|---|

| B2B订货商城 | 客户/门店下单入口 | 负责客户看货、看价、下单、查订单、发起售后，不负责仓库拣货和车辆派单。 |

| ERP经营管理系统 | 公司经营中台 | 负责商品、客户、供应商、采购、销售、库存账、价格、结算、补货、成本。 |

| WMS仓储管理系统 | 仓库作业系统 | 负责收货、上架、库位、库存、批次效期、分拣、复核、装车、盘点、退货。 |

| TMS运输管理系统 | 物流配送系统 | 负责排线、派车、司机、车辆、在途、签收、配送异常、运费计算。 |

| BI数据控制塔 | 管理驾驶舱 | 负责汇总订单、仓库、配送、异常、成本、KPI，不直接产生业务动作。 |

| 系统底座 | 账号权限与数据打通基础 | 负责账号、权限、主数据编码、接口、日志、消息、导入导出模板。 |



一句话原则：**B2B 管下单，ERP 管经营，WMS 管仓库，TMS 管配送，BI 管看板，系统底座管账号权限和数据打通。**

## 1\. 模块拆分总原则

| 原则 | 说明 | 开发落地要求 |

|---|---|---|

| 一类业务只找一个主系统 | 每个核心数据和核心动作必须有唯一主责模块。 | 不要在多个模块里重复维护同一个主档，避免后续数据打架。 |

| 前端交易归B2B | 客户登录、看商品、看价格、下单、查订单都归B2B。 | B2B只做客户入口，仓内和配送状态从WMS/TMS读取。 |

| 经营账归ERP | 采购、销售、库存账、成本、对账、补货都归ERP。 | ERP输出采购单、销售单、出库单、结算单，不直接指导拣货路线。 |

| 仓内动作归WMS | 收、存、拣、复、装、退、盘点都归WMS。 | WMS记录实物库存、库位、批次、拣货复核和装车交接。 |

| 配送执行归TMS | 路线、车辆、司机、在途、签收、运费都归TMS。 | 你现在的排线exe，应该逐步沉淀为TMS的排线调度模块。 |

| 经营看数归BI | 看进度、看异常、看成本、看KPI、看趋势都归BI。 | BI只汇总和预警，不作为业务源头系统。 |

| 共用能力归系统底座 | 账号、权限、日志、接口、消息通知、主数据编码归底座。 | 所有模块统一登录、统一权限、统一日志。 |



## 2\. 总体业务流

建议以订单为主线贯穿所有系统。

```text
客户/门店
  ↓
B2B订货商城：看商品、看价格、下单、查进度
  ↓
ERP经营管理系统：生成销售订单、校验价格/账期/库存账、生成出库计划
  ↓
WMS仓储管理系统：接收出库任务、分拣、复核、集货、装车交接
  ↓
TMS运输管理系统：排线、派车、司机执行、在途跟踪、到店签收
  ↓
ERP经营管理系统：对账、结算、成本归集、应收应付
  ↓
BI数据控制塔：订单进度、仓库进度、配送进度、异常、成本、KPI

底层：系统底座统一账号、权限、主数据、接口、日志、消息通知
```

## 3\. B2B订货商城系统

### 3.1 模块定位

B2B是客户/门店/经销商的前端入口。客户在这里登录、看商品、看价格、提交订单、查询订单和发起售后。B2B不负责仓库如何拣货，也不负责司机怎么跑线路。

### 3.2 适用用户

* 门店客户
* 经销商/商家
* 客户业务员
* 平台招商/运营人员
* 客服人员



### 3.3 功能清单

| 一级功能 | 二级功能 | 归属说明 | 优先级 |

|---|---|---|---|

| 客户登录 | 门店账号、客户身份、账号状态 | B2B前端账号可由系统底座统一认证。 | P1 |

| 商品展示 | 分类、图片、规格、单位、库存展示 | 商品主数据来自ERP，B2B负责展示。 | P1 |

| 价格展示 | 客户等级价、区域价、活动价 | 价格规则在ERP维护，B2B读取后展示。 | P1 |

| 下单购物车 | 加购、修改数量、提交订单、订单备注 | B2B产生订单草稿/客户订单。 | P1 |

| 订单查询 | 待审核、待出库、配送中、已签收、异常 | 订单源头在ERP，物流状态来自WMS/TMS。 | P2 |

| 售后申请 | 缺货、错货、破损、拒收、退货 | B2B作为客户入口，异常流转到WMS/TMS/ERP。 | P2 |

| 营销活动 | 满减、优惠券、秒杀、组合套餐 | 冷启动可后置，先保证下单闭环。 | P3 |

| 消息通知 | 订单确认、发车、预计到达、签收、异常 | 底层消息服务统一推送。 | P2 |



### 3.4 输入与输出

| 类型 | 数据/单据 | 来源/去向 |

|---|---|---|

| 输入 | 商品资料、商品图片、规格、价格、库存可售数 | ERP/WMS同步到B2B |

| 输入 | 客户账号、客户等级、客户可见商品范围 | ERP/系统底座同步 |

| 输出 | 客户订单、订单备注、收货门店、要求送达时间 | B2B提交到ERP订单中心 |

| 输出 | 售后申请、客户反馈、投诉记录 | 流转到异常处理链路 |



### 3.5 不应该放在B2B里的功能

* 不在B2B里维护实物库位库存。
* 不在B2B里做波次分拣和复核。
* 不在B2B里做排线派车。
* 不在B2B里做完整财务记账。
* 不在B2B里做司机结算。



## 4\. ERP经营管理系统

### 4.1 模块定位

ERP是公司的经营中台，负责钱、货、账、采、销、存。它更关注经营结果和账面逻辑，不直接替代WMS的实物操作，也不替代TMS的配送执行。

### 4.2 适用用户

* 老板/经营负责人
* 采购
* 销售/客服
* 财务
* 运营
* 商品负责人



### 4.3 功能清单

| 一级功能 | 二级功能 | 归属说明 | 优先级 |

|---|---|---|---|

| 商品主数据 |已有模板 | 商品唯一主档建议放ERP。 | P1 |

| 客户主数据 | 已有模板 | 客户经营属性归ERP，配送属性同步给TMS。 | P1 |

| 供应商管理 | 供应商档案、采购价、账期、结算方式 | 采购源头在ERP。 | P2 |

| 采购管理 | 采购申请、采购订单、到货计划、采购退货 | ERP生成采购单，WMS执行收货。 | P2 |

| 销售订单 | 订单审核、价格校验、库存账校验、销售出库计划 | B2B/导入订单进入ERP成为正式销售单。 | P1 |

| 库存账管理 | 账面库存、可售库存、锁定库存、调拨库存 | ERP管账面库存，WMS管库位实物库存。 | P1 |

| 价格管理 | 成本价、批发价、客户等级价、促销价 | B2B展示价格从ERP读取。 | P1 |

| 客户对账 | 应收账款、对账单、扣款、赔付、发票信息 | 签收和异常数据来自TMS/WMS。 | P2 |

| 司机/车辆费用结算 | 车次费用、里程费、点位费、附加费、扣款 | TMS生成运费明细，ERP归集结算。 | P2 |

| 补货计划 | 销量预测、安全库存、采购建议、库存周转 | 冷启动先做规则版，成熟后做算法版。 | P3 |

| 经营分析 | 商品毛利、客户毛利、区域利润、费用归集 | 明细在ERP，汇总看板在BI。 | P2 |



### 4.4 ERP与WMS的边界

| 事项 | ERP负责 | WMS负责 |

|---|---|---|

| 库存 | 账面库存、可售库存、锁定库存 | 库位库存、批次库存、实物库存 |

| 采购入库 | 采购单、供应商、采购价、应付账款 | 到货收货、验货、上架、差异记录 |

| 销售出库 | 销售订单、出库计划、收入确认 | 拣货、复核、打包、出库交接 |

| 批次效期 | 商品是否需要批次/效期管理规则 | 实际批次采集、先进先出执行、临期预警 |

| 成本 | 商品成本、费用归集、毛利 | 仓内作业效率和作业异常 |



### 4.5 输入与输出

| 类型 | 数据/单据 | 来源/去向 |

|---|---|---|

| 输入 | B2B订单、人工导入订单 | 来自B2B或Excel导入 |

| 输入 | 采购需求、供应商报价、历史销量 | 来自采购/销售/BI |

| 输出 | 销售订单、出库计划 | 推送给WMS |

| 输出 | 采购订单、到货计划 | 推送给WMS |

| 输出 | 客户对账单、供应商对账单、司机/车辆结算单 | 给财务/客户/司机 |

| 输出 | 商品、客户、价格、库存账 | 同步给B2B、WMS、TMS、BI |



### 4.6 不应该放在ERP里的功能

* 不在ERP里做具体库位拣货路线。
* 不在ERP里做司机实时定位。
* 不在ERP里处理司机到店拍照签收的具体动作。
* 不在ERP里维护每个库位的实物细节，库位细节应在WMS。



## 5\. WMS仓储管理系统

### 5.1 模块定位

WMS是仓库作业系统，负责货物从进入仓库到离开仓库的全过程。它要解决仓库现场的准确率、效率、库位、批次、复核和装车交接问题。

### 5.2 适用用户

* 仓库经理
* 仓管
* 收货员
* 上架员
* 分拣员
* 复核员
* 装车交接人员
* 盘点人员



### 5.3 功能清单

| 一级功能 | 二级功能 | 归属说明 | 优先级 |

|---|---|---|---|

| 入库管理 | 到货预约、收货验货、差异登记、质检 | 接收ERP采购到货计划。 | P1 |

| 上架管理 | 库区库位、上架任务、推荐库位、实际库位确认 | 解决货放哪里、怎么找货。 | P1 |

| 库存管理 | 库位库存、批次库存、效期库存、库存冻结、库存调整 | 实物库存源头在WMS。 | P1 |

| 波次/订单管理 | 接收出库单、波次合并、任务分配 | 从ERP接出库计划，根据线路/区域/时效组织作业。 | P1 |

| 拣货管理 | 按单拣货、波次拣货、路径优化、件散拣选 | 解决多门店小订单效率问题。 | P1 |

| 复核管理 | 商品复核、数量复核、门店复核、异常拦截 | 出库前最后质量关。 | P1 |

| 打包贴标 | 装箱、称重、贴标、门店标签、线路标签 | 冷启动可先简化为门店/线路标签。 | P2 |

| 集货管理 | 按线路集货、按车辆集货、待装区管理 | 避免司机到仓找货。 | P1 |

| 装车交接 | 装车扫描、司机确认、交接单、照片留痕 | 仓库责任与司机责任切换点。 | P1 |

| 退货管理 | 拒收退回、破损退回、退货验收、重新入库 | 逆向流程必须留痕。 | P2 |

| 盘点管理 | 日盘、周盘、循环盘点、差异处理 | 保障账实一致。 | P2 |



### 5.4 WMS关键状态

| 节点 | 状态示例 | 触发人/系统 | 后续流转 |

|---|---|---|---|

| 收货 | 待收货、收货中、已收货、收货异常 | 收货员 | 进入上架或异常处理 |

| 上架 | 待上架、上架中、已上架、上架异常 | 上架员 | 形成库位库存 |

| 拣货 | 待拣货、拣货中、已拣货、缺货异常 | 分拣员 | 进入复核 |

| 复核 | 待复核、复核中、已复核、复核异常 | 复核员 | 进入集货/打包 |

| 集货 | 待集货、已集货、待装车 | 仓管/装车员 | 等待TMS派车装车 |

| 装车 | 待装车、装车中、已交接、装车异常 | 装车员/司机 | 推送TMS发车 |

| 退货 | 待验收、已入库、报损、待处理 | 退货员 | 回ERP做账务处理 |



### 5.5 输入与输出

| 类型 | 数据/单据 | 来源/去向 |

|---|---|---|

| 输入 | ERP采购到货计划 | WMS生成收货任务 |

| 输入 | ERP销售出库计划 | WMS生成分拣/复核/装车任务 |

| 输入 | 商品主数据、箱规、批次效期规则 | ERP同步给WMS |

| 输出 | 收货结果、上架结果、库存变动 | 回传ERP |

| 输出 | 出库结果、装车交接单 | 回传ERP/TMS |

| 输出 | 仓库异常 | 推送异常闭环和BI |



### 5.6 不应该放在WMS里的功能

* 不在WMS里维护客户价格和账期。
* 不在WMS里做完整采购结算。
* 不在WMS里做路线优化和司机派单。
* 不在WMS里做老板经营利润分析，只提供仓内数据给BI。



## 6\. TMS运输管理系统

### 6.1 模块定位

TMS是物流配送系统，负责从运输任务生成、排线、派车、司机执行、在途跟踪、到店签收到运费计算的全流程。当前已有的排线exe，建议归入TMS的“排线调度中心”。

### 6.2 适用用户

* 调度
* 车队负责人
* 司机
* 运营负责人
* 客服
* 财务结算人员



### 6.3 功能清单

| 一级功能 | 二级功能 | 归属说明 | 优先级 |

|---|---|---|---|

| 运输订单 | 从WMS/ERP接收待配送订单、合并拆分运输任务 | 运输任务源头进入TMS。 | P1 |

| 门店配送档案 | 经纬度、停车点、上楼、收货时间、导航备注 | 经营资料在ERP，配送细节在TMS维护。 | P1 |

| 排线调度 | 单路线、多路线、人工排线、路线核验、到店顺序 | 当前exe核心功能。 | P1 |

| 装载管理 | 重量、方数、整件散件、车型限制、装车顺序 | 与WMS装车交接联动。 | P1 |

| 派车管理 | 车辆分配、司机分配、发车时间、承运商/自有车 | 调度核心动作。 | P1 |

| 司机任务 | 任务下发、一键导航、到店确认、异常上报 | 司机端尽量少输入，尽量点击和拍照。 | P1 |

| 在途跟踪 | GPS轨迹、到店节点、停留时长、偏航/超时预警 | 冷启动可先用节点上报，后续接GPS。 | P2 |

| 签收回单 | 电子签收、拍照、签名、拒收登记、回单上传 | 配送闭环证据。 | P1 |

| 配送异常 | 延误、破损、短少、拒收、门店无人、地址异常 | 异常产生后进入闭环处理。 | P1 |

| 运费计算 | 车次费、里程费、点位费、附加费、扣款 | TMS生成明细，ERP结算。 | P2 |



### 6.4 TMS关键状态

| 节点 | 状态示例 | 触发人/系统 | 后续流转 |

|---|---|---|---|

| 待排线 | 待排线 | ERP/WMS推送运输需求 | 进入排线 |

| 已排线 | 已生成线路、待确认 | 调度/系统 | 进入派车 |

| 已派车 | 已分配司机车辆 | 调度 | 等待到仓装车 |

| 到仓 | 司机已到仓、等待装车 | 司机/调度 | WMS装车交接 |

| 已装车 | 装车完成、交接完成 | WMS/TMS | 司机发车 |

| 配送中 | 在途、到店、卸货中 | 司机 | 签收或异常 |

| 已签收 | 正常签收、部分签收 | 司机/门店 | 回传ERP对账 |

| 异常结束 | 拒收、短少、破损、延误闭环 | 客服/运营 | 进入赔付或复盘 |



### 6.5 输入与输出

| 类型 | 数据/单据 | 来源/去向 |

|---|---|---|

| 输入 | 待配送订单、重量、方数、整件数、散件数 | ERP/WMS同步 |

| 输入 | 门店地址、经纬度、配送要求 | ERP主档/TMS配送档案 |

| 输入 | 车辆、司机、车型、载重、状态 | TMS主档 |

| 输出 | 线路方案、司机任务、派车结果 | 给调度/司机/WMS |

| 输出 | 发车、到店、签收、回单 | 回传ERP/B2B/BI |

| 输出 | 配送异常、运费明细 | 异常闭环/ERP结算/BI |



### 6.6 不应该放在TMS里的功能

* 不在TMS里维护商品成本价和客户账期。
* 不在TMS里处理仓内收货、上架、库位库存。
* 不在TMS里做完整客户订货商城。
* 不在TMS里做经营利润最终确认，但要提供车辆和线路成本明细。



## 7\. BI数据控制塔

### 7.1 模块定位

BI是管理驾驶舱，不产生原始业务数据。它负责从B2B、ERP、WMS、TMS抽取数据，形成订单、仓库、配送、异常、成本、KPI的统一看板。

### 7.2 适用用户

* 老板
* 运营负责人
* 仓库经理
* 调度负责人
* 财务
* 客服主管



### 7.3 功能清单

| 看板 | 核心指标 | 数据来源 | 优先级 |

|---|---|---|---|

| 订单总览 | 订单数、门店数、件数、重量、方数、订单状态 | B2B/ERP | P1 |

| 仓库作业 | 待拣、拣选中、待复核、待装车、出库准点率、错漏率 | WMS | P1 |

| 配送进度 | 计划车次、已派车、已发车、在途、已签收、超时预警 | TMS | P1 |

| 异常闭环 | 异常数量、异常类型、责任部门、处理状态、赔付金额 | WMS/TMS/B2B/ERP | P1 |

| 成本利润 | 单票成本、单车成本、仓库人工、配送成本、客户毛利 | ERP/TMS/WMS | P2 |

| 客户分析 | 客户订单量、毛利、异常率、账期风险 | ERP/B2B/TMS | P2 |

| 商品分析 | 爆品、滞销品、缺货品、临期品、周转天数 | ERP/WMS | P2 |

| KPI日报 | 准点率、签收率、异常闭环率、仓库人效、车效 | 各系统汇总 | P1 |



### 7.4 BI第一版建议

第一版不要追求复杂大屏，先做五张表/五张看板：

* 订单进度看板：今天多少单，跑到哪个节点。
* 仓库作业看板：分拣、复核、装车是否卡住。
* 配送进度看板：车有没有发，货有没有签。
* 异常闭环看板：异常有没有处理，责任归谁。
* 成本利润看板：今天收入、成本、赔付、毛利。



### 7.5 不应该放在BI里的功能

* 不在BI里改订单状态源数据。
* 不在BI里直接派车或指挥司机。
* 不在BI里做库存调整。
* 不在BI里维护客户价格和账期。
* BI可以触发预警，但业务处理仍回到ERP/WMS/TMS。



## 8\. 系统底座

### 8.1 模块定位

系统底座不是业务模块，但必须先设计清楚。否则后面B2B、ERP、WMS、TMS、BI都会出现账号各自一套、权限混乱、主数据重复、接口难接的问题。

### 8.2 功能清单

| 一级功能 | 二级功能 | 说明 | 优先级 |

|---|---|---|---|

| 账号管理 | 账号、密码哈希、是否启用、到期日期 | 统一登录基础。 | P1 |

| 权限管理 | 可用模块、角色权限、菜单权限、数据权限 | 控制谁能看、谁能改。 | P1 |

| 登录安全 | 临时密码、失败次数、最后失败时间、锁定原因 | 防止账号滥用。 | P1 |

| 主数据编码 | 客户、门店、商品、司机、车辆、仓库、线路编码 | 保证各系统引用同一套编码。 | P1 |

| 接口管理 | 模块间API、文件导入、数据同步、失败重试 | 冷启动可先文件导入，后续API。 | P1 |

| 操作日志 | 新增、修改、删除、导入、导出、登录日志 | 方便追责和问题排查。 | P1 |

| 消息通知 | 订单、异常、发车、签收、超时提醒 | 统一通知，不要散落到各模块。 | P2 |

| 文件中心 | 导入模板、导出报表、签收照片、回单附件 | 统一存储和权限控制。 | P2 |



### 8.3 账号字段建议沿用当前字段

| 字段 | 用途 | 备注 |

|---|---|---|

| 账号 | 用户登录名 | 唯一值，不可重复。 |

| 密码哈希 | 存储加密后的密码 | 不要明文存储密码。 |

| 是否启用 | 控制账号是否可用 | 停用后不可登录。 |

| 到期日期 | 控制账号有效期 | 适合临时人员/外协账号。 |

| 可用模块 | 控制能进入哪些模块 | 例如：TMS,WMS,BI。 |

| 备注 | 账号说明 | 记录岗位、来源、特殊权限。 |

| 最近登录时间 | 审计 | 便于识别长期未用账号。 |

| 临时密码 | 密码重置 | 建议设置有效期，首次登录强制修改。 |

| 失败次数 | 安全防护 | 达到阈值自动锁定。 |

| 最后失败时间 | 安全审计 | 用于判断异常登录。 |

| 锁定原因 | 账号冻结说明 | 例如：密码错误过多、离职、到期。 |

## 11\. 系统之间的数据接口

| 接口方向 | 触发动作 | 传递数据 | 备注 |

|---|---|---|---|

| B2B → ERP | 客户提交订单 | 客户、门店、商品、数量、价格、备注、要求送达时间 | ERP审核后生成销售订单。 |

| ERP → WMS | 订单确认/生成出库计划 | 出库单、SKU、数量、门店、批次要求、时效要求 | WMS生成拣货复核任务。 |

| WMS → ERP | 收货/出库/盘点完成 | 实际数量、差异、库存变动、批次效期 | ERP更新账面库存。 |

| WMS → TMS | 货物复核完成/待装车 | 待配送订单、线路货区、体积重量、待装状态 | TMS安排车辆和司机。 |

| TMS → WMS | 派车完成/司机到仓 | 车牌、司机、线路编号、装车顺序 | WMS按线路装车交接。 |

| TMS → ERP | 签收完成/异常闭环 | 签收状态、回单、拒收、短少、赔付、运费明细 | ERP做对账和结算。 |

| TMS → B2B | 发车/在途/签收 | 物流状态、预计到达、签收回单 | 客户可查询。 |

| 各系统 → BI | 定时/实时同步 | 订单、仓库、配送、异常、成本、KPI | BI只读为主。 |



## 12\. 开发落地建议

### 12.1 当前阶段不要直接做成五套大系统

你现在的重点不是一口气重做B2B、ERP、WMS、TMS、BI，而是先把代码、页面、表、权限、数据源按模块归位。建议先做“单体系统内部模块化”，再逐步演进成多服务或多端系统。

### 12.2 推荐菜单结构

| 一级菜单 | 二级菜单 | 归属模块 |

|---|---|---|

| 首页 | 今日任务、异常提醒、快捷入口 | BI/系统底座 |

| 基础资料 | 客户、门店、商品、司机、车辆、仓库、账号 | ERP/WMS/TMS/系统底座 |

| 订单经营ERP | 订单导入、销售订单、采购订单、库存账、价格、对账 | ERP |

| 仓库作业WMS | 收货、上架、库存、拣货、复核、装车、盘点、退货 | WMS |

| 配送调度TMS | 排线、派车、司机任务、车辆状态、签收、配送异常、运费 | TMS |

| 数据看板BI | 订单看板、仓库看板、配送看板、异常看板、成本看板 | BI |

| 系统设置 | 账号、权限、角色、接口、日志、模板、消息 | 系统底座 |



### 12.3 推荐代码目录

如果现在是Python/桌面exe/轻量后台，建议先按下面方式拆目录。

```text
project/
  app.py                         # 程序入口
  core/                           # 系统底座
    auth/                         # 登录、密码哈希、账号状态
    permissions/                  # 角色、模块权限
    config/                       # 配置、路径、环境
    logs/                         # 操作日志
    import\\\_export/                # 通用导入导出
  modules/
    b2b/                          # B2B客户下单/查询，冷启动可先空着
    erp/                          # 商品、客户、订单、采购、库存账、结算
    wms/                          # 收货、上架、库存、分拣、复核、装车
    tms/                          # 排线、派车、司机、车辆、签收、异常
    bi/                           # 看板、日报、KPI、成本分析
  data\\\_access/                    # 数据库访问层
  integrations/                   # 高德、飞书、Excel、外部系统接口
  templates/                      # Excel模板、导入模板、报表模板
  tests/                          # 测试用例
```

### 12.4 分阶段开发顺序

| 阶段 | 目标 | 要完成的模块 | 验收标准 |

|---|---|---|---|

| 第0阶段：拆清楚 | 把现有功能归位 | 模块菜单、数据字典、功能清单、权限字段 | 每个功能都有唯一归属模块。 |

| 第1阶段：TMS先跑通 | 订单导入后能排线、派车、签收 | 订单导入、门店坐标、单/多路线排线、司机任务、签收回传 | 当天订单能从导入到签收闭环。 |

| 第2阶段：WMS基础版 | 仓库分拣复核装车可控 | 出库任务、分拣、复核、线路集货、装车交接 | 司机不再进仓找货，装车责任清楚。 |

| 第3阶段：ERP基础版 | 账货和结算能算清 | 商品、客户、价格、库存账、销售单、采购单、客户对账、司机结算 | 订单、库存、结算有统一口径。 |

| 第4阶段：BI基础版 | 老板能看进度和成本 | 订单、仓库、配送、异常、成本五张看板 | 每天自动生成日报，不靠群里问。 |

| 第5阶段：B2B商城 | 客户自主下单 | 商品展示、价格、下单、订单查询、售后入口 | 客户下单不再主要靠微信/电话。 |

| 第6阶段：智能补货/优化 | 从经验驱动到数据驱动 | 销量预测、补货建议、库存周转、客户/线路利润优化 | 能给采购和运营输出建议。 |



## 13\. 第一版P0功能清单

下面是建议最先开发或梳理的P0/P1功能，不要一开始做太多。

| 模块 | P0/P1功能 | 为什么先做 |

|---|---|---|

| 系统底座 | 账号登录、模块权限、操作日志、导入导出模板 | 没有权限和模板，后续模块会乱。 |

| ERP | 客户/门店/商品主数据、订单导入、销售订单、库存账基础 | 所有仓配动作都依赖这些基础数据。 |

| TMS | 单路线、多路线、人工排线、路线核验、派车、司机任务、签收 | 这是当前最贴近业务落地的核心。 |

| WMS | 出库任务、分拣、复核、线路集货、装车交接 | 解决司机找货、错漏、发车晚。 |

| BI | 订单进度、配送进度、异常台账 | 先让老板和运营看清当天是否跑完。 |

| B2B | 暂缓完整商城，先预留订单入口 | 冷启动阶段可先导单，不急着做完整商城。 |



## 14\. 验收口径

| 模块 | 验收问题 | 通过标准 |

|---|---|---|

| B2B | 客户能不能独立下单？ | 客户能看商品、看价格、提交订单、查订单状态。 |

| ERP | 经营账能不能算清？ | 商品、客户、订单、库存账、对账、结算口径统一。 |

| WMS | 仓库能不能准确出货？ | 收货、分拣、复核、装车都有状态和责任人。 |

| TMS | 配送能不能闭环？ | 排线、派车、发车、到店、签收、异常、运费都有记录。 |

| BI | 管理层能不能看清全链路？ | 订单、仓库、配送、异常、成本五类看板可用。 |

| 系统底座 | 系统能不能安全可控？ | 账号权限、日志、接口、导入导出、消息通知基础可用。 |



## 15\. 开发时最容易踩坑的地方

| 风险点 | 表现 | 处理建议 |

|---|---|---|

| 主数据重复维护 | 客户、门店、商品在多个模块名称不一致 | 设唯一编码，ERP/底座做主档，其他模块引用。 |

| 订单状态混乱 | B2B、ERP、WMS、TMS各有一套状态 | 设计统一订单状态流，分清业务状态和作业状态。 |

| ERP和WMS库存打架 | 账面库存和库位库存不一致 | ERP管账，WMS管实物，所有实物变动回传ERP。 |

| WMS和TMS交接不清 | 司机到仓找货、发车晚、责任扯皮 | 装车交接单必须作为WMS到TMS的切换点。 |

| 异常没有闭环 | 异常散落在微信群，无法复盘 | 每个异常必须有类型、责任、处理人、关闭时间、赔付金额。 |

| BI做成假大屏 | 看起来好看，但数据不准 | 先保证数据源、口径、日报，再做大屏样式。 |

| 一开始做太重 | 开发周期长，业务等不起 | 先单体模块化，先跑通TMS/WMS，再补ERP/B2B/BI。 |



## 16\. 最终建议

当前最务实的做法是：

* 先把现有工具和表格按六大模块归位。
* 先定数据字典和状态流，不急着重写全部代码。
* 优先把TMS排线配送和WMS装车交接跑通。
* ERP先做基础主数据、订单、库存账、结算，不急着做复杂补货算法。
* BI先做日报和五张基础看板，不急着做大屏。
* B2B商城可以后置，先通过Excel/表单/导入跑订单入口。



最终目标不是把系统名字做全，而是把链路跑顺：**客户能下单，ERP能算账，仓库能准确出货，TMS能高效配送，BI能看清经营，系统底座能管住权限和数据。**
