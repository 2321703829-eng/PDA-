## 一、文档定位

这份文档只解决“系统菜单和现有功能如何重组归位”。

这里明确 3 个前提：

1. 本次菜单重组后，一级菜单层面取消“物流”模块
2. 取消“物流”一级菜单，不等于删除既有物流能力
3. 对象边界、原生模块承接和本期实施顺序，仍以现行总纲和模块归属表为准

一句话收口：

**本次是菜单重组和入口归位，不是把既有物流对象整体并入 TMS，更不是把本期优先级改成“先做 TMS 再做 ERP”。**

---

## 二、现状盘点

当前系统一级菜单主要包括：

| 现有一级菜单 | 现有子菜单 | 当前理解 |
|---|---|---|
| 天枢科技企业系统 | 首页 | 系统入口与快捷面板 |
| Contacts | Contacts, Configuration | 客户、门店、联系人底座入口 |
| 物流 | 物流工作区、调度、运单、留痕、证据、异常、导入中心、司机管理、车辆管理 | 既有物流与配送相关功能入口集合 |
| Invoicing | Dashboard, Customers, Vendors, Accounting, Review, Reporting, Configuration | 财务、发票、会计、账务相关入口 |
| Inventory | Overview, Operations, Products, Reporting, Configuration | 仓库、商品、库存、作业相关入口 |
| Employees | Employees, Departments, Configuration 等 | 员工、人事、组织相关入口 |
| Fleet | Fleet, Reporting | 车辆与车队底座入口 |

现状问题不是“物流模块不能存在”，而是：

- 现有菜单更接近按历史模块堆叠
- 不符合本期 `ERP / WMS / TMS / BI / 系统底座` 的阅读方式
- 用户很难从菜单上直接看出每块功能归属

---

## 三、重组后的一级菜单

本次正式建议将一级菜单收口为 6 个：

1. `首页`
2. `基础资料`
3. `订单经营 ERP`
4. `仓库作业 WMS`
5. `配送调度 TMS`
6. `数据看板 BI`
7. `系统设置`

说明：

- 这里取消“物流”一级菜单
- 既有物流相关入口按职责拆散到 `WMS`、`TMS` 和少量联动入口
- 若最终需要严格控制数量，可把 `首页` 作为系统默认首页而不是独立一级菜单

| 重组后的一级菜单 | 主要承接内容 | 主要来源 |
|---|---|---|

| 系统设置 | 用户、角色、权限、日志、模板、消息、接口、组织架构 | `base`、`mail`、Employees 部分入口、各模块配置页 |

## 五、逐模块正式设计

### 5.1 首页

| 二级菜单 | 来源 | 处理方式 |
|---|---|---|
| 首页 / 仪表盘 | 天枢科技企业系统 → 首页 | 保留或轻改 |
| 今日任务 | 新增 | 本期可占位 |
| 异常提醒 | 新增 | 本期可占位 |

说明：

- 首页只做入口和提醒，不承载业务主对象

### 5.2 基础资料

| 二级菜单 | 主责对象 | 主要来源 | 处理方式 |
|---|---|---|---|
| 客户管理 | ERP | `contacts` / `res.partner` | 轻改原生 |
| 门店管理 | ERP 主档 + TMS 配送档案 | `contacts` / `res.partner` | 轻改原生，后补配送字段 |
| 供应商管理 | ERP | `res.partner` 供应商 | 轻改原生 |
| 商品管理 | ERP | `product.template` / `product.product` | 轻改原生 |
| 仓库档案 | WMS | `stock.warehouse` | 轻改原生 |
| 库位档案 | WMS | `stock.location` | 轻改原生 |
| 员工档案 | 系统底座 | `hr.employee` | 轻改原生 |
| 司机档案 | TMS | `hr.employee` + 既有司机资料 | 轻改原生 + 自定义 |
| 车辆档案 | TMS | `fleet` + 既有车辆资料 | 轻改原生 |

说明：

- 账号和密码不放在“员工档案”里承接
- 用户与权限主承载仍是 `res.users / groups / access rules`

### 5.3 订单经营 ERP

| 二级菜单 | 主责对象 | 主要来源 | 处理方式 |
|---|---|---|---|
| 订单导入 | ERP | 自定义导入批次 + 既有导入入口 | 自定义 |
| 销售订单 | ERP | `sale` | 轻改原生 |
| 采购订单 | ERP | `purchase` | 轻改原生 |
| 价格管理 | ERP | 商品价格字段 + 自定义价格规则 | 轻改原生 + 自定义 |
| 库存账管理 | ERP | `stock` 结果聚合 | 轻改原生 + 自定义视图 |
| 客户对账 | ERP | `account` | 轻改原生 |
| 供应商对账 | ERP | `account` | 轻改原生 |
| 收款 / 付款 | ERP | `account.payment` | 轻改原生 |
| 司机 / 车辆结算 | ERP | TMS 运费明细回写 | 自定义 |
| 经营报表 | ERP | `sale` / `purchase` / `account` 报表底座 | 轻改原生 |
| 期间控制 / 结账 | ERP | 自定义结账对象 + `account` 基础能力 | 自定义 |

说明：

- ERP 承接以 `sale / purchase / account / stock` 为主
- 不能简单写成 “Invoicing 承接全部 ERP”
- 发票和账务是 ERP 的一部分，但不是销售、采购、价格的唯一入口

### 5.4 仓库作业 WMS

| 二级菜单 | 主责对象 | 主要来源 | 处理方式 |
|---|---|---|---|
| 仓库概览 | WMS | `stock` | 轻改原生 |
| 入库管理 | WMS | `stock.picking` + 自定义收货工作台 | 轻改原生 + 自定义 |
| 上架管理 | WMS | putaway 底座 + 自定义工作台 | 轻改原生 + 自定义 |
| 库存管理 | WMS | `stock.quant` / `stock.location` | 轻改原生 |
| 出库任务 | WMS | `stock.picking` / `stock_picking_batch` + 自定义任务 | 自定义 |
| 拣货管理 | WMS | 自定义 | 自定义 |
| 复核管理 | WMS | 自定义 | 自定义 |
| 集货管理 | WMS | 自定义 | 自定义 |
| 装车交接 | WMS | 自定义 + 既有物流装车相关留痕 | 自定义 |
| 退货管理 | WMS | `stock` 逆向作业 + 自定义 | 轻改原生 + 自定义 |
| 盘点管理 | WMS | `stock` | 轻改原生 |
| 仓库报表 | WMS | `stock` + 自定义汇总 | 轻改原生 |
| 仓库配置 | WMS | `stock` | 轻改原生 |

说明：

- WMS 负责仓内动作
- 不把拣货、复核、装车动作塞回 ERP 单据表单页

### 5.5 配送调度 TMS

| 二级菜单 | 主责对象 | 主要来源 | 处理方式 |
|---|---|---|---|
| 调度工作台 | TMS | 既有物流工作区 | 复用既有自定义 + 轻改 |
| 排线调度 | TMS | 既有调度模块 | 复用既有自定义 + 轻改 |
| 运单管理 | 既有物流域对象，对外显示在 TMS 菜单 | 既有运单模块 | 复用既有自定义 + 轻改 |
| 派车管理 | TMS | 新增 | 自定义 |
| 装载管理 | TMS / WMS 联动 | 新增 | 自定义 |
| 司机任务 | TMS | 新增或承接小程序后台视图 | 自定义 |
| 在途跟踪 | 既有物流留痕对象，对外显示在 TMS 菜单 | 既有留痕模块 | 复用既有自定义 + 轻改 |
| 签收回单 | 既有物流证据对象，对外显示在 TMS 菜单 | 既有证据模块 | 复用既有自定义 + 轻改 |
| 配送异常 | 既有物流异常对象，对外显示在 TMS 菜单 | 既有异常模块 | 复用既有自定义 + 轻改 |
| 运费计算 / 运费明细 | TMS | 新增 | 自定义 |
| 车辆状态 | TMS | `fleet` | 轻改原生 |
| TMS 报表 | TMS | 既有调度数据 + `fleet` + 自定义汇总 | 轻改原生 + 自定义 |

这里是本次重组最关键的口径：

- 菜单上不再有“物流”
- 但 `waybill / customer_line / trace_event / evidence / exception` 不因此消失
- 它们仍然是既有物流域对象
- 只是页面入口主要被归到 `TMS` 或 `WMS` 菜单下

## 六、对象边界说明

### 6.1 菜单边界

- 一级菜单取消“物流”
- 既有物流相关入口拆到 `WMS`、`TMS`、少量 `ERP` 联动页

### 6.2 对象边界

- `sale.order` 不是物流执行主对象
- `stock.picking` 不是 `waybill`
- `account.move` 不是签收或留痕对象
- `waybill / customer_line / trace_event / evidence / exception` 继续保留

### 6.3 展示边界

- 运单、留痕、证据、异常可以在 TMS 菜单中展示
- 但展示位置变化，不代表对象所有权变化

## 七、与现行方案的统一口径

这份重组稿与现行方案统一后的正式结论如下：

1. 认可取消“物流”一级菜单
2. 认可把现有入口重组为 `ERP / WMS / TMS / BI / 系统设置`
3. 不认可把既有物流对象整体改写为 TMS 对象
4. ERP 承接模块以 `sale / purchase / stock / account` 分工为准
5. 系统底座以 `base / users / groups / access rules` 为准
6. BI 只做看板和汇总
7. 本期开发优先级仍以 ERP 闭环优先

---

## 八、本期实施顺序

本期实施顺序按现行总纲执行，不按历史“先 TMS 后 ERP”的节奏执行。

建议顺序：

### 8.1 第一步：菜单和归属先调整清楚

先完成：

- 一级菜单重组
- 二级菜单归位
- 旧入口保留或平滑迁移
- 角色权限重新映射

### 8.2 第二步：先跑通 ERP 经营闭环

优先补齐：

- 基础资料
- 价格管理
- 销售订单
- 采购订单
- 库存账
- 应收应付
- 收付款
- 对账
- 结账

### 8.3 第三步：补 WMS 核心动作

优先补齐：

- 收货
- 上架
- 出库任务
- 分拣
- 复核
- 集货
- 装车交接

### 8.4 第四步：补 TMS 新增工作台

优先补齐：

- 派车管理
- 司机任务
- 运费明细
- TMS 摘要报表

说明：

- 既有调度、运单、留痕、证据、异常入口先复用
- 真正新增的 TMS 面以派车、任务、运费为主

### 8.5 第五步：补 BI 最小看板

优先补齐：

- 订单看板
- 仓库看板
- 配送看板
- 异常看板
- 成本利润看板

---

## 九、注意事项

1. 菜单重组后可以没有“物流”一级菜单
2. 菜单取消不代表底层物流对象删除或并表
3. 旧入口应尽量平滑迁移，避免用户断路
4. 标记为“暂未开发”的页面可以先占位，但不要影响既有已用功能
5. 管理员、业务员、仓库、司机、财务等角色的菜单与权限要重新收口
6. 本期不要因为菜单重组而引发对象边界大重构

---

## 十、最终结论

这份正式版认可同事稿中最核心的一点：

**本次菜单重组后，系统不再保留“物流”一级菜单。**

但同时明确：

- 这只是菜单与入口重组
- 不是对象所有权重组
- 不是本期优先级重排
- 不是把既有物流主链整体吞进 TMS

因此，最稳妥的落地方式是：

**菜单按新结构重组，底层对象按现行方案保留，新增能力按 ERP -> WMS -> TMS -> BI 顺序推进。**
