## 1. Objective

明确 `B2B` 冷启动阶段所需的最小数据模型、字段边界、接口清单、读写方向和联调顺序，保证后续开发时不把客户入口、ERP 订单承接和仓配摘要再混成一团。

## 2. Boundary

本文件只覆盖：

- `B2B` 冷启动阶段最小数据模型
- `B2B` 前后端接口
- `B2B -> ERP -> WMS/TMS` 的最小读写链

本文件不覆盖：

- 完整营销中心模型
- 完整支付域模型
- 完整售后闭环模型
- BI 明细宽表
- 独立 `b2b.order` 正式订单域

## 3. 设计原则

### 3.1 主对象原则

- 正式订单主对象仍是 `sale.order`
- `B2B` 只新增客户入口所需的轻量对象
- `WMS / TMS` 状态只以摘要形式回传 `B2B`

### 3.2 模型控制原则

当前阶段只建议新建 3 到 4 类轻量对象：

- 可见范围对象
- 购物车草稿对象
- 售后申请对象
- 可选的访问日志对象

不建议当前阶段新建：

- 独立正式订单头 / 行模型
- 独立支付头 / 行模型
- 独立履约跟踪大对象

### 3.3 接口风格

按仓库统一约定：

- admin: `/api/admin/logistics/...`
- mini: `/api/mini/logistics/...`
- open: `/api/open/logistics/...`

`B2B` 面向客户侧，建议统一走：

- `/api/open/logistics/b2b/...`

后台配置或运维接口走：

- `/api/admin/logistics/b2b/...`

## 4. 最小数据模型清单

### 4.1 继续复用的官方 / 现有对象

| 模型 | 角色 | 说明 |
|---|---|---|
| `res.partner` | 客户 / 门店主档 | 继续作为客户和门店主底座 |
| `product.template` | 商品主档 | 继续作为前台展示商品底座 |
| `product.product` | SKU | 如后续区分多规格，则取 SKU 级 |
| `sale.order` | 正式订单头 | `B2B` 提交后正式承接对象 |
| `sale.order.line` | 正式订单行 | `B2B` 提交后正式订单行 |
| `account.move` | 发票 / 应收摘要来源 | 仅用于收款摘要读取 |

## 5. 模型边界说明

### 5.1 `b2b.cart.draft` 和 `sale.order` 的关系

- `b2b.cart.draft` 只服务下单前
- 一旦提交成功，正式业务承接对象变为 `sale.order`
- 不建议把 `b2b.cart.draft` 长期保留成另一个业务订单系统

### 5.2 `b2b.after_sale.ticket` 的关系

- 它是客户入口对象
- 后续可桥接到 ERP / WMS / TMS 的异常处理链
- 当前阶段先保证入口和关联，不急着做复杂闭环

## 6. 最小接口清单

## 6.1 商品列表相关接口

### 1. 获取商品列表

- `GET /api/open/logistics/b2b/products`

用途：

- 返回当前客户可见商品列表

关键参数：

- `keyword`
- `category_lv1_id`
- `category_lv2_id`
- `brand_id`
- `only_saleable`
- `only_priced`
- `page`
- `page_size`

返回重点：

- 商品基础信息
- 展示价格
- 可售状态
- 起订量

### 2. 获取商品详情

- `GET /api/open/logistics/b2b/products/{product_id}`

用途：

- 返回商品详情页最小信息

## 6.2 购物车相关接口

### 3. 获取当前购物车

- `GET /api/open/logistics/b2b/cart`

用途：

- 返回当前客户购物车头和明细

### 4. 加入购物车

- `POST /api/open/logistics/b2b/cart/lines`

请求体重点：

- `product_id`
- `qty`
- `store_partner_id`
- `line_note`

### 5. 修改购物车行

- `PATCH /api/open/logistics/b2b/cart/lines/{line_id}`

请求体重点：

- `qty`
- `line_note`

### 6. 删除购物车行

- `DELETE /api/open/logistics/b2b/cart/lines/{line_id}`

### 7. 清空购物车

- `POST /api/open/logistics/b2b/cart/clear`

### 8. 切换购物车门店

- `POST /api/open/logistics/b2b/cart/change-store`

请求体重点：

- `store_partner_id`

返回重点：

- 重算后的价格
- 商品有效性变化
- 被影响商品提示

## 6.3 下单相关接口

### 9. 获取下单确认数据

- `GET /api/open/logistics/b2b/checkout`

用途：

- 读取当前购物车、门店、付款方式、金额汇总

### 10. 提交订单

- `POST /api/open/logistics/b2b/orders/submit`

请求体重点：

- `store_partner_id`
- `delivery_time_required`
- `delivery_note`
- `b2b_submit_note`
- `b2b_payment_method`
- `order_lines`

返回重点：

- `sale_order_id`
- `sale_order_name`
- `display_status`

## 6.4 订单查询相关接口

### 11. 获取订单列表

- `GET /api/open/logistics/b2b/orders`

关键参数：

- `order_no_keyword`
- `store_partner_id`
- `date_from`
- `date_to`
- `display_status`
- `only_exception`
- `page`
- `page_size`

### 12. 获取订单详情

- `GET /api/open/logistics/b2b/orders/{sale_order_id}`

返回重点：

- 订单头
- 商品明细
- 履约摘要
- 收款摘要
- 售后入口可见性

## 6.5 售后入口相关接口

### 13. 提交售后申请

- `POST /api/open/logistics/b2b/after-sale`

请求体重点：

- `sale_order_id`
- `sale_order_line_id`
- `ticket_type`
- `description`
- `images`

### 14. 获取售后申请列表

- `GET /api/open/logistics/b2b/after-sale`

## 7. 后台配置接口建议

### 7.1 B2B 可见范围配置

- `GET /api/admin/logistics/b2b/catalog-scopes`
- `POST /api/admin/logistics/b2b/catalog-scopes`
- `PATCH /api/admin/logistics/b2b/catalog-scopes/{id}`

## 8. 接口返回结构建议

建议统一：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

分页接口建议：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [],
    "page": 1,
    "page_size": 20,
    "total": 100
  }
}
```

## 9. 核心校验点

### 9.1 商品读取

- 只能读取当前客户可见商品
- 价格必须后台重算
- 不返回无权商品

### 9.2 购物车写入

- 商品必须可售
- 数量必须合法
- 起订量必须满足

### 9.3 提交订单

- 提交时再次重算价格
- 提交时再次校验门店、付款方式和商品有效性
- 成功后生成 `sale.order`

### 9.4 查询订单

- 只能查当前客户自己的订单
- 状态摘要来自 ERP/WMS/TMS/account 聚合结果

## 10. 联调顺序建议

建议顺序：

1. 商品列表接口
2. 购物车接口
3. 下单提交接口
4. 订单查询接口
5. 售后入口接口

## 11. 本期不做

- 完整支付接口
- 优惠券接口
- 复杂促销试算接口
- 多仓拆单接口
- 实时运费计算接口
- 订单取消复杂回滚接口

## 12. 验收口径

通过最小标准：

- 前端能通过接口完成看货、加购、改购、下单、查单
- 正式订单能正确落到 `sale.order`
- 非法商品、非法门店、非法付款方式会被拦截
- 订单详情能正确展示履约摘要和收款摘要
