## 1. Objective

细化 `B2B` 商品列表页和购物车页的字段、显示规则、交互动作和校验逻辑，作为从“看货”到“下单前确认”的直接开发依据。

## 2. Boundary

本文件覆盖：

- `B2B` 商品列表页
- 商品卡片和列表项信息
- 加购动作
- 购物车页
- 购物车数量调整、删除、门店切换和结算入口

本文件不覆盖：

- 商品详情页深度内容
- 订单提交页最终校验
- 完整售后页
- 在线支付页

## 3. 页面目标

### 3.1 商品列表页

目标是让客户快速完成：

- 找商品
- 看价格
- 看是否可售
- 快速加购

### 3.2 购物车页

目标是让客户完成：

- 复核已选商品
- 调整数目
- 选择收货门店
- 看到金额汇总
- 跳转下单页

## 4. 商品列表页设计

### 4.1 页面结构

建议分成 4 个区块：

1. 顶部搜索与筛选区
2. 客户 / 门店信息条
3. 商品列表区
4. 底部或悬浮购物车摘要条

### 4.2 搜索与筛选区字段

| 字段 | 字段键 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 搜索词 | `keyword` | 文本输入 | 否 | 支持商品名、编码、条码模糊搜索 |
| 一级分类 | `category_lv1_id` | 下拉/标签 | 否 | 商品一级分类 |
| 二级分类 | `category_lv2_id` | 下拉/标签 | 否 | 商品二级分类 |
| 品牌 | `brand_id` | 下拉/标签 | 否 | 如当前有品牌主档 |
| 是否仅看可售 | `only_saleable` | 开关 | 否 | 默认建议开启 |
| 是否仅看有价商品 | `only_priced` | 开关 | 否 | 默认建议开启 |
| 排序方式 | `sort_type` | 下拉 | 否 | 销量 / 名称 / 默认排序 |

### 4.3 客户信息条

| 字段 | 字段键 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 当前客户 | `current_customer_name` | 只读文本 | 是 | 登录客户名称 |
| 当前门店 | `current_store_name` | 只读文本 / 切换入口 | 是 | 默认门店 |
| 当前价盘说明 | `current_price_scope_desc` | 只读文本 | 否 | 如客户价 / 门店价 / 区域价 |
| 购物车商品数 | `cart_line_count` | 只读数字 | 否 | 当前已加购行数 |

### 4.4 商品列表项字段

| 字段 | 字段键 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|---|

### 4.5 商品列表页交互规则

#### A. 搜索

- 输入关键字后支持手动搜索
- 可支持防抖搜索，但后端仍需限制查询频率
- 搜索结果只返回当前客户可见商品

#### B. 筛选

- 分类、品牌、可售状态组合筛选
- 切换筛选后保留当前搜索词
- 筛选不应展示当前客户无权看的商品

#### C. 加购

- 默认数量取：
  - 商品起订量
  - 若无起订量则取 `1`
- 点击“加入购物车”时：
  - 若商品已在购物车中，则累加数量
  - 若商品未在购物车中，则新增草稿行
- 成功后更新：
  - 购物车商品数
  - 悬浮购物车摘要

#### D. 不可加购场景

以下场景按钮应禁用或提交时拦截：

- 商品不可售
- 商品无有效价格
- 商品不在客户可见范围
- 输入数量小于最小起订量

## 5. 商品列表页校验规则

### 5.1 前端即时校验

- 加购数量必须大于 0
- 加购数量应满足最小起订量
- 如存在整箱约束，应满足倍数

### 5.2 后端加购强校验

- 商品必须可见
- 商品必须启用
- 商品必须有可用价格
- 商品必须允许 `B2B` 销售
- 数量格式合法

## 6. 购物车页设计

### 6.1 页面结构

建议分成 4 个区块：

1. 门店与订货信息区
2. 购物车商品明细区
3. 汇总与结算说明区
4. 结算动作区

### 6.2 门店与订货信息区字段

| 字段 | 字段键 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| 当前客户 | `customer_name` | 只读文本 | 是 | 登录客户 |
| 收货门店 | `store_partner_id` | 下拉 | 是 | 客户可用门店 |
| 门店地址 | `store_address` | 只读文本 | 是 | 当前门店地址 |
| 付款方式摘要 | `b2b_payment_method` | 只读文本 / 可修改入口 | 是 | 当前默认付款方式 |
| 订货备注预填 | `draft_order_note` | 文本 | 否 | 可提前填写，结算页继续带出 |

### 6.3 购物车商品明细字段

| 字段 | 字段键 | 类型 | 必填 | 说明 |
|---|---|---|---|---|

| 去下单 | `go_checkout` | 按钮 | 是 | 跳到下单页 |

## 7. 购物车页交互规则

### 7.1 数量调整

- 支持 `+` / `-` / 直接输入
- 数量变化后实时刷新：
  - 行小计
  - 总数量
  - 总金额
- 数量改为 `0` 时：
  - 建议弹确认
  - 确认后删除该行

### 7.2 门店切换

- 购物车页允许切换门店
- 切换门店后需重新校验：
  - 商品是否仍可下单
  - 价格是否变化
  - 配送限制是否变化
- 若存在受影响商品，需给出提示并刷新结果

### 7.3 删除商品

- 单行删除应立即生效
- 删除后若购物车为空，应展示空态页

### 7.4 清空购物车

- 需二次确认
- 清空后返回空购物车状态

### 7.5 去下单

点击“去下单”前至少校验：

- 门店已选
- 商品行数大于 0
- 每行数量有效
- 商品仍有可用价格
- 商品仍在客户可见范围

## 8. 购物车页强校验规则

### 8.1 价格重算

进入购物车页时，后端应重新校验并返回：

- 当前价格
- 当前是否可售
- 当前起订量限制

不能直接信任列表页缓存价格。

### 8.2 门店相关校验

- 门店必须属于当前客户
- 门店必须启用
- 门店必须允许 `B2B` 下单

### 8.3 商品相关校验

- 商品仍处于 `is_b2b_visible = true`
- 商品仍在当前客户可见范围内
- 商品仍允许销售

### 8.4 数量相关校验

- 数量大于 0
- 满足最小起订量
- 若配置整箱倍数，则满足倍数

## 9. 空态与异常态

### 9.1 商品列表空态

场景：

- 无搜索结果
- 当前客户暂无可见商品

建议提示：

- `没有找到符合条件的商品，请调整筛选条件。`
- `当前账号暂无可订货商品，请联系业务人员。`

### 9.2 购物车空态

场景：

- 尚未加购
- 已全部删除

建议提示：

- `购物车还是空的，先去挑选商品吧。`

### 9.3 商品失效提示

当商品因价格、可见范围或停用失效时，建议提示：

- `商品【xxx】当前不可下单，请重新确认。`
- `商品【xxx】价格已变化，请重新确认。`
- `商品【xxx】已不在当前门店可订范围内。`

## 10. 与下单页的衔接

从购物车进入下单页时，至少传递：

- `store_partner_id`
- `b2b_payment_method`
- `draft_order_note`
- `order_lines`

下单页不应重新让用户从零选择商品，应直接承接购物车确认后的内容。

## 11. 本期不做

本期商品列表页 / 购物车页不做：

- 智能推荐
- 千人千面营销位
- 复杂促销叠加计算
- 优惠券、积分、满减自动试算
- 实时物流费试算
- 多仓拆单提示

## 12. 验收口径

页面通过最小标准：

- 客户能搜索并筛选商品
- 客户能看到自己的价格
- 客户能完成加购、改数、删行
- 购物车能正确汇总金额和数量
- 非法商品、非法数量、失效价格能被拦截
- 能顺利进入下单页
