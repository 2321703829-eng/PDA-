## 1. Objective

在正式进入开发与上线准备前，先把本期数据迁移和初始化的口径锁住，回答 4 个问题：

1. 哪些数据必须初始化
2. 哪些历史数据要迁，哪些不迁
3. 按什么顺序迁和初始化
4. 如何避免迁移后主数据、库存、状态、权限打架

---

## 2. 使用原则

- 先迁主数据，再迁业务单据，再迁汇总与辅助数据
- 能初始化的不先做复杂迁移
- 本期只迁对 P0 / P1 闭环有价值的数据
- 既有物流域不重做全量迁移，只做必要联动和引用补齐
- 历史脏数据先隔离，不强行一轮洗净再上线

---

## 3. 迁移范围分层

### 3.1 必须初始化

- 账号
- 角色
- 模块权限
- 商品主档
- 客户主档
- 供应商主档
- 仓库主档
- 库位主档
- 门店配送档案
- 司机档案
- 车辆档案
- 价格规则基础表

### 3.2 建议迁移

- 历史销售订单
- 历史采购订单
- 当前有效库存账
- 当前有效实物库存
- 当前应收应付余额
- 近阶段签收回单与配送异常

### 3.3 暂不强制迁移

- 全量历史 BI 快照
- 全量历史细碎日志
- 长周期低价值旧订单
- 全量旧版物流留痕图片链
- 已废弃工具产生的中间清洗表

---

## 4. 初始化对象清单

### 4.1 系统底座初始化

初始化内容：

- 超级管理员账号
- 业务角色模板
- 模块权限模板
- 导入导出模板注册
- 操作日志基础配置

初始化要求：

- 账号先于业务模块初始化
- 角色和模块权限要先能支持 ERP / WMS / TMS / BI 分域访问

### 4.2 主数据初始化

初始化内容：

- 商品主档
- 客户主档
- 供应商主档
- 门店经营主档
- 门店配送档案
- 仓库主档
- 库位主档
- 司机与车辆主档

初始化要求：

- 每个主档都必须先有唯一编码
- 门店经营主档与配送档案要能通过门店编码稳定关联

### 4.3 基础业务规则初始化

初始化内容：

- 基础价格规则
- 客户价 / 行业价
- 结算方式
- 账期规则
- 期间控制初始状态
- 扣赔 / 赔付规则基础项

初始化要求：

- 价格规则优先保证可查、可引用，不一开始追求完整促销体系
- 结账期间至少要明确当前开放期间

## 5. 历史数据迁移策略

### 5.1 商品、客户、供应商

迁移策略：

- 以当前有效主档为准
- 合并重复编码、重复名称、空编码记录
- 对无法自动合并的冲突项，先进入人工确认清单

不要做：

- 多个系统主档直接并存上线

### 5.2 销售订单、采购订单

迁移策略：

- 本期建议优先迁“当前有效”与“近阶段需要追溯”的订单
- 老旧已关闭单据可按归档策略处理

建议保留字段：

- 单据编号
- 客户 / 供应商
- 商品
- 数量
- 金额
- 状态
- 来源渠道
- 创建时间

### 5.3 库存数据

迁移策略：

- ERP 库存账迁当前有效结存
- WMS 实物库存迁当前库位/批次有效库存
- 两边迁完后必须做一次对账校验

必须校验：

- 商品级余额是否一致
- 仓库级余额是否一致
- 差异是否有合理解释

### 5.4 财务余额

迁移策略：

- 本期优先迁当前应收应付余额
- 历史明细不必一开始全量细化进入

建议方式：

- 余额初始化
- 关键未清单据挂接
- 后续再补明细追溯

### 5.5 WMS/TMS 历史作业数据

迁移策略：

- 本期优先迁当前有效任务、近期签收、近期异常
- 不强制全量迁旧任务流水

原因：

- 这类数据量大且结构容易脏
- 对本期闭环最重要的是“当前任务能续跑、近期结果能对账”

### 5.6 既有物流域

迁移策略：

- 既有 `waybill / customer_line / trace_event / evidence / exception` 继续保留
- 本期只补：
  - 与 ERP 销售订单的引用
  - 与 WMS 出库/装车结果的引用
  - 与 TMS 签收/异常结果的引用

不要做：

- 本期重建全量既有物流链
- 本期强行把既有物流链全量重映射进 ERP 主表

---

## 6. 初始化与迁移顺序

建议顺序如下：

1. 初始化系统底座
2. 初始化主数据编码规则
3. 导入商品 / 客户 / 供应商 / 门店 / 仓库 / 库位 / 司机 / 车辆主档
4. 初始化价格、结算方式、账期、期间控制
5. 导入当前有效销售订单 / 采购订单
6. 初始化 ERP 库存账余额
7. 初始化 WMS 实物库存
8. 做 ERP 库存账 vs WMS 实物库存对账
9. 初始化当前应收应付余额
10. 导入近期签收 / 异常 / 运费明细
11. 补既有物流域联动引用
12. 最后做 BI 初始快照

---

## 7. 迁移校验清单

迁移完成后至少检查：

### 7.1 主数据校验

- 商品编码唯一
- 客户编码唯一
- 供应商编码唯一
- 门店编码唯一
- 仓库 / 库位编码唯一
- 司机 / 车辆编码唯一

### 7.2 业务单据校验

- 销售订单总数
- 采购订单总数
- 当前有效订单状态分布
- 订单与客户/商品引用完整性

### 7.3 库存校验

- ERP 账面库存总量
- WMS 实物库存总量
- 差异商品清单
- 差异仓库清单

### 7.4 财务校验

- 应收总额
- 应付总额
- 未清账单数量
- 收付款初始化数量

### 7.5 WMS/TMS 校验

- 当前待执行任务数量
- 近期签收记录数量
- 近期异常记录数量
- 运费明细记录数量

### 7.6 既有物流域联动校验

- 销售订单是否能反查 waybill
- 出库结果是否能反查既有物流对象
- 签收 / 异常是否能反查既有留痕对象

---

## 8. 本期不建议一次性完成的迁移

本期先不要一口气做：

- 全量历史对账明细精细迁移
- 全量历史结账期间精细迁移
- 全量历史 WMS / TMS 流水细表迁移
- 全量历史 BI 指标重算
- 全量既有物流图片和证据链搬迁

建议做法：

- 当前有效优先
- 近期追溯优先
- 历史归档后置

---

## 9. Verify

这份迁移策略是否可用，可以用下面 7 条检查：

1. 是否优先服务本期 P0 / P1 闭环
2. 是否先主数据、后业务、再汇总
3. 是否避免了一次性全量迁移过重
4. 是否明确了 ERP 库存账与 WMS 实物库存的校验步骤
5. 是否保留了既有物流域，而没有要求本期重建
6. 是否能直接指导后续导入脚本和初始化脚本
7. 是否为上线前联调和试运行提供了检查口径
