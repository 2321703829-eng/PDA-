## 1. Objective

这份清单用于把当前阶段从：

- A 线可独立运行
- B 线可独立运行

推进到：

- A/B 共享环境联调通过
- 关键跨域链路闭环成立
- 后续只剩缺陷收口与统一合并

它重点回答 4 个问题：

1. A 线和 B 线之间到底要联哪些对象
2. 哪些链路必须在 `19129` 上跑通
3. 哪些问题属于联调阻塞
4. 联调通过后下一步进入什么阶段

---

## 2. Scope

本轮联调默认在：

- `http://192.168.0.17:19129/`
- 数据库：`odootest`

本轮只关心以下边界：

- A 线：ERP + 财务
- B 线：WMS + TMS + BI
- 既有物流域：保留边界，只做联动、摘要、反查

本轮不做：

- 新增大范围设计
- 重写原生核心模块语义
- 再次大规模调整菜单体系
- 重做既有物流主对象

---

## 3. 联调前置条件

进入 A/B 联调前，至少应确认以下条件已成立：

1. A 线功能已部署到 `19129`
2. B 线功能已部署到 `19129`
3. 双方数据库结构已升级到当前代码版本
4. `admin / admin` 可登录共享环境
5. 人工复核已确认 A 线基本页面可用
6. 人工复核已确认 B 线基本页面可用
7. 双方约定的共享模型归属未被打破

如果以上任一项不成立，本清单不进入正式执行。

## 5. 必跑联调链路

### 5.1 链路 A1：销售来源 -> WMS 出库

目标：
- A 线销售来源字段能被 B 线正确消费

检查项：
- 销售来源字段能落到 `stock.picking`
- `stock.picking` 能显示来源信息
- 可从出库单生成 `wms.outbound.task`
- `wms.outbound.task` 可回看来源对象摘要

阻塞判定：
- 来源对象丢失
- 来源字段落错模型
- WMS 任务无法创建

### 5.2 链路 A2：采购来源 -> WMS 收货

目标：
- A 线采购来源字段能被 B 线正确消费

检查项：
- 采购来源字段能落到入库 `stock.picking`
- 可从入库单生成 `wms.receipt.task`
- `receipt -> putaway` 可完成
- B 线页面能反查采购来源摘要

阻塞判定：
- 收货任务无法生成
- 上架任务无法挂接
- 来源字段与仓库对象不一致

### 5.3 链路 B1：出库执行 -> TMS 派车

目标：
- WMS 与 TMS 交界对象能正常传递

检查项：
- `outbound -> pick -> check -> handover` 完整
- `handover -> dispatch order` 完整
- 交接单能挂接 `route batch`
- 派车单能生成司机任务

阻塞判定：
- 交接单无法生成派车单
- `route batch` 无法挂接
- 司机任务未生成或状态异常

### 5.4 链路 B2：配送执行 -> 签收 / 异常

目标：
- TMS 结果能稳定形成业务结论

检查项：
- 司机任务可到店
- 可生成签收回单
- 可生成配送异常
- 同一派车单下允许一单签收、一单异常

阻塞判定：
- 司机任务无法生成签收或异常
- 派车状态不同步
- 异常与运单无法关联

### 5.5 链路 A3：TMS 结果 -> ERP 摘要

目标：
- A 线页面能看到 B 线执行结果摘要

检查项：
- ERP 页面可看到 WMS 摘要
- ERP 页面可看到 TMS 摘要
- 能反查交接、派车、签收、异常结果

阻塞判定：
- ERP 无法看到执行摘要
- 状态口径与 B 线页面不一致
- 反查入口丢失

### 5.6 链路 A4：财务 / 结账 -> BI

目标：
- A 线结果与 B 线执行结果能汇总到 BI

检查项：
- BI 基础快照可生成
- 快照口径与当日样本一致
- 运费、异常、签收等基础数字能读出

阻塞判定：
- 快照无法生成
- 统计口径与单据页面明显不一致
- BI 直接改写业务数据

## 6. 共享字段联调清单

本轮必须逐项确认以下字段没有打架：

### 6.1 `res.partner`

- 客户字段
- 门店字段
- 物流画像字段
- 配送约束字段

联调要求：
- A 负责主档
- B 只消费和补配送语义，不重复建表

### 6.2 `product`

- 商品编码
- 单位
- 基础分类
- 可供 WMS 消费的数量与单位字段

联调要求：
- A 负责商品主档字段定义
- B 不新建第二套商品主对象

### 6.3 `stock.picking`

- 来源类型
- 门店对象
- WMS 摘要字段
- TMS 摘要字段

联调要求：
- B 负责字段承接
- A 负责来源数据口径稳定

### 6.4 `account`

- 应收应付对象
- 对账关联字段
- 结账锁定字段

联调要求：
- A 负责主对象
- B 只回写执行结果摘要，不改财务主语义

## 8. 联调执行顺序

建议按以下顺序执行，不要打散：

1. 先过共享字段
2. 再过销售来源 -> WMS
3. 再过采购来源 -> WMS
4. 再过 WMS -> TMS
5. 再过 TMS -> ERP 摘要
6. 最后过财务/BI

不建议顺序：

- 先看 BI 再看业务链
- 先调异常再调基础签收
- A/B 各自同时乱改共享模型

每条联调链路建议至少记录：

- 联调日期
- 操作人

- 终点对象


---

## 10. 通过标准

满足以下条件即可认为 A/B 联调通过：

1. 销售来源到 WMS 可跑通
2. 采购来源到 WMS 可跑通
3. WMS 到 TMS 可跑通
4. TMS 结果能回到 ERP 摘要
5. BI 快照能读取当日联调结果
6. 共享模型未出现重复字段或重复语义
7. 没有 A/B 互相覆盖状态源头的情况

---

## 11. 不通过标准

出现以下任一项，即视为联调未通过：

- 共享模型字段重复或冲突
- 来源对象无法传到 WMS
- 交接无法传到 TMS
- 派车结果无法回到 ERP 摘要
- BI 结果与实际样本明显不一致
- 状态源头被双边同时覆盖
- 需要靠手工改库才能跑通链路

---

## 12. 联调通过后下一步

联调通过后，下一步不是继续扩设计，而是：

1. 按实施阶段验收清单做正式验收
2. 收口联调缺陷
3. 统一菜单、权限、摘要展示
4. 准备 A/B 代码合并
5. 形成本轮可回归版本

---

## 13. 当前建议

对当前阶段，建议直接按下面这 3 组优先级执行：

1. P0 联调：
   - 销售来源 -> 出库
   - 采购来源 -> 收货

2. P1 联调：
   - 出库 -> 交接 -> 派车
   - 司机任务 -> 签收 / 异常

3. P2 联调：
   - ERP 摘要回看
   - BI 快照校验

只要这三组通过，就可以进入联调缺陷收口与统一合并阶段。
