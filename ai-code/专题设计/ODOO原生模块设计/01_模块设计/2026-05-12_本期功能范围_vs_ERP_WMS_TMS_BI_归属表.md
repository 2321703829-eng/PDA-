## 1. Objective

把本期要做的功能范围，明确归到下面几类模块中：

1. ERP
2. WMS
3. TMS
4. BI
5. 系统底座
6. 既有物流域

这份表重点解决两个问题：

1. 本期每项功能应该先落在哪个主责模块
2. 哪些功能虽然会和其他模块联动，但不能放错主责位置

---

## 2. 使用原则

- 一项核心功能只认一个主责模块
- 允许跨模块联动，但不允许跨模块重复维护主责数据
- 本期优先把 ERP / WMS / TMS / BI 功能闭环做顺
- 既有物流域继续保留，但当前更多承担联动入口和边界约束职责
- 如果一项功能今天放不准，先看“谁负责最终业务结果”，再定归属

## 4. 本期必须优先收口的归属

本期最容易放错位置、又最应该先锁定的，是下面这些：

### 4.1 应明确归 ERP

- 商品主档
- 客户主档
- 供应商主档
- 价格主档
- 销售订单
- 采购订单
- 库存账
- 应收应付
- 收付款
- 对账
- 结账

不要放错到：

- WMS
- TMS
- 既有物流域

### 4.2 应明确归 WMS

- 库位
- 实物库存
- 收货
- 上架
- 分拣
- 复核
- 集货
- 装车交接
- 盘点
- 仓内退货

不要放错到：

- ERP 的销售 / 采购 / 库存账页面
- TMS 的调度与司机任务页

### 4.3 应明确归 TMS

- 排线
- 派车
- 司机任务
- 在途跟踪
- 签收回单
- 配送异常
- 运费明细
- 门店配送档案

不要放错到：

- ERP
- WMS
- 既有物流留痕页

### 4.4 应明确归 BI

- 订单进度看板
- 仓库作业看板
- 配送进度看板
- 异常闭环看板
- 成本利润看板
- KPI 日报

不要放错到：

- ERP 业务单据页
- WMS / TMS 执行页

### 4.5 应继续留在既有物流域

- `waybill`
- `customer_line`
- `trace_event`
- `evidence`
- `exception`

当前处理原则：

- 本期不是最大新增建设面
- 但绝不能因为做 ERP / WMS / TMS，就把它们吞回销售单、库存单、发票单
- 它们继续作为长期边界和联动对象保留

## 5. 一眼判断规则

| 如果问题是… | 优先归属 |
|---|---|
| 卖给谁、卖什么价、怎么结算 | ERP |
| 向谁采购、采购多少、怎么结算 | ERP |
| 货现在账上有多少 | ERP |
| 货实际在仓里哪个库位、哪个批次 | WMS |
| 仓库该怎么收、存、拣、复、装 | WMS |
| 今天哪些车跑、司机去哪里、是否签收 | TMS |
| 老板今天看经营结果、看异常、看 KPI | BI |
| 长期运单、门店节点、留痕证据对象放哪里 | 既有物流域 |

## 6. Verify

这张归属表是否合理，可以用下面 8 条检查：

1. 本期 8 个核心块是否都能映射到 ERP / WMS / TMS / BI / 系统底座中的主责模块
2. 是否没有把价格、账期、应收应付放进 WMS / TMS
3. 是否没有把库位、批次、分拣、复核放进 ERP
4. 是否没有把排线、签收、司机任务放进 ERP / WMS
5. 是否没有把 BI 当成业务动作源头
6. 是否保留了既有物流对象，没有回退到销售单、发票单、库存单
7. 是否对跨模块能力明确了“主责模块 + 配合模块”
8. 是否能支持后续从单体模块化继续演进到更清晰的 ERP / WMS / TMS / BI 架构
