# B2B 下单页面字段清单与提交校验规则

文档类型：
- 页面规则细化

当前状态：
- active

适用对象：
- 前端开发
- 后端开发
- 测试验收

关联主方案：
- [2026-05-13_B2B订货商城模块设计方案.md](./2026-05-13_B2B订货商城模块设计方案.md)

## 1. Objective

细化 `B2B` 下单页的字段、展示规则、提交校验规则和提交后生成结果，作为 `B2B` 订货入口的直接开发依据。

## 2. Boundary

本文件只覆盖：

- 商品加入购物车后的下单页
- 订单提交前校验
- 订单提交后生成 `sale.order` 的字段映射

本文件不覆盖：

- 商品列表页展示逻辑
- 完整支付页
- 售后页
- 订单查询页

## 3. 页面定位

`B2B` 下单页是客户确认本次订货内容并提交正式销售订单请求的最后一步。

页面目标：

- 让客户确认收货门店、订货明细、送达要求和付款方式
- 让系统在提交前完成最小业务校验
- 提交后直接生成 `sale.order` 和 `sale.order.line`

## 4. 页面结构

下单页建议分成 5 个区块：

1. 收货信息区
2. 订单明细区
3. 配送要求区
4. 付款与结算说明区
5. 金额汇总与提交区

## 5. 字段清单

### 5.1 收货信息区

| 字段 | 字段键 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|---|
| 客户名称 | `customer_name` | 只读文本 | 是 | 登录客户 | 当前登录客户 |
| 收货门店 | `store_partner_id` | 下拉选择 | 是 | 客户可用门店 | 默认取客户默认门店 |
| 门店联系人 | `store_contact_name` | 只读文本 | 否 | 门店主档 | 可自动带出 |
| 门店联系电话 | `store_contact_phone` | 只读文本 | 否 | 门店主档 | 可自动带出 |
| 收货地址 | `store_address` | 只读文本 | 是 | 门店主档 | 门店地址展示 |

### 5.2 订单明细区

| 字段 | 字段键 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|---|
| 商品列表 | `order_lines` | 列表 | 是 | 购物车 | 至少 1 行 |
| SKU编码 | `default_code` | 只读文本 | 是 | 商品主档 | |
| 商品名称 | `product_name` | 只读文本 | 是 | 商品主档 | |
| 规格 | `product_spec` | 只读文本 | 否 | 商品主档 | |
| 单位 | `uom_name` | 只读文本 | 是 | 商品主档 | |
| 箱规 | `package_rule` | 只读文本 | 否 | 商品主档 | |
| 单价 | `price_unit` | 只读金额 | 是 | 客户价规则 | 客户当前可见价格 |
| 数量 | `product_qty` | 可编辑数字 | 是 | 客户输入 | 必须大于 0 |
| 小计 | `line_subtotal` | 只读金额 | 是 | 前端计算 / 后端复核 | `数量 * 单价` |

| 配送备注 | `delivery_note` | 多行文本 | 否 | 客户输入 | 如上楼、停车点说明 |
| 订单备注 | `b2b_submit_note` | 多行文本 | 否 | 客户输入 | 整单备注 |

| 字段 | 字段键 | 类型 | 必填 | 来源 | 说明 |
|---|---|---|---|---|---|
| 付款方式 | `b2b_payment_method` | 下拉 | 是 | 客户主档默认值 / 可选值 | 本期不接在线支付 |

## 6. 字段默认规则

### 6.1 默认带出

- `customer_name`
  - 取当前登录客户
- `store_partner_id`
  - 默认取客户默认门店
- `b2b_payment_method`
  - 默认取客户主档 `b2b_payment_method_default`
- `payment_term_desc`
  - 默认取客户账期 / 月结 / 线下转账说明

### 6.2 不允许前端直接修改

- 客户名称
- 商品单价
- 商品基础资料
- 可售范围判断结果
- 结算规则摘要

## 7. 提交校验规则

### 7.1 页面前端即时校验

提交前至少校验：

- 已选择收货门店
- 商品行数大于 0
- 每行数量大于 0
- 每行数量满足最小起订量
- 付款方式已选择

### 7.2 后端提交强校验

后端提交时必须再次校验，不能只信任前端。

#### A. 客户与门店校验

- 当前登录用户必须绑定有效客户
- `store_partner_id` 必须属于当前客户
- 门店必须处于启用状态
- 门店必须允许 `B2B` 下单

#### B. 商品与可见范围校验

- 每个商品必须为 `is_b2b_visible = true`
- 商品必须在当前客户可见范围内
- 商品必须处于可销售状态
- 商品单位和价格必须能正确读取

#### C. 数量校验

- 数量必须大于 0
- 数量不能为非法小数格式
- 必须满足商品最小起订量 `b2b_min_qty`
- 如存在整箱约束，应满足箱规倍数

#### D. 价格校验

- 每行价格必须从后台价格规则重算，不信任前端传值
- 若客户价失效、缺失或冲突，拒绝提交
- 若提交瞬间价格已变化，以后端重算价格为准

#### E. 付款方式校验

- `b2b_payment_method` 必须在客户允许范围内
- 若客户不是账期客户，不允许提交 `credit`
- 若为线下转账客户，可允许上传付款凭证
- 本期禁止传入在线支付类值

#### F. 订单内容校验

- 整单至少保留 1 条有效订单行
- 订单总金额必须大于 0
- 订单必须能正确映射到当前销售组织 / 仓配承接逻辑

## 8. 提交失败提示建议

提示语尽量业务化，不直接暴露技术异常。

建议提示：

- `请选择收货门店后再提交订单。`
- `当前购物车没有可提交的商品。`
- `商品【xxx】的订货数量必须大于 0。`
- `商品【xxx】未满足最小起订量。`
- `商品【xxx】当前未配置可用价格，请联系业务人员。`
- `当前门店不允许提交订货单，请联系管理员。`
- `当前付款方式不适用于该客户，请重新选择。`
- `订单提交失败，请刷新页面后重试。`

## 9. 提交后的对象映射

### 9.1 订单头

提交成功后生成：

- `sale.order`

建议映射字段：

- `partner_id`
  - 当前客户
- `store_partner_id`
  - 收货门店
- `source_channel = b2b`
- `delivery_time_required`
- `b2b_submit_user_id`
- `b2b_submit_note`
- `b2b_payment_method`

### 9.2 订单行

提交成功后生成：

- `sale.order.line`

建议映射字段：

- `product_id`
- `product_uom_qty`
- `price_unit`
- `name`
- `line_note`

## 10. 提交后的状态建议

提交成功后的初始状态建议为：

- `sale.order`
  - `draft` 或 `to_review`

然后再按 ERP 审核规则流转到：

- `confirmed`
- `wms_processing`
- `tms_processing`
- `signed`
- `delivery_exception`

## 11. 本期不做

本期下单页不做：

- 微信 / 支付宝支付
- 优惠券抵扣
- 积分抵扣
- 自动拆单
- 复杂促销引擎
- 实时配送费结算
- 多地址拆分结算

## 12. 验收口径

下单页验收通过的最小标准：

- 客户能完成一次有效下单
- 系统能正确生成 `sale.order`
- 非法商品、非法数量、非法价格、非法付款方式都能被拦截
- 订单来源能正确标识为 `b2b`
- 后续能进入既有 `ERP -> WMS -> TMS` 链
