## 1. 文档定位

本文件用于从总讨论稿中抽出“执行页统一交互”相关内容，形成独立专题草稿。

当前重点不是覆盖所有前端实现细节，而是先固定：

- 四类执行页的统一入口
- 顶部 / 中部 / 底部的统一骨架
- 左侧待处理区与右侧执行区的统一交互
- 提示条 / toast / 弹窗三层反馈机制
- 未保存输入的拦截边界
- 收货 / 上架 / 拣货 / 复核的差异化模板

## 2. 范围与边界

### 2.1 当前纳入范围

- 收货执行页
- 上架执行页
- 拣货执行页
- 复核执行页
- 执行页统一反馈与确认交互
- 执行页与详情页之间的入口关系

### 2.2 当前不纳入范围

- PDA 深度扫码流程细节
- 移动端极窄屏专用布局
- 复杂异常中心设计
- 全量前端组件命名和资产清单
- 具体 OWL 组件拆分实现细节

## 3. 统一目标与适用范围

当前更推荐把四类执行页统一成：

- 同一信息架构
- 同一交互节奏
- 同一反馈分层
- 同一风格语言

并且明确沿用现有物流模块的后台页面风格：

- 先找物流中最接近的参考页
- 复用页面结构、按钮位置、状态表达、动作节奏
- 只在业务字段和业务动作上做仓管差异

一句话收口：

`执行页业务内容可不同，但页面骨架、交互节奏、反馈分层应保持为同一系统中的兄弟页面。`

## 4. 统一入口规则

当前更推荐四类执行页统一按下面的主入口逻辑：

- 列表页主要承担“查”和“进详情”
- 详情页承担主执行入口
- 执行页承担真实执行动作

也就是统一为：

`列表 -> 详情 -> 执行页`

### 4.1 四类执行页的开始入口

- 收货：入库单详情页 `开始收货`
- 上架：入库单详情页 / 待上架列表 `开始上架`
- 拣货：出库单详情页 / 待拣货列表 `开始拣货`
- 复核：出库单详情页 / 待复核列表 `开始复核`

### 4.2 开始动作后的进入方式

当前更推荐：

- 主方式：进入执行页
- 辅方式：如开始前只需极少参数，可先弹轻量向导
- 不建议：开始动作直接进入普通空白表单页

一句话收口：

`开始动作应进入带上下文的执行页，而不是重新建单。`

## 5. 执行页统一骨架

当前更推荐四类执行页统一采用：

- 顶部上下文区
- 状态 / 提示条
- 中部主从双栏
- 底部 tab 区

### 5.1 顶部上下文区

统一最小字段：

- 主单号
- 货主
- 仓库
- 当前记录状态
- 当前操作人
- 关键时间

顶部右上角主按钮最小建议：

- `返回主单`
- `刷新`
- `完成本次记录`

### 5.2 中部主从双栏

统一建议：

- 左侧 `40%`：待处理明细区
- 右侧 `60%`：当前执行操作区

不建议：

- 上下长页面作为主方案
- 对称双栏
- 一上来拆很多 tab

### 5.3 底部 tab 区

一期最小建议保留：

- `进度摘要`
- `执行日志`
- `关联执行对象`
- `证据 / 附件`

默认打开：

- `进度摘要`

## 6. 左侧待处理区统一规范

当前更推荐左侧统一采用：

- 标准表格列表
- 当前行高亮
- 与右侧联动切换

### 6.1 表格形态

当前不建议：

- 任务卡片列表作为主形态
- 重型可展开表格作为一期主形态

当前更推荐：

- 标准表格 + 当前行高亮 + 右侧联动详情

### 6.2 列结构

统一基础列：

- 商品
- 应处理数量
- 已处理数量
- 剩余数量
- 状态

按页面补少量专属列：

- 收货：条码摘要、批次摘要
- 上架：来源位、目标位摘要
- 拣货：推荐货位、批次摘要
- 复核：已拣数量参考、复核结果摘要

### 6.3 默认排序

当前更推荐：

- 按业务原始顺序稳定排序
- 优先 `sequence / 行号`
- 再用 `id` 或创建顺序兜底

不建议：

- 剩余数量优先
- 货位优先
- 智能重排作为默认排序

### 6.4 已完成行展示

当前更推荐：

- 已完成行继续显示
- 置灰弱化
- 保持原排序位置

不建议：

- 默认直接过滤掉
- 自动置底

### 6.5 自动切下一条

当前更推荐：

- 只沿当前列表向下找第一条未完成、可处理的行
- 找不到就不跳

### 6.6 顶部最小筛选与搜索

当前建议只保留：

- 关键字搜索
- `全部 / 仅看未完成`
- `全部 / 仅看有问题`
- `刷新`

### 6.7 搜索 / 筛选变化时的选中规则

当前更推荐：

- 当前行还在结果集里：保留选中
- 当前行不在结果集里但还有可处理项：切第一条可处理项
- 结果集为空：右侧进入空状态

## 7. 右侧执行区统一规范

当前更推荐右侧统一采用：

- 上方当前项摘要区
- 中部主录入区
- 下方动作区

### 7.1 当前项摘要区

统一最小内容：

- 当前商品
- 当前待处理数量 / 剩余数量
- 已处理数量
- 当前关键提示

### 7.2 主录入区

统一保留：

- 本次处理数量
- 本动作关键字段
- 即时校验提示

### 7.3 动作区

统一主按钮：

- `确认本次`
- `确认并下一条`
- `完成本次记录`
- `取消`

### 7.4 字段展示优先级

统一原则：

- 当前动作必须立即输入、立即判断、立即确认的字段常驻
- 只在部分场景出现的字段放条件区或次级区

### 7.5 状态驱动规则

统一原则：

- `draft / in_progress`：核心录入字段可编辑
- `done / cancel`：核心录入字段只读
- 状态主要影响编辑 / 只读和主按钮可用性
- 不建议一期做复杂显隐迷宫

### 7.6 确认后的联动规则

统一建议：

- `确认本次` 成功：右侧先更新，左侧再同步，默认不跳行
- `确认并下一条` 成功：右侧更新、左侧同步、自动切下一条
- 失败：左侧不变，右侧保留输入并报错

## 8. 底部 tab 区统一规范

当前更推荐底部 tab 区全部先做轻量查看型，不做重编辑型。

### 8.1 `进度摘要`

最小展示：

- 当前记录状态
- 已处理数量
- 剩余数量
- 总行数
- 已完成行数
- 是否满足完成条件

### 8.2 `执行日志`

最小展示：

- 时间
- 操作人
- 动作
- 结果
- 简短说明

### 8.3 `关联执行对象`

最小展示：

- `picking` 编号
- `move` 条数 / 数量摘要
- `move line` 条数 / 数量摘要
- 批次摘要（有则显示）

### 8.4 `证据 / 附件`

最小展示：

- 证据类型
- 上传时间
- 上传人
- 关联说明 / 备注
- 预览入口

## 9. 提示反馈统一规范

当前更推荐把执行页反馈统一分为三层：

- 提示条：页内持续反馈
- toast：短暂结果反馈
- 弹窗：需要确认或阻断决策

### 9.1 提示条

位置：

- 顶部上下文区下方
- 中部主从双栏上方

优先级：

1. 阻断性错误 / 校验
2. 当前动作结果
3. 记录级状态
4. 下一步引导

颜色语义只分三种：

- 成功
- 警告
- 错误

文案模板：

- 成功：`完成 / 满足 / 就绪`
- 警告：`提醒 / 继续 / 收尾`
- 错误：`动作未完成 + 原因`

### 9.2 toast

当前更推荐：

- 只承接成功短反馈
- 自动消失
- 不承担复杂错误解释

成功文案模板：

- `本次收货已确认`
- `本次上架已确认`
- `本次拣货已确认`
- `本次复核已确认`

必要时可加短后缀：

- `已切换到下一条`

### 9.3 弹窗

当前更推荐只用于：

- 取消记录
- 离开页面但存在未保存录入
- 覆盖已有录入
- 会导致明显业务后果的逆向 / 高风险动作

并区分：

- 普通确认
- 危险确认

最小视觉区别：

- 主确认按钮颜色
- 标题强调方式
- 风险提示语气

## 10. 未保存输入与确认弹窗规范

当前更推荐把“未保存录入”统一定义为：

`右侧执行区已有可提交改动，但尚未通过“确认本次”落账或被显式清空。`

### 10.1 算未保存录入的情况

- 已填写本次处理数量
- 已填写批次、效期、目标货位、问题备注等关键输入
- 已修改当前动作字段但未确认
- 已扫码带入可提交值但尚未提交

### 10.2 自动清空与必须确认的边界

可自动清空：

- `确认本次` 成功后
- `确认并下一条` 成功后
- 用户主动点明确的 `清空输入`

必须先弹确认：

- 返回主单
- 切换主单
- 离开页面
- 刷新整个页面
- 关闭页面
- 当前有脏数据时切换左侧到另一条明细

### 10.3 弹窗按钮原则

统一建议：

- 默认主按钮放“安全返回 / 留在当前”
- 危险或不可逆动作不抢主位

典型按钮顺序：

- `留在当前页`
- `继续离开`
- `清空后继续`

## 11. 四类执行页差异化模板

在统一骨架下，四类执行页只在业务字段和业务动作上做差异。

### 11.1 收货执行页

- 左：待收货商品明细
- 右：本次收货数量、批次、生产日期 / 效期、暂存位

### 11.2 上架执行页

- 左：待上架明细
- 右：来源位、目标货位、本次上架数量

### 11.3 拣货执行页

- 左：待拣货明细
- 右：当前货位、当前批次、本次拣货数量

### 11.4 复核执行页

- 左：待复核明细
- 右：本次复核数量、复核结果、问题备注

一句话收口：

`四类执行页骨架一致，差异只落在右侧关键字段、左侧专属列和个别入口动作上。`

## 12. 四类执行页按钮 / 字段 / tab 细矩阵

当前更推荐在统一骨架之下，再通过按钮、字段、底部 tab 的细矩阵来固化四类执行页的差异化实现口径。

### 12.1 四类执行页按钮矩阵

| 执行页 | 顶部主按钮 | 右侧主按钮 | 条件 / 次级动作 | 当前推荐说明 |
| --- | --- | --- | --- | --- |
| 收货 | `返回主单` / `刷新` / `完成本次记录` | `确认本次` / `确认并下一条` / `取消` | 批次商品要求批次；效期商品要求日期；可条件补 `清空输入` | 收货以数量确认和批次/效期校验为核心 |
| 上架 | `返回主单` / `刷新` / `完成本次记录` | `确认本次` / `确认并下一条` / `取消` | 目标货位必须明确；可条件补 `清空输入` | 上架以货位选择和本次上架数量为核心 |
| 拣货 | `返回主单` / `刷新` / `完成本次记录` | `确认本次` / `确认并下一条` / `取消` | 批次商品要求批次；可显示推荐货位；可条件补 `清空输入` | 拣货以货位 / 批次 / 数量三项联动为核心 |
| 复核 | `返回主单` / `刷新` / `完成本次记录` | `确认本次` / `确认并下一条` / `取消` | `problem` 时问题备注必填；可条件补 `清空输入` | 复核以结果确认和问题说明为核心 |

当前统一不建议：

- 在顶部重复放 `确认本次`
- 为某一页单独新增很多专属主按钮
- 把危险动作提前到主按钮链中

### 12.2 四类执行页右侧常驻字段矩阵

| 执行页 | 当前项摘要常驻 | 主录入区常驻 | 条件显示 / 次级区 |
| --- | --- | --- | --- |
| 收货 | 当前商品、剩余待收数量、已收数量 | 本次收货数量、批次、生产日期 / 效期、暂存位 | 条码详细信息、更多商品属性、历史收货说明 |
| 上架 | 当前商品、剩余待上架数量、来源位摘要 | 来源位、目标货位、本次上架数量 | 货位更多属性、容量提示、批次补充说明 |
| 拣货 | 当前商品、剩余待拣数量、已拣数量 | 当前货位、当前批次、本次拣货数量 | 其他可选货位、更详细库存分布、路径提示 |
| 复核 | 当前商品、当前待复核数量、已拣数量参考 | 本次复核数量、复核结果、问题备注 | 已拣明细展开、批次 / 货位参考详情、历史复核说明 |

当前统一原则仍然是：

- 必须立即输入、立即判断、立即确认的字段常驻
- 只在部分场景出现的字段放次级区
- 不把大量说明、日志、附件堆进右侧主录入区

### 12.3 四类执行页左侧专属列矩阵

| 执行页 | 统一基础列 | 专属补充列 | 当前推荐说明 |
| --- | --- | --- | --- |
| 收货 | 商品 / 应处理数量 / 已处理数量 / 剩余数量 / 状态 | 条码摘要、批次摘要 | 重点看“应收 / 已收 / 剩余”与条码批次 |
| 上架 | 商品 / 应处理数量 / 已处理数量 / 剩余数量 / 状态 | 来源位、目标位摘要 | 重点看“来源位 -> 目标位” |
| 拣货 | 商品 / 应处理数量 / 已处理数量 / 剩余数量 / 状态 | 推荐货位、批次摘要 | 重点看“推荐从哪拣” |
| 复核 | 商品 / 应处理数量 / 已处理数量 / 剩余数量 / 状态 | 已拣数量参考、复核结果摘要 | 重点看“已拣结果与待复核结果” |

### 12.4 四类执行页底部 tab 关注重点矩阵

| 执行页 | 默认 tab | 最值得关注的 tab | 说明 |
| --- | --- | --- | --- |
| 收货 | `进度摘要` | `进度摘要` / `关联执行对象` | 收货最需要确认数量进度和收货执行事实 |
| 上架 | `进度摘要` | `进度摘要` / `关联执行对象` | 上架最需要确认待上架进度和内部调拨事实 |
| 拣货 | `进度摘要` | `进度摘要` / `执行日志` / `关联执行对象` | 拣货更容易出现多次执行、需要回看操作日志 |
| 复核 | `进度摘要` | `进度摘要` / `执行日志` / `证据 / 附件` | 复核更容易需要问题追溯和留痕查看 |

这里的统一口径是：

- 四类执行页都默认打开 `进度摘要`
- 但不同页面最常查看的次级 tab 可以不同
- 这属于“关注重点不同”，不属于“结构不同”

### 12.5 当前推荐的一句话矩阵口径

`四类执行页统一骨架和主按钮节奏，只在右侧关键字段、左侧专属列和底部关注重点上拉开差异。`

### 13.1 业务模块承接内容

### 13.3 当前推荐的一句话实现口径

## 14. PDA / 扫码交互专章

当前更推荐把 PDA / 扫码交互理解为：

- 不是另起一套完全独立的业务流程
- 而是执行页统一交互规范在移动 / 扫码终端上的延伸形态

也就是说：

- 业务对象不变
- 主状态机不变
- 执行记录不变
- 只是输入方式和页面承载方式更偏扫描与快速确认

### 14.1 一期当前纳入的 PDA / 扫码范围

当前更推荐一期先把 PDA / 扫码范围收在四类执行动作里：

- 收货扫码
- 上架扫码
- 拣货扫码
- 复核扫码

这里的重点不是先做一个独立“PDA 系统”，而是：

- 在统一执行页规范之上
- 预留扫码入口
- 明确扫码成功 / 失败时的统一反馈节奏

### 14.2 当前推荐的总体交互原则

当前更推荐 PDA / 扫码交互遵守以下原则：

1. 仍然服从执行页的统一骨架和状态口径
2. 扫码是输入方式，不是新的业务状态
3. 扫码成功后仍然走：
   - 当前项更新
   - 左右联动
   - 提示反馈
4. 扫码失败优先用页内提示条说明原因，不靠复杂弹窗

一句话收口：

`扫码改变的是输入节奏，不改变主业务规则。`

### 14.3 四类执行页的扫码关注点

**1. 收货扫码**

当前更关注：

- 商品条码识别
- 批次商品的批次补录
- 效期商品的生产日期 / 效期补录

当前更推荐：

- 扫码先定位当前商品
- 再补数量、批次、效期等关键字段

**2. 上架扫码**

当前更关注：

- 来源位识别
- 目标货位识别
- 本次上架数量确认

当前更推荐：

- 扫来源
- 扫目标位
- 确认数量

而不是在 PDA 上堆很多额外属性面板。

**3. 拣货扫码**

当前更关注：

- 拣货货位识别
- 商品条码识别
- 批次识别
- 本次拣货数量确认

当前更推荐：

- 先扫货位
- 再扫商品 / 批次
- 再确认数量

**4. 复核扫码**

当前更关注：

- 商品条码识别
- 待复核项匹配
- 复核结果确认

当前更推荐：

- 扫码先定位待复核项
- 再确认数量与结果
- 有问题时补问题备注

### 14.4 扫码入口当前推荐落点

当前更推荐扫码入口优先放在：

- 右侧执行区主录入区顶部
- 或关键字段前的扫码输入位

不建议：

- 把扫码入口藏进很深的更多菜单
- 每个字段各自发明不同的扫码交互方式

更稳的做法是：

- 在统一执行区里保留稳定的扫码入口位置
- 让用户形成固定肌肉记忆

### 14.5 扫码成功后的统一节奏

当前更推荐扫码成功后仍走统一联动链：

1. 识别当前对象
2. 带入或更新关键字段
3. 页内即时校验
4. 用户确认本次
5. 右侧更新
6. 左侧同步
7. 根据按钮决定是否切下一条

这里和前面已经确认的执行页规则保持一致，不建议扫码后直接跳过确认动作。

### 14.6 扫码失败时的统一节奏

当前更推荐扫码失败优先按以下方式处理：

- 页内提示条提示失败原因
- 当前输入不丢
- 不自动跳行
- 不优先弹窗

典型失败原因包括：

- 条码未识别
- 条码与当前项不匹配
- 货位不匹配
- 批次不匹配
- 当前状态下不可操作

一句话收口：

`扫码失败优先用提示条解释，不打断整页节奏。`

### 14.7 PDA 与 PC 的关系边界

当前更推荐：

- PC 和 PDA 共用同一套业务模型
- 共用同一套状态机
- 共用同一套执行记录
- 共用同一套提示反馈原则

差别主要在：

- 页面宽度
- 输入方式
- 常驻字段多少
- 扫码优先级

当前不建议：

- PDA 单独再造一套业务口径
- PDA 自己维护一套不同状态
- PDA 和 PC 使用完全不同的记录模型

### 14.8 当前推荐的一句话 PDA 口径

`PDA 是执行页统一交互规范在移动扫码场景下的延伸，不是另一套独立业务系统。`

## 15. 移动端 / 窄屏退化方案

当前更推荐把移动端 / 窄屏适配理解为：

- 不是重新设计另一套执行页
- 而是在不破坏统一执行逻辑的前提下，对布局和信息密度做层级退化

也就是说：

- 主状态机不变
- 主按钮语义不变
- 左右联动规则不变
- 只是页面布局从双栏逐步退化为单栏或分段式结构

### 15.1 当前推荐的适配分档

当前建议先按 3 档理解：

**1. 标准桌面宽屏**

- 继续使用：
  - 顶部上下文区
  - 状态 / 提示条
  - 中部主从双栏
  - 底部 tab

**2. 窄屏桌面 / 小尺寸笔记本 / 横屏平板**

- 保留双栏思想
- 但压缩左右栏宽度
- 左栏只保留最关键列
- 右栏减少次级字段常驻

**3. 竖屏平板 / PDA / 移动端窄屏**

- 中部从双栏退化为上下分段
- 先看待处理列表
- 再进入当前执行面板
- 底部 tab 可退化为折叠区或分段区

### 15.2 当前推荐的退化顺序

当前更推荐按下面顺序逐层退化：

1. 先减少表格列
2. 再减少右侧次级字段常驻
3. 再压缩底部 tab 的同时可见性
4. 最后才把中部双栏退化为上下结构

这里的关键是：

- 不要一遇到窄屏就立刻推翻整个执行页节奏
- 应先保主交互，再减信息密度

### 15.3 左侧待处理区的窄屏退化规则

当前更推荐：

- 宽屏：标准表格
- 窄屏：保留基础列，专属列折叠为次级信息
- 更窄时：可退化为简化列表行，但仍按“列表选中当前项”思路保留

不建议：

- 窄屏时突然切成完全不同的卡片交互体系

### 15.4 右侧执行区的窄屏退化规则

当前更推荐：

- 优先保留当前项摘要、本次处理数量、关键字段、主按钮
- 把次级字段移到折叠区或次级区
- 把说明类内容移出主录入区

对于极窄屏，更推荐：

- 先展示当前项摘要
- 再展示主录入区
- 最后展示次级字段

### 15.5 底部 tab 的窄屏退化规则

当前更推荐：

- 宽屏：四个 tab 全保留
- 窄屏：仍保留 `进度摘要` 默认主位
- 更窄时：
  - `执行日志`
  - `关联执行对象`
  - `证据 / 附件`
  
  可退化为折叠区、二级入口或顺序分段

不建议：

- 在窄屏下强行把四个 tab 全部横向塞满

### 15.6 顶部与按钮区的窄屏退化规则

当前更推荐：

- 顶部上下文区始终保留
- 但字段数量可减少到最关键几项
- 顶部右上角只保留最重要的页面级按钮

例如：

- `返回主单`
- `刷新`
- `完成本次记录`

如果更窄，可把次要页面级动作折叠进更多菜单。

### 15.7 当前推荐的一句话退化口径

`移动端 / 窄屏适配的核心不是重做一套页面，而是在保持统一交互节奏的前提下，按“先减信息密度、后变布局结构”的顺序渐进退化。`
