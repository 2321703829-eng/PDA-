## 1. 文档定位

本文件用于把仓管模块中与接口、回传、异步任务相关的内容从总讨论稿中进一步抽出，形成一个可单独继续演进的集成专题稿。

当前重点不是一步写死所有接口字段，而是先固定：

- 一期到底做哪些导入与回传
- 同步与异步的边界
- 任务对象的最小结构
- 幂等与重试的统一口径

## 2. 范围与边界

### 2.1 当前纳入范围

- 入库单导入
- 出库单导入
- 发货状态回传
- 导入任务、回传任务、重试记录
- 幂等标识基础机制
- 任务与业务主单、`stock.picking` 的关联口径

### 2.2 当前不纳入范围

- 全量开放平台设计
- 全量接口字段定稿
- 多系统实时双向主数据同步
- 平台级租户控制面
- 复杂的接口编排中心

## 3. 当前推荐的接口总体原则

当前更推荐把仓管模块的接口与回传统一理解成：

`本地业务主线优先稳定，外部系统联动通过任务层异步补齐。`

也就是：

- 主单和执行事实先在本地落稳
- 外部回传尽量不要阻塞仓库现场动作
- 导入和回传都要尽量可追溯、可重试、可审计

## 4. 一期纳入范围

当前一期更推荐先收在这 3 条主线：

1. `导入`
   - 入库单导入
   - 出库单导入
2. `回传`
   - 发货状态回传
3. `任务`
   - 导入任务
   - 回传任务
   - 重试记录

一句话收口：

`一期集成层目标不是平台化，而是关键数据能进来、关键结果能出去、失败能看到、能重试。`

## 5. 同步与异步边界

当前统一口径为：

`本地提交和轻量校验优先同步，外部联动和重处理优先异步。`

### 5.1 适合同步的动作

- 基础表单保存
- 轻量字段校验
- 查询库存、查询主数据存在性
- 本地创建业务主单

### 5.2 适合异步的动作

- 入库单大批量导入
- 出库单大批量导入
- 发货后客户 / 平台状态回传
- 与外部系统的补偿重试
- 耗时较长或依赖外部网络的调用

### 5.3 当前推荐的一句话边界

`让用户先完成本地动作，再由系统异步把外围动作补齐。`

## 8. 幂等与重试口径

### 8.1 幂等基础原则

当前更推荐：

- 导入任务有自己的幂等键
- 回传任务有自己的幂等键
- 一条业务单据可能存在首次回传、重试回传、补偿回传

### 8.2 重试基础原则

当前更推荐：

- 回传失败后不靠人工重新点按钮覆盖一切
- 失败记录保留
- 通过任务层发起重试
- 最近一次结果和历史结果分开看

### 8.3 当前不建议的一期做法

- 失败后直接改业务主单状态伪装成功
- 只保留“最近状态”不保留历史任务
- 一个外部动作没有幂等键

## 9. 与业务主单和 stock 的关联口径

### 9.1 回传任务与业务主单的关系

当前更推荐：

- 回传任务主关联到业务主单
- 必要时再辅关联到 `stock.picking`

原因是：

- 回传的业务语义来自主单
- 回传的执行事实通常来自 `stock.picking`

### 9.2 当前推荐的最小关联方向

- 回传任务 -> 入库单 / 出库单
- 回传任务 -> `stock.picking`
- 导入任务 -> 业务主单

### 9.3 当前推荐的一句话口径

`任务主语义挂业务主单，执行事实挂 stock 对象。`

## 10. 页面与运维侧最小可见性

一期更推荐至少保证：

- 可查看导入任务列表
- 可查看回传任务列表
- 可查看失败状态
- 可查看最近错误摘要
- 可手动触发有限重试

不要求一期就做复杂任务调度台，但至少要让业务和实施能看见：

- 哪条任务失败了
- 为什么失败
- 是否已重试

## 11. 导入任务状态机与按钮联动矩阵

### 11.1 当前推荐的导入任务状态机

当前更推荐导入任务先统一采用：

- `pending`
- `processing`
- `success`
- `failed`
- `retrying`

### 11.2 当前推荐的状态理解

- `pending`：任务已创建，尚未正式处理
- `processing`：任务正在执行导入
- `success`：导入已成功落地
- `failed`：导入失败，需查看错误或后续重试
- `retrying`：系统或人工已发起重试

### 11.3 当前推荐的导入任务关键按钮

- `开始处理`
- `查看结果`
- `查看错误`
- `发起重试`
- `取消任务`

### 11.4 当前推荐的按钮联动矩阵

| 状态 | 开始处理 | 查看结果 | 查看错误 | 发起重试 | 取消任务 |
|---|---|---|---|---|---|
| `pending` | 可用 | 不可用 | 不可用 | 不可用 | 可用 |
| `processing` | 不可用 | 不可用 | 不可用 | 不可用 | 不建议普通取消 |
| `success` | 不可用 | 可用 | 不可用 | 不可用 | 不可用 |
| `failed` | 不可用 | 可选 | 可用 | 可用 | 不可用 |
| `retrying` | 不可用 | 不可用 | 可选 | 不重复显示 | 不可用 |

### 11.5 当前推荐的一句话口径

`导入任务按钮围绕“开始、查看结果、查看错误、重试”展开，不把复杂任务控制塞进一期。`

|---|---|---|---|---|---|
| `pending` | 可用 | 不可用 | 不可用 | 不可用 | 不可用 |
| `processing` | 不可用 | 不可用 | 不可用 | 不可用 | 不建议普通终止 |
| `success` | 不可用 | 可用 | 不可用 | 不可用 | 不可用 |

### 12.5 当前推荐的一句话口径

`回传任务按钮围绕“发送、查看结果、查看错误、重试”展开，本地发货动作与外部回传动作分层处理。`

## 14. 任务对象与模型 / 文件 / 方法的落地映射

### 13.1 当前推荐的任务模型归属

当前更推荐：

- 导入任务 -> `logistics_wms_integration`
- 回传任务 -> `logistics_wms_integration`
- 重试记录 -> `logistics_wms_integration`

也就是集成层统一承接任务对象，不把导入 / 回传任务散落到入库、出库主线模块中。

### 13.2 当前推荐的模型命名方向

当前更推荐：

- `logistics.wms.import.task`
- `logistics.wms.callback.task`
- `logistics.wms.retry.record`

### 13.3 当前推荐的 XML / 页面文件方向

当前更推荐：

- 任务列表 / 详情页 XML 视图放在 `logistics_wms_integration/views/`
- 搜索视图、列表视图、表单视图按对象拆分
- 菜单与 `act_window` 入口统一放在集成模块下

### 13.4 当前推荐的 Python 方法方向

当前更推荐：

- 导入任务处理主方法：
  - `action_start_import`
  - `action_retry_import`
- 回传任务处理主方法：
  - `action_start_callback`
  - `action_retry_callback`
- 公共校验 / 结果更新方向：
  - `_check_idempotency`
  - `_mark_success`
  - `_mark_failed`
  - `_build_error_summary`

### 13.5 当前推荐的落地边界

当前更推荐：

- 业务主单模块只暴露必要的创建任务 / 触发回传入口
- 任务状态流转、错误摘要、重试控制由集成模块主导
- 不把复杂任务逻辑塞回入库单 / 出库单模型本体

### 13.6 当前推荐的一句话口径

`业务主单负责触发，集成模块负责承接任务对象、状态流转和重试控制。`

## 15. search / filter / group by 与任务页按钮显隐口径

### 15.1 当前推荐的 search 口径

任务页当前更推荐优先支持：

- 任务编号
- 关联业务单号
- 幂等键
- 最近错误摘要中的关键字

### 15.2 当前推荐的 filter 口径

任务页当前更推荐优先支持：

- 任务状态
- 任务类型
- 业务主单类型
- 发起人
- 时间范围
- 仅看失败
- 仅看待重试

### 15.3 当前推荐的 group by 口径

任务页当前更推荐优先支持：

- 任务状态
- 任务类型
- 业务主单类型
- 发起人

### 15.4 当前推荐的按钮显隐联动规则

当前更推荐：

- `仅看失败` 视图下突出 `查看错误`、`发起重试`
- `仅看待重试` 视图下突出 `发起重试`、`终止重试`
- `success` 分组下弱化重试相关按钮
- `pending / processing` 分组下突出 `开始处理` 或 `立即回传`

### 15.5 当前推荐的一句话口径

`任务页的 search / filter / group by 先服务“快速定位失败、快速执行重试、快速查看结果”，按钮显隐围绕状态分组做轻量强化。`

## 16. 当前不建议的一期做法

当前不建议：

- 一开始就做全量开放平台
- 一开始就做复杂接口编排中心
- 把所有动作都做成同步调用
- 用业务主单单个状态字段替代完整任务历史
- 把回传失败直接混进主单普通状态机
