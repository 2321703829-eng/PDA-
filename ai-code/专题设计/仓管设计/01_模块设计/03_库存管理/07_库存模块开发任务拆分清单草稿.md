这份稿子当前主要解决 4 个问题：

1. 库存专题已经写出来的设计内容，后续应该拆成哪些开发任务
2. 这些任务分别归哪个模块、哪个文件和哪一层实现对象

3. 最后看 `9` 到 `11`，确定推荐推进顺序、里程碑和当前不建议提前做的事

## 1. 文档定位

本文件不替代库存专题正文，也不直接替代真实研发排期工具。

它的作用是：

- 把库存专题现有设计稿转成一组可以直接继续落实现的任务清单
- 把“对象、字段、视图、动作、联调、验收、文档回填”收成一条线
- 降低后续推进时“知道怎么设计了，但不知道先做哪块、谁归谁”的切换成本

当前更推荐把这份稿理解成：

`库存专题从设计稿进入实现前评审时的任务拆分底稿。`

## 2. 范围与边界

### 2.1 当前纳入范围

- 库存专题现有设计稿对应的开发任务拆分
- `stock.quant / stock.location / stock.warehouse` 的模型层任务
- search view、tree/form 视图、Smart Button、`ir.actions.act_window` 的视图层任务
- 权限校对、联调验证、文档回填、变更说明补录等实现前后任务
- 建议模块归属、建议文件方向、建议依赖顺序

### 2.2 当前不纳入范围

- 真实代码实现
- 工时估算和人员排班
- 真实版本发布计划
- 数据库性能压测、索引细化和大数据量优化
- 库存专题之外的主单模块完整任务拆分

### 2.3 一句话边界

`本稿先解决“库存专题要拆成哪些任务、按什么顺序做”，不直接替代项目管理系统中的正式排期。`

## 3. 当前统一目标

当前更推荐通过本稿先收住下面 6 件事：

1. 把库存专题从“连续设计稿”转成“可执行任务包”
2. 固定库存实现的第一轮边界，只围绕 Odoo 原生 `stock` 扩展，不并行新造库存真相
3. 固定 `stock.quant` 为库存结果页第一优先实现对象
4. 固定 `stock.location / stock.warehouse` 为位置层和仓层入口对象
5. 固定模型层、视图层、联调层的最小推进顺序
6. 固定代码完成后必须同步做文档回填和 change note 收口

当前更推荐的总原则是：

`先把库存页的结果阅读、反查入口和最小对象增强做稳，再继续往更细的性能优化和复杂权限实现下钻。`

## 4. 任务拆分原则

### 4.1 当前推荐的拆分维度

当前更推荐按下面四层拆任务：

1. 模型层
   - 扩展字段
   - 计算字段
   - Smart Button 方法
   - 领域组装辅助方法

2. 视图层
   - search view
   - tree/form 视图
   - Smart Button 落点
   - action 和菜单入口

3. 联调层
   - 追溯入口跳转验证
   - 权限与记录规则验证
   - 查询口径与页面摘要验证

4. 文档层
   - 设计稿回填
   - 变更说明
   - 验收结论回填

### 4.2 当前推荐的编号规则

当前更推荐采用：

- 开发任务：`INV-Txx`
- 阶段任务：`INV-PH-0x`
- 阶段里程碑：`INV-MS-0x`

### 4.3 当前推荐的依赖原则

- `stock.quant` 相关任务优先于 `stock.location / stock.warehouse`
- 模型字段与方法优先于 XML 视图与 Smart Button 落位
- action 和按钮落位优先于反查联调
- 联调结论优先于“已完成”口径

### 4.4 一句话收口

`库存专题当前最顺的拆法不是按页面零散推进，而是按“quant 优先、模型先行、视图跟进、联调收口”推进。`

### 5.2 当前推荐的主线理解

1. `INV-T01` 到 `INV-T03`

## 6. 模型层任务拆分

- 当前重点对象：
  - `warehouse_id`

  - `available_quantity`
  - `reserved_quantity`
  - `frozen_quantity`

### 6.2 `INV-T02` `stock.quant` Smart Button 与辅助方法落位

## 8. 联调与验收任务拆分

### 8.1 `INV-T08` 库存反查链路联调验证

- 当前重点验证链路：
  - `库存 -> 相关批次`
  - `库存 -> 相关运单`
  - `库存 -> 相关主单`
  - `库存 -> 留痕`
  - `库存 -> 异常`
- 当前验收点：
  - 列表页轻量入口和详情页深读入口不冲突
  - action 的 `domain / context / search_default_*` 语义一致
  - 反查顺序仍以“批次优先、运单次之”收口

### 8.2 `INV-T09` 查询口径、摘要字段与页面阅读方式验证

- 当前重点验证项：
  - 在手量、可用量、占用量、冻结量在页面上表达一致
  - 默认阅读粒度仍是 `货主 + 仓库 + 货位 + 商品 + 批次`
  - 货位页、仓级页、库存页三种视角分工清楚
- 当前验收点：
  - 页面没有出现互相矛盾的摘要字段
  - 页面查询口径与设计稿口径一致

### 8.3 `INV-T10` 权限与记录规则校对

- 当前重点校对项：
  - 菜单可见权限
  - 页面进入权限
  - Smart Button 显隐
  - 记录范围与仓库 / 货主范围控制
- 当前验收点：
  - 权限问题不晚于联调后期才暴露
  - 库存入口页与目标页权限边界基本对齐

### 8.4 `INV-T11` `INV-T12` 验收与文档回填

- 当前重点回填项：
  - 哪些任务已实现
  - 哪些任务已验证
  - 哪些仍停留在设计层
  - 哪些设计稿需同步从“草稿”升级到更正式版本
- 当前验收点：
  - 代码、设计稿、change note 三者没有断链

`库存专题当前不建议并行四处开花，更顺的是先把 quant 结果页主链做稳，再扩入口页和联调面。`

## 10. 当前不建议提前做的事项

当前更不建议在第一轮提前做下面几类事：

- 提前做复杂缓存、预聚合表或并行库存结果表
- 提前把大量摘要字段改成 `store=True`
- 在库存专题里提前发明新的重型客户端查询页
- 在 `stock.location / stock.warehouse` 上承接过多细颗粒库存事实计算
- 在反查链路还没稳定前就先做大量权限细化
- 在联调结论未稳定前就把草稿全量改名为正式规范
