## 章节总览

这份稿子当前主要解决 4 个问题：

1. 库存专题应该联调哪些对象、页面和跳转链路
2. 联调时到底先验证页面能打开，还是先验证口径和上下文正确
3. 哪些结论可以判定“通过”，哪些只能判定“通过但待补”
4. 库存专题如何和 P0、调研清单、统一验证清单接起来，而不是孤立验一轮

建议阅读顺序：

1. 先看 `1` 到 `4`，明确联调范围、边界和对象
2. 再看 `5` 到 `8`，按链路、页面、口径、权限逐组验证
3. 最后看 `9` 到 `12`，把测试数据、结论回填和联读入口一起收住

## 1. 文档定位

本文件不是替代总验证清单，也不是替代库存专题其他正文。

它的作用是：

- 把库存专题自己的联调对象和验收语言单独收口
- 让库存专题的验证不再散在口径稿、反查稿、页面稿里
- 让后续评审时能区分“设计已成立”和“联调已通过”

当前更推荐把这份稿理解成：

`库存专题进入联调前评审和联调后回填时的专项验收入口。`

## 2. 范围与边界

### 2.1 当前纳入范围

- `stock.quant / stock.location / stock.warehouse` 三类库存对象的联调
- 库存列表页、库存明细页、货位页、仓级页的页面验证
- Smart Button、轻量入口、`act_window + domain + context + search_default_*` 的动作验证
- 数量口径、页面摘要、查询视角、反查顺序的一致性验证
- 权限、空状态、异常提示、无权限提示的验证
- 验收结论、待补项、问题回填方式

### 2.2 当前不纳入范围

- 真实代码修复方案
- 详细性能压测
- 全量测试用例库
- 仓管全模块统一上线验收总表
- 库存专题之外主单模块的完整联调展开

### 2.3 一句话边界

`本稿先解决“库存专题要怎么联调和怎么判定通过”，不替代更大范围的统一测试管理。`

## 3. 当前统一目标

当前更推荐通过本稿先收住下面 6 件事：

1. 固定库存专题联调对象和联调顺序
2. 固定库存专题的“页面打开正确”与“口径正确”是两层不同结论
3. 固定反查链路验证顺序仍是 `库存 -> 批次 -> 运单 -> 留痕 / 异常`
4. 固定数量口径、页面摘要、默认筛选语义必须联动验证
5. 固定权限不足、无结果、无关联三类空状态必须区分
6. 固定库存专题联调结果要可回填到任务清单和统一验证清单

当前更推荐的总原则是：

`库存专题的联调不只是看能不能点开，而是看结果是否可读、入口是否有上下文、口径是否不互相打架。`

## 4. 联调对象与阅读顺序

### 4.1 当前联调对象

当前更推荐把库存专题联调对象分成 4 组：

1. 结果对象
   - `stock.quant`

2. 位置对象
   - `stock.location`
   - `stock.warehouse`

3. 目标对象
   - 相关批次
   - 相关运单
   - 相关主单
   - 相关留痕
   - 相关异常

4. 支撑对象
   - 搜索视图
   - 默认动作
   - Smart Button
   - 权限范围

### 4.2 当前建议的联调阅读顺序

当前更推荐：

1. 先验 `库存列表页 -> 库存明细页`
2. 再验 `库存明细页 -> 批次 / 运单 / 主单 / 留痕 / 异常`
3. 再验 `货位页` 和 `仓级页` 的入口语义
4. 最后再验数量口径、权限、空状态和异常提示

### 4.3 一句话收口

`先确认库存页自身是稳定入口，再确认它能把人送到对的目标页。`

## 5. 联调主链路

### 5.1 页面主链

当前主链路应至少验证：

- `库存列表 -> 库存明细`
- `库存列表 -> 最近关联批次`
- `库存列表 -> 最近关联运单`
- `货位页 -> 相关批次 / 运单 / 主单`
- `仓级页 -> 当前批次 / 当前运单 / 当前异常 / 当前货位`

### 5.2 反查主链

当前更推荐按下面顺序验证：

1. `库存 -> 相关批次`
2. `库存 -> 相关运单`
3. `库存 -> 相关主单`
4. `库存 -> 查看追溯`
5. `库存 -> 查看异常`

### 5.3 主链验证最小标准

- 目标页能打开
- 目标页带对了默认筛选
- 目标页保留了来源语义
- 返回后不会丢失原上下文

### 5.4 一句话收口

`库存专题联调的核心不是“跳到了一个页”，而是“跳到了对的页，并且仍然知道自己从哪来”。`

## 6. 页面与动作验证点

### 6.1 库存列表页

需要验证：

- 查询区、表格区、轻量动作区、分页区是否按设计稳定存在
- 轻量入口是否只保留高频入口
- 列表页没有堆满 Smart Button 式重入口

### 6.2 库存明细页

需要验证：

- 头部摘要、主信息区、相关对象区、日志区是否分层清楚
- Smart Button 顺序是否稳定
- `相关批次 / 相关运单 / 相关主单 / 查看追溯 / 查看异常` 命名是否一致

### 6.3 货位页与仓级页

需要验证：

- 货位页承担位置级入口，不越界承担主追溯页
- 仓级页承担聚合入口，不越界承担细颗粒库存阅读
- 仓级页与货位页没有发明和库存页完全不同的入口语言

### 6.4 动作验证

需要验证：

- `act_window` 目标模型是否正确
- `domain` 是否带对对象范围
- `context` 是否保留来源对象语义
- `search_default_*` 是否符合默认阅读路径

### 6.5 一句话收口

`页面层和动作层联调要一起看，否则很容易出现“按钮在，但语义不对”的假通过。`

## 7. 数量口径与结果一致性验证

### 7.1 当前重点验证词典

需要验证：

- 在手量
- 可用量
- 占用量
- 冻结量
- 负库存 / 负可用量的提示方式

### 7.2 当前重点一致性项

需要验证：

- 列表页、详情页、导出和后续报表使用同一组数量词典
- 货位页、仓级页、库存页对同一对象的摘要不互相冲突
- 可用量没有被页面层静默修正为更“好看”的值

### 7.3 当前仍需重点盯住的未定项

联调时仍要重点观察：

- 冻结量一期是否只先纳入位置限制和异常限制
- 占用量是否仅详情页显式，还是列表页也稳定显式
- 未启用批次商品是否统一表现为空批次
- 多货主与单货主场景下货主显隐是否一致

### 7.4 一句话收口

`库存联调的难点往往不是按钮，而是数量词典一旦漂，就会把整条线都带偏。`

## 8. 权限、空状态与异常提示验证

### 8.1 权限验证

需要验证：

- 菜单可见权限
- 页面进入权限
- Smart Button 显隐
- 记录规则下的数据可见范围

### 8.2 空状态验证

需要验证：

- 当前筛选为空时是否提示“当前筛选下暂无结果”
- 当前对象无关联结果时是否提示“当前无相关对象”
- 无权限时是否明确提示“当前角色无权限查看”

### 8.3 异常提示验证

需要验证：

- 异常关注标签是否与真实异常入口一致
- 有未闭环异常时是否正确突出 `查看异常`
- 页面不会用空白或无提示代替异常提示

### 8.4 一句话收口

`对库存查询页来说，最容易误导用户的不是报错，而是把“无权限”和“无数据”混成一种空白状态。`

## 9. 测试数据与样本建议

### 9.1 当前更推荐准备的最小样本

- 正常可用库存样本
- 部分占用库存样本
- 部分冻结库存样本
- 负可用量或异常关注库存样本
- 未启用批次商品样本
- 多货位、多仓、多货主样本

### 9.2 当前更推荐覆盖的场景

- 单仓单货主场景
- 单仓多货主场景
- 多仓场景
- 有批次与无批次并存场景
- 有异常与无异常并存场景

### 9.3 一句话收口

`库存专题如果只用“正常样本”联调，最后最容易漏掉的就是数量口径、空状态和权限边界。`

## 10. 验收结论记录方式

### 10.1 当前更推荐的结论分类

当前更推荐统一分成：

- `通过`
- `通过但待补`
- `不通过`
- `待确认`

### 10.2 当前更推荐的记录维度

建议至少记录：

- 验证对象
- 验证链路
- 结论
- 问题描述
- 关联设计稿
- 是否回填 `07_库存模块开发任务拆分清单草稿.md`
- 是否回填统一验证清单

### 10.3 当前更推荐的回填方式

- 页面与动作问题回填到页面稿、字段稿、XML稿
- 数量口径问题回填到口径稿
- 范围与优先级问题回填到 P0稿、调研清单
- 跨模块权限问题回填到权限专题

### 10.4 一句话收口

`验收记录不是附属物，它本身就是库存专题从“设计成立”走向“可落地”的证据。`

## 11. 当前不建议的一期做法

当前更不建议在一期联调里提前做下面几类事：

- 还没把基础链路走通，就先做复杂性能结论
- 还没把数量口径锁住，就先做大量页面优化结论
- 还没区分无权限与无数据，就直接宣布页面联调通过
- 还没回填设计稿和任务稿，就只在聊天或口头里记录结论
