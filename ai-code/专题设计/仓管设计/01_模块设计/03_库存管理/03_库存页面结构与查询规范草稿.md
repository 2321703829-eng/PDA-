## 章节总览

这份稿子当前主要解决 4 个问题：

1. 库存页、货位页、仓级页在页面层应该采用什么统一骨架
2. 查询页中的搜索、筛选、分组、表头该如何稳定收口
3. 反查入口应该放在列表页、详情页还是 Smart Button 层
4. 这套结构如何尽量复用 Odoo 原生 `stock.quant / stock.location / stock.warehouse` 页面而不是重画

建议阅读顺序：

1. 先看 `1` 到 `4`，明确文档职责、页面对象和分层
2. 再看 `5` 到 `9`，明确各类页面骨架、查询区和反查入口落位
3. 最后看 `10` 到 `13`，明确提示反馈、落地方向和联调验收点

## 1. 文档定位

本文件重点回答“库存页怎么组织”，不直接回答“库存数量怎么定义”。

它的作用是：

- 固定库存专题的页面结构语言
- 固定库存查询页与反查入口页的分层方式
- 避免后续库存页面一部分按列表思路做、一部分按执行页思路做

当前更推荐把这份稿理解成：

`库存专题中负责“页面骨架、查询区节奏、入口落位”的结构规范稿。`

它不直接替代：

- 库存现状与可用量口径稿
- 库存反查与追溯入口稿
- 四类主单统一页面结构规范稿
- 仓储前端接入设计稿

## 2. 范围与边界

### 2.1 当前纳入范围

- `stock.quant` 为主的库存结果列表页与详情页
- `stock.location` 为主的货位页
- `stock.warehouse` 为主的仓级页
- 搜索、筛选、分组、表头和分页的页面结构规则
- Smart Button、摘要字段、轻量快捷入口的落位规则

### 2.2 当前不纳入范围

- 独立库存执行页
- 复杂库存工作台首页
- 报表大屏和经营分析中心
- 留痕页、异常页、运单页正文结构
- 高自由度页面配置器

### 2.3 一句话边界

`本稿先把库存查询页做成稳定、可查、可反查的结果页，不把它扩成新的执行中心。`

## 3. 当前统一目标

当前更推荐通过本稿先收住下面 6 件事：

1. 让库存列表页、货位页、仓级页保持同一套后台语言和阅读节奏
2. 让库存查询页优先回答“现在有什么、在哪里、能不能继续分配”
3. 让详情页承担主要反查入口，而不是在列表页堆满深链接
4. 让搜索、筛选、分组、表头遵循仓管跨模块统一规范
5. 让 Smart Button 和摘要字段与库存反查稿保持一致
6. 让页面实现尽量建立在 Odoo 原生 `tree / form / search` 能力之上

当前更推荐的页面总原则是：

`列表页负责查找与定位，详情页负责解释与反查，货位页和仓级页负责位置与汇总视角。`

## 4. 页面对象与分层

### 4.1 当前推荐的页面对象

库存专题当前更推荐围绕下面 4 类页面对象展开：

- `库存列表页`
- `库存明细页`
- `货位页`
- `仓级页`

其中：

- `库存列表页 / 明细页` 以 `stock.quant` 为主
- `货位页` 以 `stock.location` 为主
- `仓级页` 以 `stock.warehouse` 为主

### 4.2 当前推荐的页面分层

当前更推荐按下面 3 层理解库存专题页面：

1. 查询定位层
   - 库存列表页
   - 货位列表页
   - 仓级列表页

2. 结果解释层
   - 库存明细页
   - 货位明细页
   - 仓级明细页

3. 反查分流层
   - 相关主单
   - 相关批次
   - 相关运单
   - 查看追溯
   - 查看异常

### 4.3 当前推荐的主阅读路径

当前更推荐主路径为：

`库存列表 -> 库存明细 -> 相关批次 / 相关主单 / 相关运单 -> 目标专题页`

并行补充路径为：

- `货位列表 -> 货位明细 -> 相关批次 / 相关主单`
- `仓级列表 -> 仓级明细 -> 当前批次 / 当前运单 / 当前异常`

### 4.4 当前不推荐的路径

当前不建议：

- 从库存列表页直接进入复杂深读页
- 从仓级页直接承担完整追溯阅读
- 把货位页做成第二套库存明细页

## 5. 库存列表页结构规范

### 5.1 当前推荐的列表页骨架

库存列表页当前更推荐采用：

- 顶部搜索与筛选区
- 中部标准结果表格
- 右上轻量动作区
- 底部分页区

统一理解为：

- 顶部回答“怎么找”
- 中部回答“找到了什么”
- 右上回答“还能做什么轻量动作”
- 底部回答“还有多少结果”

### 5.2 顶部搜索与筛选区

当前更推荐库存列表页顶部统一组织为 4 组：

1. 关键字搜索
   - 商品名称
   - 商品编码
   - 条码

2. 归属筛选
   - 货主
   - 仓库

3. 位置与对象筛选
   - 货位
   - 批次
   - 商品

4. 数量状态筛选
   - 有库存
   - 可用量大于 0
   - 存在占用
   - 存在冻结
   - 异常关注

### 5.3 中部标准结果表格

当前更推荐库存列表页表格按下面顺序组织列：

1. 身份列
   - 商品
   - 批次

2. 归属列
   - 货主
   - 仓库
   - 货位

3. 数量列
   - 在手量
   - 可用量
   - 占用量
   - 冻结量

4. 摘要列
   - 最近关联批次
   - 最近关联运单
   - 最新留痕时间
   - 异常关注

5. 时间列
   - 最近更新时间

### 5.4 右上轻量动作区

当前更推荐库存列表页右上动作区只保留：

- 刷新
- 导出
- 保存筛选视图或切换预置视图

当前不建议在库存列表页右上放：

- 大量新建动作
- 危险处理动作
- 直接跳复杂执行页的入口

### 5.5 列表页行级动作

当前更推荐：

- 行点击进入库存明细页
- `最近关联批次`、`最近关联运单` 可作为轻量快捷入口
- `异常关注` 仅在异常场景中提供快速进入异常列表的能力

当前不建议：

- 行内同时堆叠多个主单深链接
- 行内直接展示完整异常摘要卡片

### 5.6 一句话收口

`库存列表页先负责定位结果，再通过少量快捷入口帮助用户决定下一步下钻方向。`

## 6. 库存明细页结构规范

### 6.1 当前推荐的明细页骨架

库存明细页当前更推荐采用：

- 顶部上下文头部
- 中部主信息区
- 下部相关对象与日志区

统一节奏建议为：

1. 先看这条库存结果是什么
2. 再看这条库存结果数量如何、位置如何
3. 最后决定往哪个相关对象继续下钻

### 6.2 顶部上下文头部

当前更推荐头部左侧展示：

- 商品
- 批次
- 货主
- 仓库
- 货位
- 最近更新时间
- 结果标签

头部右侧优先承接：

- `相关批次`
- `相关运单`
- `相关主单`
- `查看追溯`
- `查看异常`

### 6.3 中部主信息区

当前更推荐主信息区拆成两块：

1. 数量摘要区
   - 在手量
   - 可用量
   - 占用量
   - 冻结量

2. 位置与对象区
   - 仓库
   - 货位
   - 商品
   - 批次
   - 货主

当前不建议在这一层直接展开完整留痕或异常正文。

### 6.4 下部相关对象与日志区

当前更推荐下部以 Tab 或分区承接：

- 相关主单摘要
- 相关批次摘要
- 相关运单摘要
- 留痕摘要
- 异常摘要

如页面实现需要更轻量，也可只保留：

- 相关对象摘要区
- 系统日志区

### 6.5 当前推荐的阅读顺序

当前更推荐库存明细页阅读顺序为：

`对象身份 -> 数量摘要 -> 位置信息 -> 相关对象 -> 日志与提示`

### 6.6 一句话收口

`库存明细页负责解释“这条结果到底是什么”，并把主要反查入口集中到头部和下部相关对象区。`

## 7. 货位页与仓级页结构规范

### 7.1 货位页骨架

货位页当前更推荐采用：

- 顶部货位上下文区
- 中部当前位置库存表格
- 下部相关对象摘要区

顶部更推荐展示：

- 货位名称
- 所属仓库
- 货位类型
- 当前批次数
- 当前运单数
- 最近留痕时间

中部更推荐展示：

- 该货位下当前库存结果表格
- 表格结构尽量沿用库存列表页，但收紧为货位内视角

下部更推荐承接：

- 相关批次
- 相关运单
- 相关主单

### 7.2 仓级页骨架

仓级页当前更推荐采用：

- 顶部仓级上下文区
- 中部汇总摘要区
- 下部明细入口区

顶部更推荐展示：

- 仓库编码
- 仓库名称
- 当前批次数
- 当前运单数
- 当前异常数
- 最近留痕时间

中部更推荐展示：

- 当前库存规模摘要
- 当前货位数摘要
- 当前重点异常摘要

下部更推荐展示：

- 当前批次入口
- 当前运单入口
- 当前异常入口
- 当前货位入口

### 7.3 当前推荐的分工

当前更推荐：

- 货位页优先回答“这个位置上现在有什么”
- 仓级页优先回答“这个仓当前总体情况如何”

所以：

- 货位页更偏明细查询
- 仓级页更偏汇总入口

### 7.4 一句话收口

`货位页偏位置明细，仓级页偏总体汇总；两者都不应直接扩成完整追溯主页面。`

## 8. 查询、筛选、分组与表头规范

### 8.1 搜索口径

库存专题当前更推荐搜索优先围绕：

- 商品名称
- 商品编码
- 条码
- 批次号
- 货位编码

### 8.2 筛选口径

库存专题当前更推荐筛选优先围绕：

- 货主
- 仓库
- 货位
- 商品
- 批次
- 数量状态
- 最近更新时间范围

### 8.3 分组口径

库存专题当前更推荐分组优先围绕：

- 按仓库分组
- 按货位分组
- 按商品分组
- 按批次分组

当前不建议一期开放过多自由组合分组预设。

### 8.4 表头优先级

当前更推荐库存查询页表头优先级为：

1. 身份列
2. 位置列
3. 数量列
4. 异常与追溯摘要列
5. 时间列

### 8.5 当前推荐的一句话原则

`搜索先找对象，筛选先缩范围，分组先换阅读视角，表头先保证“位置 + 数量 + 摘要”稳定可读。`

## 9. Smart Button 与反查入口落位

### 9.1 列表页入口落位

列表页当前更推荐只保留：

- `最近关联批次` 轻量快捷入口
- `最近关联运单` 轻量快捷入口
- `异常关注` 标签入口

### 9.2 详情页入口落位

详情页当前更推荐作为主要反查入口承载层。

当前建议把以下入口放在头部 Smart Button 区：

- `相关批次`
- `相关运单`
- `相关主单`
- `查看追溯`
- `查看异常`

### 9.3 货位页入口落位

货位页当前更推荐把入口放在头部摘要区和下部相关对象区：

- `相关批次`
- `相关运单`
- `相关主单`

### 9.4 仓级页入口落位

仓级页当前更推荐把入口放在汇总摘要和下部入口区：

- `当前批次`
- `当前运单`
- `当前异常`
- `当前货位`

### 9.5 当前不建议的做法

当前不建议：

- 列表页顶部直接堆满 Smart Button
- 在仓级页直接放完整留痕阅读入口
- 在库存页同时出现两套不同命名的追溯按钮

### 9.6 一句话收口

`轻量入口留在列表页，主要入口集中到详情页，汇总入口放在仓级页，这样页面职责最稳定。`

## 10. 状态标签、提示反馈与空状态规范

### 10.1 结果标签

库存专题当前更推荐只保留轻量结果标签，例如：

- `正常可用`
- `部分占用`
- `全部占用`
- `部分冻结`
- `全部冻结`
- `异常关注`

### 10.2 提示反馈

当前更推荐提示反馈分三层：

- 页内提示条
- 短暂 Toast
- 阻断确认弹窗

库存查询页主要使用前两层，不建议频繁触发阻断弹窗。

### 10.3 空状态

当前更推荐空状态分两类：

1. 当前筛选为空
   - 提示“当前筛选下暂无结果”
   - 提供清空筛选入口

2. 当前对象无关联结果
   - 提示“当前无相关批次 / 运单 / 主单”
   - 不报错，不弹异常

### 10.4 权限不足提示

当前更推荐：

- 若存在关联对象但无权限查看，提示“存在相关对象，当前角色无权限查看”
- 不通过空白页面伪装成无数据

### 10.5 一句话收口

`库存页更需要稳定、安静、可判断的反馈，而不是高频打断式交互。`

## 11. Odoo 落地方向

### 11.1 当前推荐的视图对象

当前更推荐库存专题优先建立在下面对象上：

- `stock.quant` 的 `tree / form / search`
- `stock.location` 的 `tree / form / search`
- `stock.warehouse` 的 `tree / form / search`

### 11.2 当前推荐的动作方向

当前更推荐：

- 普通查询页入口优先用 `act_window`
- 查询条件优先用 `search view + domain + context`
- 反查入口优先用 Smart Button + act_window

### 11.3 当前不建议的做法

当前不建议：

- 为库存查询专题单独造一套重型 client action 页面
- 用大量前端自定义组件替代原生查询页
- 在没有明确必要的情况下把库存页改造成执行型双栏页

### 11.4 一句话收口

`库存查询页优先复用 Odoo 原生视图对象，定制主要发生在字段、搜索视图、Smart Button 和默认动作层。`

## 12. 联调与验证点

### 12.1 页面结构验证

需要验证：

- 列表页是否稳定采用“查询区 + 表格 + 轻量动作区 + 分页”
- 明细页是否稳定采用“头部 + 主信息 + 相关对象 / 日志”
- 货位页和仓级页是否没有越界承担主追溯页职责

### 12.2 查询体验验证

需要验证：

- 搜索项是否足以定位库存对象
- 筛选组是否符合“归属 / 位置 / 对象 / 数量状态”节奏
- 分组项是否与库存阅读视角一致

### 12.3 入口落位验证

需要验证：

- 列表页是否只保留轻量快捷入口
- Smart Button 是否集中在详情页主位
- 仓级页入口是否以汇总入口为主而不是深读入口

### 12.4 反馈与空状态验证

需要验证：

- 空状态是否明确区分“无结果”和“无权限”
- 异常关注标签是否与实际异常入口一致
- 页面是否没有出现无上下文的空白落页

### 12.5 一句话收口

`联调时既要看页面能不能打开，也要看用户能不能按预期节奏完成“查 -> 看 -> 反查”。`
