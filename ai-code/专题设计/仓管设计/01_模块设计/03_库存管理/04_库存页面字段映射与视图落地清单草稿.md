## 章节总览

这份稿子当前主要解决 4 个问题：

1. `stock.quant / stock.location / stock.warehouse` 三类对象各自的列表页、详情页应该落哪些字段
2. 搜索视图、筛选项、分组选项应该如何从结构规范和口径规范继续下沉
3. Smart Button、快捷入口和 `act_window` 应该怎样和页面字段一起形成一套可实现清单
4. 视图、动作、XML ID 命名应该如何收口，避免后续落地时每页一套命名体系

建议阅读顺序：

1. 先看 `1` 到 `4`，明确这份清单的职责和对象范围
2. 再看 `5` 到 `7`，明确三类对象的页面字段映射
3. 最后看 `8` 到 `12`，明确 search view、动作、命名、实施顺序和验证点

## 1. 文档定位

本文件重点回答“库存页具体该落哪些字段和视图对象”，不再停留在“页面骨架怎么组织”的层面。

它的作用是：

- 把库存页面结构规范继续下沉成可实现清单
- 把库存口径稿和反查稿里的字段与入口整理成对象级映射表
- 减少后续落地时“知道要做什么，但不知道在哪个视图上补什么”的反复讨论

当前更推荐把这份稿理解成：

`库存专题中负责“对象到页面、字段到视图、入口到动作”的实现前清单稿。`

它不直接替代：

- 库存现状与可用量口径稿
- 库存反查与追溯入口稿
- 库存页面结构与查询规范稿
- 数据库设计规范稿

## 2. 范围与边界

### 2.1 当前纳入范围

- `stock.quant` 的列表 / 详情 / search view 映射
- `stock.location` 的列表 / 详情 / search view 映射
- `stock.warehouse` 的列表 / 详情 / search view 映射
- 字段展示、筛选项、分组选项、Smart Button、action 的对照清单
- 视图和动作命名建议

### 2.2 当前不纳入范围

- 真实 XML 代码实现
- 真实 Python 字段定义代码
- 留痕、异常、运单目标页正文结构
- 复杂权限矩阵明细
- 完整菜单树设计

### 2.3 一句话边界

`本稿先解决“每个页面该补什么”，不直接解决“这些字段怎么编码实现”。`

## 3. 当前统一目标

当前更推荐通过本稿先收住下面 6 件事：

1. 固定库存专题三类核心对象的页面字段最小集合
2. 固定列表页、详情页和 search view 之间的字段分工
3. 固定 Smart Button 与摘要字段的落位关系
4. 固定 action、search view 和 XML ID 的命名方向
5. 让落地清单与口径稿、反查稿、页面结构稿保持一致
6. 让后续实现时可以按对象逐个回填，而不是按页面零散补丁式回填

当前更推荐的落地原则是：

`原生对象优先复用，页面字段轻增强，反查入口集中补，search view 统一收口。`

## 4. 对象与落地层级总览

### 4.1 当前推荐的对象角色

| 对象 | 当前页面角色 | 当前重点 |
|---|---|---|
| `stock.quant` | 库存结果页 | 回答当前分布、数量状态、结果反查 |
| `stock.location` | 货位页 | 回答当前位置承载了什么、最近关联了什么 |
| `stock.warehouse` | 仓级页 | 回答仓级总体情况与主要汇总入口 |

### 4.2 当前推荐的落地层级

当前更推荐把落地清单分成 5 层理解：

1. 列表页字段
2. 详情页字段
3. search view 字段
4. Smart Button 与快捷入口
5. action / XML ID

### 4.3 当前推荐的实现归属

根据当前数据库规范稿中的对象边界，当前更推荐：

- `stock.warehouse` 扩展优先归在 `logistics_wms_base`
- `stock.location` 扩展优先归在 `logistics_wms_base`
- `stock.quant` 事实层本身继续复用 Odoo 原生对象，页面增强按库存专题落地

### 4.4 一句话收口

`这份清单不是按“页面长什么样”来拆，而是按“对象在每层视图里要承担什么”来拆。`

## 5. stock.quant 页面字段映射清单

### 5.1 当前页面定位

`stock.quant` 当前更推荐作为库存专题的第一主页面对象。

它主要回答：

- 当前库存结果是什么
- 当前库存落在哪个仓、哪个货位
- 当前在手量、可用量、占用量、冻结量如何
- 这条结果下一步应反查到哪个批次、主单或运单

### 5.2 列表页字段映射

| 字段 | 当前用途 | 当前展示层级 | 当前说明 |
|---|---|---|---|
| `product_id` | 识别对象 | 列表页必显 | 商品身份列 |
| `lot_id` | 承接批次入口 | 列表页建议显式 | 未启用批次时允许为空 |
| `owner_id` 或货主映射字段 | 归属识别 | 列表页建议显式 | 多货主场景必须显式 |
| `warehouse_id` 或仓级映射字段 | 组织归属 | 列表页必显 | 仓库列 |
| `location_id` | 位置识别 | 列表页必显 | 货位列 |
| `quantity` | 在手量底盘 | 列表页必显 | 对齐在手量口径 |
| `available_quantity` 或等价衍生字段 | 可用量 | 列表页必显 | 对齐库存口径稿 |
| `reserved_quantity` 或等价占用字段 | 占用量 | 列表页建议显式 | 一期建议显式展示 |
| `frozen_quantity` 或等价衍生字段 | 冻结量 | 列表页建议显式 | 可由规则衍生 |
| `latest_lot_display` | 最近关联批次摘要 | 列表页轻量入口 | 可点击 |
| `latest_waybill_display` | 最近关联运单摘要 | 列表页轻量入口 | 可点击 |
| `latest_trace_time` | 留痕摘要 | 列表页建议显式 | 仅提示，不一定可点 |
| `has_open_exception` | 异常关注标记 | 列表页建议显式 | 标签或布尔图标 |
| `write_date` | 最近更新时间 | 列表页建议显式 | 时间列 |

### 5.3 详情页字段映射

| 区块 | 字段 | 当前用途 |
|---|---|---|
| 头部身份区 | 商品、批次、货主、仓库、货位 | 回答“这条结果是什么” |
| 头部状态区 | 结果标签、最近更新时间 | 回答“当前结果状态如何” |
| 数量摘要区 | 在手量、可用量、占用量、冻结量 | 回答“当前数量如何” |
| 位置对象区 | 仓库、货位、商品、批次、货主 | 回答“结果落在哪里、归谁” |
| 相关对象摘要区 | 相关主单数、相关批次数、相关运单数 | 回答“下一步往哪里看” |
| 留痕异常摘要区 | 最新留痕时间、是否有未闭环异常 | 回答“是否值得继续下钻” |

### 5.4 search view 字段映射

| 类型 | 当前建议项 |
|---|---|
| 关键字搜索 | 商品名称、商品编码、条码、批次号、货位编码 |
| 快速筛选 | 有库存、可用量大于 0、存在占用、存在冻结、异常关注 |
| 常规筛选 | 货主、仓库、货位、商品、批次、更新时间范围 |
| group by | 仓库、货位、商品、批次 |

### 5.5 Smart Button 映射

| Smart Button | 当前目标 | 当前说明 |
|---|---|---|
| `相关批次` | 批次列表 / 批次详情 | 第一优先追溯入口 |
| `相关运单` | 运单追溯列表 | 第二优先追溯入口 |
| `相关主单` | 入库 / 出库 / 盘点 / 移位相关主单列表 | 第一优先业务解释入口 |
| `查看追溯` | 批次或运单追溯页 | 深读入口 |
| `查看异常` | 当前异常列表 | 异常处理入口 |

| 对象 | 当前推荐名称 |
|---|---|
| tree view | `view_logistics_wms_inventory_quant_tree` |
| form view | `view_logistics_wms_inventory_quant_form` |

## 10. 当前推荐的实现顺序

当前更推荐按下面顺序回填：

1. `stock.quant`
   - 先补 tree / form / search
   - 再补 Smart Button
   - 再补摘要字段

2. `stock.location`
   - 先补 tree / form / search
   - 再补相关批次 / 运单 / 主单入口

3. `stock.warehouse`
   - 先补 tree / form / search

### 一句话收口

`先把库存主结果页做稳，再补位置页，最后补仓级汇总页，推进成本最低。`

## 11. 联调与验证点

### 11.1 字段回填验证

需要验证：

- 列表页字段是否覆盖了身份、位置、数量、摘要、时间五组核心信息
- 详情页字段是否与页面结构稿中的区块分工一致
- 货位页和仓级页字段是否没有越界承担主追溯正文

### 11.2 search view 验证

需要验证：

- 搜索项是否足以定位对象
- 预置筛选是否符合口径稿和结构稿
- group by 是否与库存阅读视角一致

### 11.3 Smart Button 与 action 验证

需要验证：

- 按钮命名是否与反查稿一致
- action 是否能带出默认筛选
- 无关联对象和无权限场景是否有正确反馈

### 11.4 一句话收口

`联调时要一起核对字段、search view、按钮和动作，不要只看页面有没有打开。`
