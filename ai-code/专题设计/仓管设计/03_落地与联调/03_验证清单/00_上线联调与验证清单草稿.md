## 1. 文档定位

本文件用于把仓管模块中与实施、联调、验证、初始化数据、上线切换、培训相关的内容从总讨论稿中进一步抽出，形成一个可独立继续演进的落地专题稿。

当前重点不是一步写完完整项目计划，而是先固定：

- 一期联调范围
- 一期验证范围
- 初始化数据与上线切换边界
- 培训与支持基线

## 2. 范围与边界

### 2.1 当前纳入范围

- 测试口径
- 初始化数据
- 上线切换
- 培训
- 联调节奏

### 2.2 当前不纳入范围

- 全量项目管理计划
- 完整测试用例库
- 详细甘特图与排期工具方案
- 全量运维手册

## 3. 当前推荐的总体原则

当前更推荐统一理解为：

`先让核心链路可验证、可切换、可回看，再扩更复杂的实施和运维能力。`

也就是：

- 联调优先围绕 P0 主链路
- 验证优先围绕关键主单和执行页
- 上线优先保证数据、权限、入口、关键流程稳住

## 4. 一期联调与验证范围

当前一期更推荐优先覆盖：

- 主数据与基础档案
- 入库主线
- 库存查询
- 出库主线
- 盘点 / 移位主线
- 权限与角色
- 执行页关键交互
- 接口与回传主线

一句话收口：

`一期联调与验证先围绕“基础主数据 -> 入库 -> 库存 -> 出库 -> 接口 / 权限”主闭环。`

## 5. 联调清单基线

当前更推荐联调至少覆盖这些对象：

- 主数据与基础档案
- 四类主单
- 四类执行页
- 权限角色与记录规则
- 导入任务与回传任务

当前更推荐联调至少覆盖这些链路：

- 主单创建到执行页进入
- 执行页动作到主状态推进
- 主单与 `stock` 执行事实对齐
- 回传任务与业务主单 / `stock.picking` 对齐
- 页面入口与权限显隐对齐

## 6. 联调对象矩阵

当前更推荐联调对象至少按以下矩阵拆开：

| 对象类别 | 当前联调重点 | 最小联调结果 |
|---|---|---|
| 主数据与基础档案 | 编码、状态、归属、权限范围 | 能查、能进、能按范围看 |
| 四类主单 | 状态推进、按钮显隐、详情页结构 | 能创建、能流转、能回看 |
| 四类执行页 | 入口、按钮、提示、联动、返回 | 能进入、能执行、能完成 |
| 权限与角色 | 菜单、页面、按钮、记录规则 | 能区分角色边界 |
| 导入 / 回传任务 | 状态、重试、错误摘要、关联主单 | 能发起、能失败、能重试 |

一句话收口：

`联调对象先按“主数据 / 主单 / 执行页 / 权限 / 任务”五组拆开检查。`

## 7. 验证清单基线

当前更推荐验证至少覆盖：

- 主状态机是否按预期推进
- 按钮是否按状态和权限正确显隐
- 执行页是否按统一交互规范运行
- 查询、筛选、表头是否符合统一口径
- 证据 / 附件入口是否符合统一边界
- 导入 / 回传任务是否符合状态机、重试、幂等口径

## 8. 验证步骤清单

当前更推荐最小验证步骤按下面顺序推进：

1. 验证基础角色与菜单入口
2. 验证主数据与基础档案可用性
3. 验证四类主单列表页与详情页主路径
4. 验证四类执行页入口、按钮与状态联动
5. 验证权限、记录规则与按钮显隐边界
6. 验证接口与回传任务状态、错误、重试链路
7. 验证查询、筛选、表头、证据入口等跨模块规范
8. 最后做一轮主闭环串联验证

一句话收口：

`验证步骤先从入口、主数据、主单、执行页、权限、接口、跨模块规范逐层推进，最后再做整链路串联。`

## 9. 初始化数据与上线切换基线

当前更推荐初始化数据至少包括：

- 基础角色与权限组
- 货主
- 仓库
- 货位
- 商品扩展与条码映射

当前更推荐上线切换至少关注：

- 菜单与页面入口是否可见
- 关键角色是否可登录并进入对应页面
- 关键主单是否可从列表进详情再进执行
- 接口与回传任务入口是否可见

## 10. 培训与支持基线

当前更推荐培训优先覆盖：

- 仓管操作员
- 仓管主管 / 组长
- 运营 / 客服
- 实施 / 管理员

当前更推荐培训内容优先覆盖：

- 主单流转
- 执行页进入与退出
- 常见错误提示与处理方式
- 权限边界
- 上线初期问题反馈入口

## 11. 当前不建议的一期做法

当前不建议：

- 一期就写成很重的全量项目管理手册
- 在未稳定主链路前先做复杂培训体系
- 联调未完成就直接按正式运营口径切换
- 只做页面冒烟，不做状态机和权限联动验证

## 12. v0.1 收口与后续补充方向

到当前阶段，这份专题稿已经固定了以下 `v0.1` 基线：

- 上线联调与验证的总体原则

- 联调清单基线
- 联调对象矩阵
- 验证清单基线
