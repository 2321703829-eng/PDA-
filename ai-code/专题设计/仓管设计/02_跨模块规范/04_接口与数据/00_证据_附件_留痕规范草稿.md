## 1. 文档定位

本文件用于把仓管模块中与证据、附件、图片、视频、留痕相关的内容从总讨论稿中进一步抽出，形成一个跨模块统一规范草稿。

当前重点不是一步设计完整留痕平台，而是先固定：

- 一期挂点范围
- 二进制与元数据分层
- 页面最小展示口径
- 与权限、对象存储、日志的关系

## 2. 范围与边界

### 2.1 当前纳入范围

- 图片 / 视频等证据材料
- 证据元数据
- 执行页与详情页中的证据 / 附件入口
- 与对象存储的分层方向
- 与执行日志、异常信息区的边界

### 2.2 当前不纳入范围

- 完整对象存储服务设计
- 大规模媒体处理链路
- 全量审计平台
- 全量媒体权限系统

## 3. 当前推荐的总体原则

当前更推荐统一理解为：

`二进制走外部对象存储，Odoo 主体承载业务关联、元数据、状态与入口。`

也就是：

- 图片 / 视频二进制不长期压在 Odoo 默认附件体系里
- Odoo 里保留：
  - 关联对象
  - 类型
  - 上传人
  - 上传时间
  - 备注
  - 预览 / 访问 key

## 4. 一期纳入范围

当前一期更推荐先覆盖这些挂点：

- 收货
- 上架
- 拣货
- 复核
- 发货确认
- 异常处理

一句话收口：

`一期留痕重点先围绕仓内高风险动作和争议节点，不追求所有动作全量媒体化。`

## 5. 二进制与元数据分层口径

当前更推荐：

- 二进制文件：对象存储或外部文件存储
- Odoo 模型：保存元数据、业务关联、展示入口

当前元数据最小建议包括：

- 证据类型
- 业务对象类型
- 业务对象主键
- 上传人
- 上传时间
- 文件大小
- 文件 key / access key
- 备注

## 6. 当前推荐的挂点范围

当前更推荐挂到以下两层：

### 6.1 执行页挂点

- 底部 `证据 / 附件` 页签
- 右侧执行区的轻入口

### 6.2 详情页挂点

- 异常信息区
- 日志区旁的证据查看入口

## 7. 证据元数据字段字典基线

当前更推荐一期先固定这些元数据字段：

- 证据编号
- 证据类型
- 业务对象类型
- 业务对象主键
- 上传人
- 上传时间
- 文件大小
- 文件 key / access key
- 备注
- 业务状态（可选）

一句话收口：

`证据模型先围绕“身份、关联、上传、访问、说明”五类字段收口。`

## 8. 页面展示与挂点结构基线

当前更推荐最小展示：

- 证据类型
- 上传时间
- 上传人
- 备注
- 预览入口

如果当前页无证据，也允许：

- 保留结构
- 展示空状态

### 8.1 执行页挂点基线

当前更推荐：

- 底部 `证据 / 附件` 页签作为主入口
- 右侧执行区保留轻量查看或上传入口

### 8.2 详情页挂点基线

当前更推荐：

- 异常信息区侧重“问题相关证据”
- 日志区侧重“动作时间线中的证据查看”

### 8.3 当前推荐的一句话口径

`执行页负责现场留痕，详情页负责后看与审计。`

## 9. 与权限、对象存储、日志的关系

当前更推荐统一口径为：

- 证据可见性受页面权限与记录规则约束
- 对象存储只承载二进制，不承载业务语义
- 执行日志承载动作轨迹，证据区承载材料本身

一句话收口：

`日志回答“发生了什么”，证据回答“有哪些材料可以看”。`

## 10. 证据对象与权限 / 记录规则联动口径

当前更推荐：

- 证据对象本身不单独发明一套复杂权限体系
- 优先跟随所挂业务对象的页面权限和记录规则
- 下载 / 预览等能力在此基础上再做动作层控制

当前推荐的联动理解：

- 入库 / 出库 / 盘点 / 移位主单可见 -> 对应证据入口可见
- 执行页可进入 -> 对应执行页证据区可见
- 记录规则限制某货主 / 仓库范围 -> 对应证据也应跟随收口

一句话收口：

`证据可见性优先跟随业务对象可见性，不单独漂移。`

## 11. 当前不建议的一期做法

当前不建议：

- 让大体积媒体长期留在 Odoo 默认附件体系
- 让证据区和日志区互相替代
- 一期就做很重的媒体工作台
- 一开始就把所有动作全部挂证据能力

## 12. v0.1 收口与后续补充方向

到当前阶段，这份专题稿已经固定了以下 `v0.1` 基线：

- 证据 / 附件 / 留痕的总体边界
- 二进制与元数据的分层方向
- 一期优先挂点范围
- 证据元数据字段字典基线
- 页面展示与挂点结构基线
- 与权限、对象存储、日志的边界
- 证据对象与权限 / 记录规则联动口径

后续更适合继续补充的方向包括：

- 证据页 / 页签结构模板
- 证据与异常处理的更细联动
- 证据权限与下载 / 预览控制口径
