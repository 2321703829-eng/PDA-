## 1. 文档定位

本文件用于从：
- `状态与流程统一规范草稿`
- `证据 / 附件 / 留痕规范草稿`
- `接口与回传规范草稿`

继续往“日志与操作记录”这一层推进半步，专门沉淀：
- 日志对象边界
- 日志动作语义
- 日志页面承载
- 日志与异常语义、任务语义、证据语义之间的关系

## 2. 范围与边界

### 2.1 当前纳入范围

- 主单日志
- 执行记录日志
- 异常处理日志
- 任务推进日志
- 详情页日志区
- 执行页日志 tab

### 2.2 当前不纳入范围

- IM / 邮件 / 外部消息通知日志
- 审批流全量活动日志
- 全量系统技术运维日志

## 3. 统一目标

- 让日志对象回答“发生了什么动作”，而不是替代状态或证据对象
- 让终止、异常、待动作三类语义在日志层有一致表达
- 让详情页和执行页都能承接统一的日志口径
- 让日志、证据、任务状态和异常补充状态之间能稳定交叉映射

## 4. 日志分层模型

当前统一建议采用三层：

1. 业务动作日志  
回答“谁在什么时候做了什么动作”

2. 异常语义日志  
回答“这次动作是否属于终止、异常或待动作语义”

3. 页面承载日志  
回答“这些日志最终在详情页日志区还是执行页日志 tab 中展示”

## 5. 日志对象字段字典基线

当前日志对象最小字段建议：

- `name`
- `biz_model`
- `biz_id`
- `action_type`
- `action_result`
- `operator_id`
- `action_time`
- `remark`
- `exception_state`

如需扩展终止类日志，再补：
- `terminated_reason`
- `terminated_remark`
- `terminated_by`
- `terminated_at`

### 5.1 通用身份字段

| 字段 | 当前说明 | 当前用途 |
| --- | --- | --- |
| `name` | 日志编号或日志主键显示值 | 用于列表、详情、搜索中的身份标识 |
| `biz_model` | 所属业务对象模型名 | 用于区分入库、出库、盘点、移位、任务等日志归属 |
| `biz_id` | 所属业务对象主键 | 用于回跳主单、执行记录、任务详情 |

### 5.2 动作语义字段

| 字段 | 当前说明 | 当前用途 |
| --- | --- | --- |
| `action_type` | 动作类型 | 表达“创建、开始、确认、终止、登记异常、补动作完成”等业务动作 |
| `action_result` | 动作结果 | 表达成功、失败、终止、待处理、已补动作等结果语义 |
| `remark` | 简短动作说明 | 用于承接本次动作的补充说明 |

### 5.3 操作人与时间字段

| 字段 | 当前说明 | 当前用途 |
| --- | --- | --- |
| `operator_id` | 操作人 | 用于审计、追溯、页面展示 |
| `action_time` | 动作时间 | 用于时间线、日志排序、统计和回溯 |

### 5.4 异常补充状态字段

| 字段 | 当前说明 | 当前用途 |
| --- | --- | --- |
| `exception_state` | 当前异常补充状态 | 直接对齐 `EST-*` 编号体系 |
| `terminated_reason` | 终止原因枚举 | 对齐 `EST-01 / terminated` 的核心说明字段 |
| `terminated_remark` | 终止备注 | 补充终止原因明细 |
| `terminated_by` | 终止人 | 终止类日志审计字段 |
| `terminated_at` | 终止时间 | 终止类日志审计字段 |

### 5.5 一期建议优先落表字段

当前更建议一期优先先落：

- `name`
- `biz_model`
- `biz_id`
- `action_type`
- `action_result`
- `operator_id`
- `action_time`
- `remark`
- `exception_state`

若出现 `EST-01`，再优先补：

- `terminated_reason`
- `terminated_remark`
- `terminated_by`
- `terminated_at`

### 5.6 当前统一建议

1. 日志对象先围绕“业务归属 + 动作语义 + 操作人与时间 + 异常补充状态”四组字段稳定下来。
2. 不建议一期在日志对象里直接堆过多页面展示冗余字段。
3. 需要展示的派生值，优先从主单、执行记录、任务对象反查，而不是重复存一份。
4. `EST-*` 进入日志层后，优先通过 `exception_state` 与终止类扩展字段承接，不单独发明另一套异常编码字段。

## 6. 终止类日志动作口径

当前更推荐统一承载：
- 终止动作
- 终止原因说明
- 终止时间与终止人

与状态总规范中的：
- `EST-01 / terminated`

保持直接对齐。

## 7. 异常处理日志口径

当前更推荐统一承载：
- 异常登记
- 异常待处理
- 异常处理结果

与状态总规范中的：
- `EST-02 / exception`

保持直接对齐。

## 8. 待动作 / 补动作日志口径

当前更推荐统一承载：
- 待人工处理
- 待补动作
- 补动作完成

与状态总规范中的：
- `EST-03 / pending_action`

保持直接对齐。

## 9. 日志页与日志区页面结构基线

当前统一建议：
- 详情页日志区承担结构化追溯
- 执行页日志 tab 承担即时追踪

最小展示字段建议：
- 时间
- 操作人
- 动作
- 结果
- 简短说明

## 10. 日志权限与记录规则边界

当前统一建议：
- 日志查看范围服从主单 / 任务 / 证据对象的记录规则范围
- 日志对象本身不单独发明一套脱离业务对象的新范围体系
- 异常类日志应比普通成功日志更强调权限边界

## 11. 日志对象的 search / filter / group by 口径

当前统一建议把日志对象的检索口径先分成三层：

### 11.1 search 口径

优先支持：

- `name`
- `biz_model`
- `action_type`
- `action_result`
- `remark`
- `terminated_reason`

当前建议理解：

- `name` 用于精确定位某条日志
- `biz_model + biz_id` 用于从业务对象反查日志
- `action_type / action_result` 用于按动作和结果快速筛查
- `remark / terminated_reason` 用于补充说明检索

### 11.2 filter 口径

当前更建议优先保留：

- 时间范围
- 操作人
- `exception_state`
- `action_type`
- `action_result`
- 所属业务对象类型

其中异常相关更建议直接支持：

- `EST-01 / terminated`
- `EST-02 / exception`
- `EST-03 / pending_action`

### 11.3 group by 口径

当前更建议优先保留：

- 按业务对象类型分组
- 按动作类型分组
- 按动作结果分组
- 按异常补充状态分组
- 按操作人分组
- 按日期分组

### 11.4 当前统一建议

1. 日志专题一期先优先围绕“查问题、查异常、查人、查时间”组织 search / filter / group by。
2. 不建议一期把日志页做成非常重的多维统计页，统计分析更适合继续交给报表专题承接。
3. `exception_state` 在日志层里应成为最重要的异常筛选维度之一。
4. 与主单 / 执行页联动时，优先先保留“按业务对象反查日志”，不要反过来让日志页承担业务导航主入口。

## 12. 日志对象到具体模块 / 文件树映射

当前统一建议把日志对象先落成两层：

### 12.1 Python 模型层建议

| 日志对象方向 | 当前建议模块 | 当前建议文件方向 | 当前说明 |
| --- | --- | --- | --- |
| 主单日志基线 | `logistics_wms_base` | `models/logging/wms_operation_log.py` | 统一日志对象基础模型优先收在基础模块 |

| 盘点 / 移位日志扩展 | `logistics_wms_inventory` | `models/logging/wms_inventory_log.py` | 与盘点单、移位单、调整动作对齐 |
| 任务推进日志扩展 | `logistics_wms_integration` | `models/logging/wms_task_log.py` | 与导入任务、回传任务推进动作对齐 |

### 12.2 XML 页面层建议

| 页面方向 | 当前建议模块 | 当前建议文件方向 | 当前说明 |
| --- | --- | --- | --- |

| 主单详情日志区 | 各业务模块 | `views/**/*_views.xml` 内嵌日志区块或 smart button 入口 | 作为业务对象详情页的日志承载区 |
| 任务详情日志区 | `logistics_wms_integration` | `views/integration/**/*_views.xml` | 承接任务推进日志和回传日志 |

### 12.3 前端增强层建议

| 方向 | 当前建议模块 | 当前建议文件方向 | 当前说明 |
| --- | --- | --- | --- |
| 执行页日志 tab | `logistics_wms_web` | `static/src/components/log_tabs/` | 承接执行页底部日志 tab 交互层 |
| 日志增强筛选组件 | `logistics_wms_web` | `static/src/components/log_filters/` | 如后续需要执行页日志增强筛选，可集中放在 web 层 |

### 12.4 当前统一建议
