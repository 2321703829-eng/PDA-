# 小程序导入设计

## 目录定位

本目录用于沉淀“小程序原始单表导入”专题设计。

本次专题要解决的不是“再写一个脚本”，而是把下面这条业务链正式接入系统：

`上传原始单表 -> 提取客户名称/客户地址/发车单号 -> 匹配系统客户数据 -> 预校验 -> 确认导入 -> 写入排线承接对象`

其中：

- `发车单号` 直接作为 `batch_no`
- 小程序端负责入口、上传、预校验触发、结果回显、确认导入
- 服务端负责 merged cells 解析、清洗去重、客户匹配、正式写库

## 当前结论

- 本次本质是“客户名称 + 客户地址”匹配系统客户/门店主数据，再补 `batch_no` 进入正式导入链路
- 当前更适合先落到 `route planning draft` 承接链路，而不是直接裸写数据库表
- 匹配失败允许预校验，但不允许正式 confirm
