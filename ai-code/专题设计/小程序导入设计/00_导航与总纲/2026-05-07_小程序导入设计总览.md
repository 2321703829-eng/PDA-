# 2026-05-07 小程序导入设计总览

## 1. 设计目标

把“小程序导入原数据”这条线下 Excel 加工流程，升级成系统内正式导入模式。

目标主链路：

`上传原始单表 -> 提取客户名称/客户地址/发车单号 -> 匹配系统客户数据 -> 预校验 -> 确认导入 -> 写入系统`

## 2. 本次已经定下的关键口径

1. 小程序端可以作为入口，但只负责上传、触发和回显，不负责复杂解析
2. `发车单号` 直接作为 `batch_no`
3. 客户信息底表的正式来源首期直接复用系统内 `res.partner / profile` 主数据
4. 本质匹配键是 `客户名称 + 客户地址`
5. 但首期匹配成功判定先沿用旧 Excel 模板口径：
   - `客户名称/门店名称` 单命中为成功
6. 地址首期作为保留和回显字段，暂不作为 confirm 强约束
7. 匹配失败允许预校验，但不允许正式 confirm
8. 当前正式落点优先走 `route planning draft` 承接链路
9. 首期 confirm 后只写：
   - `logistics.route.planning.batch`
   - `logistics.route.planning.stop.line`

## 3. 为什么不继续依赖 Excel 模板

因为现有 `数据输入表 -> 客户信息底表 -> template` 的流程虽然能跑通，但问题很明显：

- 规则藏在 Excel 和脚本里，不在系统里
- merged cells、去重、弱匹配缺少系统级回溯
- 小程序端拿不到真正的行级反馈
- 后续规则演进会持续放大维护成本

所以这次要把 Excel 从“处理引擎”降级为“样例/参考/审计产物”。
