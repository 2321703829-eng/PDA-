## 2. 当前统一业务口径

### 2.1 主对象口径

- 执行主线：`wave -> batch -> waybill -> waybill_order_line`
- 追溯主线：`waybill -> trace_event -> evidence -> exception`
- `waybill` 是当前留痕与追溯主对象
- `order_line` 是履约明细，不是当前追溯主对象

### 2.2 当前接口路线

- 标准列表、详情、搜索、基础配置页：优先走 `Odoo RPC`
- 工作台、老板页、增强时间线、增强证据区：允许走 `JSON controller`

### 2.3 接口命名规则

为了让接口名本身就能看出查询方式，本轮统一调整为：

- `getXxxListByCondition`
- `getXxxDetailById`
- `getXxxItemsByWaybillId`
- `getXxxSummaryByDateRange`
- `markXxxById`
- `addXxxById`

含义如下：

- `ById`：通过单一主键查询或执行动作
- `ByWaybillId`：通过运单主键查询
- `ByBatchId`：通过批次主键查询
- `ByCondition`：通过一组筛选条件查询
- `ByDateRange`：通过时间范围查询

## 3. 通用请求与返回约定

### 3.1 通用分页参数

| 字段 | 类型 | 必填 | 可空 | 含义 |
|---|---|---|---|---|
| `page` | integer | 否 | 否 | 页码，从 `1` 开始，默认 `1` |
| `page_size` | integer | 否 | 否 | 每页条数，默认 `20` |
| `keyword` | string | 否 | 是 | 搜索关键词，通常用于主搜索框 |
| `order_by` | string | 否 | 是 | 排序表达式，例如 `updated_at desc` |

```json
{

    "items": [],

    "total": 0,

  },
```

```json
{
  "code": "OK",
```

## 4. 枚举值定义

### 4.1 运单状态 `current_status`

| 值 | 含义 |
|---|---|
| `draft` | 草稿，刚创建未开始执行 |
| `ready` | 已准备，待进入执行流程 |
| `dispatching` | 配送中 |
| `arrived` | 已到店/已到站 |
| `signed` | 已签收 |
| `closed` | 已闭环 |

### 4.2 证据状态 `evidence_status`

| 值 | 含义 |
|---|---|
| `missing` | 完全缺失 |
| `partial` | 部分缺失 |
| `complete` | 证据完整 |

### 4.3 异常状态 `exception_status`

| 值 | 含义 |
|---|---|
| `draft` | 草稿 |
| `open` | 已打开，待处理 |
| `processing` | 处理中 |
| `resolved` | 已解决 |
| `closed` | 已关闭 |
| `cancelled` | 已取消 |

### 4.4 严重度 `severity_level`

| 值 | 含义 |
|---|---|
| `low` | 低 |
| `medium` | 中 |
| `high` | 高 |
| `critical` | 严重 |

### 4.5 风险等级 `risk_level`

| 值 | 含义 |
|---|---|
| `low` | 低风险 |
| `medium` | 中风险 |
| `high` | 高风险 |

### 4.6 留痕类型 `trace_type`

| 值 | 含义 |
|---|---|
| `arrive_loading_point` | 到达装货点 |
| `depart_warehouse` | 仓库发车 |
| `arrive_store` | 到店 |
| `signoff` | 签收 |
| `exception_report` | 异常上报 |
| `manual_update` | 人工补录 |

## 7. 当前最小可用接口集

如果先做第一版，建议至少先落这 10 个：

1. `getWaybillListByCondition`
2. `getWaybillDetailById`
3. `getWaybillOrderLinesByWaybillId`
4. `getTraceTimelineByWaybillId`
5. `getEvidenceListByWaybillId`
6. `getExceptionListByCondition`
7. `getExceptionDetailById`
8. `addExceptionProcessNoteById`
9. `getAdminDashboardSummaryByDateRange`
10. `getAdminPriorityQueueByCondition`

核心链路：

`管理工作台 -> 运单列表 -> 运单详情 -> 留痕时间线 -> 证据 -> 异常`

## 8. 对后端协作的直接建议

1. 接口命名优先采用 `ById / ByWaybillId / ByBatchId / ByCondition / ByDateRange` 这类形式
2. 返回字段里尽量同时给：
   - 编码字段，例如 `current_status`
   - 展示字段，例如 `current_status_label`
3. 工作台和老板页不要只返回总数，还要返回足够支撑卡片跳转的对象上下文
4. 每个聚合字段都需要明确刷新策略，避免前端看到旧数字
5. 对关键字段要明确：
   - 是否必填
   - 是否允许返回 `null`
   - 是否总是返回展示文案字段
