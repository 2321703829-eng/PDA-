## 4. 当前仍然存在的不足

### 4.1 模块实现推进仍不均衡

当前真实开始落代码的主要是：

- `logistics_base`
- `logistics_dispatch`

而下面这些层还主要停留在设计层：

- `logistics_trace_core`
- `logistics_trace_exception`
- `logistics_trace_evidence`
- `logistics_trace_dashboard`

这不影响前端主链先开工，但意味着：

- 时间线区
- 证据区
- 异常页

在真实代码落地时还需要继续接上对应模块骨架。

### 4.2 部分扩展模块还没有拆到页面级

当前仍缺少一批页面级草案，例如：

- 客户与门店页面草案
- 仓库与货位页面草案
- 留痕规则配置页草案
- 异常类型配置页草案
- 编号规则页草案
- 波次 / 批次 / 运单 / 车辆 / 司机管理页面草案

这些不会阻塞 P0 主链开发，但会影响后续扩展模块的细化节奏。

### 4.3 设计文档和代码现状之间仍需要持续同步

当前最容易过期的不是草图，而是这几类文档：

- 阶段计划
- 缺失清单
- 目录现状说明
- 升级与验证说明
- 模板 README

原因很简单：

- 一旦真实模块开始落地
- 这些“状态型文档”最容易停留在上一个阶段
