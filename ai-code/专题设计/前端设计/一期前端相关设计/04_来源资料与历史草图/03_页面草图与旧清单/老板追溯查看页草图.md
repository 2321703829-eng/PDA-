## 1. 页面目标

这页不是管理员工作台的缩小版，而是老板做“争议判断”和“责任确认”的入口页。

老板进入这页后，应尽量在很短时间内完成：
1. 找到争议对象
2. 先看到结论摘要
3. 再看到关键证据链
4. 最后决定是否需要继续下钻看原始过程

所以这页的核心不是操作密度，而是判断密度。

---

## 2. 页面结构原则

老板页必须遵循这个顺序：
1. 先看结论
2. 再看风险对象
3. 再看关键证据摘要
4. 最后再决定是否进入原始详情

不能做成：
- 管理员首页的全量搬运
- 一堆待处理事项和技术字段
- 一进入就看到细碎时间线

老板页更像“决策页”，不是“操作页”。

## 4. 页面分区说明

## 4.1 顶部筛选区
建议支持：
- 时间范围
- 风险等级
- 区域
- 对象类型
- 快捷筛选标签

设计原则：
- 老板通常不会做很深的筛选配置
- 重点是用少量高价值筛选快速进入争议对象

## 4.2 结论卡区
建议固定卡片：
- 待处理争议数
- 证据不足对象数
- 高风险批次数
- 今日新增高风险数
- 闭环率

设计原则：
- 这里优先回答“今天整体怎样”
- 卡片要支持下钻，但不要承载复杂解释

## 4.3 重点争议对象列表
建议展示：
- 对象编号
- 风险结论
- 证据状态
- 最近更新时间
- 主动作

设计原则：
- 这是老板最可能直接点击的区域
- 列表应比管理员列表更短、更聚焦

## 4.4 关键证据链摘要区
这一块是老板页的核心区域。

建议每条摘要固定回答：
- 什么时候发生了关键异常
- 是否有图
- 图够不够
- 当前责任是否可判

设计原则：
- 老板不需要先看完整时间线
- 先看“证据链摘要”更接近真实决策路径

## 4.5 风险分布摘要区
建议展示：
- 异常类型分布
- 重点区域
- 多次异常对象数量

设计原则：
- 支撑老板看整体问题结构
- 不做深度运营报表

## 4.6 最近变化区
建议展示：
- 新增高风险对象
- 风险升级对象
- 证据不足风险变化

设计原则：
- 让老板快速感知最新变化
- 不用展开太长消息流

## 4.7 右侧摘要区
建议放：
- 老板摘要卡
- 快速跳转卡
- 当前结论说明
- 技术信息折叠区

设计原则：
- 右侧承担“决策辅助”作用
- 技术字段必须折叠，不进入主视野

## 5. 重点争议对象卡草图
```text
+----------------------------------------------------------------------------------------------+
| WB000029                     [破损争议] [证据不足]                                           |
| 最新更新：04-11 09:48                                                                         |
| 关键结论：当前有异常图片 2 张，但关键信息仍不足，责任待判                                    |
| 动作：[看摘要] [看证据] [看运单]                                                              |
+----------------------------------------------------------------------------------------------+
```

设计重点：
- 编号和风险结论必须一眼可见
- “责任是否可判”比技术细节更重要
- 动作不宜太多，避免老板视角变成管理员操作台

## 6. 字段落位建议

## 第一优先层
- 待处理争议数
- 证据不足对象数
- 高风险批次数
- 重点争议对象列表
- 关键证据链摘要

## 第二优先层
- 闭环率
- 风险分布摘要
- 最近变化
- 重点区域

## 第三优先层
- 对象类型过滤摘要
- 区域过滤摘要
- 多次异常对象数

## 技术层
- aggregate 说明
- 技术更新时间
- 各类外部 id

这些字段只应出现在折叠信息区。

## 7. 动作落位建议

## 主动作
- 看摘要
- 看证据
- 看运单
- 看批次

## 辅助动作
- 查看更多证据链
- 查看全部争议对象
- 查看动态详情

## 顶部动作
- 刷新
- 导出

设计原则：
- 老板页动作以阅读和下钻为主
- 不建议承载“标记处理中”“添加备注”这类管理员动作

## 9. 关键交互草图

## 9.1 看摘要
```text
[看摘要]
    -> 进入对象摘要页或详情页摘要锚点
    -> 优先展示当前状态、关键留痕、证据摘要
```

## 9.2 看证据
```text
[看证据]
    -> 进入证据查看页
    -> 自动带上当前对象和关键留痕筛选
```

## 9.3 查看全部争议对象
```text
[查看全部争议对象]
    -> 进入争议对象列表页
    -> 默认按风险和更新时间排序
```

## 11. Odoo 落地建议

建议落地为：
- `kanban` 或 dashboard action
- 以摘要卡 + 短列表 + 下钻入口为主

增强点：
- 每张卡和每个对象都能 act_window 下钻
- 关键证据链摘要可由后端聚合后直接提供
- 如果 Odoo 原生布局不足，再做轻量前端增强

注意：
- 不建议把老板页做成管理员页的复制品
- 也不建议一开始做成重 BI 大屏
- 先把“结论 -> 证据 -> 下钻”顺序做稳

---

## 12. 结论

老板追溯查看页最重要的不是看得更细，而是：

**让老板先看到结论，再决定是否继续往下看。**

只要用户在这页能快速知道：
- 哪些对象最值得关注
- 当前证据是否足够
- 是否已经能判断责任
- 下一步该看摘要、看证据还是看对象详情

这页就达标。
