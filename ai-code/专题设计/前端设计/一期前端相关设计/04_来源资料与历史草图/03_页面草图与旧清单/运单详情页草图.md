# 运单详情页草图

适用范围：
- 管理员后台
- `物流留痕 -> 追溯中心 -> 运单追溯 -> 运单详情`

关联文档：
- `管理员后台界面改造方案.md`
- `后台页面改造清单.md`
- `页面字段清单.md`
- `页面动作清单.md`

---

## 1. 页面目标

这页是管理员后台最核心的阅读页。

目标只有一个：

**让管理员在一个页面内完成运单级追溯判断。**

这页必须同时承接：
- 当前状态
- 执行上下文
- 留痕时间线
- 图片证据
- 异常摘要
- 处理动作

---

## 2. 页面结构原则

详情页必须遵循这个阅读顺序：

1. 先看摘要
2. 再看当前状态
3. 再看历史留痕
4. 再看证据
5. 最后做处理

不能做成：
- 先放大量编辑字段
- 时间线和证据被放到页面很后
- 异常只剩一个状态字段

## 4. 页面分区说明

## 4.1 头部摘要区

这是页面第一优先层。

必须固定展示：
- 运单号
- 当前状态
- 异常状态
- 证据完整度
- 最新留痕摘要

主动作也应固定放在这里：
- 查看完整时间线
- 查看证据
- 标记处理中
- 添加处理备注

设计原则：
- 先结论，后细节
- 不把动作埋到页面中下部

## 4.2 当前状态区

这一块回答：
- 现在怎么样

建议字段：
- 当前状态
- 是否签收
- 签收时间
- 当前异常类型
- 当前异常说明

设计原则：
- 用短字段说明当前状态
- 不放过多历史字段

## 4.3 执行上下文区

这一块回答：
- 这单是什么背景

建议字段：
- 批次号
- 客户名称
- 发货方
- 收货方
- 起始地址
- 目的地址
- 车牌号
- 司机名

设计原则：
- 作为背景信息区
- 不抢时间线和证据区的主阅读地位

## 4.4 留痕时间线区

这一块回答：
- 过程中发生了什么

每条时间线建议展示：
- 时间
- 留痕类型
- 提交人
- 图片数量
- 备注摘要
- 是否异常

设计原则：
- 默认倒序
- 异常留痕高亮
- 每条记录都能联动到证据

## 4.5 证据查看区

这一块回答：
- 有没有足够的图来支持判断

每张图建议展示：
- 缩略图
- 对应留痕
- 时间
- 上传人
- 图片备注
- 查看大图动作

设计原则：
- 不把证据丢到 chatter
- 一眼能看到图和归属关系
- 看大图不打断主流程

## 4.6 异常摘要区

这一块回答：
- 如果有异常，现在是什么情况

建议字段：
- 异常类型
- 当前状态
- 当前责任人
- 最近处理时间

设计原则：
- 做成右侧摘要卡
- 方便快速判断是否要进入异常详情

## 4.7 处理记录区

这一块回答：
- 后台已经做了什么处理

建议字段：
- 时间
- 处理人
- 动作
- 备注摘要

设计原则：
- 以阅读为主
- 不替代正式异常处理对象

---

## 5. 右侧摘要栏设计

右侧建议固定为“快速判断区”，而不是更多字段堆叠区。

建议放：
- 异常摘要卡
- 快速跳转卡
- 技术信息折叠区

不建议放：
- 大量可编辑字段
- 大量技术字段展开内容

## 6. 关键交互草图

## 6.1 查看时间线

```text
[查看完整时间线]
    -> 保持当前详情页上下文
    -> 展开更多历史记录或跳时间线详情视图
```

## 6.2 查看证据

```text
[查看大图]
    -> 打开证据预览层
    -> 左右切换上一张/下一张
    -> 可看到对应留痕摘要
```

## 6.3 标记处理中

```text
[标记处理中]
    -> 确认动作
    -> 刷新异常摘要区与处理记录区
```

## 6.4 添加处理备注

```text
[添加处理备注]
    -> 打开轻量备注输入
    -> 写入处理记录区
```

## 7. 字段优先级落位

## 第一优先层

- 运单号
- 当前状态
- 异常状态
- 证据完整度
- 最新留痕摘要

## 第二优先层

- 批次号
- 是否签收
- 当前异常类型
- 车牌号
- 司机名

## 第三优先层

- 客户名称
- 发货方
- 收货方
- 地址信息
- 外部单号

## 技术层

- external_shipment_id
- external_client_id
- latest_trace_external_id
- latest_image_access_key
- write_date

这些应放到折叠区。

## 8. Odoo 落地建议

这页建议落地为：
- 主表单 `form`
- `notebook` 或主分区布局
- smart button
- 运单对象上的嵌入式时间线和证据区

推荐结构：

```text
form
├─ header
├─ summary sheet
├─ main content
│  ├─ current status block
│  ├─ context block
│  ├─ timeline block
│  ├─ evidence block
│  └─ process record block
└─ side summary block
```

注意：
- 如果 Odoo 原生布局不够顺，可在证据区做轻量自定义 widget
- 但不要一开始就重写整个页面壳子

## 10. 结论

运单详情页的设计成败，取决于一件事：

**管理员能不能在一个页面里，把状态、过程、证据和异常串起来。**

所以这页最重要的不是字段全，而是顺序对：

- 先摘要
- 再过程
- 再证据
- 最后处理

只要这个顺序稳住，这页就会成为整个后台追溯体系的核心页面。
