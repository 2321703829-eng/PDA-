---

## 1. 页面目标

这页不是替代追溯列表页，而是管理员每天进入后台后的“工作入口页”。

它要帮助管理员先完成 4 件事：
1. 判断今天先看什么
2. 快速看到高风险对象分布
3. 一键下钻到运单、异常、批次等主页面
4. 不进入详情也能知道当前风险面貌

所以这页的核心不是“看全量数据”，而是“快速分流注意力”。

---

## 2. 页面结构原则

管理工作台必须围绕“优先级分发”组织，而不是围绕对象详情组织。

它主要回答：
- 今天最急的是什么
- 哪类问题最多
- 哪些对象值得先查

它不回答：
- 某张图是否足够判责
- 某条留痕到底写了什么细节

这些应继续回到运单详情、异常详情、留痕时间线、证据页。

## 4. 页面分区说明

## 4.1 顶部筛选区
建议支持：
- 时间范围
- 责任人
- 仓 / 区域
- 风险等级
- 快捷筛选标签

设计原则：
- 工作台是聚合入口，但仍需快速切换视角
- 筛选项应服务“今天先看什么”，不做复杂报表型筛选

## 4.2 概览卡区
建议固定卡片：
- 待处理异常数
- 证据不足对象数
- 高风险批次数
- 今日新增争议数
- 今日新增留痕数

设计原则：
- 每张卡都应支持下钻
- 卡片文案要更接近“行动入口”，而不是仅做展示

## 4.3 优先处理列表
这一块是页面主区。

建议优先展示：
- 高严重度异常
- 证据不足且未闭环对象
- 异常集中批次

每行建议展示：
- 对象编号
- 风险原因
- 严重度
- 最近更新时间
- 主跳转动作

设计原则：
- 工作台不能只有统计卡，必须能直接带用户进入处理路径
- 这里是管理员最有可能开始操作的区域

## 4.4 风险分布区
建议展示：
- 异常类型分布
- 证据完整度分布
- 高风险批次 Top N

设计原则：
- 用于帮助管理员形成“今天风险主要集中在哪”的全局感
- 不追求复杂 BI，重点是支撑决策

## 4.5 最近变化区
建议展示：
- 新增高严重度异常
- 某批次风险跳升
- 证据不足对象增长

设计原则：
- 这一块承担“动态提醒”作用
- 不需要像消息流那样无限展开

## 4.6 待处理争议对象区
建议展示：
- 争议异常对象
- 争议运单
- 争议批次

设计原则：
- 让管理员能快速聚焦最需要人工判断的对象

## 4.7 右侧辅助区
建议放：
- 今日摘要卡
- 快速跳转卡
- 技术信息折叠区

设计原则：
- 右侧只承担辅助判断与导航
- 不是第二个主工作区

## 6. 字段落位建议

## 第一优先层
- 待处理异常数
- 证据不足对象数
- 高风险批次数
- 今日新增争议数
- 优先处理对象列表

## 第二优先层
- 异常类型分布
- 证据完整度分布
- 最近变化
- 今日闭环数 / 未闭环数

## 第三优先层
- 今日新增留痕数
- 责任人过滤摘要
- 仓 / 区域过滤摘要

## 技术层
- 各类 aggregate 字段
- 统计来源说明
- 更新时间戳

这些适合放在折叠区，不应挤占首页主阅读空间。

## 9. 关键交互草图

## 9.1 点击概览卡
```text
点击「待处理异常」
    -> 进入当前异常列表页
    -> 自动带上待处理筛选
```

## 9.2 点击优先处理对象
```text
点击优先处理对象
    -> 进入对应详情页
    -> 如果是异常对象则优先进异常详情
    -> 如果是运单对象则进运单详情
    -> 如果是批次对象则进批次详情
```

## 9.3 点击风险分布项
```text
点击「破损 8」
    -> 进入异常列表页
    -> 自动带上异常类型=破损
```

## 11. Odoo 落地建议

建议落地为：
- `kanban` 或 dashboard action
- 若 Odoo 原生 dashboard 不够，可用轻量自定义看板布局

增强点：
- 每张卡支持 act_window 下钻
- 优先处理列表可使用 list / kanban 混合表达
- 统计卡不做复杂交互，重点是把入口做稳

注意：
- 不建议一开始就做成重 BI 页面
- 先保证“卡片 -> 列表 -> 详情”的入口链条顺畅

---

## 12. 结论

管理工作台最重要的不是“信息很多”，而是：

**让管理员一进后台就知道今天先看什么。**

只要用户在这页能快速知道：
- 当前最急的风险是什么
- 哪些对象最值得先查
- 点击后应该去哪里

这页就达标。
