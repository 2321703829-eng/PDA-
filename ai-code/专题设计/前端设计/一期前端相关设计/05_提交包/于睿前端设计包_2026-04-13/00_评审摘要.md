# 于睿前端设计包评审摘要

## 1. 这套设计包解决什么问题

本包用于把 Odoo 物流留痕系统中“管理员后台”和“老板追溯界面”这两条前端线，整理成一套可评审、可接开发、可持续维护的正式设计资料。

它重点解决：

- 后台入口如何组织
- 管理员如何完成追溯与处理
- 老板如何完成判断与决策
- 一期到底先做哪些页面
- 前端到底依赖哪些聚合字段和后端能力

## 2. 当前核心设计结论

当前已固定：

- 业务主线：`wave -> batch -> waybill -> trace_event -> evidence -> exception`
- 管理员主闭环：`工作台 -> 运单 -> 留痕 -> 证据 -> 异常处理`
- 老板主闭环：`总览看板 -> 争议对象 -> 关键证据摘要 -> 决策记录`
- 一期先以 Odoo 原生壳 + 聚合字段 + 轻量增强为主
- 不在一期引入大而全协同壳、重 BI、重前端重构

## 3. 本轮冻结的一期范围

P0 本轮建议冻结为：

1. 管理工作台
2. 运单追溯列表页
3. 运单详情页
4. 留痕时间线区
5. 证据查看区
6. 当前异常列表页
7. 异常详情页基础处理区
8. 老板总览页
9. 争议对象列表页

## 4. 当前提交形态

本提交包由两层组成：

- 现行正式正文
- 提交包目录下的评审入口文档

这样做的目的，是保证：

- 提交时资料成套
- 维护时仍只有一套正文源头

## 5. 当前最适合评审关注的问题

建议评审优先看这几件事：

1. 管理员页和老板页的边界是否认同
2. 一期冻结范围是否认同
3. 聚合字段依赖和查询性能预期是否认同
4. 正文与附件划分是否足够清楚
5. 命名、状态机、编号规则的引用顺序是否认同

## 6. 当前状态

这套设计包已经可以直接用于：

- 内部方案评审
- 分工确认
- 前后端对接
- 首轮开发启动
