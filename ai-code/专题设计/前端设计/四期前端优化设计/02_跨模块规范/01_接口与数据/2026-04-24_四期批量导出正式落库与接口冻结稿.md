# 2026-04-24 四期批量导出正式落库与接口冻结稿

## 文档定位

- 本文用于把四期批量导出从“专题方案”推进到“可直接进入开发拆分”的正式落库与接口冻结稿。
- 自 2026-04-24 起，本文以以下文档为共同基线：
  - `2026-04-24_四期批量导出模块设计方案.md`
  - `2026-04-21_四期数据库底表设计稿 v1（第二次修正版）.md`
  - `2026-04-23_四期导入任务正式落库迁移方案.md`
  - `2026-04-23_四期导入错误码清单.md`
- 本文覆盖标准主链批量导出首轮正式实现，不展开图片 ZIP 导出与司机侧阅读导出。

## Outcome

- 标准批量导出正式落到独立的 `export_source_scope / export_task / export_task_line / export_error_line` 审计链。
- 导出任务、结果页、错误明细、错误报告、下载接口统一围绕 `task_no` 运转。
- 标准导出文件首轮固定为与正式导入模板兼容的四 Sheet `xlsx`。
- 首轮权限口径冻结为“全量标准导出按动作授权，不在同一导出文件里做字段级脱敏分叉”。

## Behavior

- 用户从批次、运单、客户三个入口发起导出时，系统先落 `export_source_scope`，再创建 `export_task`。
- `export_task.total_count / success_count / fail_count / skipped_count` 统计的是“入口对象任务行”，不是四 Sheet 明细行数。
- 四 Sheet 真实导出规模通过 `exported_waybill_count / exported_customer_line_count / exported_order_line_count / exported_goods_line_count` 返回。
- 结果页继续复用导入模块阅读节奏：
  - 任务摘要
  - 行结果
  - 错误明细
  - 错误报告
  - 导出文件下载

## Boundary

- 首轮对象类型只冻结 `dispatch_main` 标准数据导出。
- 首轮入口类型只冻结：
  - `from_batch`
  - `from_waybill`
  - `from_customer`
- 首轮输出模式只冻结 `standard_xlsx`，不补 ZIP、不补 PDF、不补导出中心。
- 首轮不把导出任务并入 `import_task`，但任务号、结果阅读节奏、错误报告风格尽量与导入保持一致。
- 首轮不做同一文件内字段级权限脱敏变体；如后续需要脱敏导出，应新增独立 `export_mode`，不污染 `standard_xlsx`。

## 核心结论

1. 正式导出链维持四表结构，不额外拆 `export_file` 表；导出文件元数据直接挂在 `export_task`。
2. 导出文件二进制首轮不落 `ir.attachment`，统一走本地文件存储路径，数据库只存元数据和 `storage_path`。
3. `task_no` 继续作为正式任务主键，建议使用 `EXT260424-00001` 这一类编号格式。
4. `from_batch / from_waybill / from_customer` 是入口类型；导出文件内部正式层级仍是：
   - `Waybill`
   - `CustomerLine`
   - `OrderLine`
   - `GoodsLine`
5. 标准导出首轮按“全量标准文件是否允许导出”控权限，不在同一个四 Sheet 文件里做列删减或值脱敏。

## 3. 正式任务链冻结

```text
export_source_scope -> export_task -> export_task_line -> export_error_line
```

语义冻结如下：

- `export_source_scope`
  - 记录本次导出来自哪个页面、哪个模型、选中了哪些对象、当时的查询快照是什么。
- `export_task`
  - 记录正式任务头、统计信息、文件元数据、任务状态。
- `export_task_line`
  - 记录每个入口对象的结果，不直接按四 Sheet 明细行拆开。
- `export_error_line`
  - 记录字段级、对象级、阶段级失败信息，用于结果页和错误报告。

## 5. 约束与索引冻结

### 5.1 `_sql_constraints`

- `export_source_scope`
  - `uniq_export_scope_no`: `unique(scope_no)`
- `export_task`
  - `uniq_export_task_no`: `unique(task_no)`
- `export_task_line`
  - `uniq_export_task_line`: `unique(task_id, line_no)`

### 5.2 `CHECK` 建议

- `total_count >= 0 and success_count >= 0 and fail_count >= 0 and skipped_count >= 0`
- `success_count + fail_count + skipped_count <= total_count`
- `exported_waybill_count >= 0`
- `exported_customer_line_count >= 0`
- `exported_order_line_count >= 0`
- `exported_goods_line_count >= 0`

### 5.3 手工索引建议

- `CREATE INDEX idx_export_task_scope_type_status ON export_task (source_scope_id, object_type, status);`
- `CREATE INDEX idx_export_task_entry_status ON export_task (entry_type, status, expires_at);`
- `CREATE INDEX idx_export_task_line_task_status ON export_task_line (task_id, status, target_res_id);`
- `CREATE INDEX idx_export_error_task_stage ON export_error_line (task_id, error_stage, id);`

## 6. 下载文件保存策略冻结

### 6.1 正式策略

- 标准导出主文件首轮不走 `ir.attachment`。
- 正式导出主文件统一写入本地文件系统，数据库只保留元数据：
  - `output_file_name`
  - `output_file_ext`
  - `output_storage_path`
  - `output_file_sha256`
  - `output_file_size`

### 6.2 目录建议

建议目录：

```text
.odoo_data/export_tasks/{YYYY}/{MM}/{DD}/{task_no}/
```

示例：

```text
.odoo_data/export_tasks/2026/04/24/EXT260424-00001/TSL-EXPORT-FROM-WAYBILL-20260424-103000.xlsx
```

### 6.3 文件命名冻结

```text
TSL-EXPORT-{ENTRY_TYPE}-{YYYYMMDD-HHMMSS}.xlsx
```

示例：

- `TSL-EXPORT-FROM-BATCH-20260424-103000.xlsx`
- `TSL-EXPORT-FROM-WAYBILL-20260424-103000.xlsx`
- `TSL-EXPORT-FROM-CUSTOMER-20260424-103000.xlsx`

### 6.4 生命周期冻结

- 文件生成成功后写入：
  - `download_ready_at`
  - `expires_at`
- 首轮默认过期策略建议：
  - `expires_at = download_ready_at + 7 天`
- 任务到期后：
  - `export_task.status` 可切为 `expired`
  - 下载接口返回文件不可用

### 6.5 错误报告策略

- `error-report` 首轮不单独持久化文件元数据。
- `GET /error-report` 由服务层根据 `export_error_line` 动态生成 CSV 并流式返回。
- 主导出文件与错误报告分离处理，避免再加一张 `export_file` 表。

## 7.1 顶层响应码

| `code` | 名称 | 说明 |
| --- | --- | --- |
| `0` | 成功 | 请求成功 |
| `4001` | 参数错误 | 必填参数缺失或格式非法 |
| `4003` | 无权限 | 当前用户无导出权限或无下载权限 |
| `4004` | 资源不存在 | 任务、范围、对象、文件不存在 |
| `4090` | 状态冲突 | 当前任务状态不允许执行该动作 |

说明：

- 与导入模块保持同一套顶层码风格。
- 业务失败原因继续进入 `export_error_line.error_code`。

## 7.2 创建导出任务

### 路由

- `POST /api/admin/logistics/exports/batch`
- `POST /api/admin/logistics/exports/waybill`
- `POST /api/admin/logistics/exports/customer`

### 请求体冻结

```json
{
  "object_type": "dispatch_main",
  "entry_type": "from_waybill",
  "selected_ids": [101, 102, 103],
  "export_mode": "standard_xlsx",
  "from_page": "waybill_list",
  "scope_snapshot": {
    "domain": [["delivery_date", "=", "2026-04-24"]],
    "filters": {
      "warehouse_code": "WH"
    }
  }
}
```

字段说明：

- `object_type`
  - 首轮固定传 `dispatch_main`
- `entry_type`
  - 必须与路由匹配
- `selected_ids`
  - 首轮必传，且至少 1 条
- `export_mode`
  - 首轮固定 `standard_xlsx`
- `from_page`
  - 记录入口页面，不参与实际取数
- `scope_snapshot`
  - 只作审计快照

## 8. 错误码冻结

## 8.1 通用业务错误码

| `error_code` | 说明 | 归属 |
| --- | --- | --- |
| `EXPORT_SOURCE_SCOPE_NOT_FOUND` | 导出范围快照不存在 | 通用 |
| `EXPORT_TASK_NOT_FOUND` | 导出任务不存在 | 通用 |
| `EXPORT_TASK_OBJECT_TYPE_INVALID` | `object_type` 非允许值 | 通用 |
| `EXPORT_TASK_ENTRY_TYPE_INVALID` | `entry_type` 非允许值 | 通用 |
| `EXPORT_MODE_INVALID` | `export_mode` 非允许值 | 通用 |
| `EXPORT_TASK_STATUS_INVALID` | 当前状态不允许执行动作 | 通用 |
| `EXPORT_TASK_NOT_FINISHED` | 任务尚未完成，当前不允许读取结果 | 通用 |
| `EXPORT_TASK_EXPIRED` | 文件或任务已过期 | 通用 |
| `EXPORT_SCOPE_EMPTY` | `selected_ids` 为空 | 通用 |
| `EXPORT_SCOPE_SNAPSHOT_INVALID` | `scope_snapshot` 非法 | 通用 |
| `EXPORT_OUTPUT_FILE_NOT_READY` | 主文件尚未生成 | 通用 |
| `EXPORT_OUTPUT_FILE_MISSING` | 主文件元数据存在但物理文件缺失 | 通用 |
| `EXPORT_FILE_WRITE_FAILED` | 文件写盘失败 | 通用 |
| `EXPORT_FILE_READ_FAILED` | 文件读取失败 | 通用 |
| `EXPORT_WORKBOOK_BUILD_FAILED` | Excel 工作簿生成失败 | 通用 |
| `EXPORT_DOWNLOAD_PERMISSION_DENIED` | 当前用户无下载权限 | 通用 |
| `EXPORT_SENSITIVE_SCOPE_FORBIDDEN` | 当前用户无标准全量导出权限 | 通用 |

## 8.2 `from_batch / from_waybill / from_customer` 入口错误码

| `error_code` | 说明 | 推荐 `field_name` |
| --- | --- | --- |
| `EXPORT_BATCH_NOT_FOUND` | 批次不存在或已不可读 | `selected_ids` / `batch_id` |
| `EXPORT_WAYBILL_NOT_FOUND` | 运单不存在或已不可读 | `selected_ids` / `waybill_id` |
| `EXPORT_CUSTOMER_NOT_FOUND` | 客户不存在或已不可读 | `selected_ids` / `customer_id` |
| `EXPORT_CUSTOMER_SCOPE_AMBIGUOUS` | 客户导出口径被错误当成主档全量导出 | `entry_type` |
| `EXPORT_TARGET_NO_DOWNSTREAM_DATA` | 入口对象无可导出的下游执行数据 | `selected_ids` |
| `EXPORT_TARGET_RELATION_BROKEN` | 入口对象与下游对象关系断裂 | 关系字段 |
| `EXPORT_WAYBILL_DATA_INCOMPLETE` | 运单包必要字段缺失，无法组装正式导出包 | `waybill_no` / 相关字段 |
| `EXPORT_ORDER_LINE_RELATION_BROKEN` | 订单层父子关系断裂 | `order_line` |
| `EXPORT_GOODS_LINE_RELATION_BROKEN` | 货物层父子关系断裂 | `goods_line` |

## 8.3 阶段与错误码使用规则

1. 路由级失败
   - 顶层 `code != 0`
   - 可返回顶层 `error_code`
2. 任务执行中的单行失败
   - 顶层任务查询仍返回 `code = 0`
   - 失败写入：
     - `export_task.fail_count`
     - `export_task_line.status = failed`
     - `export_error_line.error_code`
3. 行被跳过
   - `export_task_line.status = skipped`
   - 仍可写 `export_error_line`
   - 推荐使用 `EXPORT_TARGET_NO_DOWNSTREAM_DATA`

## 9. 权限口径冻结

### 9.1 角色建议

- `logistics_dispatch.group_logistics_export_user`
  - 允许发起标准批量导出
  - 允许读取自己发起的导出任务、行结果、错误明细和主文件下载
- `logistics_dispatch.group_logistics_export_manager`
  - 允许读取所有导出任务
  - 允许下载所有导出主文件与错误报告
  - 允许后续接入取消、过期处理等管理动作

### 9.2 模型访问建议

首轮建议：

- `export_source_scope`
  - user: `read/create`
  - manager: `read/create/write`
- `export_task`
  - user: `read/create`
  - manager: `read/create/write`
- `export_task_line`
  - user: `read`
  - manager: `read`
- `export_error_line`
  - user: `read`
  - manager: `read`

补充规则：

- 首轮不开放普通业务用户手工修改或删除导出任务模型记录。
- 如需进一步收紧，可在 record rule 中把普通用户限制为“只读自己的任务”。

### 9.3 与业务对象权限的关系

- 导出权限不是对底层业务对象读权限的替代。
- 发起导出前，仍需校验当前用户是否有对应入口对象的读取权限：
  - `from_batch` 校验批次读取权限
  - `from_waybill` 校验运单读取权限
  - `from_customer` 校验客户/门店读取权限

### 9.4 敏感字段策略冻结

- 标准四 Sheet 导出首轮不做字段级脱敏分支。
- 也就是说，当前标准导出文件要么允许导出完整标准文件，要么不允许导出。
- 原因是：
  - 四 Sheet 结构需要保持与正式导入模板兼容
  - 若同一 `standard_xlsx` 因角色不同删列或脱敏，会直接破坏“可修订、可再导入”闭环

设计结论：

- 首轮按动作授权，不按列授权。
- 如后续要支持脱敏导出，应新增独立 `export_mode`，例如：
  - `standard_xlsx_masked`
  - `read_only_summary_xlsx`

## 10. 当前不纳入首轮冻结的内容

- 图片 ZIP 导出
- 司机侧 PDF 导出
- 导出中心历史列表页
- 超大批量离线分片与合并
- 公共下载 token 或复杂权限穿透下载
- 标准导出文件内的字段级脱敏分支

## 11. 实施顺序建议

1. 先按本文补齐 `logistics_dispatch` 的导出正式模型与 sequence。
2. 再在 `logistics_web` 落控制器、服务层和错误报告生成。
3. 首个真实切片优先做 `from_waybill`。
4. `from_waybill` smoke 稳定后，再补 `from_batch`。
5. `from_customer` 最后接入，避免口径漂移。
