# 2026-04-24 客户画像与货物画像导出正式落库与接口冻结补丁稿

- 本文只补充客户画像导出和货物画像导出所需的正式落库、枚举、接口、错误码与权限口径，不重写原冻结稿中 `dispatch_main` 已生效部分。

## Outcome

- 在现有正式导出任务链上，新增两条正式业务导出线：
  - 客户画像导出
  - 货物画像导出
- 两条导出线继续复用 `task_no -> result -> lines -> errors -> download` 结果链。
- 客户画像导出主对象正式收口到 `res.partner`。
- 货物画像导出主对象正式收口到 `product.template`，规格层正式收口到 `logistics.product.unit`。

## Behavior

- 新对象类型不新增独立任务底座，继续复用：
  - `export_source_scope`
  - `export_task`
  - `export_task_line`
  - `export_error_line`
- 当前 `dispatch_main` 专用统计字段继续保留。
- 为支持客户画像和货物画像导出，任务头和任务行新增通用 `metrics_json` 承接结构化统计。
- 创建任务路由新增：
  - `POST /api/admin/logistics/exports/customer-profile`
  - `POST /api/admin/logistics/exports/product-profile`
- 任务读取、行结果、错误明细、错误报告、主文件下载路由继续共用现有 `/tasks/{task_no}/...`。

## Boundary

- 本补丁稿不修改 `from_waybill` 已上线行为。
- 本补丁稿不把 `goods_line` 升级成货物画像主档。
- 本补丁稿不新增独立 `goods_profile` 表。
- 本补丁稿不要求本轮立即落地 `logistics.customer.product.profile`，但为其二阶段接入预留结构。

## 核心补丁结论

1. `object_type` 从只支持 `dispatch_main` 扩展为同时支持 `customer_profile` 和 `product_profile`。
2. `entry_type` 新增 `from_product`，用于货物画像导出入口。
3. `package_structure` 新增：
   - `customer_profile_bundle_v1`
   - `customer_profile_bundle_v2`
   - `product_profile_bundle_v1`
   - `product_profile_bundle_v2`
4. `export_task` 新增 `package_metrics_json`，`export_task_line` 新增 `line_metrics_json`。
5. 客户画像导出任务的正式主对象为 `res.partner`，并要求 `is_logistics_partner = True`。
6. 货物画像导出任务的正式主对象为 `product.template`，并通过 `logistics.product.unit` 展开规格层。

```text
TSL-EXPORT-CUSTOMER-PROFILE-{YYYYMMDD-HHMMSS}.xlsx
TSL-EXPORT-PRODUCT-PROFILE-{YYYYMMDD-HHMMSS}.xlsx
```

示例：

- `TSL-EXPORT-CUSTOMER-PROFILE-20260424-153000.xlsx`

- 这两类文件名按 `object_type` 命名，而不是按 `entry_type` 命名。
- 原因是客户画像导出和执行数据的 `from_customer` 会共用入口类型，若继续按 `entry_type` 命名会产生歧义。

## 6. 错误码补丁冻结

## 7. 权限口径补丁冻结

## 7.1 客户画像导出

- 发起导出前，必须校验当前用户对 `res.partner` 目标对象具有读取权限。
- 仅当目标对象满足 `is_logistics_partner = True` 时允许纳入客户画像正式导出。
- 客户画像导出权限不依赖 Odoo 原生 `group_allow_export`。

## 7.2 货物画像导出

- 发起导出前，必须校验当前用户对 `product.template` 目标对象具有读取权限。
- 服务层需要同时校验关联 `logistics.product.unit` 的读取权限。
- 货物画像导出权限不依赖 Odoo 原生 `group_allow_export`。

## 7.3 导出结果权限

- 普通导出用户：
  - 允许读取自己发起的客户画像与货物画像导出任务
  - 允许下载自己发起的导出主文件与错误报告
- 导出管理用户：
  - 允许读取和下载全部客户画像与货物画像导出任务

## 8. 与现有实现的兼容策略

1. 当前 `from_waybill` 已上线代码不要求同步改名或回填。
2. `dispatch_main` 相关统计字段继续保留，不做破坏式迁移。
3. 新导出线正式落地时，只需要在现有任务模型上增量加：
   - `package_metrics_json`
   - `line_metrics_json`
   - 新枚举值
4. 结果页前端实现建议按 `object_type` 分支：
   - `dispatch_main`：继续读旧四段统计
   - `customer_profile / product_profile`：读 `metrics_json`
