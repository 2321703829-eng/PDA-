# 2026-04-23 四期导入错误码清单

## 文档定位

- 本文用于冻结四期导入链错误码口径。
- 自 2026-04-23 起，本文统一以四期数据库底表设计稿为当前有效基线。
- 本文区分两层错误码：
  - 接口顶层响应码
  - `import_error_line.error_code` 字段级业务码

## 核心结论

1. 接口顶层继续保留兼容型数字码，便于管理后台统一处理。
2. 字段级失败码统一使用英文大写下划线字符串，直接落 `import_error_line.error_code`。
3. 字段级错误码应能够对应到：
   - 哪一行失败
   - 哪个字段失败
   - 原始值是什么
   - 映射后值是什么
   - 失败原因是什么
4. `dispatch_main` 与 `image_package` 共用一套顶层接口码，分别扩展对象级业务码。

## 1. 接口顶层响应码

| `code` | 名称 | 使用场景 |
| --- | --- | --- |
| `0` | 成功 | 请求成功，`data` 可正常消费 |
| `4001` | 参数错误 | 缺少必填参数、参数格式不合法 |
| `4003` | 无权限 | 当前用户无导入或结果回读权限 |
| `4004` | 资源不存在 | 任务、源文件、错误报告或业务对象不存在 |
| `4090` | 状态冲突 | 任务状态不允许当前动作 |
| `5000` | 服务异常 | 服务层或写库过程异常 |

说明：

- 顶层 `code` 用于路由级和请求级失败。
- 具体到行和字段的失败原因，统一查 `import_error_line.error_code`。

## 2. 通用业务错误码

下面这些错误码既可作为顶层 `error_code`，也可作为任务执行过程中写入错误明细：

| `error_code` | 说明 | 归属 |
| --- | --- | --- |
| `IMPORT_SOURCE_FILE_NOT_FOUND` | 源文件不存在或已失效 | 通用 |
| `IMPORT_TASK_NOT_FOUND` | 导入任务不存在 | 通用 |
| `IMPORT_TASK_OBJECT_TYPE_INVALID` | `object_type` 非允许枚举值 | 通用 |
| `IMPORT_TASK_STATUS_INVALID` | 任务状态非法 | 通用 |
| `IMPORT_TASK_NOT_FINISHED` | 任务尚未完成，当前不允许读取目标结果 | 通用 |
| `IMPORT_ERROR_REPORT_NOT_READY` | 当前任务没有可下载错误报告 | 通用 |
| `IMPORT_ROW_DUPLICATED_IN_FILE` | 同一文件内存在重复业务行 | 通用 |
| `IMPORT_VALUE_ENUM_INVALID` | 枚举值不合法 | 通用 |
| `IMPORT_VALUE_DATE_INVALID` | 日期或时间格式不合法 | 通用 |
| `IMPORT_VALUE_NUMBER_INVALID` | 数值格式不合法 | 通用 |
| `IMPORT_TARGET_WRITE_FAILED` | 后端写入目标模型失败 | 通用 |

## 3. `dispatch_main` 字段级错误码

说明：

- 当前正式标准模板已按“四 Sheet 正式模板”收口，单表仍只作为快捷导入模式保留。
- 因此 `dispatch_main` 错误码需要同时覆盖：
  - 主链写入
  - 同文件内一致性
  - 四 Sheet 关系校验

### 3.1 运单与门店节点

| `error_code` | 说明 | 推荐 `field_name` |
| --- | --- | --- |
| `IMPORT_WAYBILL_NO_REQUIRED` | 正式导入缺少 `waybill_no` | `waybill_no` |
| `IMPORT_WAYBILL_NO_NOT_FOUND` | 运单号未命中正式运单 | `waybill_no` |
| `IMPORT_WAYBILL_GROUP_NO_CONTROL_ONLY` | `waybill_group_no` 只能作导入控制字段 | `waybill_group_no` |
| `IMPORT_CUSTOMER_LINE_NO_CONFLICT` | 同一运单下 `customer_line_no` 发生冲突 | `customer_line_no` |
| `IMPORT_CUSTOMER_LINE_TARGET_NOT_FOUND` | 未在当前运单下命中门店节点 | `customer_line_no` |
| `IMPORT_STORE_NO_TARGET_NOT_FOUND` | 通过 `store_no` 也未命中门店节点 | `store_no` |
| `WAYBILL_NO_ALREADY_EXISTS` | 运单号已存在，当前模式仅允许新建主链 | `waybill_no` |
| `WAYBILL_SNAPSHOT_CONFLICT` | 同一文件内相同运单号对应的运单级字段不一致 | `waybill_no` / 冲突字段 |
| `CUSTOMER_LINE_KEY_MISSING` | 门店节点缺少可归并的稳定标识 | `customer_line_no` |
| `CUSTOMER_LINE_SNAPSHOT_CONFLICT` | 同一门店节点下客户/门店快照字段不一致 | `customer_line_no` / 冲突字段 |

说明：

- `customer_line_no` 的唯一性范围按 `(waybill_id, customer_line_no)` 收口。
- 不允许返回“按门店名称模糊猜测命中”的错误口径。

### 3.2 订单与货物

| `error_code` | 说明 | 推荐 `field_name` |
| --- | --- | --- |
| `BATCH_SNAPSHOT_CONFLICT` | 同一文件内相同批次号对应的批次级字段不一致 | `batch_no` / 冲突字段 |
| `BATCH_WAREHOUSE_CONFLICT` | 系统中已有批次的仓库与导入文件不一致 | `batch_no` |
| `BATCH_WAVE_CONFLICT` | 系统中已有批次的波次与导入文件不一致 | `batch_no` / `wave_no` |
| `WAVE_SNAPSHOT_CONFLICT` | 同一文件内相同波次号对应的波次级字段不一致 | `wave_no` / 冲突字段 |
| `WAVE_WAREHOUSE_CONFLICT` | 系统中已有波次的仓库与导入文件不一致 | `wave_no` |
| `WAVE_DATE_CONFLICT` | 系统中已有波次的配送日期与导入文件不一致 | `delivery_date` |
| `IMPORT_ORDER_KEY_REQUIRED` | 订单识别键缺失，无法定位订单层 | `source_doc_no` / `sales_order_no` |
| `IMPORT_PRODUCT_NAME_REQUIRED` | 商品名称缺失 | `product_name` |
| `IMPORT_PRODUCT_CODE_NOT_FOUND` | 商品编码未命中主档，且不满足当前导入策略 | `external_product_code` |
| `IMPORT_GOODS_LINE_PARENT_REQUIRED` | 货物行缺少有效订单归属 | `order_line_id` / 订单识别键 |
| `WAYBILL_NO_DUPLICATED_IN_SHEET` | `Waybill` Sheet 内运单号重复 | `waybill_no` |
| `CUSTOMER_LINE_DUPLICATED_IN_WAYBILL` | 同一运单下门店节点编号重复 | `customer_line_no` |
| `ORDER_LINE_NO_DUPLICATED_IN_FILE` | `OrderLine` Sheet 内订单行编号重复 | `order_line_no` |
| `WAYBILL_REFERENCE_NOT_FOUND` | 子 Sheet 引用的运单号未在 `Waybill` Sheet 中出现 | `waybill_no` |
| `CUSTOMER_LINE_REFERENCE_NOT_FOUND` | `OrderLine` 引用的门店节点未在 `CustomerLine` Sheet 中出现 | `customer_line_no` |
| `ORDER_LINE_REFERENCE_NOT_FOUND` | `GoodsLine` 引用的订单行未在 `OrderLine` Sheet 中出现 | `order_line_no` |
| `ORDER_LINE_KEY_DUPLICATED_IN_PARENT` | 同一父级下订单键重复或冲突 | `source_doc_no` / `sales_order_no` |

- 不再使用“一个订单行只能有一个货物行”的错误口径。

## 5. 接口顶层与字段级错误的关系

推荐处理方式：

1. 路由、权限、参数、资源不存在：
   - 返回顶层 `code != 0`
   - 可带顶层 `error_code`
2. 导入任务执行过程中的单行失败：
   - 顶层任务查询仍返回 `code = 0`
   - 失败信息进入：
     - `import_task.fail_count`
     - `import_task_line.status = failed`
     - `import_error_line.error_code`
3. 结果页、错误报告、错误明细页：
   - 不根据顶层错误码展示行级失败
   - 应读取任务统计和错误明细

## 6. 结果页推荐展示口径

结果页第一页建议展示：

- 顶层任务状态：
  - `pending`
  - `running`
  - `success`
  - `partial_failed`
  - `failed`
  - `cancelled`
- 行级失败数：
  - `fail_count`
- 当前最常见错误码前几项：
  - `top_error_codes`

推荐把 `top_error_codes` 做成聚合结果，例如：

```json
[
  {
    "error_code": "IMPORT_CUSTOMER_LINE_TARGET_NOT_FOUND",
    "count": 3
  },
  {
    "error_code": "IMPORT_WAYBILL_NO_REQUIRED",
    "count": 2
  }
]
```

说明：

- `top_error_codes` 是服务层聚合字段，不要求在底表单独建表。

## 7. 当前不再使用的旧口径

- 不再把所有失败都压成单个 `failure_reason` 文本。
- 不再只保留“成功 / 失败”两态，不区分 `partial_failed`。
- 不再只给页面一个布尔型 `error_report_url` 而不返回字段级 `error_code`。
