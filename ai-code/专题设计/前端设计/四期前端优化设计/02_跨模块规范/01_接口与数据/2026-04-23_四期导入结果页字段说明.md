# 2026-04-23 四期导入结果页字段说明

## 文档定位

- 本文用于冻结四期导入结果页当前已落地的页面结构、字段说明和读取口径。
- 自 2026-04-23 起，本文以数据库底表设计稿、导入接口返回样例和当前 `logistics_web` 结果页实现为共同基线。
- 本文覆盖标准主数据导入首轮结果页闭环，不展开图片包导入的独立页面差异。

## 核心结论

1. 结果页正式围绕 `task_no` 读取，不再围绕旧 `import_batch_no` 组织页面。
2. 结果页当前固定承接三层数据：
   - `import_task`
   - `import_task_line`
   - `import_error_line`
3. 结果页不再只是摘要页，而是固定包含：
   - 任务结果摘要
   - 文件与任务信息
   - 行结果明细
   - 字段错误明细
   - 错误报告入口
4. 结果页首轮已经支持：
   - 行结果状态筛选
   - 行结果分页
   - 字段错误明细分页
5. 标准主数据导入首轮业务统计扩展为 `wave / batch / waybill / customer_line / goods_line`，仍不在结果页展示 `written_order_line_count`。

## 1. 页面目标

结果页需要回答下面 5 个问题：

1. 这次导入对应哪个正式任务。
2. 当前任务状态是什么。
3. 成功了多少、失败了多少、写入了哪些业务对象。
4. 哪些行成功、哪些行失败、失败集中在哪些字段。
5. 下一步应继续核验、下载错误报告，还是回到导入中心。

## 2. 页面固定结构

结果页首轮固定为 7 个区域：

1. 顶部结果头
2. 任务摘要卡区
3. 文件与任务信息区
4. 行结果明细区
5. 字段错误明细区
6. 后续动作区
7. 失败说明与错误报告区

说明：

- 第 7 区在无失败时可以轻量化显示。
- 第 4 区固定具备状态筛选和分页。
- 第 5 区固定具备分页，不做状态筛选。

## 3. 顶部结果头字段

| 字段 | 来源 | 必显级别 | 说明 |
| --- | --- | --- | --- |
| `task_no` | `import_task.task_no` | 硬必显 | 结果页主读取键 |
| `object_type` | `import_task.object_type` | 硬必显 | 任务对象类型 |
| `object_type_label` | 服务层翻译 | 硬必显 | 页面中文对象名 |
| `status` | `import_task.status` | 硬必显 | 任务状态枚举值 |
| `status_label` | 服务层翻译 | 硬必显 | 页面状态标签 |
| `summary_message` | `import_task.summary_message` | 硬必显 | 一句话结果摘要 |

## 4. 任务摘要卡字段

首轮固定展示 8 张摘要卡：

| 卡片 | 字段 | 说明 |
| --- | --- | --- |
| 总行数 | `total_count` | 本次任务总处理行数 |
| 成功行数 | `success_count` | 成功写入或成功命中的行数 |
| 失败行数 | `fail_count` | 失败行数 |
| 新建波次数 | `business_summary.written_wave_count` | 成功写入波次数 |
| 新建批次数 | `business_summary.written_batch_count` | 成功写入批次数 |
| 新建运单数 | `business_summary.written_waybill_count` | 成功写入运单数 |
| 新建客户明细数 | `business_summary.written_customer_line_count` | 成功写入客户明细数 |
| 新建货物明细数 | `business_summary.written_goods_line_count` | 成功写入货物明细数 |

显示规则：

- 0 值必须正常显示为 `0`。
- `fail_count > 0` 时，失败卡片需要与错误明细区和错误报告区形成阅读联动。

## 6. 行结果明细区字段

结果页直接读取：

- `GET /api/admin/logistics/imports/tasks/{task_no}/lines`

### 6.1 列表字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `line_no` | `import_task_line.line_no` | 任务内行号 |
| `source_row_no` | `import_task_line.source_row_no` | 原始文件行号 |
| `status` | `import_task_line.status` | 行状态 |
| `status_label` | 服务层翻译 | 行状态中文名 |
| `business_key` | `import_task_line.business_key` | 行级业务摘要 |
| `target_model` | `import_task_line.target_model` | 写入目标模型 |
| `target_res_id` | `import_task_line.target_res_id` | 命中或创建后的目标主键 |
| `message` | `import_task_line.message` | 行结果说明 |

### 6.2 筛选参数

| 参数 | 类型 | 是否必传 | 说明 |
| --- | --- | --- | --- |
| `status` | string | 否 | 行状态筛选；支持 `pending / success / failed / skipped` |
| `page` | int | 否 | 页码，默认 `1` |
| `page_size` | int | 否 | 页大小，结果页当前固定 `20` |

### 6.3 分页元信息

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `page` | 服务层返回 | 当前页码 |
| `page_size` | 服务层返回 | 当前页大小 |
| `total` | 服务层返回 | 筛选后的总条数 |
| `total_pages` | 服务层返回 | 总页数 |
| `has_prev` | 服务层返回 | 是否存在上一页 |
| `has_next` | 服务层返回 | 是否存在下一页 |
| `showing_from` | 服务层返回 | 当前页起始序号 |
| `showing_to` | 服务层返回 | 当前页结束序号 |
| `status_filter` | 服务层返回 | 当前生效的状态筛选值 |
| `status_filter_label` | 服务层返回 | 当前生效的状态筛选中文名 |

显示规则：

- 默认按 `line_no asc` 排序。
- 页面默认先展示全部行结果第一页。
- 切换状态筛选时，页码必须重置到第一页。
- 页面必须明确展示当前页码和当前区间，例如 `第 2 页，共 5 页`、`21-40 / 共 95 条`。

## 7. 字段错误明细区字段

结果页直接读取：

- `GET /api/admin/logistics/imports/tasks/{task_no}/errors`

### 7.1 列表字段

| 字段 | 来源 | 说明 |
| --- | --- | --- |
| `line_no` | 通过 `task_line_id` 回带 | 任务内行号 |
| `business_key` | 通过 `task_line_id` 回带 | 行级业务摘要 |
| `source_row_no` | `import_error_line.source_row_no` | 原始文件行号 |
| `field_name` | `import_error_line.field_name` | 出错字段 |
| `raw_value` | `import_error_line.raw_value` | 原始值 |
| `mapped_value` | `import_error_line.mapped_value` | 映射值 |
| `error_code` | `import_error_line.error_code` | 字段级错误码 |
| `error_message` | `import_error_line.error_message` | 错误说明 |

### 7.2 分页参数与元信息

| 字段/参数 | 说明 |
| --- | --- |
| `page` | 当前页码，默认 `1` |
| `page_size` | 当前页大小，结果页当前固定 `20` |
| `total` | 错误总数 |
| `total_pages` | 总页数 |
| `has_prev / has_next` | 翻页可用性 |
| `showing_from / showing_to` | 当前页区间 |

显示规则：

- 默认按 `source_row_no asc, id asc` 排序。
- 错误区当前不支持 `status` 筛选。
- 页面必须优先展示 `field_name + error_message`，不能只堆错误码。

## 8. 错误报告区字段

| 字段 | 来源 | 必显级别 | 说明 |
| --- | --- | --- | --- |
| `error_report.download_ready` | 服务层返回 | 硬必显 | 是否可下载 |
| `error_report.download_url` | 服务层返回 | 条件显示 | 错误报告下载地址 |
| `fail_count` | `import_task.fail_count` | 硬必显 | 失败行数 |
| `failure_reason` | 服务层聚合 | 条件显示 | 首要失败原因摘要 |

交互规则：

- `download_ready = true` 时，展示“下载错误报告”。
- `download_ready = false` 且 `fail_count = 0` 时，展示轻量提示。
- `download_ready = false` 且 `fail_count > 0` 时，提示用户稍后刷新。

## 9. 后续动作区

固定动作建议：

| 动作 | 条件 | 说明 |
| --- | --- | --- |
| `刷新结果` | 始终可用 | 重新请求任务头、行结果和错误明细 |
| `下载错误报告` | `error_report.download_ready = true` | 下载错误文件 |
| `返回导入中心` | 始终可用 | 返回导入入口 |
| `进入运单列表` | 存在成功写入结果 | 进入运单阅读链 |
| `按任务继续核验` | 存在任务号 | 带 `task_no` 进入后续核验链 |

## 10. 当前不再使用的旧口径

- 不再把结果页主键写成 `import_batch_no`。
- 不再只返回一个 `failure_reason` 文本就结束结果反馈。
- 不再把结果页设计成只看摘要、不看行结果和错误明细。
- 不再要求用户离开结果页后，才能做基础的行结果分页阅读。
- 不再在标准主链结果页首轮返回 `written_order_line_count`。
