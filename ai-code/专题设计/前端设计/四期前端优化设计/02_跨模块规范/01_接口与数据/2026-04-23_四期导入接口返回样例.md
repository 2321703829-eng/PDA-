# 2026-04-23 四期导入接口返回样例

## 文档定位

- 本文用于冻结四期导入链当前已落地的接口返回结构。
- 自 2026-04-23 起，本文以数据库底表设计稿、当前代码实现和结果页联调现状为共同基线。
- 本文覆盖标准主数据导入首轮实现，不展开图片包导入执行细节。

## 核心结论

1. 标准导入任务不是通过独立 `POST /api/admin/logistics/imports/tasks` 创建，而是由预校验接口直接创建。
2. 当前标准链路收口为：
   - `POST /api/admin/logistics/imports/waybill-standard/precheck`
   - `POST /api/admin/logistics/imports/waybill-standard/confirm`
   - `GET /api/admin/logistics/imports/tasks/{task_no}`
   - `GET /api/admin/logistics/imports/tasks/{task_no}/lines`
   - `GET /api/admin/logistics/imports/tasks/{task_no}/errors`
   - `GET /api/admin/logistics/imports/tasks/{task_no}/error-report`
3. 预校验阶段即正式落库到：
   - `import_source_file`
   - `import_task`
   - `import_task_line`
   - `import_error_line`
4. `task_no` 是正式任务主键；`import_batch_no` 只作为兼容回传字段保留。
5. 结果页当前已经直接消费 `/lines` 和 `/errors`，并支持：
   - 行结果状态筛选
   - 行结果分页
   - 字段错误明细分页

## 1. 通用响应外壳

```json
{
  "code": 0,
  "message": "成功",
  "data": {},
  "request_id": "req_import_task_20260423_001"
}
```

说明：

- `code = 0` 表示接口成功返回。
- 业务失败码进入 `data.errors[*].error_code` 或 `import_error_line.error_code`。
- 下载错误报告成功时直接返回文件流，不走 JSON 外壳。

- 预校验阶段 `success_count / fail_count` 不单独返回，继续沿用 `passed_row_count / failed_row_count` 语义。
- 新预校验任务不再写入旧 `logistics.import.batch`。

- `target_model / target_res_id` 仅在命中目标对象时返回。
- `total_pages / has_prev / has_next / showing_from / showing_to` 为结果页分页直接消费字段。

## 7. 错误报告下载

`GET /api/admin/logistics/imports/tasks/{task_no}/error-report`

成功时：

- 直接返回 CSV 文件流。
- 当前导出列固定为：
  - `任务号`
  - `原始行号`
  - `字段名`
  - `原始值`
  - `映射值`
  - `错误码`
  - `错误说明`

无错误报告时返回：

```json
{
  "code": 1,
  "message": "下载错误报告失败",
  "data": {
    "errors": [
      {
        "error_code": "ERROR_REPORT_NOT_FOUND",
        "error_message": "当前任务没有可导出的错误报告。"
      }
    ]
  },
  "request_id": "req_import_task_error_report_001"
}
```

## 9. 兼容边界

- 旧结果页兼容路由仍保留：
  - `GET /api/admin/logistics/imports/waybill-standard/result`
  - `GET /api/admin/logistics/imports/waybill-standard/error-report`
- 旧参数仍允许兼容读取：
  - `import_batch_no`
  - `precheck_token`
- 但从新预校验开始，标准主链导入不再继续写入旧 `logistics.import.batch`。
