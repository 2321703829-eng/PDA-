# 2026-04-21 四期后端数据库与接口影响面调研稿

## 文档定位

- 本文用于同步四期首轮范围收口后的后端数据库、模型、接口 DTO、服务层和前端联动口径。
- 自 2026-04-23 起，本文统一以《四期数据库底表设计稿 v1（第二次修正版）》为当前有效数据库基线。
- 本文优先描述当前已经冻结的数据库对象、导入任务模型和接口影响面，不把下一阶段对象扩展混入本轮口径。

## 当前结论

1. 首轮只保留司机画像和车辆画像，不正式落库司机/车辆调度状态表、分配历史表。
2. 司机和车辆当前运行态，统一由 `logistics.dispatch.batch` 事实数据实时推导。
3. `logistics.product.unit` 改为“一行一个销售单位”，不再在同一行维护小/中/大三套价格和条码。
4. 地址字段改为“完整地址 + 经纬度 + 结构化地址 JSON”并同步到门店快照层。
5. 当前司机事实来源仍然是 `batch.driver_employee_id`，车辆事实来源仍然是 `batch.vehicle_id`。
6. 主数据导入与图片导入都需要纳入统一导入任务审计链，当前对象类型分别是 `dispatch_main` 和 `image_package`。
7. 商品主数据后续规划为“全局商品主档 + 规格/SKU层 + 客户商品关系层 + 运单货物执行层”分层结构。
8. `logistics_customer_product_profile` 只作为后续规划对象保留在设计中，本期不正式建表。

### 首轮需要重点同步的字段改动

#### 1. `logistics_product_unit`

旧口径是“一条记录里同时放小/中/大单位字段”，当前改为“一条记录只表达一个销售单位”。

保留字段：

- `product_tmpl_id`
- `spec_desc`
- `unit_name`
- `sale_unit_name`
- `barcode`
- `standard_price`
- `purchase_price`
- `retail_price`
- `package_count`
- `weight`
- `volume`

删除字段：

- `small_barcode`
- `middle_barcode`
- `large_barcode`
- `small_standard_price`
- `middle_standard_price`
- `large_standard_price`
- `small_purchase_price`
- `middle_purchase_price`

补充说明：

- 当前行只维护当前 `sale_unit_name` 对应的字段。
- `small_* / middle_* / large_*` 这类跨单位字段不再补回。
- 同商品多单位信息通过多行 `logistics_product_unit` 记录表达。

状态说明：

- 本对象当前只保留为后续规划设计。
- 本期不建表、不出正式接口、不纳入当前模块升级范围。

后续如果启动客户商品关系层，再新增一张关系表承接客户商品默认规则。

- `partner_id`
- `product_tmpl_id`
- `product_unit_id`
- `customer_product_code`
- `customer_product_name_alias`
- `default_signoff_requirement`
- `default_package_requirement_text`
- `default_temperature_zone`
- `allow_substitute_unit`
- `min_delivery_qty`
- `is_frequently_ordered`
- `is_disabled`
- `sort_order`
- `relation_remark`

推荐唯一约束：

- `unique(partner_id, product_tmpl_id, product_unit_id)`

边界说明：

- 本表只表达“这个客户如何使用这个商品/销售单位”。

### 本轮最关键的 DTO 收口点

#### 1. 商品单位 DTO

无论是导入 DTO、保存 DTO 还是返回 DTO，都应改成单单位结构。

推荐请求体：

```json
{
  "product_tmpl_id": 1001,
  "spec_desc": "550ml*24",
  "unit_name": "箱",
  "sale_unit_name": "中",
  "barcode": "690000000001",
  "standard_price": 108.0,
  "purchase_price": 92.5,
  "retail_price": 118.0,
  "package_count": 24,
  "weight": 13.2,
  "volume": 0.035
}
```

不再接收：

- `small_*`
- `middle_*`
- `large_*`

#### 1.1 客户商品关系 DTO

状态说明：

- 本 DTO 当前只保留为后续规划。
- 本期接口不新增该 DTO，不调整当前导入与保存主链。

后续如果启动客户商品关系层，推荐新增单独 DTO 对象，不把客户商品默认规则塞回商品单位 DTO。

推荐请求体：

```json
{
  "partner_id": 2001,
  "product_tmpl_id": 1001,
  "product_unit_id": 3001,
  "customer_product_code": "KH-A-0001",
  "customer_product_name_alias": "矿泉水标准箱",
  "default_signoff_requirement": "需门店负责人签收",
  "default_package_requirement_text": "整箱配送，不拆零",
  "default_temperature_zone": "常温",
  "allow_substitute_unit": false,
  "min_delivery_qty": 1.0,
  "is_frequently_ordered": true,
  "is_disabled": false,
  "sort_order": 10,
  "relation_remark": ""
}
```

说明：

- `partner_id + product_tmpl_id + product_unit_id` 是当前推荐关系命中键。
- 如果后续需要只按商品本体粒度管理，再单独设计产品级关系模式，不在本轮混入。

#### 2. 门店地址 DTO

门店画像、门店导入、客户节点快照都应统一为以下口径：

```json
{
  "address_full": "广东省广州市白云区 xx 街道 xx 号",
  "longitude": 113.2621234,
  "latitude": 23.156789,
  "address_region_json": {
    "province": "广东",
    "city": "广州",
    "district": "白云",
    "detail": "广东省广州市白云区 xx 街道 xx 号"
  }
}
```

说明：

- `longitude / latitude` 应传数字，不再传字符串。
- `province/city/district/detail` 放在 `address_region_json` 中，便于接口与数据库口径统一。

#### 3. 导入任务 DTO

主数据与图片导入的统一返回结构至少应包含：

```json

  "status": "running",
  "total_count": 120,
  "success_count": 0,
  "fail_count": 0,
  "summary_message": ""

```

说明：

- 图片包导入时 `object_type` 改为 `image_package`。
- 行结果与字段级错误应可通过任务明细接口继续读取。

## 响应体口径

### 司机画像概览响应

司机概览页应返回：

- `status`
- `status_label`
- `dispatch_enabled`
- `allow_night_shift`
- `shift_type`
- `shift_type_label`
- `current_vehicle`
- `current_warehouse`
- `current_batch`
- `recent_vehicle`

说明：

- 这些字段现在由“司机画像 + 当前活跃 batch”实时推导。
- 不再返回或依赖 `dispatch_state` 独立表对象。

### 车辆画像概览响应

车辆概览页应返回：

- `status`
- `status_label`
- `dispatch_enabled`
- `current_driver`
- `current_warehouse`
- `current_batch`
- `recent_driver`

说明：

- 当前车辆状态也改为从 `batch` 推导，不再从独立调度状态表读取。

### 导入任务响应

任务响应至少应返回：

- `task_no`
- `object_type`
- `status`
- `total_count`
- `success_count`
- `fail_count`
- `summary_message`

行结果响应至少应返回：

- `line_no`
- `source_row_no`
- `object_type`
- `status`
- `business_key`
- `target_model`
- `target_res_id`
- `message`

错误行响应至少应返回：

- `source_row_no`
- `field_name`
- `raw_value`
- `mapped_value`
- `error_code`
- `error_message`

## 服务层影响

### `logistics_web` 服务层

司机与车辆管理页的运行态来源改为：

- 画像模型
- 当前活跃 `logistics.dispatch.batch`
- 当前记录 `active` 状态

运行态判定规则：

- 记录停用时，状态为 `disabled`
- 存在当前活跃 batch 时，状态为 `assigned`
- 其他情况为 `idle`

司机班次类型规则：

- 以 `actual_depart_time` 或 `planned_depart_time` 推导
- 18:00 之后或 06:00 之前视为 `night`
- 其他时间视为 `day`

## 前端联动影响

当前前端实际资产包应与以下字段口径保持一致：

- 司机列表支持 `warehouse_options`
- 司机详情展示 `current_warehouse / current_vehicle / current_batch`
- 车辆列表支持 `warehouse_options`
- 车辆详情展示 `current_driver / current_warehouse / current_batch`
- 导入结果页支持按任务、按行、按字段级错误回读

不应继续依赖：

- `has_own_vehicle_options`
- 独立 `dispatch_state` 读取
- 旧的未审计式导入结果页口径

## 本轮请求体与数据库同步关系

### 必须一并同步的内容

1. 请求体字段名
2. 后端 DTO 字段名
3. ORM 模型字段名
4. 视图字段清单
5. 服务层响应组装逻辑
6. 导入任务与错误行接口返回结构

### 否则容易出现的问题

- 前端请求参数传了，但后端不再识别
- 后端筛选项返回结构和前端模板不一致
- 模型字段已经删除，但导入 DTO 还在传旧字段
- 数据库字段已经改成浮点，接口还在传字符串
- 导入任务已落库，但前端结果页没有正式任务号可回查

## 执行建议

1. 先以本文为准同步请求体与响应体口径。
2. 再同步导入任务、行结果、错误行接口。
3. 再同步接口实现、服务层与前端模板。
4. 最后执行模块升级或开发库重建。
