# 2026-04-21 四期业务评审问题清单

## 已按数据库设计冻结的结论

1. 四期主结构是 `waybill -> customer_line -> order_line -> goods_line`。
2. 一个运单下允许多个门店节点，数据库按 `waybill 1 -> n customer_line` 建模。
3. `waybill_no` 是正式运单键，`waybill_group_no` 只是导入控制字段。
4. `customer_line_no` 是稳定业务键，但唯一性范围按 `(waybill_id, customer_line_no)` 收口。
5. `order_line` 到 `goods_line` 按 `1 -> n` 建模，不再保留“首轮强制 1:1”的判断。
6. 图片导入独立于主数据导入，任务对象类型区分为 `dispatch_main` 和 `image_package`。
7. 司机事实归属层仍是 `batch`。

## 本轮仍建议确认的问题

### 1. `customer_line_no` 是否默认对业务用户展示

- 数据库口径已经冻结为稳定业务键
- 但前端模板、结果页、阅读页是否默认展示，仍可按体验再收口

### 2. 司机电话、车辆号是否进入首轮单表

- 当前数据库允许这些字段作为快照扩展
- 但是否纳入第一批模板字段，还需要业务与实施一起确认

### 3. 图片包首轮标准清单是否固定一种格式

- 当前设计允许 `manifest.xlsx` 或 `manifest.csv`
- 若要减少联调分支，建议尽快决定首轮唯一标准

### 4. 兼容输入模式是否继续对业务用户开放

- 当前旧标准模板可以继续作为兼容输入模式
- 但业务主入口是否只保留单表，还需要产品和实施一起确认
