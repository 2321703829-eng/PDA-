# 数据库与接口现状盘点说明-2026-04-21

## 文档定位

- 本文保留现状盘点用途，但当前判断统一以四期数据库底表设计稿为准。
- 本文用于说明：哪些现状可以继续复用，哪些接口与文档需要回收旧口径。

## 现状盘点摘要

### 1. 当前最值得复用的现状

- `waybill` 仍然是主执行对象
- `customer_line`、`order_line`、`goods_line` 都有现成模型基础
- 导入服务已有基础可复用
- 图片上传与访问已有单图能力
- 导入任务、行结果、错误行已经在数据库设计中形成统一审计口径

### 2. 当前最需要重新强化的方向

- `waybill_no` 与 `waybill_group_no` 的职责边界
- `customer_line_no` 的运单内唯一口径
- `customer_line_id / order_line_id` 的正式关联使用
- `dispatch_main / image_package` 两类导入任务的接口区分

### 3. 当前最需要补的方向

- 单表导入接口与导入任务结果接口
- 门店节点详情接口与页面
- 图片包导入/导出与结果反馈

## 数据库层现状判断

### 可以继续复用

- `logistics.dispatch.waybill`
- `logistics.dispatch.waybill.customer.line`
- `logistics.dispatch.waybill.order.line`
- `logistics.dispatch.waybill.goods.line`
- `import_source_file`
- `import_task`
- `import_task_line`
- `import_error_line`

### 需要重新作为四期核心承接

- `logistics_dispatch_waybill_customer_line`
- 导入任务对象类型 `dispatch_main`
- 图片导入对象类型 `image_package`

### 需要回收的旧理解

- 把 `waybill_group_no` 当正式运单键
- 把 `customer_line_no` 当全局主键
- 把 `goods_line` 收成首轮强制 1:1
- 只谈页面结构，不接导入任务审计

## 接口层现状判断

### 优先要改

- 单表导入接口
- 导入任务结果接口
- 运单详情接口
- 门店节点详情接口
- 图片导入/导出接口

### 首轮可后置

- 小程序接口
- `trace / evidence` 后续衔接接口

## 当前统一结论

数据库和接口设计都应统一围绕下面 4 条判断：

1. 正式业务链是 `waybill -> customer_line -> order_line -> goods_line`
2. 导入审计链是 `source_file -> import_task -> import_task_line -> import_error_line`
3. `waybill_group_no` 是导入控制字段，不替代正式运单键
4. `customer_line_no` 是运单内稳定业务键，不替代数据库主键
