# 2026-04-24 四期司机侧Excel导出模块设计方案
## Objective

- 在不改动现有司机侧 PDF 方案的前提下，补一版独立的司机侧 Excel 导出设计。
- 让调度、运营、现场人员可以一次性导出当天所有路线，用一张最简路线清单把整条路的顺序和门店联系信息发给司机。
- 首轮尽量把实现收到最简单，只保留一个直接批量导出接口。

## Boundary

- 本文只讨论司机侧 Excel 导出，不替代现有司机侧 PDF 方案。
- 本文首轮导出范围按“当天所有路线”定义，主入口按 `delivery_date`。
- 本文首轮只做单表司机清单，不做多 Sheet。
- 本文首轮只保留已确认的 9 个字段，不扩展时间窗、卸货要求、货量摘要等字段。
- 本文只冻结结构、字段、接口和展示规则，不直接进入编码实现。

## OBB

### Outcome

- 系统支持按配送日期一次性导出当天所有路线的 Excel 清单。
- 清单只解决一件核心事情：让司机快速知道这条路怎么送、每家店联系谁、备注是什么。

### Behavior

- 调度或运营按当天配送日期发起司机侧 Excel 批量导出。
- 系统直接返回一个 Excel 文件下载，不额外引入任务创建、状态查询、结果下载三套接口。
- Excel 文件只有一张主表，每一行就是一个停靠点。
- 如果表内存在缺字段、顺序异常或运单缺少停靠点，文件首行要显示“异常提醒”，提示人工复查。

### Boundary

- 首轮不做四 Sheet。
- 首轮不做标准导出那种结构化层级。
- 首轮不做司机移动端在线作业。

## Current Understanding

你现在要的不是复杂工作簿，也不是给司机看一堆业务字段，而是一张最简单、最直接的“当天所有路线送货顺序清单”。

正式口径收成：

- 一个文件，对应当天所有路线
- 一张表
- 一行一个停靠点
- 只保留 9 个字段

## 1. 正式定位

### 1.1 模块定位

司机侧 Excel 导出是独立于标准导出和司机侧 PDF 导出的第三种输出形式：

- 标准导出：`standard_export`
- 司机侧 PDF 导出：`driver_route_export_pdf`
- 司机侧 Excel 导出：`driver_route_export_excel`

### 1.2 目标用户

首轮目标用户是：

- 调度
- 运营
- 现场管理人员

### 1.3 主阅读范围

司机侧 Excel 首轮以“当天所有路线”为主阅读范围。

- 一个导出文件承接某一天全部批次的路线信息
- 文件内仍然按批次号区分不同路线
- 每个批次内部都必须完整展开该批次下所有停靠客户信息

## 2. 导出入口与接口

### 2.1 首轮正式入口范围

首轮正式入口按配送日期发起，正式建议为：

- `delivery_date`

原因：

1. 业务目标是一次性导出当天所有路线，而不是单个批次。
2. 当天路线天然可能覆盖多个批次。
3. 当前历史导入数据可能缺失波次号，先按日期导出最稳。

### 2.2 首轮正式接口

首轮只保留一个直接批量导出接口：

- `POST /api/admin/logistics/exports/driver-route-excel/direct-download`

入参建议：

- `delivery_date`
- `file_locale`

返回建议：

- 直接返回 `xlsx` 文件流

### 2.3 后续演进

为了首轮快速落地，当前不先做：

- 创建导出任务接口
- 查询任务状态接口
- 结果下载接口

后续如果文件体量变大、生成耗时变长，再演进为标准任务链。

## 3. Excel 文件结构设计

### 3.1 正式输出格式

首轮正式输出格式：

- `xlsx`

### 3.2 正式工作表结构

首轮只保留 1 个工作表，建议中文名为：

- `司机路线清单`

英文内部 code 可用：

- `DriverRouteList`

### 3.3 行粒度

正式行粒度固定为：

- 一行 = 一个停靠点 = 一个客户/门店配送站点

### 3.4 为什么仍然保留批次号

虽然首轮导出范围是“当天所有路线”，但单表里仍必须保留 `批次号`，因为：

1. 同一天会有多条路线。
2. 批次号是当前最稳定的路线分辨字段。
3. 司机和调度在同一张表里需要快速区分不同路线。

## 4. 单表字段设计

### 4.1 正式字段顺序

首轮字段顺序固定为：

1. 批次号
2. 送货顺序
3. 运单号
4. 客户名称
5. 门店名称
6. 联系人
7. 联系电话
8. 地址
9. 客户/门店备注

### 4.2 字段分组理解

虽然最终只是一张表，但逻辑上可分 3 组：

- 路线主线：`批次号 / 送货顺序 / 运单号`
- 店铺识别：`客户名称 / 门店名称 / 联系人 / 联系电话 / 地址`
- 备注信息：`客户/门店备注`

## 5. 字段来源与复用规则

### 5.1 字段来源基线

司机侧 Excel 的字段来源以当前已有稳定字段为准：

- 批次层：`logistics.dispatch.batch`
- 运单层：`logistics.dispatch.waybill`
- 停靠点层：`logistics.dispatch.waybill.customer.line`
- 客户层：`res.partner`

### 5.2 必带字段

首轮必带字段只保留这 9 个：

- 批次号
- 送货顺序
- 运单号
- 客户名称
- 门店名称
- 联系人
- 联系电话
- 地址
- 客户/门店备注

### 5.3 缺失波次号时的系统补齐规则

当前导入数据可能缺失 `wave_no`，首轮正式口径建议如下：

- `wave_no` 可为空，不作为首轮司机侧 Excel 导出的前置依赖。
- 系统在导入正式落库时，若发现 `wave_no` 缺失，则按配送日期自动生成默认波次号。
- 默认波次号建议格式：
  - `AUTO-WV-YYYYMMDD-001`
- 同时建议保留波次来源标识：
  - `wave_source = manual / auto`
- 若连配送日期也缺失，则按下面优先级补齐日期来源：
  1. 业务日期字段
  2. 可推断的上游日期
  3. 导入任务创建日期
  4. 仍无法确定时进入 `UNKNOWN` 桶
- 无法确定日期时，默认波次号建议格式：
  - `AUTO-WV-UNKNOWN-001`
- 同时建议保留日期来源标识：
  - `date_source = business / inferred / import_created_at / unknown`

这条规则的作用是：

1. 不让历史数据因为缺失波次号而卡住导出。
2. 后续如果要补波次入口，系统已经有默认组织层可用。
3. 即使日期缺失，也能先把数据归入默认组织桶，不阻断后续人工复查。
4. 但首轮司机侧 Excel 导出本身仍以 `delivery_date` 为主入口，不强依赖波次号。

## 6. 排序与展示规则

### 6.1 同批次内客户排序规则

同批次内所有停靠点都按统一排序结果展示，正式口径为：

1. 优先按 `stop_seq_in_waybill`
2. 缺失或冲突时按 `waybill.route_seq`
3. 再按 `waybill_no`
4. 再按 `customer_line_no`
5. 最后按记录 `id`

### 6.2 多运单展示规则

- 当天文件内多批次统一合并展示。
- 每个批次内多运单统一合并展示。
- 全部按停靠点顺序字段给司机看。
- 运单号只作为辅助识别字段保留。

### 6.3 Excel 展示增强

首轮建议固定：

- 首行冻结
- 开启自动筛选
- 关键列宽预设
- 地址和备注列允许自动换行

建议重点列宽：

- 客户名称
- 门店名称
- 地址
- 客户/门店备注

### 6.4 异常提醒展示规则

首轮异常提醒不新增业务字段列，避免破坏当前 9 个字段清单，统一采用下面的方式：

1. 文件首行做一条总提醒
   - 正常时显示 `异常提醒：无`
   - 异常时显示 `异常提醒：本表包含 X 条需人工复查的数据`
2. 仍保留第 2 行为正式表头
3. 存在问题的关键单元格做底色高亮
4. 异常范围首轮只覆盖：
   - 批次号缺失
   - 送货顺序缺失
   - 运单号缺失
   - 客户名称缺失
   - 门店名称缺失
   - 联系电话缺失
   - 地址缺失
   - 运单存在但没有任何停靠点

## 7. 字段缺失与降级展示规则

### 7.1 阻断生成

以下关键标识缺失时，整天导出不生成司机 Excel：

- `delivery_date`

### 7.2 允许降级展示

以下字段缺失时，允许继续生成，但要降级显示：

- 客户名称：显示 `客户名称缺失`
- 联系电话：显示 `电话缺失`
- 地址：显示 `地址缺失`
- 客户/门店备注：留空

### 7.3 顺序缺失

`stop_seq_in_waybill` 缺失或冲突时：

- 使用兜底排序继续输出
- 送货顺序列按兜底结果输出

## 8. 实现拆分清单

### 8.1 后端任务

#### Task B1: 按配送日期取数与数据装配

目标：

- 按 `delivery_date` 取到当天所有批次的停靠点清单数据。

范围：

- 读取当天全部批次、运单、停靠点、客户联系信息。
- 统一整理成单表 DTO。

#### Task B2: 排序与降级规则落地

目标：

- 把排序和字段缺失降级规则固化到服务层。

#### Task B3: 缺失波次号自动补齐

目标：

- 在导入正式落库阶段补齐默认波次号，避免当天路线导出被缺失波次号卡住。

范围：

- `wave_no` 缺失识别
- 默认波次号生成
- `wave_source` 标记

#### Task B4: 直接导出文件生成

目标：

- 不走任务链，直接生成并返回 Excel 文件。

### 8.2 Excel 工作簿生成任务

#### Task W1: 单表骨架生成

目标：

- 生成 `司机路线清单` 单表结构。

范围：

- 表头顺序
- 首行冻结
- 自动筛选
- 列宽预设

#### Task W2: 数据写入与单元格样式

目标：

- 把单表 DTO 写入工作表，并补基础样式。

范围：

- 地址和备注自动换行
- 关键列宽

### 8.3 接口任务

#### Task A1: 直接批量导出接口

建议接口：

- `POST /api/admin/logistics/exports/driver-route-excel/direct-download`

入参建议：

- `delivery_date`
- `file_locale`

返回建议：

- 直接下载 `xlsx`

### 8.4 页面入口任务

#### Task P1: 当天路线导出入口按钮

建议入口文案：

- `司机侧Excel导出`

建议入口位置：

- 当天路线页
- 调度页
- 配送日期筛选区附近

#### Task P2: 导出中心说明卡片

卡片需说明：

- 适用对象：调度/运营/司机发包
- 文件格式：Excel
- 文件结构：单表路线清单
- 导出范围：当天所有路线

## 9. 实施顺序建议

建议按下面顺序推进：

1. `B1 + B2`
2. `B3`
3. `W1 + W2`
4. `B4 + A1`
5. `P1 + P2`

## 10. 首轮验收建议

首轮建议用 1 个真实配送日期做 smoke，重点验这几件事：

1. 能成功按当天配送日期发起司机侧 Excel 导出。
2. 下载的是单表清单。
3. 文件里包含当天全部批次的路线信息。
4. 所有停靠点按既定顺序展开。
5. 联系人、联系电话、地址、备注等核心字段在同一行可见。
6. 缺失 `wave_no` 的数据也不会阻断当天导出。

## 11. 首轮双入口落位

首轮司机侧 Excel 导出入口固定放在 2 处：

1. 导入中心内的统一入口区块
2. 批次页上的业务快捷入口

具体口径：

- 导入中心内新增 `司机侧路线导出` 区块
- 区块内只保留 `delivery_date` 和 `导出当天路线`
- 批次页新增 `司机路线导出` 按钮
- 批次页入口点击后，跳转到导入中心，并尽量预填当前批次对应的 `delivery_date`
- 如当前批次下存在多个日期或无法识别日期，则保留人工确认提示

两个入口最终统一调用：

- `POST /api/admin/logistics/exports/driver-route-excel/direct-download`
