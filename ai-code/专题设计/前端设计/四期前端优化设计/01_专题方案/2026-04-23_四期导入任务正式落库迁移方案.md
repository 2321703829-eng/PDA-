# 2026-04-23 四期导入任务正式落库迁移方案

## 文档定位

- 本文用于收口四期标准主数据导入从旧 `logistics.import.batch` 过渡到正式 `import_source_file / import_task / import_task_line / import_error_line` 的实现边界。
- 自 2026-04-23 起，本文以四期数据库底表设计稿与当前 `logistics_web` 导入实现为共同基线。
- 本文覆盖标准主数据导入首轮迁移，不展开图片包导入执行细节。

## Outcome

- 预校验阶段直接创建正式 `import_task(dispatch_main)`。
- 正式导入确认以 `task_no` 为标准入口，不再以 `precheck_token` 作为主链路入口。
- 行结果与字段级错误正式落到 `import_task_line`、`import_error_line`。
- 导入中心、结果页、错误报告、行结果查询统一围绕 `task_no` 运转。

## Behavior

### 1. 预校验阶段

- 上传文件后先创建 `import_source_file`。
- 原始文件通过 `storage_path` 落到临时文件存储，用于正式导入阶段重读。
- 预校验完成后直接创建 `import_task`：
  - `object_type = dispatch_main`
  - `status = pending`
  - `total_count = 总数据行数`
  - `success_count / fail_count` 在 `pending` 阶段临时表示“预校验通过 / 失败行数”
- 每一条源数据行进入 `import_task_line`
  - 无预校验错误：`status = pending`
  - 有预校验错误：`status = failed`
- 每一条字段级失败进入 `import_error_line`
- 预校验返回值直接携带正式任务头信息：
  - `task_no`
  - `object_type / object_type_label`
  - `status / status_label`
  - `source_file`
  - `error_report`

### 2. 正式导入阶段

- 标准确认入口为 `POST /api/admin/logistics/imports/waybill-standard/confirm`。
- 正式导入主入参为 `task_no`；`import_batch_no / precheck_token` 仅保留兼容。
- 执行前从 `import_source_file.storage_path` 重读原始文件并重新解析，不再依赖旧 `source_rows_json` 快照。
- 任务开始执行时：
  - `import_task.status = running`
  - `started_at` 记录开始时间
- 执行完成后：
  - `import_task.status` 按结果收口为 `success / partial_failed / failed`
  - `success_count / fail_count` 改写为最终导入成功 / 失败行数
  - `finished_at` 记录完成时间

### 3. 行结果与错误明细

- `GET /api/admin/logistics/imports/tasks/{task_no}/lines` 的唯一来源是 `import_task_line`。
- `GET /api/admin/logistics/imports/tasks/{task_no}/errors` 的唯一来源是 `import_error_line`。
- 标准三工作表首轮不单独落 `sheet_name` 字段，因此采用以下承接方式：
  - `task_line.business_key` 必须带上 `sheet_name + source_row_no + 业务摘要`
  - 错误明细通过 `task_line_id` 回带 `line_no / business_key`
- 结果页汇总统计当前以 `waybill / customer_line / goods_line` 为准，不在首轮补 `order_line` 汇总字段。

### 4. 路由与兼容策略

- 新任务正式读取路径：
  - `GET /api/admin/logistics/imports/tasks/{task_no}`
  - `GET /api/admin/logistics/imports/tasks/{task_no}/lines`
  - `GET /api/admin/logistics/imports/tasks/{task_no}/errors`
  - `GET /api/admin/logistics/imports/tasks/{task_no}/error-report`
- 旧兼容路径保留：
  - `GET /api/admin/logistics/imports/waybill-standard/result`
  - `GET /api/admin/logistics/imports/waybill-standard/error-report`
- 对历史旧批次数据，允许结果读取阶段做兼容回退。
- 但新创建的标准预校验任务不得继续写入 `logistics.import.batch`。

## Boundary

### 本轮纳入

- 标准主数据导入首轮迁移
- `dispatch_main` 正式任务头
- 行结果与字段级错误正式落库
- 导入中心到结果页的 `task_no` 参数收口
- 结果查询、错误报告、行结果、错误明细路由收口

### 本轮不纳入

- 图片包导入迁移到正式任务链
- 导入任务取消能力
- 导入任务历史中心
- 旧 `logistics.import.batch` 物理删表
- 标准主链结果页首轮补齐 `order_line` 维度统计

## 核心结论

1. `storage_path` 是首轮替代 `source_rows_json` 的关键落点。
2. `task_no` 是预校验、正式导入、结果页、行结果、错误明细、错误报告的统一正式任务键。
3. `pending` 阶段的 `success_count / fail_count` 允许先承载预校验通过 / 失败行数；任务完成后再切换为最终导入成功 / 失败行数。
4. 旧 `logistics.import.batch` 只保留历史兼容读取，不再作为新任务的正式落库承载。
