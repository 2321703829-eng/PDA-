# 2026-04-16 三期统计图表接口补充清单

适用范围：

- 用于后续拆三期统计图表专题的后端任务、接口联调和评审收口
- 当前只覆盖后台 `admin` 场景下的全局统计图表页
- 当前不覆盖司机画像详情页中的个人趋势图接口

当前状态：

- 本文件是三期统计图表接口的补充清单
- 它承接 `2026-04-16_Odoo物流后台统计图表专题方案.md`
- 涉及指标口径时，继续以 `2026-04-16_三期统计指标字典讨论版.md` 为准

---

## 1. 文档定位

这份清单只回答一个问题：

**三期全局统计图表页，需要补哪些接口，哪些能力继续复用，哪些事项不要误判成需要新接口。**

统一拆成 4 类：

1. 继续复用
2. 新增接口域
3. 图表与接口映射
4. 当前不建议重复开口

---

## 2. 当前统一业务口径

### 2.1 页面口径

- 本文档只服务三期全局统计图表页
- 全局统计页第一页按 `执行概览 / 风险概览 / 司机与资源 / 区域与质量` 4 组组织
- 全局统计页第一版正式保留 `10 张图`
- 推进顺序按 `P0 8 张 + P1 2 张`

### 2.2 指标口径

- 运单、司机、地区相关统计默认按 `delivery_date`
- 异常总量和异常类型按 `exception.report_time`
- 客户与地区相关统计按 `customer_line`
- 地区主口径统一挂在 `门店地区`
- 缺证据统一包含 `missing + partial`
- 高风险批次排行按：
  1. `批次异常率`
  2. `严重异常数`
  3. `超时运单数`

### 2.3 页面分工口径

- 全局统计页中的司机图表只保留 `司机月均异常率排行图`
- 司机个人趋势图继续留在司机画像详情页，不在本清单中重复拆接口

### 2.4 当前接口路线

- 全局统计页聚合统计优先走 `JSON controller`
- 下钻后业务列表和详情页，优先复用原业务域接口，不重做“统计专用列表接口”
- 后台接口前缀统一优先使用：`/api/admin/logistics/...`

---

## 3. 复用与不重复开口径

### 3.1 继续复用的能力

| 能力 | 当前处理方式 | 说明 |
|---|---|---|
| 运单列表与运单详情 | 继续复用现有运单业务页与业务接口 | 图表点击后的运单下钻，不单独再造统计专用运单接口 |
| 异常列表与异常详情 | 继续复用现有异常业务页与业务接口 | 异常趋势图、异常类型分布图的下钻继续回到原异常域 |
| 批次列表与批次详情 | 继续复用现有批次业务页与业务接口 | 高风险批次排行点击后，继续进入原批次域 |
| 司机画像详情页 | 继续复用司机管理专题中的司机画像页承接 | 全局统计页中的司机排行，只负责发现问题，不负责解释个人趋势 |

### 3.2 当前不建议重复开的接口

| 不建议新增项 | 原因 |
|---|---|
| `getWaybillTrendOnly`、`getExceptionTrendOnly` 这类每图一口的单用途接口 | 三期统计页图表数量较多，按图一口会导致接口碎片化 |
| `getDriverTrendForGlobalStats` | 司机个人趋势图已移入司机画像页，不再属于全局统计页范围 |
| `getStatsWaybillList`、`getStatsExceptionList` 之类统计专用列表接口 | 下钻后应优先复用原业务列表接口与页面 |
| `getRegionTypeBreakdown` 之类“地区来源/类型混合口径”接口 | 当前地区口径已冻结为 `门店地区`，不再混入来源/类型维度 |

## 4. 三期新增接口域清单

### 4.1 统计页总览接口域

#### 1. `getStatsPageOverview`

- 用途：全局统计页首屏聚合总览
- 推荐路线：`JSON controller`
- 建议路径：`GET /api/admin/logistics/stats/overview`

建议承接：

- 顶部摘要卡
- 当前筛选条件下的核心概览值
- 页面 4 个分组的首屏概要信息

建议请求参数：

```json
{
  "date_from": "2026-04-01",
  "date_to": "2026-04-30",
  "granularity": "day"
}
```

建议返回结构：

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "summary": {
      "waybill_count": 1860,
      "signed_rate": 0.93,
      "timeout_rate": 0.08,
      "exception_count": 126
    },
    "groups": [
      {"group_code": "execution", "group_label": "执行概览"},
      {"group_code": "risk", "group_label": "风险概览"},
      {"group_code": "driver", "group_label": "司机与资源"},
      {"group_code": "region", "group_label": "区域与质量"}
    ]
  },
  "request_id": "req_stats_overview_001"
}
```

说明：

- 如果后续首屏只保留图表，不做摘要卡，这个接口也可作为全页公共筛选上下文接口继续保留

### 4.2 趋势类接口域

#### 2. `getStatsTrendMetrics`

- 用途：承接趋势图和双指标趋势图
- 推荐路线：`JSON controller`
- 建议路径：`GET /api/admin/logistics/stats/trends`

建议支持的 `metric_code`：

- `waybill_count`
- `signed_rate`
- `timeout_rate`
- `exception_count`
- `missing_evidence_rate`
- `missing_evidence_waybill_count`

### 4.5 下钻承接说明

#### 5. `getStatsDrilldownContext`

- 用途：把图表点击行为转成可复用的下钻筛选上下文
- 推荐路线：可选 `JSON controller`
- 建议路径：`POST /api/admin/logistics/stats/drilldown-context`

说明：

- 如果前端能直接根据图表点击结果拼出原业务页筛选条件，也可以不单独开这个接口
- 只有在筛选条件映射较复杂、需要后端统一解释时，才建议增加这一口

建议请求参数：

```json
{
  "metric_code": "region_exception_rate_ranking",
  "bucket_key": "浦东新区",
  "date_from": "2026-04-01",
  "date_to": "2026-04-30"
}
```

建议返回结构：

```json
{
  "code": "OK",
  "message": "success",
  "data": {
    "target_page": "exception_list",
    "filters": {
      "store_region": "浦东新区",
      "date_from": "2026-04-01",
      "date_to": "2026-04-30"
    }
  },
  "request_id": "req_stats_drilldown_001"
}
```

建议：

- 如果项目当前前端筛选拼装能力足够，优先不新增这一接口，减少额外维护面

## 5. 图表与接口映射表

| 图表 | 接口域 | 优先级 | 下钻目标 |
|---|---|---|---|
| 运单量趋势折线图 | `getStatsTrendMetrics` | `P0` | 运单列表 |
| 运单签收率 + 超时率双折线图 | `getStatsTrendMetrics` | `P0` | 已签收 / 超时运单列表 |
| 异常总量趋势折线图 | `getStatsTrendMetrics` | `P0` | 异常列表 |
| 异常类型分布图 | `getStatsDistributionMetrics` | `P0` | 对应异常类型列表 |
| 高风险批次排行图 | `getStatsRankingMetrics` | `P0` | 批次详情或批次异常运单列表 |
| 司机月均异常率排行图 | `getStatsRankingMetrics` | `P0` | 司机画像页 |
| 地区运单量分布图 | `getStatsDistributionMetrics` | `P0` | 对应地区运单列表 |
| 地区异常率排行图 | `getStatsRankingMetrics` | `P0` | 对应地区异常运单列表 |
| 地区签收率对比图 | `getStatsRankingMetrics` | `P1` | 对应地区签收 / 未签收运单列表 |
| 缺证据率 + 缺证据运单数双指标趋势图 | `getStatsTrendMetrics` | `P1` | 缺证据运单列表 |

## 6. 分期建议

### 6.1 P0 先补到什么程度

P0 阶段后端至少应补齐：

1. `getStatsPageOverview`
2. `getStatsTrendMetrics`
3. `getStatsDistributionMetrics`
4. `getStatsRankingMetrics`

说明：

- 只要趋势、分布、排行 3 个核心接口域稳定，`P0 8 张图` 就能全部落下
- 首屏总览接口是否保留摘要卡，可由前端专题最终样式决定，但建议先预留

### 6.2 P1 再补什么

P1 阶段不一定新增新接口域，更多是补：

- `region_signed_rate_ranking`
- `missing_evidence_rate`
- `missing_evidence_waybill_count`

也就是说：

- `P1` 更多是补 `metric_code`
- 不建议再为 `P1` 单独设计第二套接口体系
