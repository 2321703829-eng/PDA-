# 三期物流分析中心权限与状态说明

适用范围：
- 三期 `所有统计图表`、`物流工作台`、`管理看板` 三个分析入口的菜单可见性、页面读取权限与只读边界
- 当前重点覆盖：统计图表中心页面、物流工作台摘要页、管理看板摘要页，以及它们对应的后端聚合接口

优先基准：

- `../../00_导航与总纲/2026-04-17_三期前端优化设计总纲.md`

## 1. 文档定位

这份文档用于说明：
- 谁能看到 `所有统计图表 / 物流工作台 / 管理看板`
- 谁能读取分析中心聚合数据
- 为什么当前采用一套共享查看组，而不是三套彼此独立的菜单组

它是三期前端入口级权限口径，不替代后端底层模型 ACL，也不替代未来企业隔离方案。

## 2. Outcome

本轮权限收口后，应满足：

1. `所有统计图表`、`物流工作台`、`管理看板` 默认共用一套 `物流分析中心查看` 组
2. 无该组的内部账号不会在前端菜单树里看到这些入口
3. 即使直接访问分析接口，也会被后端统一返回 `403 forbidden`
4. 系统管理员继续保留默认穿透能力，避免影响配置和验收

## 3. Odoo Baseline Comparison

### 3.1 Odoo 已有能力

- Odoo 原生支持菜单按 `groups` 控制可见性
- Odoo 原生支持模型方法里按 `has_group()` 做细粒度权限判断
- 当前版本 `ir.actions.client` 不支持直接挂 `groups_id`

### 3.2 当前项目仍缺少的部分

- 分析入口之前没有真正的共享查看组
- 统计图表虽然走了独立接口，但没有做后端统一鉴权
- 物流工作台和管理看板前端之前直接读取异常模型，页面能绕过入口权限

### 3.3 设计路径判断

- 分析入口菜单：`extend Odoo`
- 分析聚合数据读取：`extend Odoo + custom capability`
- 共享查看组：`create custom capability`

## 4. 权限边界

本文覆盖：
- 分析入口菜单可见性
- 分析聚合接口访问权限
- 页面只读查看边界

本文不覆盖：
- 运单、批次、异常原生列表页的底层 ACL
- 后续企业隔离、多公司和套餐能力
- 统计图表下钻后目标列表页的 record rule 细节

## 5. 共享权限口径

当前共享组定义：
- `物流分析中心查看`
- `物流分析中心管理`

其中 `物流分析中心管理` 继承 `物流分析中心查看`。

不拆独立入口组的原因：
- `物流工作台` 和 `管理看板` 当前都挂在 `所有统计图表` 菜单树下
- 如果拆成完全独立的菜单组，会出现父菜单不可见但子入口又需要独立放行的冲突
- 当前三期设计稿也更偏向把这三个页面视为同一条分析入口线

## 6. 页面与接口映射

| 页面 / 接口 | 默认权限 |
| --- | --- |
| `所有统计图表` 菜单 | 系统管理员 / 物流分析中心查看 |
| `物流工作台` 菜单 | 系统管理员 / 物流分析中心查看 |
| `管理看板` 菜单 | 系统管理员 / 物流分析中心查看 |
| `/api/admin/logistics/stats/*` | 系统管理员 / 物流分析中心查看 |
| `/api/admin/logistics/dashboard/summary` | 系统管理员 / 物流分析中心查看 |
| `/api/admin/logistics/boss_trace/summary` | 系统管理员 / 物流分析中心查看 |

## 7. 后端落地说明

当前代码层统一采用下面的收口方式：

1. 菜单通过 `groups` 控制前端入口可见性
2. 统计服务方法在模型层统一调用 `_ensure_logistics_analysis_access()`
3. 工作台和管理看板改为走受控 summary 接口，不再直接在页面里 `searchRead/search_count`
4. 接口无权时统一返回 `403 forbidden`

## 8. 当前边界结论

- 这是一套入口级、聚合数据级的共享查看权限
- 它解决的是“谁能进分析中心、谁能读分析摘要”
- 它不替代下钻到运单、批次、异常列表后的原模块权限
