- 本文件优先回答共享层怎么统一、哪些页面先统一、窄屏与状态层怎么验收，而不是重新讨论业务范围。

## Outcome

三期主要前端页面在不改变业务边界和信息架构的前提下，统一到同一套页面骨架、状态语言、筛选区节奏和窄屏收口规则中。

本轮要达成的结果是：

1. 用户在不同页面间切换时，能稳定识别同一套 Hero / Panel / State 语言
2. 筛选区不再各页各写，各自出现字段堆叠、按钮抢层级和窄屏断裂
3. 列表和结果表在窄屏下优先保证“可滚动、可读、可操作”，而不是硬挤压
4. 加载态、空态、错误态、无权限态不再只剩零散文案，而是都有统一状态壳

## Boundary

本文件覆盖：

- 三期主要前端页面的共享视觉骨架
- 页头、面板、筛选区、摘要卡、状态壳、列表表格的统一规则
- 桌面端到窄屏的主要断点行为
- 状态文案的统一写法和优先级

本文件不覆盖：

- 全站设计系统重建
- 动效系统、插画系统和品牌手册级产物
- 业务字段、接口口径、权限模型的重新设计
- 非三期主线页面的大范围返工

## 1. 页面级统一规则

### 1.1 Hero 页头

三期正式页面默认使用 Hero 页头，不再回退到普通白底页头。

Hero 固定由 3 部分组成：

1. 左侧主信息区
   - kicker
   - 页面标题
   - 一句副标题
2. 右侧辅助信息区
   - 2 到 3 个状态 badge
   - 一张说明卡
3. 页面级背景氛围
   - 保留页面专题差异色
   - 但必须仍属于同一套三期语言

约束：

- 不在 Hero 里放复杂筛选器
- 不在 Hero 里塞超过 2 个一级动作
- Hero 副标题优先解释“这页先看什么，再看什么”

### 1.2 Panel Shell

三期页面主体区块优先使用 `o_logistics_web_panel_shell`。

适用场景：

- 摘要区
- 筛选区
- 图表区
- 记录区
- 导入结果和批次信息区

约束：

- 同一页面避免混用大量自定义大壳和共享壳
- 共享壳内再用局部差异色，不另起一套结构语言

### 1.3 页面节奏

默认页面节奏统一为：

1. Hero
2. 页面说明或工具区
3. 摘要层
4. 主信息层
5. 最近记录 / 后续动作层

说明：

- `统计图表`、`物流工作台`、`司机管理`、`导入结果页` 都应能落回这套节奏
- `管理看板` 允许更偏经营判断，但仍不能脱离这套主次顺序

---

## 2. 筛选区统一规则

### 2.1 结构

筛选区默认拆成：

1. 输入区
   - 搜索
   - 日期
   - 粒度
   - 状态
   - 车辆等枚举筛选
2. 动作区
   - 查询
   - 刷新
   - 重置

### 2.2 桌面端规则

- 输入区优先靠左展开
- 动作区优先靠右收口
- 字段标签统一在控件上方
- 高度统一为同一档
- 不允许搜索框和按钮出现明显高度错层

### 2.3 窄屏规则

在窄屏下，筛选区统一转为纵向堆叠：

1. 字段逐项换行
2. 动作区单独占一行
3. 按钮宽度优先拉满
4. 不允许字段挤压成难点选的小控件

### 2.4 适用页面

- `统计图表`
- `司机管理`
- `导入中心` 的上传与结果动作条

---

## 3. 摘要卡与信息卡规则

### 3.1 摘要卡

摘要卡统一承担“快速判断当前状态”的职责，不承接复杂解释。

固定组成：

1. 标签
2. 核心值
3. 一句说明

约束：

- 摘要卡文案长度要可控
- 高风险色只用于异常、失败、超时等场景
- 成功色用于签收、通过、完成等场景

### 3.2 信息卡

信息卡用于承接批次信息、文件信息、画像摘要、记录说明等较长内容。

约束：

- 一张卡优先只承担一类信息
- 避免在同一卡中同时堆明细、操作和解释
- 文字较长时优先断行，不强行单行省略

---

## 4. 表格与横向溢出规则

### 4.1 基本原则

三期表格在窄屏场景下优先保证：

1. 可横向滚动
2. 列含义不丢失
3. 操作按钮仍可点击

不要求所有表格在窄屏下都硬改成卡片列表。

### 4.2 列表表格

适用：

- `司机管理` 列表
- `导入中心` 预校验错误明细表

规则：

- 表格外层必须有独立滚动容器
- 表格本体应有合理 `min-width`
- 重要列可保留 `white-space: nowrap`
- 明细说明列允许换行或断词
- 操作列宽度保持稳定，避免窄屏下挤没

### 4.3 结果信息表

对于 `导入结果页` 这类 `dl / info-row` 结构：

- 桌面端允许左右对齐
- 窄屏下统一改为纵向排列
- 值字段允许断词，不能把卡片撑爆

---

## 5. 状态层统一规则

### 5.1 状态类型

三期统一处理 4 类页面状态：

1. 加载态
2. 空态
3. 错误态
4. 无权限态

### 5.2 统一状态壳

状态优先使用：

- `o_logistics_web_state_panel`
- `o_logistics_boss_state_panel`
- `o_logistics_web_feedback_strip`

规则：

- 页面级错误优先：反馈条 + 状态壳
- 区块级空态优先：占位面板或状态壳
- 无权限态不只提示失败，还要明确“当前账号暂无查看权限”

### 5.3 文案规则

状态文案统一采用“两段式”：

1. 标题：说明当前状态是什么
2. 说明：告诉用户下一步做什么

推荐写法：

- 加载态：
  - 标题：`正在加载……`
  - 说明：`正在同步当前页面数据，请稍后。`
- 空态：
  - 标题：`当前暂无……`
  - 说明：`请调整筛选条件，或等待业务数据写入后再查看。`
- 错误态：
  - 标题：直接展示错误主信息
  - 说明：`请先确认筛选条件、权限和接口状态，再刷新页面或稍后重试。`
- 无权限态：
  - `当前账号暂无查看……的权限。`

禁止：

- 坏编码占位文案
- 只有问号或只有一行笼统报错
- 同一页面同时出现多套明显不同的错误口径

---

## 6. 窄屏断点规则

当前三期统一优先按以下断点回扫：

1. `1180px`
   - Hero 间距压缩
   - 大网格改两列或一列
2. `900px`
   - Hero 改单列
   - 状态壳、摘要卡、信息卡减小内边距
   - 结果信息区左右布局改上下
3. `760px`
   - 筛选区字段全宽
   - 动作按钮堆叠或拉满
   - 表格容器启用稳定横向滚动

回扫重点：

- 标题是否仍可读
- 说明卡是否压坏
- badge 是否成串挤压
- 筛选区和动作区是否错层
- 表格是否还能看到完整列标题和操作入口

## 7. 页面范围与优先级

### 7.1 第一优先级

1. `统计图表`
2. `物流工作台`
3. `司机管理`
4. `导入中心`
5. `导入结果页`

### 7.2 第二优先级

1. `管理看板`
2. `首页`

说明：

- 第一优先级页面直接承接三期主线和核心验收链
- 第二优先级页面要跟主线页面语言对齐，但不反过来主导样式规则

## 8. 当前实现边界提醒

1. 本轮统一视觉只处理结构、样式、状态和可读性，不新增业务能力
2. 不为视觉统一单独重开第二套接口或状态模型
3. 页面隐藏和按钮禁用只算体验层，权限仍以后端校验为准
4. 视觉统一优先在现有页面上渐进收口，不重做整站框架
