# 三期界面系统化美化联调与验收清单

## 文档定位

- 本文件用于把三期“界面系统化美化”拆成可直接人工回扫的联调与验收清单。
- 它服务于共享样式层、页面视觉层和状态层的统一收口，不替代业务接口联调和权限自动化测试。
- 本清单重点核验窄屏、筛选区、表格溢出和状态文案，不把验收扩展成全站美术审查。

## 阅读关系

1. 先读 `../01_专题方案/2026-04-17_Odoo物流后台界面系统化美化专题方案.md`
2. 再读 `../02_跨模块规范/02_交互与组件/三期界面系统化美化交互与组件说明.md`
3. 再读近期视觉相关变更记录：
   - `../../../docs/change_notes/2026-04-20_phase3_visual_system_bootstrap_and_stats_sample.md`
   - `../../../docs/change_notes/2026-04-20_phase3_shared_hero_state_cleanup.md`
   - `../../../docs/change_notes/2026-04-21_phase3_state_language_unification_round1.md`
4. 然后按本清单逐页回扫三期主要页面

## 适用边界说明

本清单覆盖：

- `统计图表`
- `物流工作台`
- `管理看板`
- `司机管理`
- `导入中心`
- `导入结果页`
- 与以上页面直接共享的 Hero / State / Panel 层

本清单不覆盖：

- 非三期主线页面的大范围返工
- 动效、插画、品牌规范
- 业务流程正确性和后端性能压测

---

## Objective

本轮验收重点核验 6 类内容：

1. 共享 Hero 与 Panel 结构是否统一
2. 窄屏断点是否稳定
3. 筛选区是否统一且可操作
4. 列表与结果表是否能稳定横向滚动
5. 状态文案是否统一且无坏占位
6. 三期主要页面之间是否已经形成同一套视觉语言

## 核验前准备

1. 浏览器强刷缓存，例如：
   `Ctrl + F5`
2. 确认已升级到当前 `logistics_web` 资源版本
3. 建议至少准备以下宽度进行人工观察：
   - `1440px`
   - `1180px`
   - `900px`
   - `760px`
4. 建议准备以下数据状态：
   - 正常有数据
   - 无数据
   - 接口异常
   - 无权限账号
5. 建议准备以下页面入口：
   - 统计图表
   - 物流工作台
   - 管理看板
   - 司机管理
   - 导入中心
   - 导入结果页

---

## 一、共享层验收

### 1. Hero 页头

- [ ] 主要三期页面均已使用 Hero 页头
- [ ] Hero 统一包含 kicker、标题、副标题、badge、说明卡
- [ ] Hero 没有被普通白底页头样式污染
- [ ] Hero 在 `1180px / 900px / 760px` 下仍保持主次清晰
- [ ] Hero 右侧说明卡不会在窄屏下挤压或脱位

### 2. Panel Shell

- [ ] 主要内容区块已接入统一 `panel shell`
- [ ] 面板圆角、边框、阴影和内边距属于同一套语言
- [ ] 没有出现同页大量混用不同“大壳”的情况

### 3. 共享状态壳

- [ ] 加载态已统一进入 `state panel`
- [ ] 空态已统一进入 `placeholder / state panel`
- [ ] 错误态已统一为“反馈条 + 状态壳”或等价结构
- [ ] 无权限态有明确“当前账号暂无查看权限”文案

---

## 二、窄屏验收

### 1. 1180px

- [ ] Hero 间距收紧后仍有清晰层级
- [ ] 双列 / 三列区域会合理转成单列或更紧凑布局
- [ ] 摘要卡不会出现明显断行压坏

### 2. 900px

- [ ] Hero 已转为单列
- [ ] 说明卡和 badge 不会把页面首屏撑爆
- [ ] 信息卡左右布局已转为上下结构
- [ ] 状态壳 padding 和圆角已统一压缩

### 3. 760px

- [ ] 筛选字段已改为全宽堆叠
- [ ] 主要按钮优先拉满或稳定换行
- [ ] 表格外层可以稳定横向滚动
- [ ] 页面无明显横向抖动或内容被切断

---

## 三、筛选区验收

### 1. 统计图表

- [ ] 日期、粒度、动作按钮处于同一套筛选结构
- [ ] 桌面端字段与动作区主次清晰
- [ ] 窄屏下字段逐项堆叠，按钮不挤压
- [ ] 不出现字段标签和控件错层

### 2. 司机管理

- [ ] 搜索、筛选和排序区层级清晰
- [ ] 搜索输入框与按钮高度统一
- [ ] 状态、自有车辆、当前车辆筛选器在窄屏下全宽显示
- [ ] 排序按钮在窄屏下仍能完整展示和点击

### 3. 导入中心 / 导入结果页

- [ ] 上传动作条与结果动作条在窄屏下能自然堆叠
- [ ] 按钮不会因文本过长而溢出容器
- [ ] 结果页后续动作区主次按钮清晰

---

## 四、表格与溢出验收

### 1. 司机管理列表

- [ ] 表格存在独立滚动容器
- [ ] 窄屏下可横向滚动查看全部列
- [ ] 列标题不会被过度压缩到无法辨认
- [ ] 操作列不会被挤出可点击区域
- [ ] 姓名、状态、最近执行时间、月均异常率等核心列仍易读

### 2. 导入中心错误明细表

- [ ] 错误明细表存在稳定横向滚动能力
- [ ] Sheet、行号、字段、错误编码、错误说明列都可查看
- [ ] 错误说明列允许断行，不撑爆整页
- [ ] 表头在窄屏下仍能辨认

### 3. 导入结果信息区

- [ ] `批次信息 / 文件信息` 卡在窄屏下改为纵向行
- [ ] 值字段过长时允许断词
- [ ] 不会因批次号或模板版本过长而撑破卡片

---

## 五、状态文案验收

### 1. 坏占位与编码

- [ ] 三期主要页面不再出现 `???` 或坏编码文案
- [ ] 状态标题不再出现无意义占位文字
- [ ] 分页按钮、空态标题、加载标题均为可读中文

### 2. 加载态

- [ ] 标题统一为“正在加载……”
- [ ] 说明文字能解释当前在同步什么数据
- [ ] 不再只有单行“Loading...”或纯骨架无说明

### 3. 空态

- [ ] 空态标题能说明“当前暂无什么”
- [ ] 空态说明能提示用户下一步动作
- [ ] 同类页面不会各写一套完全不同口径

### 4. 错误态

- [ ] 错误态保留实际错误主信息
- [ ] 辅助文案统一强调：
  - 检查筛选条件
  - 检查权限
  - 刷新页面或稍后重试
- [ ] 导入结果页错误态保留“返回导入中心”动作

### 5. 无权限态

- [ ] 无权限页面明确写“当前账号暂无查看……的权限”
- [ ] 不用笼统“加载失败”替代无权限态

---

## 六、页面专项验收

### 1. 统计图表

- [ ] Hero、筛选区、摘要卡、4 个分区属于同一套视觉节奏
- [ ] 统计页已形成三期样板页语言
- [ ] 区块级空态和错误态表现稳定

### 2. 物流工作台

- [ ] Hero、摘要卡、优先队列、最新动态、入口卡与统计图表语言一致
- [ ] 但页面节奏仍更偏执行调度入口，不会误做成第二张统计页

### 3. 管理看板

- [ ] Hero、重点提醒、入口分组、管理判断区主次清晰
- [ ] 空态、错误态、无权限态已统一接入状态壳

### 4. 司机管理

- [ ] 列表页和画像页已经进入同一套视觉语言
- [ ] 列表工具区、排序区、表格区层级清楚
- [ ] 画像头部、KPI、趋势区、风险区、最近记录区之间层次分明

### 5. 导入中心

- [ ] Hero、模板区、上传区、预校验区、结果回看区节奏统一
- [ ] 预校验通过、未开始、失败三类状态都有清晰文案

### 6. 导入结果页

- [ ] Hero、结果头部、摘要卡、批次信息、后续动作、失败说明已统一
- [ ] 顶层错误态和返回路径清晰
