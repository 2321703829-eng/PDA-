# 2026-04-27 企业隔离 `P0 / P1` 租户初始化安装与首轮验收 SOP

## 1. 文档定位

- 本文用于把企业隔离 `P0 / P1` 下的租户初始化、模块安装和首轮验收动作收口成统一 SOP。
- 本文适用于当前阶段的人工或半人工实施方式。
- 本文不扩展到：
  - 平台自动开租户
  - 平台任务状态机
  - 套餐、授权、计费

## 2. 适用范围

本文适用于以下场景：

- 新建一个租户库并准备进入 `P1`
- 已有一个空租户库，需要安装当前物流模块
- 已有一个已装基础模块的租户库，需要执行首轮验收

## 3. 输入与输出

### 3.1 输入

- 已确认的 `tenant_code`
- 已确认的数据库名
- 已确认的访问域名
- 已确认的 `dbfilter` 与反向代理配置
- 当前待安装模块列表

### 3.2 输出

- 一个可通过域名访问的目标租户库
- 已安装基础物流模块的租户环境
- 一份首轮验收记录
- 是否允许进入 `P1` 业务联调的判断结论

## 4. 角色分工

### 4.1 运维 / 环境负责人

- 创建或确认数据库
- 配置域名、反向代理、`Host` 透传和 `dbfilter`
- 执行备份与恢复验证

### 4.2 Odoo 实施 / 配置负责人

- 安装模块
- 初始化管理员和基础配置
- 回扫菜单、权限、主链对象可见性

### 4.3 业务验收 / 联调负责人

- 验证 `waybill / customer_line / order_line / goods_line`
- 验证 `trace / evidence / exception`
- 记录通过项、待修项和阻塞项

## 5. 标准步骤

### 5.1 步骤一：确认租户基础标识

- [ ] 确认 `tenant_code`
- [ ] 确认数据库名
- [ ] 确认主访问域名
- [ ] 确认登记清单已记录

通过标准：

- 三者一一对应且可人工逆推

### 5.2 步骤二：准备访问与路由

- [ ] 配置反向代理
- [ ] 配置 `Host` 透传
- [ ] 配置 `dbfilter`
- [ ] 关闭数据库列表
- [ ] 收口数据库管理入口

通过标准：

- 访问租户域名时可稳定命中目标数据库

### 5.3 步骤三：创建或确认租户数据库

- [ ] 创建目标租户库或确认目标库为空
- [ ] 确认数据库编码、访问用户和环境信息可用
- [ ] 确认该库不会被其他租户域名命中

通过标准：

- 目标数据库可独立识别且未混入其他租户用途

### 5.4 步骤四：安装基础模块

首轮建议先安装：

- `logistics_base`
- `logistics_dispatch`

然后再按 `P1` 需要安装：

- `logistics_trace_core`
- `logistics_trace_evidence`
- `logistics_trace_exception`

检查项：

- [ ] 模块可独立安装
- [ ] 模块依赖关系正常
- [ ] 安装后菜单、模型、视图可正常读取

### 5.5 步骤五：初始化管理员与基础参数

- [ ] 创建或确认租户管理员账号
- [ ] 确认管理员可通过租户域名登录
- [ ] 初始化必要基础参数
- [ ] 明确默认语言、时区、基础组织信息

通过标准：

- 租户管理员可独立进入本租户环境，且不依赖手工选库

### 5.6 步骤六：执行 `P0` 首轮验收

按 `P0` 验收说明至少检查：

- [ ] 域名命中数据库正确
- [ ] 数据库列表与数据库管理入口收口正确
- [ ] 基础模块安装可用
- [ ] 备份恢复链路可验证

只有 `P0` 通过，才继续下面业务验收。

### 5.7 步骤七：执行 `P1` 主链回扫

至少检查：

- [ ] `waybill` 可读取
- [ ] `customer_line` 可读取
- [ ] `order_line` 可读取
- [ ] `goods_line` 可读取
- [ ] 页面主阅读链仍符合 `waybill -> customer_line -> order_line`

### 5.8 步骤八：执行 `P1` 三层模块回扫

至少检查：

- [ ] `logistics_trace_core` 可安装并读取
- [ ] `logistics_trace_evidence` 可安装并读取
- [ ] `logistics_trace_exception` 可安装并读取
- [ ] 模块读取仅针对当前租户库

### 5.9 步骤九：执行首轮人工验收

建议顺序：

1. `trace_core`
2. `evidence`
3. `exception`
4. 三层联动回归

至少记录：

- 通过项
- 待修项
- 阻塞项
- 是否涉及对象挂点、入口口径或权限边界偏移

## 6. 首轮验收通过标准

### 6.1 `P0` 通过

- 域名、数据库、`dbfilter` 三者关系稳定
- 不出现串库
- 单库安装与恢复链成立

### 6.2 `P1` 通过

- `waybill / customer_line / order_line / goods_line` 主链稳定
- `trace / evidence / exception` 三层可安装、可读取、可联动
- 当前租户内角色、导入、导出和摘要不越界到其他租户库

## 7. 首轮验收记录模板

每个租户首轮验收建议至少记录：

- 验收日期
- 环境名
- 租户编码
- 数据库名
- 域名
- 已安装模块
- `P0` 结论
- `P1` 结论
- 通过项
- 待修项
- 阻塞项
- 是否允许进入下一轮业务联调

## 8. 常见失败点提醒

- `dbfilter` 写得过宽，导致错误域名也能命中数据库
- 数据库列表或数据库管理入口未真正关闭
- 只安装了模块，但没有验证独立域名访问
- 只恢复数据库，没有恢复文件存储
- 租户库内主链能看，但 `trace / evidence / exception` 仍停留在旧口径
