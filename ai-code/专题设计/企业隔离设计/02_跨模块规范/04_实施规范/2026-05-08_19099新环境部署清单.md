# 2026-05-08 `19099` 新环境部署清单

## 1. 文档目标

本文用于把“企业隔离回归原设计实施方案”落成可执行部署清单。

目标不是继续增加一个单库联调环境，而是：

- 新开 `19099`
- 使用一套 Odoo 服务
- 承接多个 `tenant_*` 数据库
- 通过 `Host + dbfilter` 命中租户库

## 2. 环境目标

新环境建议标识：

- 端口：`19099`
- 环境名：`enterprise-multidb-odoo19`
- 数据库实例：`enterprise-isolation-pg18`

目标支持的首批租户库：

- `tenant_hq`
- `tenant_kebi`
- `tenant_template`

## 3. 部署前确认

### 3.1 代码基线

- [ ] 选择一套当前较干净的 Odoo 19 代码基线
- [ ] 保留当前已验证过的 `database_guard` 修复
- [ ] 不直接复用 `19089` 的旧容器运行态

### 3.2 数据库基线

- [ ] `enterprise-isolation-pg18` 正常运行
- [ ] `tenant_hq` 可连接
- [ ] `tenant_kebi` 可连接
- [ ] `tenant_template` 可连接

### 3.3 命名与访问基线

- [ ] 统一租户命名遵守 `tenant_<tenant_code>`
- [ ] 统一内部测试域名方案
- [ ] 已确定 `hosts` 或内网 DNS 临时映射方案

## 4. 容器与端口部署

### 4.1 新容器

- [ ] 创建新 Odoo 容器
- [ ] 容器建议名：`enterprise-multidb-odoo19`
- [ ] 不覆盖：
  - `odoo-lite-test-v19-web`
  - `enterprise-hq-odoo19`
  - `enterprise-isolation-odoo19`

### 4.2 端口映射

- [ ] 配置宿主机端口：
  - `19099 -> 8069`
- [ ] 确认宿主机上 `19099` 未被占用

## 5. Odoo 配置清单

### 5.1 必需配置

- [ ] `db_host = enterprise-isolation-pg18`
- [ ] `list_db = False`
- [ ] `dbfilter` 已配置为多租户命中形式

### 5.2 禁止配置

- [ ] 不写死 `db_name = tenant_hq`
- [ ] 不保留数据库列表开放配置

### 5.3 推荐配置口径

建议目标口径：

```ini
db_host = enterprise-isolation-pg18
dbfilter = ^tenant_%d$
list_db = False
```

说明：

- `%d` 依赖 `Host`
- 只有在 `Host` 与租户命名规则严格一致时才成立

## 6. 代理与域名清单

### 6.1 首期内部验证建议

建议使用内部测试域名：

- `hq.odoo.test`
- `kebi.odoo.test`
- `template.odoo.test`

若希望与库名更强一致，也可使用：

- `tenant-hq.odoo.test`
- `tenant-kebi.odoo.test`
- `tenant-template.odoo.test`

### 6.2 hosts / DNS

- [ ] 将测试域名映射到 `192.168.0.17`
- [ ] 保证不同测试域名均能访问 `19099`

### 6.3 代理透传

- [ ] 反向代理或入口层必须正确透传 `Host`
- [ ] 不允许入口层把不同域名压平成同一个固定主机名

## 8. 企业隔离关键安全项

### 8.1 数据库入口

- [ ] `/web/database/selector` 关闭
- [ ] `/web/database/manager` 关闭
- [ ] `/web/database/list` 关闭

### 8.2 命中安全

- [ ] 正确 `Host` 命中正确租户库
- [ ] 错误 `Host` 不误命中其他库
- [ ] 不允许通过页面手工切库

## 9. 备份恢复准备

### 9.1 基线原则

- [ ] 数据库与文件存储按一组对象处理
- [ ] 不接受只恢复库、不恢复文件存储的正式口径

### 9.2 首批准备

- [ ] 明确 `tenant_hq` 文件存储位置
- [ ] 明确 `tenant_kebi` 文件存储位置
- [ ] 明确 `tenant_template` 文件存储位置

## 10. 部署完成判定

满足以下条件可判定 `19099` 部署完成：

1. `19099` 可访问
2. 同一套 Odoo 服务未写死单库
3. 至少 2 个 `tenant_*` 数据库能通过不同 `Host` 命中
4. 数据库入口全部关闭
5. 基础物流页面可登录并加载

## 11. 当前不做

- 不做平台后台
- 不做自动开租户
- 不做跨租户汇总看板
- 不做套餐/授权/计费

## 12. 一句话收口

`19099` 的部署成功标准，不是“又起了一个 Odoo 容器”，而是“第一次把原设计里的单服务多租户命中底盘重新跑起来”。
