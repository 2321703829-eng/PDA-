# 2026-04-27 企业隔离 `P1` trace / evidence / exception 验收清单

## 1. 文档定位

- 本文用于企业隔离专题 `P1` 范围内 `trace / evidence / exception` 的人工验收与联调执行。
- 本文默认以“单个租户数据库已经安装现有物流模块”为前提。
- 本文不承担 `P2 / P3` 平台能力验收。

## 2. 验收前提

- [ ] 目标租户数据库可通过独立域名正常访问。
- [ ] `logistics_base`、`logistics_dispatch` 已安装。
- [ ] `waybill / customer_line / order_line / goods_line` 主链可正常读取。
- [ ] 图片导入链已区分 `dispatch_main` 与 `image_package`。
- [ ] 当前租户已准备：
  - 至少 1 个批次
  - 至少 1 个运单
  - 至少 1 个 `customer_line`
  - 至少 1 组图片包样例
  - 至少 1 组异常处理样例

## 3. 验收结果判定

- `通过`：功能、权限、阅读链、数据边界都符合当前口径。
- `部分通过`：主链可用，但存在字段、入口、状态或权限偏差。
- `不通过`：对象挂点、权限边界、任务口径或租户隔离被破坏。

## 4. `logistics_trace_core` 验收清单

### 4.1 安装与可见性

- [ ] 当前租户库可单独安装 `logistics_trace_core`。
- [ ] 安装后不会要求 `evidence`、`exception` 模块先安装才可进入基础留痕页。
- [ ] 当前租户可见的留痕菜单、动作只读取本租户数据。

### 4.2 事件创建与读取

- [ ] 可创建批次级留痕事件。
- [ ] 可创建运单级留痕事件。
- [ ] 不要求也不允许直接把订单作为留痕主对象创建事件。
- [ ] `event_type`、`trace_time`、提交人、备注等基础字段可正常保存并回读。

### 4.3 页面阅读

- [ ] 运单详情页可看到当前运单留痕摘要或时间线入口。
- [ ] 批次详情页可看到当前批次留痕摘要或时间线入口。
- [ ] 门店节点阅读区如果展示现场事实，不会把留痕主归属改写成 `customer_line`。

### 4.4 权限

- [ ] 无权限角色无法通过后端动作新增或修改留痕。
- [ ] 页面隐藏后，绕过页面直调模型动作仍会被拒绝。
- [ ] 同一租户内不同角色的可见与可编辑范围符合预期。

## 5. `logistics_trace_evidence` 验收清单

### 5.1 安装与基础读取

- [ ] 当前租户库可单独安装 `logistics_trace_evidence`。
- [ ] 证据页或证据区只读取本租户数据。
- [ ] `trace_event_id` 可作为证据主归属稳定回读。

### 5.2 图片导入与命中

- [ ] 图片导入任务进入 `import_task.object_type = image_package`。
- [ ] 运单包、门店包、单图三级结果反馈可读。
- [ ] 优先按 `waybill_no + customer_line_no` 命中门店节点。
- [ ] `customer_line_no` 缺失时，可按 `waybill_no + store_no` 兜底。
- [ ] 系统不会按门店名称、地址自由猜测命中。

### 5.3 页面阅读链

- [ ] 运单详情页有图片汇总与导出入口。
- [ ] 运单详情页是图片主阅读入口。
- [ ] 运单详情页可按 `scene_code` 分组预览图片。
- [ ] 图片不会脱离运单主阅读入口而散落到不受控的辅助页面。
- [ ] 图片不会直接主挂到订单阅读区。

### 5.4 追溯关系

- [ ] 证据对象正式挂点仍在 `trace_event`。
- [ ] 从图片业务阅读进入追溯时，可定位到相关留痕或证据对象。
- [ ] `waybill_id / batch_id` 如存在，仅作为查询或摘要补充。

### 5.5 导出与审计

- [ ] 运单整包导出入口只导出当前租户当前运单图片。
- [ ] 如存在结构层明细导出入口，也只导出当前租户当前运单范围内图片。
- [ ] 图片导出操作有审计记录。
- [ ] 无权限用户不可读取或下载他人不应见的图片结果。

## 6. `logistics_trace_exception` 验收清单

### 6.1 安装与基础读取

- [ ] 当前租户库可单独安装 `logistics_trace_exception`。
- [ ] 异常列表页与详情页只读取本租户数据。
- [ ] 模块安装后不会把异常默认挂回订单对象。

### 6.2 异常创建与状态流转

- [ ] 可从运单上下文提报异常。
- [ ] 可从批次上下文提报异常。
- [ ] 如由留痕触发异常，可正确关联 `trace_event_id`。
- [ ] `exception_type`、`severity_level`、`state`、处理人、关闭说明可正常保存并回读。

### 6.3 异常详情阅读

- [ ] 异常详情可反读关联运单。
- [ ] 异常详情可反读关联批次。
- [ ] 异常详情可反读关键留痕。
- [ ] 异常详情可反读关键证据摘要或入口。
- [ ] 当前详情不会要求异常对象自身重复存储完整证据主数据。

### 6.4 角色与动作

- [ ] 提报角色可创建异常，但不能越权关闭。
- [ ] 处理角色可跟进、指派、补备注。
- [ ] 管理角色可关闭异常。
- [ ] 只读角色可查看历史但不可执行写动作。
- [ ] 绕过页面直接调用关键动作时，模型层仍会做权限校验。

## 7. 三层联动验收清单

### 7.1 主链一致性

- [ ] 留痕、证据、异常三层都没有破坏 `waybill` 主阅读入口口径。
- [ ] `customer_line` 已按“一运单一门店”强约束正确收口为兼容 / 扩展结构层。
- [ ] `goods_line` 不需要成为首轮页面一级入口，但不会在数据层被忽略。

### 7.2 挂点一致性

- [ ] 留痕事实主归属仍为 `batch / waybill`。
- [ ] 图片业务阅读优先围绕 `waybill`，命中与补链仍可借助 `customer_line`。
- [ ] 正式证据对象仍围绕 `trace_event`。
- [ ] 异常仍优先围绕 `waybill / batch / trace_event`。

### 7.3 任务与错误反馈

- [ ] `dispatch_main` 与 `image_package` 结果页、错误码、错误行不会混口径。
- [ ] 图片失败时能明确落到运单包级、门店包级或单图级。
- [ ] 异常或留痕相关错误不会错误写入主数据导入对象类型。

### 7.4 租户隔离

- [ ] 从当前租户看不到其他租户的留痕、证据、异常记录。
- [ ] 下载、预览、结果回读都不会暴露其他租户对象标识。
- [ ] 任何聚合计数、摘要、导出都只基于当前租户数据库。

## 8. 不通过判定条件

出现以下任一情况，应直接判定本轮不通过：

- 把 `order_line` 重新抬成留痕或异常主对象。
- 把 `customer_line` 错误抬成当前 `P1` 的主阅读入口，导致 `waybill` 主阅读链被打散。
- 把图片证据直接主挂到订单。
- `image_package` 与 `dispatch_main` 混用一套对象口径。
- 留痕、证据、异常任一模块出现跨租户串读。
- 只靠页面隐藏控制权限，模型动作可被绕过执行。

## 9. 联调输出要求

每次联调后至少记录：

- 验收日期
- 验收租户库
- 验收模块范围
- 通过项
- 待修项
- 阻塞项
- 是否涉及对象挂点、权限边界或导入任务口径偏移
