# 2026-05-08 企业隔离 `P0` 恢复验收清单

## 1. 文档目标

本文用于验收 `19099` 新环境是否真正回到企业隔离原设计的 `P0` 路线。

验收核心问题只有一个：

**同一套 Odoo 服务，能否稳定承接多个租户数据库，并通过 `Host + dbfilter` 命中正确租户库，且不串库。**

## 2. 验收范围

本轮只验：

1. 多租户库命中
2. 数据库入口关闭
3. 基础物流模块访问
4. 不串库
5. 备份恢复口径

本轮不验：

- 平台后台
- 自动开租户
- 跨租户聚合
- 套餐/授权/计费

## 3. 验收前提

- [ ] `19099` 新环境已部署
- [ ] Odoo 可启动
- [ ] `enterprise-isolation-pg18` 正常
- [ ] 至少可用租户库：
  - `tenant_hq`
  - `tenant_kebi`
- [ ] `Host` 透传已配置
- [ ] `list_db = False`

## 4. 验收对象

首批重点验收租户：

- `tenant_hq`
- `tenant_kebi`

可选补充：

- `tenant_template`

## 6. 失败归类

### 6.1 路由类

- `Host` 未透传
- `dbfilter` 命中失败
- 错域名误命中

### 6.2 入口类

- 数据库入口未关闭
- 页面仍能手工选库

### 6.3 模块类

- 模块未安装
- schema 缺列
- 页面白屏

### 6.4 数据类

- 租户库本身数据异常
- 文件存储缺失

## 7. 通过标准

满足以下条件，可判定 `P0` 恢复通过：

1. 同一套 `19099` 服务成功承接至少两个租户库
2. 通过不同 `Host` 稳定命中正确租户数据库
3. 数据库管理入口全部关闭
4. 至少两个租户可独立登录并加载物流页面
5. 不出现串库
6. 至少一个租户完成成对恢复验证

## 8. 不通过标准

出现以下任一情况，直接判定不通过：

- 错域名命中到其他租户库
- 任意租户页面可看到另一租户真实业务数据
- `/web/database/*` 可作为选库入口继续使用
- 只恢复数据库不恢复文件存储仍被当作“通过”

## 9. 一句话收口

`P0` 恢复验收通过的标志，不是页面能打开，而是“同一套 `19099` 服务已经真正具备数据库级租户隔离底盘能力”。
