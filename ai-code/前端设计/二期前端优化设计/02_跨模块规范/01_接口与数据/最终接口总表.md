## 1. 文档定位

这份文档用于回答二期接口层最关键的问题：

1. 一期哪些接口继续沿用
2. 二期哪些能力必须新增接口
3. 二期哪些页面只是扩字段，不需要重开一整套接口
4. 新增接口优先走 RPC 还是 JSON controller

---

## 2. 一期与二期的关系

### 2.1 一期继续复用的接口域

继续复用一期主接口口径：

- 运单基础列表
- 批次基础列表与详情
- 留痕时间线增强读取
- 证据查看
- 异常列表与详情

说明：

- 这些能力在二期仍然有效
- 若只是名称、文案、菜单和视觉层升级，不默认重开接口

### 2.2 二期明确新增或升级的接口域

二期新增接口主要集中在下面 4 组：

1. 首页聚合
2. 所有统计图表
3. 运单详情三层阅读结构
4. 标准导入模板主路径

---

## 3. 二期统一升级结论

### 3.1 接口路线口径

- 标准对象列表、详情、子表读取：优先 `Odoo RPC`
- 首页聚合、统计图表、标准导入流程：优先 `JSON controller`

### 3.2 API 前缀口径

二期新增后台接口统一优先按后台前缀设计：

- `admin`：`/api/admin/logistics/...`

当前这批二期文档只覆盖后台场景，不展开 `mini` 与 `open` 前缀。

### 3.3 命名口径

- 读取类：`getXxx...`
- 预校验类：`precheckXxx...`
- 正式导入类：`confirmXxx...`
- 结果读取类：`getXxxResult...`
- 下载类：`downloadXxx...`

## 6. 当前不建议误判为“必须新增接口”的事项

下面这些二期改动不默认要求新业务接口：

- 品牌壳层改造
- 菜单重命名
- 导航显隐
- 中文化文案
- 列表页显性导入按钮

说明：

- 这些优先通过菜单、权限、前端壳层、i18n 和 Odoo 原生能力承接
- 若后续实现中发现被现有能力卡住，再补最小接口
