## 1. 文档目标

二期需要补充解释的不是“能不能取到数据”，而是：

1. 首页为什么不能只沿用一期工作台摘要
2. 统计图表为什么不能只靠一期老板页摘要扩字段
3. 运单详情三层结构哪些继续走 RPC，哪些不该做成 controller
4. 标准导入模板主路径为什么必须走一套受控导入接口

---

## 2. 一期路线继续成立的部分

一期的正式结论仍然成立：

- 标准对象列表、详情、搜索：优先 `Odoo RPC`
- 聚合摘要、证据预览、增强读取：允许少量 `JSON controller`

因此二期不是推翻一期，而是扩展例外边界。

---

## 3. 二期新增路线判断

## 3.1 首页：必须走 JSON controller

原因：

- 首页不是单一对象页，而是多模块聚合入口
- 需要角色化卡片、今日重点、最近动态、引导区
- 前端不能自己拼多个 RPC 再组装首页，否则接口边界会失控

结论：

- 首页聚合统一走 `JSON controller`
- 建议统一挂到 `/api/admin/logistics/home/*`

## 3.2 所有统计图表：必须走 JSON controller

原因：

- 涉及趋势、排行、环比、多维筛选
- 统计粒度不属于单一 Odoo 原生对象详情读取
- 很多字段本身就是聚合结果，不适合前端临时拼装

结论：

- 统计图表统一走 `JSON controller`
- 建议统一挂到 `/api/admin/logistics/stats/*`

## 3.3 运单详情三层阅读：优先 RPC

二期新增：

- 客户明细页签
- 货物明细页签

原因：

- 这两层本质仍然是运单下子表读取
- 更接近标准后台详情页与子列表语义
- 适合继续复用 Odoo 权限、上下文和子表查询方式

结论：

- 运单概览、客户明细、货物明细优先走 `RPC`
- 只有摘要聚合字段在模型层或轻量方法层补齐，不单独开 controller

## 3.4 标准导入模板主路径：必须走 JSON controller

二期新增：

- 模板下载
- 预校验
- 正式导入
- 导入结果页

原因：

- 这是一个多步骤业务流程，不是单次对象 CRUD
- 需要返回错误清单、统计摘要、导入批次号、结果报告
- Odoo 原生导入页可继续保留，但不足以承载二期标准模板主路径

结论：

- 标准导入主路径走 `JSON controller`
- 兼容导入仍可保留 Odoo 原生导入入口

## 4. 二期统一路线表

| 能力 | 推荐路线 | 原因 |
|---|---|---|
| 首页今日工作区 | JSON controller | 多对象聚合 |
| 首页最近动态 | JSON controller | 多对象聚合 |
| 首页角色化引导 | JSON controller | 角色化输出 |
| 所有统计图表摘要 | JSON controller | 聚合指标 |
| 趋势图 / 环比图 | JSON controller | 统计结果 |
| 排行榜 | JSON controller | 聚合排行 |
| 运单概览页签 | RPC | 标准详情语义 |
| 客户明细页签 | RPC | 子表读取 |
| 货物明细页签 | RPC | 子表读取 |
| 标准模板下载 | JSON controller / file | 文件分发 |
| 预校验 | JSON controller | 流程接口 |
| 正式导入 | JSON controller | 流程接口 |
| 导入结果页 | JSON controller | 流程结果查询 |

---

## 5. 路径前缀升级结论

为对齐当前项目接口硬规则，二期新增后台接口统一建议使用：

- `/api/admin/logistics/home/...`
- `/api/admin/logistics/stats/...`
- `/api/admin/logistics/imports/...`

不再继续扩散使用一期示例中的无终端前缀 `/api/logistics/...` 作为新接口写法。

---

## 6. 不要误开接口的场景

下面这些二期改动，默认不应先开新接口：

1. 品牌色板替换
2. 顶部导航改名
3. 模块隐藏与显隐
4. 页面中文文案改写
5. 工作台卡片标题改写

这些优先通过：

- Web 壳层
- 菜单
- 权限
- i18n
- 现有 act_window / client action 配置

来解决。
