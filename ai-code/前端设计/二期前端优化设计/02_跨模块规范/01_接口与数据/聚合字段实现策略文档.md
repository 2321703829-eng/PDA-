# 二期聚合字段实现策略文档

适用范围：
- 二期首页、所有统计图表、运单详情三层阅读相关的聚合输出
- 当前不展开留痕、证据、异常一期已稳定聚合字段的重复设计

> 状态说明：
> - 本文档只补二期新增聚合字段策略。
> - 一期已经定义的运单、批次、工作台摘要字段继续沿用一期 `聚合字段实现策略文档.md`。

---

## 1. 文档目标

二期新增接口里，最容易失控的不是路径，而是“哪些字段应该后端聚合输出”。

本文件用于回答：

1. 首页哪些字段必须做成聚合结果
2. 统计图表哪些字段必须由后端直接算好
3. 运单详情三层阅读需要哪些汇总字段
4. 哪些字段不建议前端临时拼

---

## 2. 二期总体策略

### 2.1 首页字段必须聚合

首页强调：

- 今天先做什么
- 风险在哪里
- 点进去处理什么

因此首页字段不应让前端自己拼多次 RPC。

### 2.2 统计图表字段必须由后端直接输出

趋势、排行、环比天然属于聚合计算结果。

前端职责是：

- 展示
- 筛选
- 跳转

不负责重新计算。

### 2.3 运单详情三层摘要优先挂运单主对象或子表汇总

客户层和货物层新增后，详情页首屏仍应先拿到：

- 客户子表数量
- 货物行数量
- 总数量
- 总件数
- 总重量
- 总体积

这些字段优先做成稳定摘要，不建议前端分页后自行累加。

## 3. 首页聚合字段

### 3.1 今日工作区

建议字段：

| 字段 | 语义 | 推荐刷新策略 |
|---|---|---|
| `todo_exception_count` | 待处理异常数 | 近实时 |
| `todo_evidence_count` | 待补证据对象数 | 近实时 |
| `todo_waybill_count` | 待执行运单数 | 近实时 |
| `timeout_risk_waybill_count` | 超时风险运单数 | 近实时 |

### 3.2 核心指标区

建议字段：

| 字段 | 语义 | 推荐刷新策略 |
|---|---|---|
| `signed_rate` | 已签收率 | 定时刷新 |
| `evidence_completion_rate` | 证据补齐率 | 定时刷新 |
| `exception_waybill_rate` | 异常运单率 | 定时刷新 |
| `store_signoff_rate` | 门店签收完成率 | 定时刷新 |

### 3.3 最近动态区

建议字段：

| 字段 | 语义 | 推荐刷新策略 |
|---|---|---|
| `latest_exception_items` | 最新异常项 | 近实时 |
| `latest_evidence_items` | 最新补证据项 | 近实时 |
| `latest_signoff_items` | 最新签收项 | 近实时 |
| `latest_risk_batch_items` | 最新高风险批次项 | 近实时 |

## 4. 统计图表聚合字段

### 4.1 摘要指标

| 字段 | 语义 | 推荐刷新策略 |
|---|---|---|
| `waybill_total` | 运单总量 | 定时刷新 |
| `batch_total` | 批次总量 | 定时刷新 |
| `in_transit_waybill_count` | 在途运单数 | 定时刷新 |
| `signed_waybill_count` | 已签收运单数 | 定时刷新 |
| `exception_waybill_rate` | 异常运单率 | 定时刷新 |
| `timeout_waybill_rate` | 超时运单率 | 定时刷新 |
| `evidence_completion_rate` | 证据补齐率 | 定时刷新 |

### 4.2 趋势图字段

趋势图统一建议输出：

- `metric_code`
- `metric_label`
- `current_value`
- `previous_value`
- `change_rate`
- `points`

说明：

- `points` 内不要再混杂业务对象详情
- 趋势图详情点击后，跳业务列表或统计详情页

### 4.3 排行字段

排行统一建议输出：

- `rank_no`
- `object_id`
- `object_code`
- `object_label`
- `metric_value`

## 5. 运单详情三层阅读聚合字段

### 5.1 运单层新增摘要字段

| 字段 | 语义 | 推荐刷新策略 |
|---|---|---|
| `customer_line_count` | 客户子表总数 | 近实时 |
| `goods_line_count` | 货物明细总数 | 近实时 |
| `total_qty` | 货物总数量 | 近实时 |
| `total_package_count` | 总件数 | 近实时 |
| `total_weight` | 总重量 | 近实时 |
| `total_volume` | 总体积 | 近实时 |

### 5.2 客户层摘要字段

| 字段 | 语义 | 推荐刷新策略 |
|---|---|---|
| `total_qty` | 客户货物总数量 | 近实时 |
| `total_package_count` | 客户货物总件数 | 近实时 |
| `total_weight` | 客户货物总重量 | 近实时 |
| `total_volume` | 客户货物总体积 | 近实时 |
| `exception_status` | 客户层异常摘要 | 近实时 |

### 5.3 当前不建议做成聚合字段的项

- 自动判责结论
- 客户层复杂履约评分
- 货物层综合风险分

原因：

- 规则不稳定
- 容易引起误读
- 一期与二期当前都没有足够成熟的业务冻结口径

---

## 6. 导入结果聚合字段

导入结果页建议后端直接聚合输出：

- `created_waybill_count`
- `created_customer_line_count`
- `created_goods_line_count`
- `updated_record_count`
- `skipped_record_count`
- `failed_record_count`

说明：

- 这些字段不建议前端从错误列表或结果列表自行反推
- 否则正式导入结果页和导入日志会出现口径偏差
