## 3. 二期有没有新增数据库字段或改模型结构

结论先说清楚：

- **有**
- 但要区分两类：
  1. **真正会影响数据库表结构的新增模型/新增持久字段**
  2. **为导入导出和页面展示服务的计算别名字段**

第二类很多是 `compute + inverse` 字段，默认 **不 store**，通常不会新增独立数据库列。

## 4. 二期明确新增的模型/表

### 4.1 `logistics.import.batch`

对应文件：

- [logistics_import_batch.py](/d:/Desktop/Odoo/custom_addons/logistics_dispatch/models/logistics_import_batch.py)

这是二期导入链路新增的正式模型，对应一张新的业务表。

用途：

- 记录一次标准导入的批次号
- 记录预校验 token
- 记录模板版本、文件信息、错误快照
- 记录正式导入结果和错误报告地址

主要持久字段包括：

- `name`
- `precheck_token`
- `template_code`
- `template_version`
- `file_name`
- `file_checksum`
- `state`
- `expires_at`
- `can_confirm_import`
- `total_row_count`
- `passed_row_count`
- `failed_row_count`
- `source_rows_json`
- `errors_json`
- `confirmed_at`
- `finished_at`
- `created_waybill_count`
- `created_customer_line_count`
- `created_goods_line_count`
- `updated_record_count`
- `skipped_record_count`
- `failed_record_count`
- `error_report_url`
- `failure_reason`

业务意义：

- 它是二期标准导入闭环的核心持久化对象
- 没有这张表，就做不成 `precheck / confirm / result / error-report` 这条链路

## 8. 关于“数据库字段变化”的判断口径

为了避免理解偏差，这里特别说明：

### 8.1 可以明确视为数据库/模型结构变更的内容

- 新增模型 `logistics.import.batch`
- 运单、客户明细、货物明细、批次、波次上的持久化统计字段
- 客户层、货物层承接业务语义的正式字段

### 8.2 不应直接按“新增物理列”理解的内容

- `waybill_no`
- `batch_no`
- `wave_no`
- `customer_no`
- `customer_name`
- `store_no`
- `store_name`

这些字段很多是：

- `compute + inverse`
- 主要服务导入导出映射
- 主要服务业务主键反查和页面表达

也就是说：

- **模型结构被扩展了**
- 但**不代表每一个二期新增字段都在数据库里形成了独立持久列**
