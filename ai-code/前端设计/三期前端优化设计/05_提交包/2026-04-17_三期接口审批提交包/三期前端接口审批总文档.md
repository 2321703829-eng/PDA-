# 三期前端接口审批总文档

适用范围：
- 用于主管审批三期前端优化相关接口设计
- 当前覆盖 `admin` 终端下的 `司机管理`、`统计图表`、`导入结果页页面化`
- 本文档作为三期接口审批单一主稿，优先级高于同目录下分散补充稿的阅读顺序

当前状态：
- 本文档已将三期分散接口稿、指标字典和二期承接的导入结果页补充稿收口为一份审批版总文档
- 本文档重点回答“接口是否足够详细到可以批准开发”这一问题
- 本文档不替代后续实现时的 controller、service、model 代码说明，但已冻结审批所需的接口范围、命名、字段和口径

---

## 1. 文档定位

这份文档用于让主管一次性看清三期接口层的 6 件事：

1. 三期到底新增哪些接口，复用哪些接口
2. 每个页面分别依赖哪些接口
3. 每个接口的请求参数、返回结构和关键字段含义
4. 统计类和司机类聚合指标到底怎么计算
5. 二期承接到三期的导入结果页接口是否已经收口
6. 当前还有哪些风险项、待确认项和明确不做项

---

## 2. 审批目标与希望批准的事项

本次希望主管批准下面 5 个事项：

1. 批准三期接口范围冻结为 `司机管理`、`统计图表`、`导入结果页页面化` 三组
2. 批准继续复用现有运单、异常、批次、导入链路，不为三期重复新开第二套业务接口
3. 批准三期新增聚合接口统一走 `/api/admin/logistics/...` 前缀
4. 批准三期接口返回包统一采用 `code / message / data / request_id`
5. 批准统计口径、司机口径、导入结果页扩字段口径以本文档为准

本次审批不包含：

- 企业分离功能实现方案
- 套餐、租户、跨企业统计能力
- 非运单对象导入中心化扩建
- 固定需求 / 临时需求体系
- 界面系统化美化的纯视觉样式稿

---

## 3. Outcome / Behavior / Boundary

### 3.1 Outcome

审批通过后，三期接口层应满足：

- 司机管理页面能完成列表、筛选、画像、趋势、风险、下钻
- 统计图表页面能完成总览、趋势、分布、排行和必要下钻
- 导入结果页能复用二期真实导入链路，并扩充为独立结果详情 / 回看页
- 开发时不再需要在多份小文档之间来回找接口口径

### 3.2 Behavior

- 页面读取类接口优先只读，不承载写入动作
- 标准对象列表类优先复用 RPC
- 聚合类、画像类、统计类优先使用 JSON controller
- 图表点击后的下钻优先跳原业务页，不重复发明“统计专用列表页”
- 导入结果页优先扩现有结果接口，不新开第二套导入结果体系

### 3.3 Boundary

- 本文档只冻结三期接口，不扩展到企业分离或套餐体系
- 本文档只覆盖 `admin` 终端
- 本文档只冻结审批粒度，不展开 SQL、索引、缓存和性能压测方案
- 本文档不要求界面系统化美化必须新开接口

## 5. 统一设计原则

### 5.1 终端与前缀

- 后台管理端统一使用 `/api/admin/logistics/...`

### 5.2 路线选择

| 场景 | 推荐路线 |
| --- | --- |
| 标准对象列表、筛选、短平快读取 | RPC |
| 画像页、聚合卡片、趋势图、统计图表 | JSON controller |
| 文件下载 | 继续沿用现有 HTTP 下载接口 |

### 5.3 返回包统一口径

三期审批稿统一冻结为：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "req_xxx"
}
```

失败时：

```json
{
  "code": 4004,
  "message": "data not found",
  "data": {},
  "request_id": "req_xxx"
}
```

口径说明：

- `code = 0` 表示成功
- `code != 0` 表示失败或业务异常
- 旧稿中个别示例使用的 `code: "OK"` 在本审批稿中废止
- 二期已落地的导入域现网兼容返回仍可能保留 `0/1`，三期审批口径以“顶层字段统一、成功为 0、失败为非 0”为冻结目标

### 5.4 时间口径

| 指标对象 | 时间基准 |
| --- | --- |
| 运单相关 | `delivery_date` |
| 批次相关 | 关联运单的 `delivery_date` |
| 异常总量 / 异常类型 | `exception.report_time` |
| 异常关闭时长 | `exception.close_time` |
| 司机相关 | 司机归属运单的 `delivery_date` |
| 客户与地区相关 | `customer_line.delivery_date` |

### 5.5 通用业务口径

- 有效对象默认排除 `draft`、`cancelled`
- 司机按执行归属统计
- 地区主口径统一挂在 `门店地区`
- 客户与地区统计按 `customer_line`
- 缺证据统一包含 `missing + partial`
- 图表下钻优先跳回原业务页，不新增“统计专用列表体系”

## 7. 司机管理接口设计

### 7.0 司机管理业务口径

- 后台工作人员管理是组织对象入口
- 司机管理是执行资源对象入口
- 当前不拆 `自有司机 / 外协司机`
- 当前统一以“司机”作为执行资源对象
- 保留 `是否自己有车` 字段

### 7.1 接口总览

| 接口 | 方式 | 建议路径 / 路线 | 用途 |
| --- | --- | --- | --- |
| `getDriverList` | RPC | 模型方法 | 司机列表主查询 |
| `getDriverFilterOptions` | RPC | 模型方法 | 司机列表筛选项初始化 |
| `getDriverProfileOverview` | GET | `/api/admin/logistics/drivers/{driver_id}/profile` | 司机画像页顶部概要 |
| `getDriverKpiCards` | GET | `/api/admin/logistics/drivers/{driver_id}/kpis` | 司机 KPI 卡片 |
| `getDriverRiskSummary` | GET | `/api/admin/logistics/drivers/{driver_id}/risk-summary` | 风险与异常摘要 |
| `getDriverTrendMetrics` | GET | `/api/admin/logistics/drivers/{driver_id}/trends` | 司机趋势图 |

### 7.2 `getDriverList`

用途：
- 司机列表页主查询

请求参数：

| 参数 | 类型 | 必填 | 说明 |

| `keyword` | string | 否 | 模糊匹配司机姓名、手机号、车牌摘要 |

| `page` | integer | 否 | 默认 `1` |
| `page_size` | integer | 否 | 默认 `20` |

返回字段：

| 字段 | 类型 | 说明 |

| 有效对象范围 | 排除 `draft`、`cancelled` |
| 司机归属 | 按执行归属统计，优先取运单 / 批次上的最终有效司机 |
| 客户与地区粒度 | 按 `customer_line` |
| 地区主口径 | `门店地区` |
| 缺证据定义 | 证据状态为 `missing` 或 `partial` |

### 10.2 核心指标字典

| `metric_code` | 指标名 | 定义 | 时间基准 |
| --- | --- | --- | --- |
| `waybill_count` | 运单量 | 统计周期内有效运单数 | `delivery_date` |
| `signed_rate` | 签收率 | 已签收运单数 / 有效运单数 | `delivery_date` |
| `timeout_rate` | 超时率 | 超时运单数 / 有效运单数 | `delivery_date` |
| `exception_count` | 异常总量 | 统计周期内异常记录总数 | `report_time` |
| `exception_type_distribution` | 异常类型分布 | 各异常类型记录数分布 | `report_time` |
| `month_waybill_count` | 司机月度运单量 | 某司机在某自然月关联的有效运单数 | `delivery_date` |
| `exception_rate` | 司机异常率 | 有异常的司机归属运单数 / 司机有效运单数 | `delivery_date` |
| `month_avg_exception_rate` | 司机月均异常率 | 统计期内每月异常率的平均值 | 自然月 |
| `missing_evidence_waybill_count` | 缺证据运单数 | 证据状态为 `missing` 或 `partial` 的有效运单数 | `delivery_date` |
| `missing_evidence_rate` | 缺证据率 | 缺证据运单数 / 有效运单数 | `delivery_date` |
| `region_waybill_distribution` | 地区运单量分布 | 按门店地区统计运单量 | `customer_line.delivery_date` |
| `region_exception_rate_ranking` | 地区异常率排行 | 有异常地区客户明细数 / 有效地区客户明细数 | `customer_line.delivery_date` |
| `region_signed_rate_ranking` | 地区签收率排行 | 已签收地区客户明细数 / 有效地区客户明细数 | `customer_line.delivery_date` |
| `high_risk_batch_ranking` | 高风险批次排行 | 按批次异常率、严重异常数、超时运单数排序 | 关联运单 `delivery_date` |
| `driver_month_avg_exception_rate_ranking` | 司机月均异常率排行 | 按司机月均异常率排序 | 自然月 |

### 10.3 高风险批次排序规则

排序优先级固定为：

1. 批次异常率
2. 严重异常数
3. 超时运单数

### 10.4 图表下钻规则

- 趋势图点时间桶：跳带时间筛选的业务列表
- 排行图点对象：跳对象详情或对象关联业务列表
- 分布图点分类：跳对应分类筛选后的业务列表

## 11. 权限、错误码与状态口径

### 11.1 权限口径

- 所有三期接口都只服务 `admin` 终端
- 需要已登录后台用户
- 页面是否可见继续以菜单 / action / 角色权限为准
- 无权限场景统一返回失败包，不通过静默空数据掩盖

### 11.2 推荐错误码

| `code` | 含义 | 说明 |
| --- | --- | --- |
| `0` | success | 成功 |
| `4001` | invalid params | 参数非法 |
| `4003` | forbidden | 无权限 |
| `4004` | data not found | 数据不存在 |
| `4090` | state conflict | 状态冲突 |
| `5000` | internal error | 服务端异常 |

导入结果页兼容说明：

- 二期已有导入接口当前实现可能继续保留 `0/1`
- 三期新增接口开发时应以本表为准
- 若导入域短期内不做细粒度错误码升级，至少保持顶层字段一致

### 11.3 状态口径

| 对象 | 建议状态 |
| --- | --- |
| 司机 | `active`、`inactive` |
| 导入批次 | `pending`、`processing`、`finished`、`failed` |
| 统计粒度 | `day`、`week`、`month` |
