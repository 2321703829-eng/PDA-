# 三期开发启动与代码落位说明

## 文档定位

- 本文件用于把三期前端优化设计从“文档已成套”进一步收口为“可直接启动开发”的入口说明
- 它服务于新对话接手、开发启动、代码落位和最小验证顺序判断

## 阅读关系

1. 先读 `../../00_导航与总纲/2026-04-17_Odoo物流后台三期前端优化设计总纲.md`
2. 再读 `../../00_导航与总纲/三期待补文档清单.md`
3. 再读 `../../02_验收与联调/当前已验证通过项与待修项.md`
4. 然后按当前任务主题进入对应专题、接口、交互和验收文档
5. 进入实现时，用本文件确认代码落位、实现顺序和最小验证动作

## 适用边界说明

- 本文件只服务三期前端优化当前已冻结范围
- 本文件不替代专题方案、接口细稿和验收清单
- 本文件不承接企业分离方案中的企业隔离层、套餐能力层和跨租户能力

---

## Objective

让三期后续开发可以按统一口径启动，而不是每次都重新判断：

1. 先读哪些文档
2. 先做哪条线
3. 代码大致落在哪
4. 哪些情况能直接编码，哪些情况需要先补文档
5. 最低应该做哪些验证

---

## Boundary

本说明覆盖：

- 三期当前已冻结的功能范围
- 三期推荐开发顺序
- 三期前端与接口代码的主要落位建议
- 开发启动前的最小阅读链
- 开发完成后的最小验证和回扫动作

本说明不覆盖：

- 后端详细字段级契约
- 企业分离和平台控制面实现
- 未来提交包整理
- 全站统一设计系统的完整技术规范

---

## 1. 当前可直接启动开发的范围

当前三期中，下面 3 条线已经具备“专题 + 接口/交互 + 验收”的基本闭环，可直接进入实现：

1. `司机管理`
2. `统计图表`
3. `导入结果页页面化`

当前仍建议先补文档、再决定是否编码的范围：

1. `界面系统化美化`
2. 复杂接口细稿拆分
3. 聚合字段实现策略

结论：

- 如果任务落在前 3 条线，可直接进入代码实现
- 如果任务落在后 3 类，默认先补文档

---

## 2. 默认开发顺序

当用户只说“继续三期”而未指定子线时，默认按下面顺序推进：

1. `司机管理`
2. `统计图表`
3. `导入结果页页面化`
4. `界面系统化美化`

原因：

- `司机管理` 与 `统计图表` 是三期两条主主线，且资料最完整
- `导入结果页页面化` 已作为二期可承接收尾项补齐到可开发状态
- `界面系统化美化` 当前仍缺更细的交互稿和验收稿

## 4. 代码落位建议

## 4.1 前端页面与动作

优先检查和落位：

- `custom_addons/logistics_web/static/src/js/actions/`
- `custom_addons/logistics_web/static/src/xml/`
- `custom_addons/logistics_web/static/src/scss/`

适用内容：

- 页面 action
- 页面模板
- 页面样式
- action 注册与路由承接

## 4.2 接口与控制器

优先检查和落位：

- `custom_addons/logistics_web/controllers/`
- `custom_addons/logistics_web/services/`
- `custom_addons/logistics_web/views/`

适用内容：

- `admin` 端 JSON controller
- 已有接口服务封装
- action / menu / asset 接线

## 4.3 业务对象与聚合来源

优先联查：

- `custom_addons/logistics_dispatch/`
- `custom_addons/logistics_base/`

说明：

- 司机管理和统计图表虽然是前端专题，但多数数据源仍来自现有业务对象和聚合逻辑
- 如遇到对象边界不清，先回到业务主线文档和专题稿，不要直接在前端硬推导字段

---

## 5. 默认实现模式

三期前端任务默认采用下面顺序：

1. 先确认 `Outcome / Behavior / Boundary`
2. 先读对应专题的接口稿、交互稿、验收稿
3. 先查现有代码中是否已有 action、controller、service 或旧入口可复用
4. 能复用则扩展，不能复用再新增
5. 实现后按验收清单回扫
6. 同步更新 change note

---

## 6. 何时先补文档再编码

遇到下面情况，默认先补文档：

- 任务属于 `界面系统化美化`
- 需要拆字段级接口契约
- 需要定义复杂 controller 示例响应
- 需要说明聚合字段口径或下钻口径
- 需要让新对话稳定接手复杂实现

优先补位文档：

- `三期界面系统化美化交互与组件说明.md`
- `三期界面系统化美化联调与验收清单.md`
- `三期接口路线决策文档.md`
- `三期前后端接口字段级契约清单.md`
- `三期 controller 示例响应.md`
- `三期聚合字段实现策略文档.md`

---

## 7. 实现边界提醒

1. 页面隐藏和按钮禁用只作为体验层，不是最终安全边界
2. 关键动作仍应依赖后端权限或能力校验
3. 不要把企业分离层、套餐能力层和跨租户能力混入三期前端范围
4. 不要为导入结果页重开第二套接口体系
5. 不要让统计页和司机画像页产生图表职责重叠

---

## 8. 最低验证动作

每次完成三期任务后，至少做下面 6 件事：

1. 对照对应专题的验收清单逐项回扫
2. 检查菜单、action、模板、样式和接口是否全部接线
3. 检查是否误越出三期边界
4. 检查是否需要同步更新相关设计文档
5. 更新 `ai-code/docs/change_notes/`
6. 向用户说明人工复核路径和未验证项

---

## 9. 给新对话的最短交接口径

如果要在新对话中快速启动三期开发，建议至少先给出下面 4 个入口：

1. `三期前端优化设计总纲`
2. `三期待补文档清单`
3. `当前已验证通过项与待修项`
4. 当前任务对应的专题稿 + 接口稿 + 交互稿 + 验收稿

如果新对话还需要一个“默认执行入口”，优先使用本地 skill：

- `ai-code/.agents/skills/phase3-frontend-delivery/SKILL.md`
