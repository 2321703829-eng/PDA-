# 2026-04-16 三期司机管理接口补充清单

适用范围：

- 用于后续拆三期司机管理专题的后端任务、接口联调和评审收口
- 当前只覆盖后台 `admin` 场景
- 当前重点覆盖“司机管理”而不是整个员工模块的所有 HR 能力

当前状态：

- 本文件是三期司机管理接口的补充清单
- 它承接 `2026-04-16_Odoo物流后台员工模块分层与司机管理专题方案.md`

## 1. 文档定位

这份清单只回答一个问题：

**三期司机管理专题，需要补哪些接口，哪些能力继续复用，哪些事项不要误判成需要新接口。**

统一拆成 4 类：

1. 直接复用
2. 新增接口
3. 升级或扩字段
4. 当前不建议单独开新接口

---

## 2. 当前统一业务口径

### 2.1 对象口径

- 后台工作人员管理是组织对象入口
- 司机管理是执行资源对象入口
- 本文档只覆盖司机管理接口，不展开后台工作人员管理接口细稿

### 2.2 司机对象口径

- 当前不拆 `自有司机 / 外协司机`
- 当前统一以“司机”作为执行资源对象
- 保留 `是否自己有车` 字段

### 2.3 指标口径

司机相关指标和图表，后续统一依赖下面结论：

- 司机按执行归属统计
- 超时按“超过承诺时效仍未签收”判断
- 缺证据统一包含 `missing + partial`
- 客户与地区相关统计按 `customer_line`

### 2.4 当前接口路线

- 司机基础列表、基础详情读取：优先 `RPC`
- 司机画像页指标卡、趋势图、聚合区块：优先 `JSON controller`
- 后台接口前缀统一优先使用：`/api/admin/logistics/...`

---

## 3. 复用与不重复开口径

### 3.1 继续复用的基础能力

| 接口 / 能力 | 当前处理方式 | 说明 |
|---|---|---|
| 员工基础档案读取 | 继续复用 Odoo / 现有主数据读取 | 后台工作人员基础资料不需要在三期司机专题里重开同类接口 |
| 联系方式基础字段读取 | 继续复用 | 姓名、手机号等基础字段不需要独立聚合接口 |
| 车辆基础信息读取 | 继续复用车辆基础对象读取 | 司机页只消费车辆摘要，不单独新开车队接口 |
| 全局统计页中的 `司机月均异常率排行图` | 继续复用后续统计图表接口域 | 不建议为司机排行再单独开一套 `driver ranking` 专用接口 |

### 3.2 当前不建议重复开的接口

| 不建议新增项 | 原因 |
|---|---|
| `getDriverRanking` | 全局司机排行应归入统计图表接口域，不在司机管理专题里重复开口 |
| `getDriverOwnVehicleTypeBreakdown` | 当前不区分自有司机 / 外协司机，不建议提前开这类分类接口 |
| `getDriverVehicleHistoryList` | 第一版只要求当前所属车辆和最近使用车辆，历史车辆关系可后置 |

## 4. 三期新增接口清单

### 4.1 司机列表接口域

#### 1. `getDriverList`

- 用途：司机管理列表页主查询
- 推荐路线：`RPC`
- 推荐路径：模型方法
- 前端用途：
  - 司机列表页
  - 支持搜索、筛选、排序、分页

建议请求参数：

```json
{
  "keyword": "张",
  "status": "active",
  "has_own_vehicle": true,
  "vehicle_id": 12,
  "date_from": "2026-04-01",
  "date_to": "2026-04-16",
  "sort_by": "month_avg_exception_rate",
  "sort_order": "desc",
  "page": 1,
  "page_size": 20
}
```

建议返回核心结构：

```json
{
  "items": [
    {
      "driver_id": 101,
      "driver_name": "张师傅",
      "mobile": "138****8888",
      "status": "active",
      "status_label": "在用",
      "current_vehicle_id": 12,
      "current_vehicle_label": "沪A12345 / 4.2米厢车",
      "has_own_vehicle": true,
      "latest_execution_at": "2026-04-15 18:30:00",
      "waybill_count": 268,
      "month_avg_exception_rate": 0.06
    }
  ],
  "total": 58
}
```

#### 2. `getDriverFilterOptions`

- 用途：司机列表页筛选项初始化
- 推荐路线：`RPC`
- 说明：如果列表页筛选项较少，也可合并进 `getDriverList` 首屏返回

建议返回：

- 状态选项
- 车辆选项
- 是否自己有车选项

### 4.3 司机趋势图接口域

#### 6. `getDriverTrendMetrics`

- 用途：司机画像页 3 张个人趋势图
- 推荐路线：`JSON controller`
- 建议路径：`GET /api/admin/logistics/drivers/{driver_id}/trends`

建议支持的 `metric_code`：

- `month_waybill_count`
- `exception_rate`
- `signed_rate`
- `timeout_rate`

  "driver_id": 101,

    "exception_rate",

### 4.4 司机关联记录接口域

#### 7. `getDriverRecentWaybills`

- 用途：司机画像页最近运单区
- 推荐路线：`RPC`
- 推荐路径：模型方法

建议返回字段：

- 运单号
- 门店
- 门店地区
- 状态
- 配送日期
- 是否超时
- 是否缺证据

#### 8. `getDriverRecentExceptions`

- 用途：司机画像页最近异常区
- 推荐路线：`RPC`
- 推荐路径：模型方法

建议返回字段：

- 异常编号
- 运单号
- 异常类型
- 状态
- 上报时间

#### 9. `getDriverWaybillDrilldownList`

- 用途：司机画像页指标卡、趋势图点击后的运单下钻列表
- 推荐路线：`JSON controller`
- 建议路径：`POST /api/admin/logistics/drivers/{driver_id}/waybills/drilldown`

建议支持场景：

- 本月运单量下钻
- 当前月签收率下钻
- 当前月超时率下钻
- 缺证据率下钻
- 趋势图某时间点下钻

#### 10. `getDriverExceptionDrilldownList`

- 用途：司机画像页异常相关指标和趋势点位下钻
- 推荐路线：`JSON controller`
- 建议路径：`POST /api/admin/logistics/drivers/{driver_id}/exceptions/drilldown`

建议支持场景：

- 月均异常率下钻
- 关联异常数下钻
- 最近异常跳转后的异常筛选列表

## 5. 三期升级或扩字段接口

| 接口 | 当前基础能力 | 三期升级内容 | 建议处理方式 |
|---|---|---|---|
| 员工基础详情读取 | 已有员工基础档案 | 若司机对象与员工对象共用主档，可补司机标签字段 | 在基础对象上扩字段，不单独重写员工接口 |
| 车辆基础信息读取 | 已有车辆主数据 | 增加司机页可直接消费的车辆摘要 label | 优先扩返回摘要字段 |
| 全局统计排行接口 | 二期已规划司机排行维度 | 三期继续承接 `司机月均异常率排行图` | 在统计排行接口中保留司机维度，不重复开司机排行接口 |

---

## 6. 当前不建议单独开新接口的事项

| 改动项 | 当前建议 | 说明 |
|---|---|---|
| 司机详情页第一页命名为 `概览` | 不开新接口 | 页面结构与命名 |
| 司机与后台工作人员导航分层 | 不开新接口 | 菜单与信息架构调整 |
| 所属车辆在列表页显性展示 | 不一定开新接口 | 优先在司机列表接口中直接带出车辆摘要 |
| 自有司机 / 外协司机拆分 | 当前不展开 | 用户已明确三期暂不做类型拆分 |
| 历史车辆关系完整页 | 当前不展开 | 第一版不要求完整车辆历史台账 |
