# 三期界面系统化美化人工验收执行顺序

## 文档定位

- 本文件用于指导三期“界面系统化美化”的人工验收执行顺序。
- 它服务于真实浏览器下的统一回扫，不替代各专题的正式验收清单。
- 本文件重点回答“先验什么、后验什么、每一轮主要看什么”，避免多人回扫时顺序混乱。

## 阅读关系

1. 先读 `三期界面系统化美化联调与验收清单.md`
2. 再读 `../02_跨模块规范/02_交互与组件/三期界面系统化美化交互与组件说明.md`
3. 再按本文件执行人工验收
4. 记录时配合：
   - `../03_模板与样例/三期页面逐项勾验记录模板.md`

## Outcome

通过一套固定顺序，把三期主要页面的视觉统一问题收口为：

1. 已通过项
2. 需修复项
3. 可延后优化项

本轮人工验收重点只看：

- 窄屏
- 筛选区
- 表格溢出
- 状态文案

不把回扫扩展成全量业务回归。

## Boundary

本轮执行顺序覆盖：

- `统计图表`
- `物流工作台`
- `管理看板`
- `司机管理`
- `导入中心`
- `导入结果页`

本轮不覆盖：

- 非三期页面
- 后端接口正确性细查
- 自动化测试替代
- 视觉品牌层面的开放式讨论

## 一、验收前准备

### 1. 环境准备

1. 强刷浏览器缓存：
   `Ctrl + F5`
2. 确认前端资源已更新到当前本地代码
3. 准备 3 组账号：
   - 管理员
   - 查看权限账号
   - 无权限或低权限账号

### 2. 数据准备

建议至少准备下面 4 组数据状态：

1. 正常有数据
2. 空数据
3. 接口异常或模拟错误
4. 无权限访问

### 3. 宽度准备

每个页面至少看 4 个宽度：

1. `1440px`
2. `1180px`
3. `900px`
4. `760px`

说明：

- `1440px` 用来看桌面端主层级
- `1180px` 用来看大布局开始压缩时是否稳
- `900px` 用来看 Hero 和双列布局转单列
- `760px` 用来看筛选区、按钮、表格溢出

## 二、推荐执行顺序

### Round 1. 共享层基线

先看 2 个样板页：

1. `统计图表`
2. `物流工作台`

本轮重点：

- Hero 是否统一
- Panel shell 是否统一
- 状态壳是否统一
- 页面节奏是否稳定

通过标准：

- 如果这 2 页的共享层都不稳，就不要继续逐页深挖
- 先记录共享问题，再集中修共享层

### Round 2. 经营页与分析页

接着看：

1. `管理看板`
2. `司机管理`

本轮重点：

- 是否沿用了共享 Hero / Panel / State 语言
- 页面主次是否和样板页一致
- 司机管理的筛选区、排序区、列表区是否稳定
- 管理看板是否保持“经营判断页”，没有变成另一张统计页

### Round 3. 导入链路页

最后看：

1. `导入中心`
2. `导入结果页`

本轮重点：

- 导入动作条在窄屏下是否可用
- 错误明细表是否能横向滚动
- 结果页信息卡、状态壳、返回路径是否清楚

说明：

- 导入链路页最容易暴露“长文案 + 表格 + 多按钮”叠在一起的问题
- 所以放在第三轮集中看更合适

## 三、每页固定验收动作

每进入一个页面，固定按下面顺序检查：

### Step 1. 看桌面端首屏

检查：

1. Hero 是否完整
2. 标题、副标题、badge、说明卡是否主次清楚
3. 首屏是否能一眼看懂“这页先看什么”

### Step 2. 看筛选区和动作区

检查：

1. 字段标签是否清楚
2. 输入框和按钮高度是否统一
3. 搜索 / 刷新 / 重置 / 跳转动作是否抢层级

### Step 3. 看摘要层和主体区

检查：

1. 摘要卡是否同一套语言
2. 主体区是否仍遵循“摘要 -> 主信息 -> 最近记录 / 后续动作”
3. 是否有某个局部块明显跳出三期统一风格

### Step 4. 切到空态 / 错误态 / 无权限态

检查：

1. 加载态是否有明确标题
2. 空态是否说明“当前暂无什么”
3. 错误态是否说明下一步怎么做
4. 无权限态是否明确提示无权限

### Step 5. 依次切 1180 / 900 / 760

检查：

1. `1180px`
   - 大布局压缩是否平稳
2. `900px`
   - Hero 是否单列
   - 双列区块是否顺利改上下
3. `760px`
   - 筛选区是否全宽堆叠
   - 按钮是否可点
   - 表格是否可横向滚动

## 四、页面级重点关注项

### 1. 统计图表

先看：

- Hero
- 全局筛选区
- 4 大分组

重点问题：

- 筛选区字段和动作区是否在窄屏下断裂
- 区块级空态 / 错误态是否统一

### 2. 物流工作台

先看：

- Hero
- 摘要卡
- 今日重点 / 优先处理队列 / 最新动态 / 常用入口

重点问题：

- 工作台是否仍偏执行调度，而不是被做成第二张统计页

### 3. 管理看板

先看：

- Hero
- 重点提醒
- 入口分组
- 管理判断区

重点问题：

- 空态和错误态是否统一
- 判断区是否仍保留经营聚焦感

### 4. 司机管理

先看：

- 列表筛选区
- 排序区
- 列表表格
- 画像头部

重点问题：

- 表格窄屏下是否还能滚动和操作
- 分页、空态、画像错误态文案是否统一

### 5. 导入中心

先看：

- Hero
- 模板区
- 上传区
- 预校验区
- 导入结果回看区

重点问题：

- 长按钮和长提示语在窄屏下是否溢出
- 错误明细表是否可读

### 6. 导入结果页

先看：

- Hero
- 结果头部
- 摘要卡
- 批次信息卡
- 后续动作区

重点问题：

- 错误态和返回路径是否清楚
- 信息卡在窄屏下是否改成纵向且不撑爆

## 五、问题记录优先级

现场记录时统一分 3 级：

### P0

直接影响验收通过：

- 文案坏编码
- 按钮不可点
- 表格主要列看不到
- 页面状态壳失效
- 窄屏结构严重断裂

### P1

不阻断流程，但明显影响质量：

- 筛选区错层
- Hero 说明卡挤压
- 卡片密度不一致
- 某些页面状态口径不统一

### P2

可后续打磨：

- 文案还可更精炼
- 卡片气质还能更统一
- 部分留白和字号还能继续优化

---

## 六、建议执行方式

推荐按下面方式组织人工验收：

1. 一人主操作页面
2. 一人只负责记录
3. 每页固定 5 分钟到 10 分钟
4. 每轮结束后先收共享问题，再收页面个性问题

推荐顺序：

1. 先完整跑 `统计图表 -> 物流工作台`
2. 确认共享层没大问题后，再跑剩余页面
3. 最后集中整理为：
   - 共享层问题
   - 页面专属问题
   - 可延后优化项

---

## 七、验收输出物

本轮人工验收结束后，至少产出下面 3 类结果：

1. 一份逐页勾验记录
2. 一份问题清单
3. 一份本轮结论

推荐格式：

1. 页面名称
2. 验收宽度
3. 已通过项
4. 待修项
5. 优先级
6. 是否阻断本轮通过

---

## 八、当前一句话结论

人工验收最稳的做法不是“想到哪看哪”，而是先用 `统计图表 / 物流工作台` 锁共享层，再按 `管理看板 / 司机管理 / 导入链路` 逐页回扫，并统一用记录模板收口。
