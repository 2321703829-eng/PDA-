## 2. 当前统一口径

## 2.1 主对象口径

- 执行主线：`wave -> batch -> waybill -> waybill_order_line`
- 追溯主线：`waybill -> trace_event -> evidence -> exception`
- 订单不是留痕主对象
- 异常优先挂运单、批次、留痕事件

## 2.2 接口路线口径

当前统一采用：

- **主路线：Odoo RPC**
- **补充路线：少量 JSON controller**

也就是说：

- 标准列表、详情、搜索、配置页，优先走 RPC
- 聚合卡片、增强时间线、证据预览、老板摘要页，允许走 controller

## 2.3 统一命名口径

- 字段统一用 `snake_case`
- 文案字段统一用 `*_label`
- 摘要字段统一用 `*_summary`
- 聚合计数字段统一用 `*_count`
- 时间字段统一用 `*_at`

## 3. 通用请求与返回规范

## 3.1 通用列表请求参数

| 字段 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| `page` | integer | 否 | 页码，从 `1` 开始 |
| `page_size` | integer | 否 | 每页条数，默认 `20` |
| `keyword` | string | 否 | 主搜索关键字 |
| `order_by` | string | 否 | 排序字段，如 `updated_at desc` |

## 3.2 通用列表返回结构

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0,
  "has_more": false
}
```

## 3.3 通用 controller 返回结构

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "request_id": "req_demo_001"
}
```

失败时：

```json
{
  "code": "FORBIDDEN",
  "message": "当前用户无权查看该对象",
  "data": null,
  "request_id": "req_demo_002"
}
```

| 页面/能力 | 推荐路线 | 说明 |
|---|---|---|
| 运单追溯列表页 | RPC | 标准搜索 + 列表页 |

| 工作台概览卡 | JSON controller | 聚合数据 |
| 工作台优先处理队列 | JSON controller | 聚合摘要队列 |
| 时间线增强读取 | JSON controller | 结构化卡片流 |

| 老板追溯摘要页 | JSON controller | 高层聚合摘要 |

## 7. 当前最小可用接口集

如果先做第一版，建议至少先落这 10 个：

1. `getWaybillList`
2. `getWaybillDetail`
3. `getWaybillOrderLines`
4. `getTraceTimelineByWaybill`
5. `getEvidenceListByWaybill`
6. `getExceptionList`
7. `getExceptionDetail`
8. `addExceptionProcessNote`
9. `getAdminDashboardSummary`
10. `getAdminPriorityQueue`

这 10 个一旦稳定，核心链路就能先跑起来：

`工作台 -> 运单列表 -> 运单详情 -> 时间线 -> 证据 -> 异常`
