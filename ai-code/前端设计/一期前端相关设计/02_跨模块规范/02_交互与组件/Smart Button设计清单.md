# Smart Button设计清单

适用范围：
- `ai-code/前端相关设计/` 下的跨模块入口设计文档
- 用于统一定义 Odoo 原生页面与物流执行/追溯主链之间的 Smart Button 接入方式

优先基准：
- `前端模块结构与菜单总表.md`
- `仓储管理前端接入设计草案.md`
- `业务单据前端接入设计草案.md`
- `运输与调度模块前端设计草案.md`

---

## 1. 文档定位

这份文档不设计新的业务页面，而是解决一个很实际的问题：

**哪些原生页面需要补 Smart Button，补了以后应该跳到哪里。**

它的目标是把“复用 Odoo 原生页面”和“进入物流主链”这两件事接顺。

---

## 2. 设计原则

1. Smart Button 优先承担“跳转入口”，不承担主阅读职责。
2. Smart Button 的第一价值是反查，不是替代详情页。
3. 默认优先跳到 `批次 / 运单 / 追溯 / 异常`，不跳到过深的证据细节。
4. 跳转统一优先走 Odoo `act_window + domain + context`。
5. 同一类对象在不同页面上的 Smart Button 命名尽量一致。

## 4. 推荐命名口径

推荐统一使用这些中文标签：

- `关联批次`
- `关联运单`
- `查看追溯`
- `查看异常`
- `今日批次`
- `相关运单`

技术命名建议：

```text
smart_{source}_{target}
```

例如：

- `smart_picking_batch`
- `smart_picking_waybill`
- `smart_sale_trace`
- `smart_vehicle_batches`

---

## 5. 跳转规则

### 5.1 优先跳列表还是详情

- 当来源对象可能关联多个目标对象时，优先跳列表。
- 当来源对象通常只关联单个目标对象时，可以直跳详情。

### 5.2 统一保留筛选上下文

建议跳转时保留：

- 来源对象类型
- 来源对象 ID
- 默认筛选条件
- 默认排序

### 5.3 不建议的跳转

当前不建议直接做这些：

- 从原生页面直接跳证据大图页
- 从原生页面直接跳处理日志末级页
- 一个来源页堆太多 Smart Button

---

## 6. 当前结论

当前 Smart Button 的重点不是“把所有页面都连起来”，而是优先打通这 3 组反查链：

1. `仓储单据 -> 批次 / 运单 / 追溯`
2. `业务单据 -> 运单 / 批次 / 异常`
3. `资源对象 -> 今日任务 / 相关运单`

只要这三组入口打顺，Odoo 原生页面和物流主链之间的协作就会顺很多。
