# 批次详情页草图

适用范围：
- 管理员后台
- `物流留痕 -> 追溯中心 -> 批次追溯 -> 批次详情`

关联文档：
- `管理员后台界面改造方案.md`
- `后台页面改造清单.md`
- `页面字段清单.md`
- `页面动作清单.md`

---

## 1. 页面目标

这页不是“把批次所有字段都摊开”，而是让管理员从批次视角完成一次聚合判断。

这页要回答 4 个问题：
1. 这一批现在整体处于什么状态
2. 风险主要集中在哪些运单或异常对象上
3. 最近发生了什么变化
4. 下一步该跳到哪个对象继续深入

所以这页更像“中枢页”，而不是最终证据判责页。

运单、留痕、图片仍然是事实和证据的主层；批次详情负责把这些对象组织起来。

---

## 2. 页面结构原则

批次详情页应遵循以下阅读顺序：
1. 先看批次摘要
2. 再看执行上下文
3. 再看关联运单分布
4. 再看最近留痕和异常摘要
5. 最后决定往哪个对象下钻

不能做成：
- 大量运单明细直接铺满首页
- 把图片证据区做成主阅读区
- 用很多可编辑字段打断管理员判断

## 4. 页面分区说明

## 4.1 头部摘要区
这是页面第一优先层。

必须固定展示：
- 批次号
- 批次状态
- 运单总数
- 异常运单数
- 证据完整度
- 最新留痕摘要

主动作也应固定放在这里：
- 查看关联运单
- 查看留痕摘要
- 添加处理备注

设计原则：
- 先让管理员得到“批次是否健康”的结论
- 再决定向运单层还是异常层下钻

## 4.2 批次当前状态区
这一块回答：
- 这一批现在整体怎样

建议字段：
- 当前状态
- 是否高风险
- 已签收运单数 / 总运单数
- 当前异常类型摘要
- 当前异常说明摘要

设计原则：
- 这是批次层判断，不是单个运单层判断
- 只保留能解释“整体风险”的信息

## 4.3 执行上下文区
这一块回答：
- 这批货处于什么执行环境里

建议字段：
- 车牌号
- 司机姓名
- 发车时间
- 到达时间
- 运输线路摘要

设计原则：
- 作为背景层存在
- 不抢占留痕和异常区域的视觉重点

## 4.4 关联运单概览区
这一块回答：
- 问题集中在哪一类运单上

建议字段：
- 运单总数
- 已签收数
- 未签收数
- 异常运单数
- 高风险运单摘要

设计原则：
- 这里用“概览 + 跳转”即可
- 不建议直接塞进完整运单大表
- 真正的运单级判断仍回到运单列表和运单详情

## 4.5 最近留痕摘要区
这一块回答：
- 最近发生了什么

每条摘要建议展示：
- 时间
- 留痕类型
- 提交人
- 涉及运单数
- 图片数
- 备注摘要

设计原则：
- 批次详情页只做留痕摘要，不取代完整时间线阅读
- 让管理员知道“变化来自哪里”，再决定是否继续下钻

## 4.6 异常摘要区
这一块回答：
- 当前异常是否集中，以及集中在哪种类型

建议字段：
- 当前未闭环异常数
- 按异常类型分布
- 重点异常摘要

设计原则：
- 重点是“批次层风险聚合”
- 不是把每个异常展开到细节页粒度

## 4.7 处理记录区
这一块回答：
- 后台已经对这一批做了什么判断或备注

建议字段：
- 时间
- 处理人
- 动作
- 备注摘要

设计原则：
- 用于记录管理侧的阅读结论
- 不替代正式异常处理对象

---

## 5. 右侧摘要栏设计

右侧建议固定成“快速判断区”，而不是第二个详情区。

建议放：
- 风险摘要卡
- 快速跳转卡
- 技术信息折叠区

不建议放：
- 大量可编辑字段
- 大段说明文本
- 完整运单列表

## 6. 关键交互草图

## 6.1 查看关联运单
```text
[查看关联运单]
    -> 进入运单追溯列表页
    -> 自动带上当前批次号筛选
    -> 默认按风险和更新时间排序
```

## 6.2 查看异常对象
```text
[查看异常对象]
    -> 进入异常列表页
    -> 自动带上当前批次号筛选
    -> 默认只看未闭环异常
```

## 6.3 查看留痕摘要
```text
[查看留痕摘要]
    -> 展开更多批次相关留痕
    -> 或进入批次留痕摘要页
```

## 6.4 添加处理备注
```text
[添加处理备注]
    -> 打开轻量备注输入
    -> 写入批次处理记录区
    -> 不直接改变运单和异常对象状态
```

## 7. 字段优先级落位

## 第一优先层
- 批次号
- 批次状态
- 运单总数
- 异常运单数
- 证据完整度
- 最新留痕摘要

## 第二优先层
- 已签收运单数
- 是否高风险
- 车牌号
- 司机姓名
- 异常类型分布

## 第三优先层
- 发车时间
- 到达时间
- 运输线路摘要
- 批次备注

## 技术层
- external_batch_id
- external_client_id
- latest_trace_external_id
- latest_image_access_key
- write_date

这些应进入折叠技术信息区，不进入主阅读区。

---

## 8. 动作优先级落位

## 主动作
- 查看关联运单
- 查看异常对象
- 查看留痕摘要

## 辅助动作
- 复制批次号
- 查看执行上下文

## 状态动作
- 添加处理备注

设计原则：
- 批次详情页的主要价值是“组织上下文并下钻”
- 不是在批次页做大规模状态流转

## 10. Odoo 落地建议

建议落地为：
- 主表单 `form`
- 摘要区 + 主内容区 + 右侧摘要区布局
- smart button / button object / act_window

推荐结构：
```text
form
├─ header
├─ summary sheet
├─ main content
│  ├─ batch current status block
│  ├─ execution context block
│  ├─ related waybills overview block
│  ├─ trace summary block
│  ├─ exception summary block
│  └─ process record block
└─ side summary block
```

注意：
- 不建议一开始把批次详情页做成前端重写页面
- 先用 Odoo 原生 form 布局打顺阅读链
- 若后续需要，可对摘要卡或留痕摘要区做轻量 widget 增强

---

## 11. 结论

批次详情页设计成败，取决于一件事：

**管理员能不能在批次层迅速看懂整体状态，并准确跳向真正需要深入的对象。**

所以这页最重要的不是字段越多越好，而是结构要稳：
- 先看批次整体
- 再看执行环境
- 再看运单分布
- 再看留痕和异常摘要
- 最后再下钻

只要这个顺序稳定，批次详情页就会成为追溯后台里非常有价值的中枢页。
