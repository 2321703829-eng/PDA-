# 后台页面改造清单

适用范围：
- 物流留痕系统管理员后台
- Odoo 后台中的追溯、异常、证据、看板相关页面

关联文档：
- `管理员后台界面改造方案.md`
- `后台信息架构图.md`
- `于睿_后台前端与追溯界面工作大纲.md`

---

## 1. 文档目标

本清单用于把管理员后台需要改造和新增的页面，按下面几个维度固定下来：

- 页面名称
- 服务对象
- 页面类型
- 所属入口
- 优先级
- 依赖模块
- 是否依赖聚合字段
- 页面目标
- 推荐 Odoo 落地方式

这份清单的作用不是描述视觉，而是作为：

- 页面范围基线
- 评审基线
- 排期基线
- 后续字段清单和动作清单的上游文档

补充约定：
- 本文中的页面编码统一使用 `waybill` 语义表示运单主对象
- 若实现层暂沿用历史 `order` 命名，只能视为技术兼容命名，不再代表“订单是主对象”

### 状态说明
- **设计状态**：待设计 → 设计中 → 设计完成 → 设计已评审
- **评审状态**：待评审 → 评审中 → 评审通过 → 评审驳回（需修改）
- **开发状态**：待开发 → 开发中 → 开发完成 → 联调通过
- **测试状态**：待测试 → 测试中 → 测试通过 → 测试失败
- **上线状态**：待上线 → 已上线 → 已回滚 → 已废弃

### 使用建议
1. 每周更新一次状态跟踪表，同步到项目周报
2. 状态变更时记录日期和负责人
3. 阻塞问题在“备注”栏标注，并关联到具体 issue
4. P0页面优先更新，确保核心链路进度可视

## 5. P0 页面说明

P0 页面是当前必须优先收口的页面。

## 5.1 运单追溯列表页

页面目标：
- 快速定位目标运单
- 快速判断是否值得进入详情

为什么是 P0：
- 这是管理员最高频入口
- 是后台主闭环的起点

最低需要支持：
- 搜索运单
- 看当前状态
- 看最新留痕摘要
- 看证据完整度
- 进详情

## 5.2 运单详情页

页面目标：
- 用一个页面承接运单级完整追溯判断

为什么是 P0：
- 这是后台最核心阅读页
- 时间线、证据、异常都要在这里汇合

最低需要支持：
- 当前状态摘要
- 执行上下文
- 时间线阅读
- 证据阅读
- 异常摘要和处理动作

## 5.3 留痕时间线区

页面目标：
- 快速理解历史过程

为什么是 P0：
- 没有时间线，就没有追溯能力

最低需要支持：
- 倒序查看
- 留痕类型
- 提交人
- 备注摘要
- 图片数量
- 异常标记

## 5.4 证据查看区

页面目标：
- 不离开主详情页完成证据核对

为什么是 P0：
- 没有证据阅读，管理员无法完成判断

最低需要支持：
- 缩略图
- 大图查看
- 图片顺序
- 对应留痕
- 时间与上传人

## 6. P1 页面说明

P1 页面用于把系统从“能追溯”补成“能运营”。

## 6.1 批次追溯列表页

页面目标：
- 从批量视角识别集中问题

当前价值：
- 适合仓内管理和批量问题排查

## 6.2 批次详情页

页面目标：
- 从批次看运单分布、异常分布和执行上下文

当前价值：
- 补强批次视角，但不替代运单详情

## 6.3 当前异常列表页

页面目标：
- 从问题出发直接进入处理

当前价值：
- 管理员第二高频入口

## 6.4 历史异常列表页

页面目标：
- 支持复盘与历史查证

## 6.5 待处理争议列表页

页面目标：
- 把高优先级问题对象单独暴露出来

说明：
- 可以是异常模型上的预设筛选动作

## 6.6 异常详情页

页面目标：
- 从异常直接读到对象、留痕和证据

当前价值：
- 让异常对象真正成为处理对象，不只是标签

## 6.7 管理工作台

页面目标：
- 帮管理员决定“今天先看什么”

当前价值：
- 作为后台总入口，但不替代追溯列表页

## 7. P2 页面说明

P2 页面是增强层，不建议前置。

## 7.1 缺图看板

用途：
- 关注证据完整度

## 7.2 异常闭环看板

用途：
- 看问题从发现到处理是否顺畅

## 7.3 车次追溯页

用途：
- 从运输执行视角补强追溯

说明：
- 当前依赖 `logistics_dispatch` 边界进一步稳定

## 7.4 证据总览页

用途：
- 从证据维度做辅助汇总

说明：
- 默认不应替代对象详情中的证据阅读

## 7.5 配置与规则页

用途：
- 承接系统配置

说明：
- 当前不属于后台体验主战场

## 10. 页面依赖最重的后端能力

下面这些页面最依赖后端聚合字段和摘要能力，后续需要优先联动。

| 页面 | 最关键依赖 |
|---|---|
| 运单追溯列表页 | 当前状态、最新留痕摘要、证据完整度 |
| 运单详情页 | 时间线查询、证据关联、异常摘要 |
| 批次追溯列表页 | 批次状态、运单数、异常数、留痕完整度 |
| 异常列表页 | 异常状态机、责任人口径、证据完整度 |
| 管理工作台 | 聚合统计、快捷筛选、下钻动作 |

## 11. 当前不建议纳入清单的页面

当前不建议把下面这些页面放入本轮页面改造清单：

- Discuss 风格消息页
- 聊天页
- 频道页
- 日历页
- 会议页
- 联系人中心页
- CRM 式客户运营页
- 与留痕无关的复杂审批页

原因：
- 会稀释追溯主闭环
- 当前不是项目成败关键

---

## 12. 推荐排期顺序

建议按下面顺序推进页面设计和评审：

1. 运单追溯列表页
2. 运单详情页
3. 留痕时间线区
4. 证据查看区
5. 当前异常列表页
6. 异常详情页
7. 批次追溯列表页
8. 批次详情页
9. 管理工作台

这个顺序的核心逻辑是：
- 先打通主闭环
- 再补问题入口
- 最后补聚合入口

---

## 13. 结论

这份清单的核心作用，是把管理员后台从“想到什么页面就改什么页面”，变成“按主闭环和优先级有序推进”。

当前最重要的结论是：

- P0 只围绕运单、时间线、证据
- P1 再补异常和批次
- P2 再补车次、证据总览和高级看板

只要这条顺序不乱，后续字段清单、动作清单和页面草图就会很稳。
