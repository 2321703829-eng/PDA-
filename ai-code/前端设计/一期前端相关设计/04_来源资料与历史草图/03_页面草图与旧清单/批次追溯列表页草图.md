适用范围：
- 管理员后台
- `物流留痕 -> 追溯中心 -> 批次追溯`

关联文档：
- `管理员后台界面改造方案.md`
- `后台页面改造清单.md`

- `页面动作清单.md`

---

## 1. 页面目标

这页的目标不是替代运单详情，而是让管理员先从“批次聚合视角”发现问题。

管理员进入这页后，应尽量在列表层先完成 4 件事：
1. 找到目标批次
2. 判断该批次是否值得优先进入详情
3. 判断问题是“执行风险”还是“异常集中”
4. 一键跳到批次详情、异常对象或关联运单

所以这页必须突出：
- 批次整体状态
- 运单规模和异常规模
- 最近留痕变化
- 证据是否足够支撑继续判断

---

## 2. 页面结构原则

批次页和运单页不应做成同一层阅读对象。

批次列表页更像一个“聚合监控页”，它回答的是：
- 这批货现在整体怎样
- 这批货里有没有集中风险
- 要不要进一步下钻

它不回答：
- 单张图片到底拍了什么
- 某一单的最终责任怎么判

这些问题应继续留给运单详情、异常详情和留痕事实层。

## 4. 页面分区说明

## 4.1 顶部操作区
包含：
- 面包屑
- 页面标题
- 刷新
- 导出

设计原则：
- 顶部只放全局动作
- 不在这里放批量处理型重动作
- 进入页面后应立即能开始搜索和筛选

## 4.2 搜索区
主搜索框建议支持：
- 批次号
- 车牌号
- 司机姓名
- 关联运单号
- 异常编号

设计原则：
- 用一个主搜索框覆盖高频定位需求
- 搜索应服务“快速找到批次”，而不是把每个字段拆成独立输入框

## 4.3 快捷筛选区
建议固定展示：
- 全部
- 有异常
- 高风险
- 今日有更新
- 证据不足
- 未闭环
- 异常运单较多

设计原则：
- 这些筛选是业务判断入口，不只是技术筛选条件
- 一眼可见，比隐藏在高级搜索里的效率高很多

## 4.4 高级筛选区
建议承载：
- 时间范围
- 批次状态
- 异常状态
- 证据完整度
- 司机
- 车牌
- 异常运单数范围

设计原则：
- 高级筛选用于“缩小问题范围”
- 不替代快捷筛选的第一轮判断价值

## 4.5 列表区
第一行放主判断字段，第二行放执行摘要。

第一行建议字段：
- 批次号
- 批次状态
- 运单总数
- 异常运单数
- 最新留痕时间
- 最新留痕类型
- 证据完整度
- 操作

第二行建议字段：
- 车牌号
- 司机姓名
- 已签收运单数
- 当前风险等级摘要
- 更新时间

设计原则：
- 先让管理员知道这批货整体是否健康
- 再补执行上下文
- 不要把单个运单明细字段塞进列表主层

- 每行动作不宜超过 3 个

## 6. 字段落位建议

## 第一优先层
- 批次号
- 批次状态
- 运单总数
- 异常运单数
- 最新留痕时间
- 最新留痕类型
- 证据完整度

## 第二优先层
- 车牌号
- 司机姓名
- 已签收运单数
- 当前风险等级摘要
- 更新时间

## 不建议默认主展示
- 发车时间
- 到达时间
- 批次备注
- 当前异常说明长文本
- latest_image_access_key
- external_batch_id
- external_client_id

这些字段更适合放到详情页或折叠信息区。

---

## 7. 动作落位建议

## 主动作
- 查看详情
- 查看异常对象

## 辅助动作
- 查看关联运单
- 复制批次号

## 顶部动作
- 刷新
- 导出当前结果

设计原则：
- 批次列表页的主动作是“下钻”
- 不建议在这一层承担复杂状态处理
- 列表页以判断和跳转为主，不以编辑为主

---

## 8. 状态标签建议

## 批次状态标签
建议层级：
- 中性：未开始 / 待发车 / 待签收
- 进行中：运输中 / 处理中
- 完成：已完成

## 风险标签
建议文案：
- 正常
- 中风险
- 高风险

## 证据完整度标签
建议文案：
- 完整
- 基本完整
- 不足
- 缺失

## 9. 关键交互草图

## 9.1 查看异常对象
```text
[查看异常对象]
    -> 进入异常列表页
    -> 自动带上当前批次号筛选
    -> 默认只看未闭环或高严重度异常
```

## 9.2 查看关联运单
```text
[查看关联运单]
    -> 进入运单追溯列表页
    -> 自动带上当前批次号筛选
    -> 保留当前时间范围条件
```

## 9.3 点击批次号
```text
点击批次号
    -> 进入批次详情页
    -> 保持批次视角上下文
```

## 11. Odoo 落地建议

建议落地为：
- `act_window`
- `search view`
- `tree view`

增强点：
- 使用 badge / decoration 表达风险和证据状态
- 通过 search view 承载快捷筛选和高级筛选
- 第一列点击进入批次详情

注意：
- 不建议一开始就把批次页做成复杂 dashboard
- 先把“列表判断 -> 详情下钻 -> 进入运单/异常”链路打顺

---

## 12. 结论

批次追溯列表页的核心不是展示尽可能多的信息，而是：

**让管理员先从聚合层判断，这一批是否值得优先投入注意力。**

也就是说，用户在不进入详情时，就应该能知道：
- 这批现在整体如何
- 问题是否集中
- 证据是否够用
- 下一步该进批次详情、异常页，还是运单列表

只要这 4 件事能在列表层成立，这页就达标。
