## Objective

将四期首轮任务拆成一份可直接勾选的联调与人工验收清单，重点核验下面 7 类内容：

1. 单表导入入口与映射链
2. 单表导入结果页与结果统计
3. 运单、门店节点、订单三层阅读链
4. 图片包导入链路
5. 图片结果页与图片预览链路
6. 运单包/门店包导出
7. 与现有三 Sheet 过渡契约和旧结果链的兼容性

---

## Boundary

本验收单覆盖：

- 单表快捷导入
- 单表映射到四层对象结构
- 单表复用三 Sheet 预校验
- 运单详情、门店节点阅读区、订单阅读区
- 图片批量导入、图片导入结果页、图片预览和图片导出

本验收单不覆盖：

- 移动端拍照链路
- 非运单对象导入中心扩展
- 历史全量数据迁移
- 订单层图片挂点

---

## 核验前准备

1. 确认四期相关页面与接口已完成基本接线
2. 确认浏览器已强刷缓存，例如：
   `Ctrl + F5`
3. 建议准备至少 4 类主数据样例：
   - 单表导入成功样例
   - 单表部分失败样例
   - 订单键缺失样例
   - 同一订单键下多商品样例
4. 建议准备至少 3 类图片样例：
   - 运单包整体成功样例
   - 运单包部分门店失败样例
   - manifest 缺失或 `scene_code` 非法样例
5. 建议准备至少 2 类页面回看样例：
   - 有图门店节点
   - 无图门店节点

## 一、单表快捷导入联调

### 1. 入口与模板

- [ ] 导入中心存在单表快捷导入入口
- [ ] 三 Sheet 入口可隐藏或降级为高级入口
- [ ] 单表模板下载可用
- [ ] 单表模板字段分组与设计稿一致

### 2. 映射链

- [ ] 单表上传后进入映射阶段
- [ ] 映射阶段会生成：
  - `waybill`
  - `customer_line`
  - `order_line`
  - `goods_line`
- [ ] `order_line` 在预校验前于内存中生成
- [ ] 单表导入没有单独长出第二套预校验体系
- [ ] 映射后继续复用现有三 Sheet 预校验主链

### 3. 聚合规则

- [ ] 运单按 `waybill_no` 聚合
- [ ] 门店节点优先按 `customer_line_no` 聚合
- [ ] 无 `customer_line_no` 时按 `waybill_no + store_no`
- [ ] 再退化时按 `waybill_no + customer_no`
- [ ] 订单键优先级为：
  - `单据号`
  - `订单号`
  - `销售订单号`

### 4. 冲突与失败

- [ ] 运单共享字段冲突时直接失败
- [ ] 门店节点共享字段冲突时直接失败
- [ ] 同一订单键下多商品时直接失败
- [ ] 缺 `waybill_no` 时直接失败
- [ ] 无法生成 `customer_line_no` 时直接失败

## 四、图片导入链路验收

### 1. 上传入口

- [ ] 导入中心有图片批量导入入口
- [ ] 运单详情有图片批量导入入口
- [ ] 首轮不要求门店节点页直接上传散图

### 2. 运单包解析

- [ ] 上传运单图片整合包后能读取运单包 manifest
- [ ] 能识别门店子包数量
- [ ] 能识别每个门店包路径

### 3. 门店包解析

- [ ] 能读取门店包 manifest
- [ ] 能读取 `customer_line_no / store_no / longitude / latitude`
- [ ] 能读取 `file_name / scene_code / image_seq`

### 4. 命中规则

- [ ] 优先按 `customer_line_no` 命中门店节点
- [ ] 否则按 `waybill_no + store_no`
- [ ] 命不中时门店包失败，不按名称猜测
