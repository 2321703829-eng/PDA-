# 2026-04-21 Odoo物流后台单表快捷导入映射规则专题方案

## 文档定位

- 本文定义单表快捷导入如何映射到四期内部结构。
- 当前映射规则统一以四期数据库底表设计稿为准，不再沿用与底表冲突的旧导入口径。

## 核心结论

单表导入统一走这条链：

`source_file -> import_task(dispatch_main) -> waybill -> customer_line -> order_line -> goods_line`

并遵守：

1. 单表只是输入入口，不替代内部四层对象结构。
2. `waybill_no` 是正式运单键，`waybill_group_no` 只作导入控制字段。
3. `customer_line_no` 是门店节点稳定业务键，但正式唯一性按 `(waybill_id, customer_line_no)` 收口。
4. `order_line` 必须在校验前生成，`goods_line` 必须归属有效 `order_line`。
5. 同一订单下允许多条 `goods_line`，导入不再按 1:1 假设设计。

## 映射步骤

### 步骤 1：接收源文件并创建导入任务

- 文件先进入 `import_source_file`
- 主数据导入任务对象类型统一记为 `dispatch_main`
- 行处理结果进入 `import_task_line`
- 字段级失败进入 `import_error_line`

### 步骤 2：运单归并

- 正式落库前必须命中或生成有效 `waybill_no`
- `waybill_group_no` 只可用于导入阶段的预分组、提示或辅助校验
- 不允许用 `waybill_group_no` 代替正式运单键直接入库

同一 `waybill_no` 下以下字段必须一致，否则报错：

- `delivery_date`
- `driver_name`
- `warehouse_code`
- `route`

### 步骤 3：生成 `customer_line`

- 优先使用导入值 `customer_line_no`
- 若未提供，则在已命中 `waybill_no` 前提下由系统生成运单内唯一编号
- 生成时优先使用 `store_no`
- 若 `store_no` 缺失，可结合 `external_customer_code` 作为辅助
- 若仍不足以生成稳定节点键，则直接报错

同一 `waybill_no + customer_line_no` 下以下字段必须一致，否则报错：

- `store_name`
- `contact_name`
- `contact_phone`
- `address`
- `longitude`
- `latitude`
- `stop_seq`
- `signoff_requirement`

### 步骤 4：生成 `order_line`

- 在正式校验前生成 `order_line` 内存对象
- 订单键优先级固定为：
  - `source_doc_no`
  - `order_no`
  - `sales_order_no`
- `source_ref_no` 与 `third_party_doc_no` 作为补充快照，不作为首选正式唯一键

同一订单聚合键下以下字段必须一致，否则报错：

- `doc_date`
- `doc_source`
- `doc_status`
- `audit_status`
- `payment_status`
- `settlement_status`
- `business_type`

### 步骤 5：生成 `goods_line`

- 单表每一行默认生成一条 `goods_line`
- `goods_line` 归属于上一步命中的 `order_line`
- 同一订单键下允许挂多条 `goods_line`
- 冲突规则只针对订单快照共享字段，不再因为多商品直接报错

## 首轮硬规则

### 1. 正式落库必须有 `waybill_no`

- `waybill_group_no` 不可替代正式运单键

### 2. `customer_line_no` 必须满足运单内唯一

- 导入值可由用户提供
- 未提供时由系统生成
- 最终都要满足 `(waybill_id, customer_line_no)` 唯一

### 3. 经纬度硬必填

- `longitude`
- `latitude`

### 4. 订单键至少命中一组

至少提供以下之一：

- `source_doc_no`
- `order_no`
- `sales_order_no`

### 5. 动态必填

以下字段采用“主数据优先、快照兜底”规则：

- `spec`
- `barcode`
- `uom`
- `weight`
- `volume`
- `package_type`

规则：

- 若 `goods_code` 能命中完整主数据，可为空
- 若命不中或主数据不完整，则必须在导入行中显式提供

## 结果对象理解

### `waybill`

- 运单总容器
- 正式业务键为 `waybill_no`

### `customer_line`

- 运单下的门店节点
- 稳定业务键为运单内的 `customer_line_no`

### `order_line`

- 门店节点下的订单快照层
- 页面主阅读层之一

### `goods_line`

- 订单下的货物事实明细
- 允许一张订单挂多条货物

## 当前与数据库设计对齐后的关键口径

1. 不再把 `waybill_group_no` 写成正式运单聚合主键。
2. 不再把 `customer_line_no` 写成全局主键。
3. 不再把 `goods_line` 限死为 `1 order_line -> 1 goods_line`。
4. 不再只谈单表映射，不谈导入任务与错误行审计。
