## 文档定位

本清单用于把四期图片模块的两层 manifest、图片挂点和导入校验规则收口到字段级。

它重点回答：

1. 运单包 manifest 有哪些字段
2. 门店包 manifest 有哪些字段
3. 哪些字段硬必填，哪些字段可选
4. 图片导入时按什么规则命中业务对象
5. 错误反馈应该如何分层

---

## 1. 固定边界

四期图片模块当前已经冻结：

- 图片主数据链路与 XLSX 主数据链路分开
- 图片物理结构为：
  - `运单图片包 -> 门店图片包 -> 图片文件`
- 图片业务最小挂点是 `customer_line`
- 首轮不直接认 `order_line`
- 首轮 `scene_code` 枚举固定为：
  - `arrival`
  - `sign`
  - `exception`
  - `other`

结合 2026-04-21 图片链路现状盘点，还应补充 3 条当前现状判断：

1. 当前上传链路已经存在，但更接近“先建 evidence，再传单张图片”，不是成熟的批量包导入能力。
2. 当前访问链路已经存在，但 `preview_url / full_url` 还没有真正形成缩略图与原图双链路。
3. 当前导出能力基本仍停留在单张访问链接，真正的业务化批量导出和 ZIP 打包需要四期新增。

## 2. 运单包 manifest 字段

建议文件名：

- `package_manifest.json`

| 字段 | 必填级别 | 校验规则 | 说明 |
| --- | --- | --- | --- |
| `manifest_version` | 硬必填 | 版本号非空 | 清单版本 |
| `package_type` | 硬必填 | 固定为 `waybill_package` | 包类型 |
| `waybill_no` | 硬必填 | 必须命中运单 | 运单锚点 |
| `delivery_date` | 可选 | 日期格式 | 配送日期 |
| `driver_name` | 可选 | 文本长度限制 | 司机姓名 |
| `route` | 可选 | 文本长度限制 | 线路 |
| `store_package_count` | 硬必填 | 非负整数，且与子包数一致 | 门店包数量 |
| `store_packages[]` | 硬必填 | 数组非空 | 门店子包列表 |

`store_packages[]` 子项字段：

| 字段 | 必填级别 | 校验规则 | 说明 |
| --- | --- | --- | --- |
| `store_no` | 建议硬必填 | 非空 | 门店编码 |
| `store_name` | 硬必填 | 非空 | 门店名称 |
| `customer_line_no` | 可选 | 如有值则必须可命中 | 门店节点锚点 |
| `stop_seq` | 可选 | 正整数 | 停靠点顺序 |
| `package_path` | 硬必填 | 包路径存在 | 门店包路径 |
| `image_count` | 硬必填 | 非负整数 | 子包图片数 |

## 3. 门店包 manifest 字段

建议文件名：

- `manifest.json`

| 字段 | 必填级别 | 校验规则 | 说明 |
| --- | --- | --- | --- |
| `manifest_version` | 硬必填 | 版本号非空 | 清单版本 |
| `package_type` | 硬必填 | 固定为 `store_package` | 包类型 |
| `waybill_no` | 硬必填 | 必须命中运单 | 运单锚点 |
| `customer_line_no` | 可选 | 如有值则优先命中门店节点 | 门店节点锚点 |
| `store_no` | 硬必填 | 非空；若无法命中则失败 | 门店编码 |
| `store_name` | 硬必填 | 非空 | 门店名称 |
| `stop_seq` | 可选 | 正整数 | 停靠点顺序 |
| `contact_name` | 可选 | 文本长度限制 | 联系人 |
| `contact_phone` | 可选 | 手机或固话格式 | 联系电话 |
| `address` | 可选 | 文本长度限制 | 地址 |
| `longitude` | 硬必填 | 数值范围合法 | 经纬度首轮硬必填 |
| `latitude` | 硬必填 | 数值范围合法 | 经纬度首轮硬必填 |
| `image_count` | 硬必填 | 与 `images[]` 长度一致 | 图片数量 |
| `images[]` | 硬必填 | 数组非空 | 图片列表 |

`images[]` 子项字段：

| 字段 | 必填级别 | 校验规则 | 说明 |
| --- | --- | --- | --- |
| `file_name` | 硬必填 | 文件必须存在且唯一 | 图片文件名 |
| `scene_code` | 硬必填 | 枚举值 | 场景码 |
| `image_seq` | 硬必填 | 正整数 | 图片顺序 |
| `taken_at` | 可选 | 时间格式 | 拍摄时间 |
| `remark` | 可选 | 文本长度限制 | 图片备注 |
| `source_doc_no` | 可选 | 文本长度限制 | 可用于追溯来源单据 |

## 4. 匹配与挂点规则

### 4.1 首轮命中优先级

门店包进入系统时按以下顺序命中业务对象：

1. `customer_line_no`
2. `waybill_no + store_no`

若上述两条均失败：

- 该门店包失败
- 不再按 `store_name` 或地址猜测

### 4.2 业务挂点

首轮固定为：

- 图片挂到 `customer_line`

不直接挂到：

- `order_line`
- `goods_line`

后续若要延伸到订单层，应另起设计说明。

补充说明：

- 当前系统里已经存在以 `image_access_key` 为核心的单张图片访问方式
- 四期图片包设计不是替代这条能力，而是在其上新增：
  - 包级导入
  - 包级结果
  - 门店级聚合
  - 运单级聚合

## 5. 文件与结构校验

### 5.1 运单包层

- 必须存在运单包 manifest
- `store_package_count` 必须与实际门店包数量一致
- 每个 `package_path` 必须存在

### 5.2 门店包层

- 每个门店包必须存在门店包 manifest
- `image_count` 必须与实际图片数量一致
- `file_name` 不得重复

### 5.3 图片层

- `file_name` 必须能在包内找到对应文件
- `scene_code` 必须在枚举内
- `image_seq` 在同一门店包内应唯一

### 5.4 现状兼容提醒

由于当前底层更接近“单 evidence 单图片”，四期首轮图片包导入需要明确：

- 包级结构是新增能力
- 单图仍可继续沿现有访问链路提供 `preview_url / full_url / image_access_key`
- 若后续要真正支持一条 evidence 多图、主图标记、单张删除、单张补传，应另起模型层扩展设计

---

## 6. 导入结果反馈结构

图片导入结果要支持三层反馈：

### 6.1 运单包层

- 整包是否成功
- 命中哪张运单
- 一共多少个门店包
- 成功多少个门店包
- 失败多少个门店包

### 6.2 门店包层

- 该门店包命中了哪个 `customer_line`
- 成功多少张图片
- 失败多少张图片
- 失败原因是什么

### 6.3 单图层

- 哪张图失败
- 属于哪个门店包
- `scene_code` 是否非法
- 文件是否缺失

## 7. 错误码建议

### 7.1 包结构级

- `IMAGE_PACKAGE_MANIFEST_MISSING`
- `IMAGE_STORE_PACKAGE_MISSING`
- `IMAGE_PACKAGE_COUNT_MISMATCH`

### 7.2 字段级

- `IMAGE_FIELD_REQUIRED`
- `IMAGE_FIELD_FORMAT_INVALID`
- `IMAGE_SCENE_CODE_INVALID`

### 7.3 关联级

- `IMAGE_WAYBILL_NOT_FOUND`
- `IMAGE_CUSTOMER_LINE_NOT_FOUND`
- `IMAGE_STORE_NOT_MATCHED`

### 7.4 文件级

- `IMAGE_FILE_NOT_FOUND`
- `IMAGE_FILE_DUPLICATED`
- `IMAGE_SEQ_DUPLICATED`
