## 文档定位

这份文档用于回答：

1. 单表中的每一个业务字段最终落到哪一层
2. 首轮它是导入必填、动态必填、可选还是二阶段字段
3. 它在映射阶段承担什么角色
4. 它是否允许由货物基础信息或系统规则补齐

说明：

- 本文档以四期已经拍板的结构为准
- 当前 `客户名称 = 门店名称`
- `order_line` 承接订单快照
- `goods_line` 承接货物事实源和较稳定基础信息

## 1. 字段状态说明

| 状态 | 含义 |
| --- | --- |
| `首轮硬必填` | 当前正式导入主路径必须提供 |
| `首轮动态必填` | 命不中货物基础信息时必须提供 |
| `首轮可选` | 当前可为空 |
| `二阶段` | 当前不进最小导入模板，但预留落位 |
| `导出优先` | 更适合作为导出/阅读字段，而不是首轮原子导入字段 |

## 7. 司机执行视角导出字段

这批字段首轮更适合作为导出阅读字段，而不是全部变成导入强约束：

| 字段 | 建议归属 | 当前建议 |
| --- | --- | --- |
| 货物信息 | `order_line` 聚合展示 | 导出优先 |
| 司机姓名 | `waybill.driver_name` | 已纳入首轮导入 |
| 停靠点顺序 | `customer_line.stop_seq` | 已纳入首轮导入 |
| 门店名称 | `customer_line.store_name` | 已纳入首轮导入 |
| 详细地址 | `customer_line.address` | 已纳入首轮导入 |
| 经度/纬度 | `customer_line.longitude/latitude` | 已纳入首轮导入 |

## 8. 关键映射结论

1. 用户单表的主业务阅读结果应形成：
   - `waybill -> customer_line -> order_line`
2. `goods_line` 保留为事实源和扩展层，不作为首轮主阅读层。
3. 订单对应货物的规格、条码、体积、重量、备注等信息，首轮在 `order_line` 上可直接读到。
4. 若货物主数据足够完整，快照重复字段允许为空。
5. 若货物主数据不完整，快照字段必须显式提供。
