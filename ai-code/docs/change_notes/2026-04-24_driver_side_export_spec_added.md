# 2026-04-24 司机侧导出模块设计方案补充

- 为标准导出之外的司机阅读场景补一份独立设计方案。
- 明确司机侧导出不再追求四 Sheet 结构化数据包，而是服务排线后阅读和分发。

## Summary

- 司机侧导出被正式定义为独立于标准导出的第二条导出线。
- 方案明确首轮目标是帮助司机快速理解线路、停靠顺序、客户需求和货物摘要。
- 方案已收口为首轮只保留 `from_batch` 一个正式入口，波次、运单和司机入口后续再补。
- 输出格式首轮固定优先为 `PDF`，不再继续沿用四 Sheet `xlsx` 作为司机主阅读文件。
- 正文结构固定为：线路总览、停靠顺序清单、客户需求卡、货物摘要。
- 已按最新确认，把司机正文必带字段进一步冻结，包括批次号、线路名称、运单号、客户/门店信息、送货顺序、收货时间窗、停车/卸货要求、手推车/托盘/保温箱置换、总件数/总重量/总体积。
- 已进一步补充 PDF 页面草图、每页字段排版顺序、重点样式和分页规则，方便后续直接进入页面实现或打印样稿讨论。
- 已补充“司机 PDF 低保真页面示意图”，把封面摘要页、停靠顺序页、客户需求卡页、货物摘要页和补充备注页的版面结构固化下来。
- 已补充“字段缺失与降级展示规则”，明确主信息、客户识别、时间窗、配送要求、汇总字段在缺失时的显示口径和任务级降级规则。
- 已补充“重点标签生成规则”，明确哪些字段会压缩成司机快速识别的短标签，以及停靠顺序页和客户需求卡页的标签优先级与展示方式。
- 已补充“同批次内客户排序规则”，首轮明确优先按 `stop_seq_in_waybill` 排，缺失或冲突时再按运单与客户键兜底。
- 已补充“批次内多运单展示规则”，首轮明确跨运单统一混排，按停靠点顺序字段给司机看，运单号只作为辅助识别字段保留。
