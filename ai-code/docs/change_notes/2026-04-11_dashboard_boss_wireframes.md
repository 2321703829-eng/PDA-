## 变更原因

订单页、异常页、批次页、留痕页、证据页已经形成较完整的阅读链，但还缺少两类高层入口：
- 管理员每天进入后台后的工作入口
- 老板从争议和证据结论切入的判断入口

如果没有这两页：
- 后台会缺少真正的总入口
- 管理员和老板会被迫直接进入全量列表页
- 不同角色的阅读顺序很难被区分开

因此本次继续补齐：
- 管理工作台草图
- 老板追溯查看页草图

## 设计结论

### 管理工作台
- 这是管理员的工作入口页，不是详情页
- 页面重点是优先级分发、待处理异常、证据不足对象、高风险批次、最近变化
- 主动作以进入订单、异常、批次、证据页面为主
- 页面不承担复杂状态处理，重点是分流注意力

### 老板追溯查看页
- 这是老板的决策入口页，不是管理员工作台缩小版
- 页面重点是结论卡、重点争议对象、关键证据链摘要、风险分布摘要
- 页面强调“先看结论，再看证据，再决定是否下钻”
- 不建议承载管理员型处理动作

## 对整体阅读链的补充

本次补齐后，后台页面层次更完整：
1. 工作台 / 老板页决定先看什么
2. 列表页做第一轮筛选
3. 详情页做对象级汇总判断
4. 留痕时间线页做事实阅读
5. 证据查看页做证据阅读
