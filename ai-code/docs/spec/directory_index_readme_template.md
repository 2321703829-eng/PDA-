# 目录索引版 README 模板

适用范围：

- `ai-code/专题设计/` 下的阶段目录
- `ai-code/专题设计/` 下的子目录
- 需要承担“目录入口 + 文件阅读顺序”职责的 `README.md`

---

## 1. Objective

统一目录索引版 `README.md` 的写法，避免不同目录各写各的，后续越补越长、越补越乱。

---

## 2. 什么时候使用

目录内存在多个核心 `.md` 文件，且读者进入目录后需要先判断：

1. 这个目录是干什么的
2. 哪些文件优先看
3. 哪些文件只是草稿或归档

此时应为目录补一份索引版 `README.md`。

---

## 3. 基本结构

目录索引版 `README.md` 默认使用下面结构：

```text
# 目录名

本目录承接……

## 当前角色

- 现行方案层 / 现行规范层 / 归档层

## 核心文件索引

| 现行 | 草稿 | 归档 |
| --- | --- | --- |
| `...` | `...` | `...` |

## 其余文件处理规则

- 说明未列出的文件如何理解
- 说明是否继续作为补充材料保留

## 状态标识

- 默认按 `现行` / `draft` / `archive` 理解
```

---

## 4. 分类规则

### 4.1 现行

满足以下任意情况时，可列入 `现行`：

- 当前仍作为实施、联调、评审依据
- 与当前主专题、主规范、主链路一致
- 没有被后续文档明确替代

### 4.2 草稿

满足以下任意情况时，应列入 `草稿`：

- 文件名、标题或正文明确写有草案、草稿、待确认
- 方向可参考，但尚未收口为正式口径
- 只用于帮助讨论，不作为当前默认依据

### 4.3 归档

满足以下任意情况时，应列入 `归档`：

- 已被更新稿替代
- 主要承担追溯或来源材料作用
- 属于历史草图、旧清单、旧阶段产物

---

## 5. 全量列出还是只列核心

### 5.1 小目录

如果目录下核心 `.md` 文件数量不多，且全量列出不会明显拖长阅读入口，可直接全量列出。

建议条件：

- 目录内核心 `.md` 文件不超过 10 个

### 5.2 大目录

如果目录下 `.md` 文件较多，不应把所有文件全部堆进表格。

建议条件：

- 目录内 `.md` 文件超过 10 个
- 同类草图、清单、历史稿很多
- 全量表格已经影响读者快速判断

此时改用：

1. `核心文件索引`
2. `其余文件处理规则`

只列最值得先看的核心文件，其余文件按集合规则说明，不再逐个堆叠。

---

## 6. 大目录精修写法

大目录建议使用下面模板：

```text
## 核心文件索引

| 现行 | 草稿 | 归档 |
| --- | --- | --- |
| `核心文件 A` | `草稿文件 A` | `归档主文件 A` |
| `核心文件 B` | `草稿文件 B` |  |

## 其余文件处理规则

- 未列入“现行”的同类文件，默认按补充材料理解
- 未列入“草稿”的讨论稿，默认按待确认参考理解
- 未列入“归档主文件”的草图和旧清单，默认按历史补充材料理解
```

要求：

1. 只列核心，不追求面面俱到
2. 让第一次进入目录的人知道先看什么
3. 其余文件的角色必须有明确归类规则

---

## 7. 维护要求

目录新增或调整文件时，应同步检查：

1. 是否需要更新 `核心文件索引`
2. 是否出现新的 `draft`
3. 是否有文件应降级为 `archive`
4. 是否已有表格过长，需要改成核心索引模式
