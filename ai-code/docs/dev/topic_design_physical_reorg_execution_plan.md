## 5. 兼容策略

推荐采用“批量修路径 + 顶层过渡入口”的混合策略。

### 5.1 推荐策略

1. 搬迁到 `专题设计/` 后，批量修复所有现行入口和活跃文档中的路径。
2. 在旧根目录位置保留过渡目录，只放：
   - `README.md`
   - 必要的迁移说明
3. 旧根目录 `README.md` 只做 redirect，不再承载正文。

### 5.2 为什么不建议只靠一次性批量修路径

- 历史 `change_notes` 和治理说明里有大量旧路径
- 一次性全仓重写历史留痕，改动量过大，也容易引入误改
- 对人来说，旧根目录保留一个“你要找的内容已迁到哪里”的说明，恢复成本更低

### 5.3 为什么不建议完整保留旧目录镜像

- 等于长期双份维护
- 后续会再次制造“到底哪个路径是现行”的混乱

### 5.4 旧名字保留规则

可以只保留在历史留痕里的旧名字：

- `仓管模块设计`
- `企业分离功能文件夹`
- `高并发承载能力优化设计`

可以继续保留在历史语境里的旧路径：

- 已归档 `change_notes`
- 历史治理记录
- 明确写着“迁移前路径”的说明段落

不应继续作为现行入口展示名使用的位置：

- 根 `README`
- `docs/README.md`
- `专题包导航总表.md`
- 各专题包根 `README.md`

## 8. 决策建议

当前最稳的做法是：

1. 先按本方案冻结目标结构与命名。
2. 再单独开一轮真实物理归并。
3. 归并时优先保证“主入口可读”和“现行文档不断链”。
4. 历史留痕允许保留旧名字，但不再把旧名字当作现行展示名。
