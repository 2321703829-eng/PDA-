# 来源资料重命名规范与归档等级

## 1. 目的

本规范用于统一管理仓库中的 Office、Excel、来源稿、模板样例和辅助表格，解决以下问题：

- 文件名里出现 `副本`、`(1)`、`最终版`、`正式版`、`更新日期4.22` 这类临时命名
- 同类资料缺少统一归档口径
- 难以区分“现行基线”“现行参考”“来源留档”和“临时文件”

## 2. 推荐命名规则

默认文件名结构：

```text
YYYY-MM-DD_主题_类型.ext
```

或在日期不明确时使用：

```text
主题_类型.ext
```

命名要求：

1. 优先用明确日期，格式固定为 `YYYY-MM-DD`
2. 主题名称要表达业务对象或用途，例如：
   - `项目研讨会议纪要`
   - `数据库底表`
   - `客户信息样例`
   - `小程序输入模板`
3. 类型名称要表达文件角色，例如：
   - `样例`
   - `模板`
   - `纪要`
   - `字段清单`
4. 版本号只在确实存在并行版本时保留，例如：
   - `_v1`
   - `_v2`
   - `_v100`

## 3. 禁止继续使用的临时命名

以下命名默认应清理：

- `副本`
- `(1)`、`(2)` 这类系统自动重名后缀
- `最终版`
- `正式版`
- `更新日期4.22`
- 含糊但无业务意义的缩写或纯临时备注

处理原则：

- `正式版`、`最终版` 这类状态词，优先转为日期或归档等级表达
- `副本`、`(1)` 直接移除，并根据内容改成稳定主题名
- `更新日期4.22` 优先改成正式日期前缀 `2026-04-22`

## 4. 归档等级

### `A-基线`

适用于：

- 当前正式基线文件
- 当前默认应阅读、应维护的正式规范

说明：

- 优先使用 Markdown 正文
- 不建议把 Office / Excel 直接作为 `A-基线`

### `B-参考`

适用于：

- 当前仍在使用的模板样例
- 字段核对表
- 需要反复查阅但不直接作为最终规格正文的参考材料

说明：

- 可以是 Excel、Office、辅助 Markdown
- 应该能明确对应到哪份正式文档

### `C-来源`

适用于：

- 早期来源稿
- 原始资料
- 会议纪要
- 历史输入表和外部提供材料

说明：

- 只用于追溯背景和设计起点
- 不直接作为现行结论入口

### `D-临时`

适用于：

- 尚未整理的外部副本
- 临时导出文件
- 待确认版本

说明：

- `D-临时` 不应长期保留在仓库根目录
- 一旦确认用途，应尽快升级到 `B-参考` 或 `C-来源`，并完成重命名

## 5. 目录建议

- 项目会议纪要：`docs/context/meeting_notes/`
- 项目级来源稿：`docs/context/source_materials/`
- 合规资料：`docs/context/compliance/`
- 数据库来源稿与底表：`docs/architecture/source_materials/database/`
- 协作与分工稿：`docs/dev/project_coordination/`
- 测试样例数据：`docs/dev/test_data/`
- 专题模板样例：对应专题的 `03_模板与样例/`
- 专题原始资料：对应专题的 `04_来源资料与历史草图/01_原始资料/`

## 6. 配套要求

每个资料目录都应有 `README.md`，至少写清：

- 文件来源
- 文件用途
- 当前归档等级
- 对应哪份正式 Markdown
