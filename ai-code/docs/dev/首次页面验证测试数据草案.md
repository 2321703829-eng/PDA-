用于第一次页面装载验证后的最小人工测试，覆盖：

- Management Dashboard
- Boss Trace Overview

- Exception Queue list / form

## 2. 最小数据范围

建议先只准备一组主链数据：

- `1` 个波次

这样既能验证正常链路，也能验证异常链路。

## 7. 页面验证重点

### 7.1 工作台

- `Pending Exceptions` 应大于 `0`
- `Evidence Missing` 应大于 `0`
- `Priority Queue` 应出现异常对象
- 点击异常卡应进入异常列表

### 7.2 老板页

- `Open Disputes`、`Critical Disputes`、`High Risk Batches` 应有值
- `Dispute Focus Objects` 应能看到运单、批次、负责人
- `Open Exception / Open Waybill / Open Batch` 应都能点

### 7.3 运单详情

- 时间线区应出现真实留痕事件
- 证据区应出现真实证据
- 时间线卡片应能打开证据列表与异常列表
- 证据区应能打开相关留痕和相关异常

### 7.4 异常队列

- 默认进入时应只看到 `open / processing`
- 列表应优先把 `critical` 或 `overdue` 对象排前
- 打开异常详情后应能继续跳运单、批次、留痕、证据

## 8. 推荐造数顺序

1. 建波次
2. 建批次
3. 建运单
4. 建留痕事件
5. 建证据
6. 建异常
7. 回到页面逐页验证

## 9. 备注

- 第一次验证不必追求全量真实业务数据
- 优先保证一条“正常链”和一条“异常链”都能读通
- 如果页面先跑通，再逐步补更多门店、司机、车辆数据会更稳
