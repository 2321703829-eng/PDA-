# 配送节点页缺口清单

## 目标

- 明确 `配送节点明细` 页面应该承载哪些信息
- 明确当前页面缺了哪些节点层字段
- 明确哪些“客户经营信息”不应该继续塞进本页
- 为后续页面补齐与导入口径补齐提供单一检查清单

## 边界

- 本清单只讨论 `logistics.dispatch.waybill.customer.line` 对应的页面
- 本清单不包含实际编码
- 本清单不把客户经营画像层字段混入节点页

## 当前判断

1. 当前页面不应该承载“所有客户信息”。
2. 当前页面应该承载“本次运单下配送节点快照信息”。
3. 当前页面现在没有把节点层应有信息展示完整。
4. 当前导入模板口径与设计稿、模型字段之间也存在缺口。

## 一、字段缺口

### 1. 当前模型已有、设计稿要求有、但页面未展示

- `internal_customer_code_snapshot`
  - 设计稿定位：内部客户编号快照
  - 当前状态：模型有，页面未展示
- `external_customer_code_snapshot`
  - 设计稿定位：外联客户编号快照
  - 当前状态：模型有，页面未展示
- `signoff_requirement_snapshot`
  - 设计稿定位：签收要求快照
  - 当前状态：模型有，页面展示的是 `signoff_requirement`，不是快照字段
- `basement_height_limit_text_snapshot`
  - 设计稿定位：地库限高快照
  - 当前状态：模型有，页面未展示
- `customer_ref`
  - 当前状态：模型有，页面未展示
  - 备注：需要业务确认它是否属于节点页正式展示字段，还是仅保留技术字段

### 2. 当前页面已展示，但字段语义需要收口

- `customer_name`
  - 当前状态：作为页头主标题
  - 风险：这是主档联动字段，不是节点快照字段
  - 建议：页面主阅读优先使用 `customer_name_snapshot`
- `customer_no`
  - 当前状态：页面展示
  - 风险：这是计算字段，未明确区分内部客户号和外联客户号
  - 建议：拆清“内部客户编号快照 / 外联客户编号快照”
- `signoff_requirement`
  - 当前状态：页面展示
  - 风险：当前页是运单节点页，建议优先展示 `signoff_requirement_snapshot`

## 四、不应混入本页的信息

以下内容不应继续塞进 `配送节点明细` 页面主阅读区：

- 客户状态
- 是否允许货到付款
- 内部往来单位
- 其他客户经营画像字段

原因：

- 设计稿已明确这些属于客户经营画像层，不属于门店配送节点快照
- 若强行放入本页，会继续放大“节点页和客户主档页打架”的问题

## 五、页面结构建议

### 1. 本页应聚焦三块

- 节点识别
  - 门店节点编号
  - 运单
  - 门店名称快照
  - 内部/外联客户编号快照
- 节点交付信息
  - 联系人快照
  - 联系电话快照
  - 地址快照
  - 经纬度快照
  - 结构化地址快照
  - 运单内顺序
  - 签收要求快照
- 节点配送要求
  - 配送可达性快照
  - 上楼层数快照
  - 地库限高快照
  - 配送备注

### 2. 本页不应扩成经营画像页

- 若用户想看客户经营信息，应从这里跳到：
  - 客户经营画像
  - 门店配送画像
