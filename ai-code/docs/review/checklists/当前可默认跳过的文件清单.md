# 当前可默认跳过的文件清单

## 目的

这份清单用于减少后续阅读时反复进入“当前阶段不需要”或“仅作历史参考”的资料。

原则不是删除文件，而是明确：

- 哪些内容默认不作为当前实现入口
- 哪些内容只在需要追溯历史决策时再阅读
- 哪些内容属于归档或待归档资料

补充说明：

- 本文中历史提到的 `ai-code/前端相关设计/`，当前统一映射为 `ai-code/专题设计/前端设计/一期前端相关设计/`
- 若内容明确属于二期、三期、四期专题，再进入对应的阶段目录理解

---

## 一、默认可跳过的目录

### 1. `ai-code/odoo-reconstruct/`

状态：

- 历史重构资料目录
- 默认不作为当前现行设计基线

什么时候再看：

- 需要追溯历史方案来源
- 需要核对曾经的边界收缩、合规判断、旧模块规划

### 2. `ai-code/专题设计/前端设计/一期前端相关设计/04_来源资料与历史草图/`

状态：

- 历史草图与来源资料目录
- 默认不作为当前前端实现入口

什么时候再看：

- 需要回看早期页面草图
- 需要核对某份新文档的来源

### 3. `ai-code/专题设计/前端设计/一期前端相关设计/99_待归档/`

状态：

- 待归档资料目录
- 默认不作为当前开发依据

什么时候再看：

- 需要整理目录
- 需要确认某份文档是否应正式归档

## 二、默认可跳过的文档类型

### 1. 范围排除型文档

典型文件：

- `ai-code/odoo-reconstruct/odoo-19.0/明确暂不需要的模块和功能.md`

用途：

- 说明当前阶段不纳入哪些模块和能力

默认动作：

- 看过结论即可
- 不要把它当成当前实现入口反复阅读

### 2. 历史桥接型文档

典型文件：

- `ai-code/docs/architecture/logistics_order_addon_design_bridge.md`
- `ai-code/docs/architecture/logistics_trace_addon_design_bridge.md`
- `ai-code/docs/architecture/logistics_exception_addon_design_bridge.md`
- `ai-code/docs/architecture/logistics_order_mapping_bridge.md`
- `ai-code/docs/architecture/logistics_trace_mapping_bridge.md`

用途：

- 解释旧命名如何映射到当前口径

默认动作：

- 非必要不读
- 只有在处理历史命名、兼容旧资料时再打开

### 3. 旧计划或旧任务单

典型文件：

- `ai-code/docs/dev/next_step_plan_2026-04-10.md`
- `ai-code/docs/review/文档回调清单_v1_运单主对象调整.md`

用途：

- 反映历史阶段的待办和回调过程

默认动作：

- 不作为当前执行清单

### 4. 待确认主数据草图

典型文件：

- `ai-code/docs/context/odoo_logistics_master_data_draft.md`

用途：

- 记录客户、门店、人员、仓库等领域的方向性假设

默认动作：

- 默认不作为当前开发入口
- 只有在主数据专题被明确拉起时再深入阅读
