# 联调环境缓存与页面异常排查手册

## 1. 文档目的

本文档用于指导 Odoo 物流项目在联调阶段排查以下高频问题：

- 页面还是旧版本，改动看不到
- 页面打不开、偶发 `502`
- 登录后报 `invalid CSRF token`
- 本机能开、联调服打不开
- 接口通了，但页面没变化

本文档重点不是解释底层理论，而是提供一套**可重复执行的排查流程**。

---

## 2. 先记住一句话

联调阶段的“页面过时/打不开”，通常不是单一缓存问题，而是下面 5 类因素叠加造成的：

1. Odoo 前端资产包还是旧的
2. 浏览器缓存、cookie、session 还是旧的
3. 看错了环境或入口
4. 服务重启了，但模块没升级或升级不完整
5. 公网代理 / 隧道 / 转发链路不稳定

---

## 3. 先确认你看的到底是哪套环境

这是最重要的一步。

### 3.1 常见入口

项目里常见入口可能包括：

- 本机：
  - `http://127.0.0.1:19069/...`
- 联调服内网：
  - `http://192.168.0.17:19069/...`
- 联调服公网：
  - `http://8.166.131.218:7084/...`
- SSH 隧道本地映射：
  - `http://127.0.0.1:19070/...`

### 3.2 必须先确认的事

每次联调前先确认：

- 我现在看的到底是本机，还是联调服？
- 如果是联调服，我是走公网、内网，还是 SSH 隧道？

### 3.3 推荐口径

联调时优先使用：

- **SSH 隧道 + 本地端口映射**

例如：

```powershell
ssh -L 19070:127.0.0.1:19069 tianshukeji@192.168.0.17
```

然后浏览器访问：

```text
http://127.0.0.1:19070/web/login?db=odoo_logistics_webtest_v19
```

优点：

- 比公网代理稳定
- 比直接记多个入口更不容易混淆

---

## 4. Odoo 前端为什么容易“改了没生效”

### 4.1 原因

Odoo 前端资源并不是每次都直接读散文件，而是会打成：

- `/web/assets/...`

也就是说：

- 你改了 `static/src/js/...`
- 改了 `static/src/xml/...`
- 改了 `static/src/scss/...`

页面不一定立刻吃到新内容。

### 4.2 会出现的现象

- 代码改了但按钮没出现
- 页面布局还是老的
- JS 逻辑还是旧的
- 换浏览器偶尔又好了

---

## 5. 标准排查顺序

遇到“页面不对”时，按下面顺序查，不要乱跳。

### 第一步：确认是不是看错环境

先问自己：

- 我当前访问的是哪条地址？
- 它是不是我刚刚升级/重启的那套环境？

如果这一步没确认，后面所有刷新都可能白做。

### 第二步：确认模块有没有真的升级

排查点：

- 代码是不是已经同步到目标服务器
- `-u 模块名` 有没有真正执行
- 升级日志里有没有报错

### 第三步：确认前端资产是不是旧的

排查点：

- 是否清过 `/web/assets/%`
- 是否重新加载过前端资源
- 是否还在吃旧的打包产物

### 第四步：确认浏览器 cookie / session / 缓存是不是旧的

典型现象：

- 登录页没问题，但登录后报错
- 报 `invalid CSRF token`
- 普通窗口不行，无痕窗口行

### 第五步：确认代理 / 公网转发 / 隧道链路是否稳定

典型现象：

- curl 能通，浏览器不通
- 内网能通，公网 502
- 同事能打开，你打不开

---

## 6. 最推荐的固定操作流程

每次前端联调都尽量按这套做。

### 6.1 如果改了前端文件

涉及：

- `static/src/js/...`
- `static/src/xml/...`
- `static/src/scss/...`

则建议顺序：

1. 同步代码到目标环境
2. 升级相关模块
3. 清旧 assets
4. 重启 Odoo
5. 用无痕窗口打开页面验证

### 6.2 如果改的是后端接口

涉及：

- controller
- service
- model

建议顺序：

1. 同步代码到目标环境
2. 升级相关模块
3. 重启 Odoo
4. 先测接口
5. 再看页面

原因：

- 先确认后端是不是已经新了
- 再判断页面是否只是缓存

---

## 7. 浏览器排查手册

## 7.1 首选无痕窗口

每次联调验证页面，优先用：

- Edge InPrivate
- Chrome 无痕

这样可以绕开很多：

- 旧 cookie
- 旧 session
- 旧资源缓存

## 7.2 如果登录时报 `invalid CSRF token`

优先处理步骤：

1. 关闭当前站点所有标签页
2. 新开无痕窗口
3. 重新打开登录页
4. 重新登录

如果还不行，再做：

5. 清该站点 cookie
6. 清 `.odoo_data/sessions`
7. 重启 Odoo

### 7.3 如果浏览器提示安全连接问题

如果是公网 `http://` 地址，可能会遇到浏览器安全提示。

这类情况先区分两件事：

- 服务端是不是真的挂了
- 还是浏览器策略拦了

判断方法：

先用命令行试：

```powershell
curl.exe -i "http://8.166.131.218:7084/web/login?db=odoo_logistics_webtest_v19"
```

如果命令行能拿到完整 HTML，说明：

- 服务大概率是好的
- 问题更像浏览器链路或代理策略

## 8. SSH 隧道排查手册

### 8.1 常见错误

你已经连上 SSH，但浏览器还是打不开。

### 8.2 高概率原因

- 本地端口被占用
- 远端目标端口写错
- 远端宿主机没有监听你转发的端口

### 8.3 正确排查方式

#### 先在服务器查容器端口映射

```bash
docker ps --format "table {{.Names}}\t{{.Ports}}"
```

例如看到：

```text
0.0.0.0:19069->8069/tcp
```

那么 SSH 隧道就应该写成：

```powershell
ssh -L 19070:127.0.0.1:19069 tianshukeji@192.168.0.17
```

不是写 `8069`。

#### 然后浏览器访问

```text
http://127.0.0.1:19070/web/login?db=odoo_logistics_webtest_v19
```

### 8.4 如果终端出现

```text
channel X: open failed: connect failed: Connection refused
```

说明：

- SSH 已连上
- 但远端目标端口选错了，或该端口没服务监听

不是浏览器问题。

---

## 9. 公网入口排查手册

### 9.1 公网入口的特点

例如：

- `http://8.166.131.218:7084/...`

通常会多一层：

- Nginx / 代理 / FRP / 端口映射

### 9.2 常见问题

- 偶发 `502`
- 浏览器和 curl 表现不一致
- 同事能开，你打不开

### 9.3 建议

公网入口只作为备用入口，不作为主联调入口。

主联调优先级建议：

1. SSH 隧道
2. 内网 IP
3. 公网入口

---

## 10. 如何快速判断“到底是不是缓存问题”

用下面 4 个判断点。

### 判断点 1：接口是不是新的

先直接测接口。

如果接口返回已经是新逻辑：

- 后端是新的
- 页面不对就更像前端缓存

### 判断点 2：是否能看到明显的新文案

每次前端改动最好故意留一个“肉眼可见”的变化，例如：

- 新按钮标题
- 新字段名
- 新区块标题

这样一眼就能判断你是不是在看新版本。

### 判断点 3：无痕窗口有没有变化

如果无痕窗口好了，普通窗口没好，几乎就是缓存 / session 问题。

### 判断点 4：当前实例是不是对的

如果你看错了环境，再怎么清缓存都没用。

---

## 11. 遇到问题时的建议反馈格式

让同事反馈时，尽量一次给齐这几样：

1. 当前访问地址
2. 当前环境说明
   - 本机 / 联调服 / 公网 / SSH 隧道
3. 具体报错截图
4. 浏览器控制台报错（如果有）
5. 对应接口返回
6. 最近一次升级/重启日志

这样排查会快很多。

---

## 12. 推荐的联调值班习惯

建议你们形成固定动作：

1. 每次联调前先说清楚今天看哪套环境
2. 每次改前端后都：
   - 升模块
   - 清 assets
   - 重启
3. 页面验收优先用无痕窗口
4. 出现异常先测接口再看页面
5. 公网入口只当备用，不当主入口

---

## 13. 一句话总结

联调环境里“页面过时或打不开”并不只是缓存问题，而是：

**资产打包、浏览器缓存/session、多环境入口、服务升级状态、代理转发链路** 共同造成的。

最有效的规避方式不是只靠 `Ctrl + F5`，而是：

- 固定验证入口
- 升级模块后清 assets
- 联调用无痕窗口
- 先确认实例，再判断缓存
- 尽量使用 SSH 隧道作为主联调入口
