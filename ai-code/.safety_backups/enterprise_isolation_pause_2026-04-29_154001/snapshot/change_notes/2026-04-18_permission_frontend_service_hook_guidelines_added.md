# 2026-04-18 权限与角色规范补充前端 service / hook 设计口径

## 本次变更

补充 `仓管模块设计/01_模块设计/08_设置与规则/00_权限与角色规范草稿.md`：

- 新增 `22. 更细的前端权限辅助 service / hook 设计口径`
- 将原 `v0.1 收口与后续补充方向` 顺延为 `23`

## 本次补充的重点

### 1. 把权限专题继续推进到前端辅助层

本次继续沿着：

- 前端显隐与后端兜底分工
- XML / Python / JS 三层映射
- 模块文件树索引

往前端实现层推进，明确了哪些权限辅助逻辑更适合做成：

- `service`
- `hook`

### 2. 固定了 service 和 hook 的当前职责边界

本次明确：

- `service` 更适合承接跨页面的稳定上下文与共性封装
- `hook` 更适合承接页面内的轻量组合判断
- 真正的权限裁决仍然以后端为准

这让前端辅助层不会误长成“第二套权限引擎”。

### 3. 给出了可直接复用的命名方向

本次补进了一组更靠近实现的命名方向，例如：

- `wmsPermissionService`
- `wmsRoleService`
- `wmsExecutionAccessService`
- `useWmsReadonlyState`
- `useWmsActionAvailability`
- `useWmsUnsavedInputGuard`
- `useWmsHintPriority`

后面如果开始做执行页前端，就可以直接沿这组口径继续细化。

## 当前意义

这次补充后，这份权限专题已经不只是在定义权限规则和页面边界，也开始说明前端辅助层该怎么抽。  
后续如果继续补“总规范层的 v0.1 基线清单”，这份权限稿就可以作为其中一份比较完整的前端/后端协同基线引用。
