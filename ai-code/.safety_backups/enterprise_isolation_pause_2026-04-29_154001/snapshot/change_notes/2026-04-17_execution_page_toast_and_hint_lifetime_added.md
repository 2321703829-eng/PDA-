# 2026-04-17 执行页成功 toast 与提示条时长规则补入讨论稿

## 本次变更

更新文档：
- `仓管模块设计/00_导航与总纲/仓管模块设计启动讨论稿.md`

补充了本轮已确认的内容：

- 一期执行页中成功 `toast` 的当前建议：
  - 短时显示
  - 自动消失
  - 不要求用户手动关闭
- 一期执行页中提示条的当前建议：
  - 默认持续显示
  - 直到被新提示替换，或当前状态解除
  - 不依赖自动消失
- 当前推荐这一处理方式的主要原因
- 当前不建议一期优先采用的方式

## 变更目的

把执行页反馈机制从“成功/失败反馈分工”进一步推进到“显示时长与消失方式”，为后续确定提示条是否需要手动关闭能力建立统一前提。

## 当前说明

本次更新仍属于讨论稿沉淀，后续还会继续细化：

- 提示条是否需要手动关闭能力
- 成功 toast 的具体时长
- 不同优先级提示之间的替换节奏
