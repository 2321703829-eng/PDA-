# 2026-04-17 执行页状态/提示条优先级方案补入讨论稿

## 本次变更

更新文档：
- `仓管模块设计/00_导航与总纲/仓管模块设计启动讨论稿.md`

补充了本轮已确认的内容：

- 执行页状态/提示条按以下优先级显示：
  1. 阻断性错误或校验
  2. 当前动作结果
  3. 记录级状态
  4. 下一步引导
- 当前建议同一时刻只显示一条主提示
- 各类提示的当前定位和示例
- 当前不建议一期优先采用的多提示并列或轮播方式

## 变更目的

把执行页轻量状态/提示条从“承接哪些信息”进一步收紧到“不同信息的显示优先级”，为后续确定提示条、toast 和弹窗之间的边界建立统一前提。

## 当前说明

本次更新仍属于讨论稿沉淀，后续还会继续细化：

- 状态/提示条与 toast、弹窗的边界
- 不同优先级提示的显示时长
- 提示条颜色和视觉语义
