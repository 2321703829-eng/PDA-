# Change Notes

## 本轮目标

- 将四期数据库底表设计稿收口到首轮可落地范围
- 移除司机/车辆调度状态层与历史层的首轮建表要求
- 简化 `logistics_product_unit` 的单位价格结构
- 为门店地址补充结构化 JSON 存储口径

## 修改文件

- `前端设计/四期前端优化设计/02_跨模块规范/01_接口与数据/2026-04-21_四期数据库底表设计稿 v1（第二次修正版）.md`

## 修改原因

- 业务要求首轮只保留司机和车辆画像，不提前落库调度和历史表
- 现有 `logistics_product_unit` 设计将小/中/大单位价格放在同一行，不符合“一条记录表达一个销售单位”的口径
- 地址信息需要同时保留经纬度与省市区结构，便于后续接口和导入统一

## 改动摘要

- 新增首轮收口修订记录
- 将司机/车辆设计从“三层落库”调整为“首轮仅主档 + 画像扩展层”，把调度状态表与历史表改为后续预留
- 删除首轮表清单、约束、索引、模型清单中对调度状态表、历史表、`dispatch_state_change_log` 的正式落库要求
- 将 `logistics_product_unit` 改为单行单销售单位，移除同一行内小/中/大条码与价格组，改为 `barcode`、`standard_price`、`purchase_price`、`retail_price`
- 将门店地址调整为 `address_full + longitude + latitude + address_region_json`
- 将门店节点快照同步调整为 `address_full_snapshot + longitude_snapshot + latitude_snapshot + address_region_json_snapshot`

## 影响范围

- 四期数据库设计评审口径
- 后续 Odoo 模型建模清单
- 导入字段映射与接口 DTO 设计
- 首轮建表、索引、约束与审计日志范围

## 是否影响模型 / 视图 / 权限 / 数据兼容性

- 影响模型设计：是
- 影响视图：否
- 影响权限：否
- 影响数据兼容性：有潜在影响
  - 后续若已按旧稿实现调度状态或历史表，需要按本次收口结果回退到“暂不启用”

## 验证方法

- 通读并检索设计稿，确认以下旧口径已不再作为首轮正式要求：
  - 司机/车辆调度状态表
  - 司机/车辆历史关联表
  - `dispatch_state_change_log`
  - `logistics_product_unit` 的小/中/大三组价格与条码字段
- 确认地址章节、快照章节、Odoo Model 字段清单已同步出现 `address_region_json`

## 风险点

- 其他四期接口/影响面文档仍可能保留旧口径，需要后续继续同步
- 若开发已按旧稿实现调度状态页或历史页，需要再次确认是否延期
- `address_region_json` 的键名若未统一，后续接口容易出现多套字段名

## 回滚建议

- 若后续业务重新决定首轮即做排线和历史追溯，可按本次 change note 反向恢复对应表、索引、日志章节
