## 3. 任务拆分原则

- 一律围绕 `waybill` 主阅读入口排任务。
- `customer_line` 只允许承接结构层、快照层、命中辅助层任务。
- 正式对象归属不改写：
  - `trace_event` 不变
  - `trace_event_id` 不变
  - `waybill / batch / trace_event` 异常主挂点不变
- 任务描述必须包含：
  - 模型 / 字段
  - 服务 / 接口
  - 菜单 / 页面
  - 权限 / 记录规则
  - 验收用例

## 4. 任务总表

| 任务包 | 模型 / 字段 | 服务 / 接口 | 菜单 / 页面 | 权限 / 记录规则 | 验收用例 |

## 5. 建议排期顺序

### 第一阶段

- A1. 留痕对象归属校对
- A2. 批次与运单回跳链

目标：

- 先把 `trace` 正式对象与阅读入口稳住

### 第二阶段

- B1. 图片命中辅助字段
- B2. 证据正式补链

目标：

- 先命中，再补链，再开放稳定阅读与导出

### 第三阶段

- C1. 异常状态流转
- C2. 异常详情联动

目标：

- 让异常在已有留痕与证据链上闭环

### 第四阶段

- D1. 页面职责收口
- D2. 角色矩阵收口

目标：

- 把三层联动、页面职责、角色边界统一收口

## 6. 交付物要求

每个任务包交付时至少要带：

- 变更说明
- 涉及模块与文件列表
- 影响的字段 / 接口 / 页面列表
- 验收自测结果
- 是否影响联调顺序

## 7. 联调顺序

固定联调顺序继续使用：

1. `trace_core`
2. `evidence`
3. `exception`
4. 三层联动回归

## 8. 联调通过标准

### 8.1 `trace_core`

- `trace_event` 继续只围绕 `batch / waybill`
- `waybill` 页留痕摘要和入口稳定
- `batch / waybill / trace_event` 回跳成立

### 8.2 `evidence`

- 图片导入任务按 `image_package` 独立审计
- 图片可先命中结构层，再补链到正式 `trace_event`
- `waybill` 页稳定承担图片与证据主阅读职责

### 8.3 `exception`

- 异常状态流转受模型层控制
- 异常详情可反读留痕与证据
- `waybill` 页异常摘要与详情入口稳定

### 8.4 三层联动回归

- `waybill -> 留痕 / 图片预览 / 证据 / 异常` 统一成立
- 正式对象归属没有被页面口径带偏
- 角色边界、导出边界、处理边界一致

## 9. 风险提醒

- 不要把 D 包误做成平台权限系统设计。
- 不要因为导入命中用了 `customer_line`，就把它重新抬成主阅读入口。
- 不要把摘要区字段和正式对象归属混为一谈。
- 不要跳过 A/B 直接做 C。

## 10. 一句话结论

这版 `v2` 的目标不是再讨论方向，而是把 `trace -> evidence -> exception -> 角色矩阵` 四块直接拆成能排期、能指派、能联调、能验收的执行任务。
