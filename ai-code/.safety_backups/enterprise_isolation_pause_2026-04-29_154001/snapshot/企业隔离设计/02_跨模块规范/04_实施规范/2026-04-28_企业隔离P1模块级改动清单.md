# 2026-04-28 企业隔离 `P1` 模块级改动清单

## 1. 文档定位

- 本文用于把当前企业隔离 `P1` 已经形成的细稿、落位稿和模块映射，进一步压成按模块拆开的改动清单。
- 本文主要服务开发分工、并行开发和首轮排期，不替代细稿本身。
- 本文只覆盖当前 `P1` 首轮编码，不展开 `P2 / P3` 平台能力。

本文主要回答：

- `logistics_trace_core` 首轮要改什么
- `logistics_trace_evidence` 首轮要改什么
- `logistics_trace_exception` 首轮要改什么
- `logistics_dispatch` 需要配合什么
- 哪些内容可以并行，哪些需要前置依赖

## 2. 前置基线

- 当前企业隔离 `P1` 主阅读入口：`waybill`
- 页面主阅读链：`waybill -> order_line`

- 企业之间靠数据库级隔离，租户内权限继续复用 Odoo 原生权限体系与现有模块权限骨架

## 3. 使用原则

- 优先沿现有模块边界增量扩展，不为首轮 `P1` 新起大模块。
- 优先补“模型层约束 + 摘要字段 + 入口动作 + 权限收口”，不先做平台控制面。
- 首轮开发顺序固定为：
  1. `logistics_trace_core`
  2. `logistics_trace_evidence`
  3. `logistics_trace_exception`
  4. `logistics_dispatch` 联动回归与配合收口

## 5. `logistics_trace_core` 改动清单

### 5.1 本轮目标

- 稳住 `trace_event` 正式对象锚点。
- 让 `waybill` 页能稳定读取留痕摘要、留痕时间线入口和最近留痕信息。
- 把留痕提交、查看的最小权限口径收紧到当前 `P1` 方案。

### 5.2 重点改动项

1. 校对 `logistics.trace.event` 的字段口径
- 统一 `trace_time`
- 统一 `submit_user / operator`
- 统一 `remark`
- 统一 `source_channel`
- 校对 `is_exception`

2. 校对 `trace_event -> waybill / batch` 主归属
- 保证 `waybill_id` 仍是当前 `P1` 的核心阅读归属
- 保证批次信息只作为上下文，不反向替代运单主阅读

3. 补 `waybill` 留痕摘要字段与计算
- `trace_count`
- `latest_trace_time`
- `latest_trace_type`
- `latest_trace_summary`
- `has_exception_related_trace`

4. 补 `waybill` 页留痕入口
- 留痕摘要区
- 查看全部留痕入口
- 最近留痕回跳 `trace_event` 详情

5. 收口留痕权限
- 谁能查看
- 谁能提交
- 谁只能只读
- 哪些按钮只做显隐，哪些动作必须模型层兜底

### 5.3 主要承接文件

- `custom_addons/logistics_trace_core/models/logistics_trace_event.py`
- `custom_addons/logistics_trace_core/models/logistics_dispatch_waybill.py`
- `custom_addons/logistics_trace_core/views/logistics_trace_event_views.xml`
- `custom_addons/logistics_trace_core/security/logistics_trace_core_security.xml`
- `custom_addons/logistics_trace_core/security/ir.model.access.csv`

### 5.4 验收重点

- `waybill` 页能稳定显示留痕摘要
- 留痕列表能按 `waybill_id` 稳定打开
- 非法留痕写入或越权提交能被拦截

## 7. `logistics_trace_exception` 改动清单

### 7.1 本轮目标

- 稳定异常状态流转和模型层约束。
- 让异常详情页能反读 `waybill / trace_event / evidence`。
- 让 `waybill` 页能读异常摘要和异常入口。

### 7.2 重点改动项

1. 校对异常状态机
- 初始态允许 `draft / open`
- 主流转围绕 `open -> processing -> resolved -> closed`
- `cancelled` 保留为兼容最终态

2. 落模型层约束
- 非法状态迁移直接拦截
- 最终态必须有 `close_summary`
- `closed_time` 由模型层统一维护
- 过程日志只允许系统生成

3. 补对象一致性校验
- `trace_event_id` 与 `waybill_id` 一致性
- `waybill_id` 与 `batch_id` 一致性
- 不允许异常主挂到 `customer_line / order_line`

4. 补 `waybill` 异常摘要
- `open_exception_count`
- `latest_exception_time`
- `latest_exception_type`
- `highest_exception_status`
- `has_processing_exception`

5. 补异常详情联动
- 回跳 `waybill`
- 回跳 `batch`
- 回跳 `trace_event`
- 查看相关证据
- 查看处理日志

6. 收口异常权限
- 谁能提报
- 谁能跟进
- 谁能关闭
- 谁只能只读

- `custom_addons/logistics_trace_exception/models/logistics_trace_exception_process_log.py`

### 7.4 验收重点

- 非法状态迁移被模型层拦截
- 关闭异常前必须有关闭说明
- 异常详情能稳定回读留痕、证据与处理日志
- 越权关闭、越权改日志被拦截

## 8. `logistics_dispatch` 配合清单

### 8.1 本轮定位

- `logistics_dispatch` 不是要吞掉 `trace / evidence / exception` 三层，而是承担主链对象、主阅读页和导入任务协同。
- `waybill` 作为当前 `P1` 主阅读入口，相关摘要区与入口动作必须由它稳定承接。

### 8.2 重点配合项

1. 校对 `waybill` 页阅读链
- 保持 `waybill -> order_line`
- 保持 `waybill -> 图片预览 / 留痕 / 证据`
- 不把 `customer_line` 再抬回主阅读入口

2. 配合展示摘要区
- 留痕摘要区
- 证据摘要区
- 异常摘要区
- 跳转按钮和智能入口

3. 配合导入任务与图片包任务区分
- `dispatch_main`
- `image_package`

4. 保留结构辅助字段
- `customer_line` 仍作为命中辅助结构层
- 但不承担当前 `P1` 主阅读职责

5. 协同联调
- `trace_core` 接上后回扫 `waybill` 页留痕摘要
- `evidence` 接上后回扫图片预览与证据摘要
- `exception` 接上后回扫异常摘要与异常入口

### 8.3 主要承接文件

- `custom_addons/logistics_dispatch/models/logistics_dispatch_waybill.py`
- `custom_addons/logistics_dispatch/models/logistics_dispatch_waybill_customer_line_v2.py`
- `custom_addons/logistics_dispatch/models/logistics_import_log.py`
- `custom_addons/logistics_dispatch/models/logistics_import_batch.py`
- `custom_addons/logistics_dispatch/views/logistics_dispatch_waybill_views.xml`
- `custom_addons/logistics_dispatch/security/logistics_dispatch_security.xml`
- `custom_addons/logistics_dispatch/security/ir.model.access.csv`

### 8.4 验收重点

- `waybill` 页成为统一主阅读入口
- 三块摘要区入口稳定可用
- 导入任务与图片任务口径不混

## 9. 并行与依赖建议

### 9.1 可并行

- `trace_core` 权限收口 与 `dispatch` 页面展示准备 可并行
- `evidence` 命中字段落位 与 `waybill` 证据摘要展示准备 可并行
- `exception` 详情页展示 与 `process log` 只读表现 可并行

### 9.2 必须前置

1. `trace_event` 锚点与留痕摘要先稳
2. 再接 `evidence` 命中与补链
3. 再接 `exception` 状态流与详情反读
4. 最后做 `dispatch` 主阅读页三层回归
