# 2026-04-27 企业隔离 `P0 / P1` 缺失项总表

## 1. 文档定位

- 本文用于把当前企业隔离专题在 `P0 / P1` 范围内的真实缺失项统一收口成一张总表。
- 本文只统计“当前应该补，但还没真正落下”的缺口。
- 本文不把明确后置到 `P2 / P3` 的平台能力混入当前缺失项。

## 2. 适用口径

本文默认以下口径已成立：

- 企业之间靠数据库隔离
- 当前只做 `P0 / P1`
- 当前 `P1` 主阅读入口为 `waybill`
- `customer_line` 当前为结构 / 快照 / 命中辅助层
- 正式对象归属不变：
  - `trace_event`
  - `trace_event_id`
  - `waybill / batch / trace_event`

## 3. 判定说明

- `是否阻塞 P1 = 是`
  表示该项如果不补，会直接影响当前定义下的 `P1` 成立、联调或验收。
- `是否阻塞 P1 = 否`
  表示该项虽然应补，但不一定阻断当前 `P1` 最小闭环，可后续并行补强。

## 5. 先后顺序建议

### 5.1 第 0 优先级

- `P0` 真实验收记录
- `P0 / P1` 文档旧口径回扫

原因：

- 不先确认底盘是否真的成立，后面 `P1` 的开发与联调会缺少真实落地前提。
- 不把文档口径回扫干净，开发和实施容易继续引用旧表述。

### 5.2 第 1 优先级

- `trace` 角色分层
- `waybill` 留痕摘要与查询入口
- `batch / waybill / trace_event` 回跳链

原因：

- `trace` 是三层正式事实基础。
- `evidence` 和 `exception` 都依赖 `trace_event` 锚点稳定。

### 5.3 第 2 优先级

- 图片命中规则
- `image_package` 专项导入与结果链
- 证据正式补链
- 证据预览 / 导出 / 审计分权
- `waybill` 证据摘要与导出入口

原因：

- 当前 `P1` 下最明显的工程缺口就在图片包与证据化链路。

### 5.4 第 3 优先级

- 异常动作边界
- 异常详情反读联动
- `waybill` 异常摘要区

原因：

- 异常依赖前面两层先稳住，适合在留痕和证据链稳定后收尾。

### 5.5 第 4 优先级

- 页面职责全面收口
- 统一权限判断入口
- 四类能力一致性校验
- `P1` 首轮真实联调记录

原因：

- 这层更像“全面收口与验收固化”，适合放在功能链已经跑通之后。

## 6. 当前最关键的 4 个缺口

如果只看最影响当前 `P1` 落地的 4 项，可以收口成：

1. `P0` 底盘真实验收记录还没沉淀。
2. `image_package` 图片包命中、导入、补链工程链还没真正落下。
3. 租户内角色边界还没细化到查看 / 提交 / 处理 / 导出四层。
4. 页面职责虽然已经设计清楚，但还没有完全转成实现与联调闭环。

## 7. 一句话结论

当前企业隔离 `P0 / P1` 真正缺的，不是再补一轮大方向，而是把底盘验收、图片补链、角色边界和页面职责这四类执行缺口真正落成代码与验收记录。
