# 2026-04-28 企业隔离 `P0` 环境参数样例稿

## 1. 文档定位

- 本文用于给企业隔离 `P0` 的底盘验证、环境搭建和首轮验收提供一份可直接照抄的样例参数。
- 本文是对 `租户库命名、域名映射与 dbfilter 规范` 的样例化补充，不替代正式规范。
- 本文样例面向开发、运维和联调同学，重点是让“第一套能跑起来”更快。

相关文档：

- `2026-04-27_企业隔离P0租户库命名_域名映射与dbfilter规范.md`
- `2026-04-27_企业隔离P0多数据库底盘验证与验收说明.md`
- `2026-04-27_企业隔离P0P1租户初始化安装与首轮验收SOP.md`

## 2. 样例使用原则

- 样例值仅用于环境准备和联调说明，不要求与生产最终值一致。
- 样例仍然必须遵循正式规范：
  - 通过 `tenant_code` 做稳定映射
  - 不直接用企业显示名做数据库名
  - 域名、数据库名和 `dbfilter` 保持确定性一对一映射

## 3. 最小参数样例

### 3.1 基础变量

| 参数项 | 样例值 | 说明 |
| --- | --- | --- |
| `base_domain` | `example.com` | 基础域名 |
| `tenant_code` | `alpha` | 租户稳定编码 |
| `db_name` | `tenant_alpha` | 租户数据库名 |
| `tenant_domain` | `alpha.example.com` | 租户访问域名 |
| `dbfilter` | `^tenant_%d$` | Odoo 路由过滤方向 |

### 3.2 第二租户样例

| 参数项 | 样例值 | 说明 |
| --- | --- | --- |
| `tenant_code` | `beta` | 第二租户编码 |
| `db_name` | `tenant_beta` | 第二租户数据库 |
| `tenant_domain` | `beta.example.com` | 第二租户访问域名 |

## 4. `tenant_code` 样例规则

### 4.1 推荐格式

- 小写英文开头
- 仅使用：
  - 小写字母
  - 数字
  - 中划线

### 4.2 推荐样例

- `alpha`
- `beta`
- `north-1`
- `east2`

### 4.3 不建议样例

- `华东一部`
- `Acme Ltd`
- `tenant alpha`
- `alpha_demo#1`

原因：

- 中文、空格、特殊字符不适合数据库名与域名映射
- 显示名变化不应带动数据库名变化

## 5. 数据库名样例

### 5.1 推荐格式

统一：

- `tenant_<tenant_code>`

### 5.2 样例

| `tenant_code` | 数据库名样例 |
| --- | --- |
| `alpha` | `tenant_alpha` |
| `beta` | `tenant_beta` |
| `north-1` | `tenant_north-1` |

### 5.3 不建议

- `acme`
- `华东物流`
- `enterprise_alpha_db`

原因：

- 规则不统一
- 不利于一眼反推库与域名
- 不利于 `dbfilter` 保持简单

## 6. 域名样例

### 6.1 推荐格式

统一：

- `<tenant_code>.<base_domain>`

### 6.2 样例

| `tenant_code` | `base_domain` | 域名样例 |
| --- | --- | --- |
| `alpha` | `example.com` | `alpha.example.com` |
| `beta` | `example.com` | `beta.example.com` |
| `north-1` | `example.com` | `north-1.example.com` |

### 6.3 映射关系样例

| 域名 | 数据库 |
| --- | --- |
| `alpha.example.com` | `tenant_alpha` |
| `beta.example.com` | `tenant_beta` |

## 7. `dbfilter` 样例

### 7.1 推荐方向

推荐使用：

- `^tenant_%d$`

说明：

- `%d` 对应当前访问域名中的子域部分
- `alpha.example.com` 会命中 `tenant_alpha`

### 7.2 样例解释

| 访问域名 | 子域提取 | 命中数据库 |
| --- | --- | --- |
| `alpha.example.com` | `alpha` | `tenant_alpha` |
| `beta.example.com` | `beta` | `tenant_beta` |

### 7.3 不建议方向

- 直接按显示名匹配数据库
- 允许多库模糊命中
- 让数据库列表页参与人工选择

## 8. 最小登记信息样例

建议至少为每个租户登记：

| 项目 | 样例值 |
| --- | --- |
| 租户显示名 | `阿尔法测试租户` |
| `tenant_code` | `alpha` |
| 数据库名 | `tenant_alpha` |
| 域名 | `alpha.example.com` |
| 环境 | `test` |
| 状态 | `active` |
| 备注 | `企业隔离P0联调样例租户` |

说明：

- 显示名给人看
- `tenant_code` 给技术映射和运维用
- 两者不要混用

## 9. 首轮验证样例步骤

1. 准备 `tenant_code=alpha`
2. 建库 `tenant_alpha`
3. 配域名 `alpha.example.com`
4. 配 `dbfilter=^tenant_%d$`
5. 访问域名并确认命中 `tenant_alpha`
6. 安装 `P0 / P1` 首轮模块
7. 按验收说明做多数据库隔离验证

## 10. 一句话收口

这份样例稿的作用，就是把 `P0` 正式规范里的命名与路由规则，进一步翻成“环境怎么配、值长什么样、联调第一套怎么搭”的可操作样例。
