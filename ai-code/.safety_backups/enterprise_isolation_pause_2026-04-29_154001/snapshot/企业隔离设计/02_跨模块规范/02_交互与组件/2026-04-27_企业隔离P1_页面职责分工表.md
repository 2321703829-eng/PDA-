# 2026-04-27 企业隔离 `P1` 页面职责分工表

## 1. 文档定位

- 本文用于把企业隔离 `P1` 当前现行口径下的页面职责直接收口成可执行分工表。
- 本文重点解决“哪个页面看什么、跳什么、不能抢什么职责”。
- 本文默认基于“一运单一门店”强约束，不再沿用 `customer_line` 主阅读入口假设。

## 3. 总原则

- 当前 `P1` 页面主阅读入口统一为 `waybill`。
- 当前 `P1` 图片、留痕、证据、异常的主阅读入口都围绕 `waybill` 收口。
- `customer_line` 当前保留为结构 / 快照 / 命中辅助层，不再承担主阅读入口职责。
- 正式对象归属不因页面入口变化而变化：
  - `trace_event` 仍是正式留痕对象
  - `evidence` 仍正式挂在 `trace_event`
  - `exception` 仍优先围绕 `waybill / batch / trace_event`

## 4. 页面职责总表

| 页面 / 对象 | 当前页面定位 | 必须承接的内容 | 可以跳转到哪里 | 当前不应承接的内容 |
| --- | --- | --- | --- | --- |
| `batch` 详情页 | 仓侧 / 装车发车上层上下文页 | 批次基础信息、仓侧留痕摘要、批次下运单关联入口 | `waybill`、`trace_event` | 不做图片主阅读页，不做异常主处理页 |
| `waybill` 详情页 | 当前 `P1` 主阅读入口 | 留痕摘要、留痕时间线入口、证据摘要、图片预览入口、异常摘要、回跳主入口 | `batch`、`trace_event`、`evidence`、`exception`、`order_line` | 不把正式证据对象改挂在页面层，不把结构层职责下沉到主阅读入口之外 |
| `customer_line` 页 | 结构 / 快照 / 命中辅助页 | 门店结构信息、快照字段、导入命中辅助信息、导出结构层信息 | `waybill`、必要时回跳上层 | 不做图片主阅读入口，不做留痕主时间线，不做异常主阅读入口 |
| `order_line` 页 / 区域 | 业务明细阅读层 | 订单明细、货品明细、与运单相关的业务阅读 | 回到 `waybill` | 不做正式留痕入口，不做证据主挂点，不做异常主挂点 |
| `trace_event` 详情页 | 单条事实事件详情页 | 事件时间、事件类型、提交人、备注、相关证据、相关异常 | `waybill`、`batch`、`evidence`、`exception` | 不替代 `waybill` 汇总阅读页 |
| `evidence` 详情 / 结果页 | 正式证据详情与结果反馈页 | 图片预览、元数据、关联 `trace_event`、导出入口、审计结果 | `waybill`、`trace_event`、必要时 `exception` | 不替代 `waybill` 做总览阅读 |
| `exception` 详情页 | 问题闭环与状态流转页 | 异常状态、处理日志、相关留痕、相关证据、回跳入口 | `waybill`、`trace_event`、`evidence` | 不扩成完整工单平台 |

## 5. `waybill` 页职责拆分

| 区块 | 最小必须项 | 可选增强项 | 禁止越界点 |
| --- | --- | --- | --- |
| 留痕摘要区 | 最新留痕时间、事件类型、总数、查看全部入口 | 关键事件标签、异常关联提示 | 不直接替代 `trace_event` 详情 |
| 证据摘要区 | 证据总数、最近图片、查看全部、导出入口 | 分 `scene_code` 分组预览 | 不把证据正式对象改挂到 `waybill` 本身 |
| 异常摘要区 | 开放异常数、最近异常时间、查看全部入口 | 异常级别、状态徽标 | 不在摘要区直接承接完整处理流 |
| 业务明细区 | `order_line / goods_line` 业务阅读 | 汇总统计 | 不把业务明细层抬成留痕或证据主入口 |

## 6. 页面跳转规则

| 起点 | 允许的主跳转 | 说明 |
| --- | --- | --- |
| `batch` | `waybill`、`trace_event` | 先看批次，再进入运单或事件 |
| `waybill` | `trace_event`、`evidence`、`exception`、`order_line` | 当前统一主阅读入口 |
| `customer_line` | `waybill` | 结构层以回到主阅读入口为主 |
| `trace_event` | `waybill`、`batch`、`evidence`、`exception` | 单条事件向上下游回跳 |
| `evidence` | `waybill`、`trace_event` | 证据页不脱离正式事件上下文 |
| `exception` | `waybill`、`trace_event`、`evidence` | 异常详情反读事实与证据 |

## 7. 页面显隐与只读原则

- 查看入口显隐由页面层控制。
- 真实是否可查、可导、可处理由接口层与模型层共同兜底。
- 只读人员可以看到摘要，不等于可以导出或关闭异常。
- 图片导入与补链入口只对授权角色开放。

## 8. 当前页面职责通过标准

- 团队对“主阅读入口 = `waybill`”没有分歧。
- `customer_line` 不再被当成主阅读页继续加摘要大区和主入口按钮。
- `trace / evidence / exception` 的详情页都有稳定回跳链。
- 页面显隐、接口权限、模型校验口径一致。

## 9. 一句话结论

当前企业隔离 `P1` 的页面职责分工要点很简单：`waybill` 负责主阅读，`batch` 负责上层上下文，`customer_line` 负责结构层，`trace_event / evidence / exception` 各自负责正式详情与联动，不再混做多个主入口。
