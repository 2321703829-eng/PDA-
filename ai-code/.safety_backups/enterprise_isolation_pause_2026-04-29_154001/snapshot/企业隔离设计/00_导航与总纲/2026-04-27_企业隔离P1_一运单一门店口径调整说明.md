# 2026-04-27 企业隔离 `P1` “一运单一门店”口径调整说明

## 1. 文档目的

- 本文用于记录企业隔离 `P1` 在 2026-04-27 确认的一项关键强约束：`一个 waybill 只能对应一个门店`。
- 本文用于说明该强约束对当前 `P1` 阅读链、对象分层、验收口径和既有讨论稿的直接影响。
- 本文是当前企业隔离 `P1` 的现行口径补充文档，优先级高于同日早些时候基于 `customer_line` 主阅读入口假设形成的讨论稿。

## 2. 本次确认的强约束

- 当前业务按强约束收口：`一个 waybill 只能对应一个门店`。
- 当前 `P1` 不再默认假设“一个运单下存在多个独立门店节点”的常态场景。
- `customer_line` 在当前阶段继续保留，但不再承担“门店级主阅读入口”的设计职责。

## 3. 不变的部分

以下口径在本次调整后继续成立：

- 企业之间隔离默认仍靠数据库级隔离。
- 同一企业内部如有多法人或多公司协同，才考虑 `multi-company`。
- `P1` 数据主链仍保留：
  - `wave -> batch -> waybill -> customer_line -> order_line -> goods_line`
- 正式留痕主对象仍围绕 `waybill / batch / trace_event`。
- 正式证据对象仍围绕 `trace_event`。
- 异常正式主挂点仍优先围绕 `waybill / batch / trace_event`。
- 当前阶段仍只做 `P0 / P1`，不展开 `P2 / P3` 平台控制面与商用运营能力。

## 4. 被调整的部分

### 4.1 页面主阅读入口调整

- 当前 `P1` 页面主阅读入口统一收口为：`waybill`
- 当前 `P1` 页面主阅读链统一收口为：`waybill -> order_line`

### 4.2 图片业务阅读链调整

- 当前 `P1` 图片业务主阅读链统一收口为：
  - `waybill -> 图片预览 / 留痕 / 证据`
- `waybill` 继续承担图片汇总、证据摘要、导出入口和异常联动入口。

### 4.3 `customer_line` 对象定位调整

- `customer_line` 当前收口为运单下的兼容 / 扩展结构层。
- `customer_line` 可继续承接：
  - 结构映射
  - 快照信息
  - 导入命中辅助字段
  - 导入导出结构层信息
  - 后续扩展预留
- `customer_line` 当前不再作为 `P1` 主阅读入口，也不再要求优先承接 trace / evidence / exception 的页面入口职责。

## 5. 对 `trace / evidence / exception` 的直接影响

### 5.1 `trace`

- `trace_event` 的正式归属继续保持在 `batch / waybill`。
- `waybill` 继续作为当前 `P1` 的留痕主阅读入口。
- 不再要求在本轮先补一条“`customer_line` 主阅读入口下的反读链”才能认为 `P1` 成立。

### 5.2 `evidence`

- 图片业务当前主阅读继续围绕 `waybill`。
- 图片命中与补链如仍需使用 `customer_line`，其职责也应理解为“结构与命中辅助层”，而不是页面主阅读层。
- 正式证据对象仍需挂到 `trace_event`，不因页面阅读入口调整而改变。

### 5.3 `exception`

- 异常详情、异常摘要和异常联动当前继续以 `waybill` 为主阅读入口。
- `customer_line` 如保留相关展示，也只作为辅助结构上下文，不作为当前 `P1` 的主异常阅读入口。

## 6. 对验收口径的直接影响

当前 `P1` 是否成立，应重点看下面几点：

- `waybill` 是否能稳定承担当前页面主阅读入口职责。
- `waybill` 是否能稳定承接图片预览、留痕、证据、异常的汇总阅读职责。
- `trace / evidence / exception` 是否能在租户库内独立安装、联动和回读。
- `customer_line` 是否被正确保留为结构层，而不是被误抬为新的主阅读入口。

以下不再作为当前 `P1` 的必过条件：

- 必须先把 `customer_line` 立成图片、留痕、异常的主阅读入口。
- 必须先补完整的 `customer_line -> trace_event / evidence / exception` 页面反读闭环。

## 7. 对既有文档的处理原则

- 同日早些时候基于“`customer_line` 应成为 `P1` 主阅读入口”假设形成的说明稿，保留作为讨论过程留痕。
- 这些旧稿不再作为当前现行口径引用。
- 当前现行口径应优先以以下文档为准：
  - `00_导航与总纲/企业隔离方案可行性与分期落地调整说明.md`
  - `00_导航与总纲/2026-04-27_企业隔离P1_一运单一门店口径调整说明.md`
  - `00_导航与总纲/2026-04-27_企业隔离P1_trace_evidence_exception设计推进总纲.md`

## 8. 一句话结论

在“一运单一门店”强约束下，当前企业隔离 `P1` 应把 `waybill` 收口为主阅读入口，把 `customer_line` 收口为结构与扩展层；这样既不打坏现有正式对象归属，也能显著降低本轮 `P1` 的实现复杂度和返工风险。
