# 2026-04-29 `P0` 方案 A 正式反向代理配置说明

## 1. 文档定位

- 本文用于给当前 `P0` 正式部署阶段提供一份可直接交给运维参考的反向代理配置说明。
- 本文默认继续采用 **方案 A：子域名 -> dbfilter -> 数据库**。
- 本文当前只针对首个正式测试租户 `kebi`。

## 2. 当前固定口径

### 2.1 租户信息

- `tenant_code`：`kebi`
- 数据库名：`tenant_kebi`
- 正式测试子域名：`kebi.tianshu.cn`

### 2.2 代理目标

当前建议把：

```text
kebi.tianshu.cn
```

转发到目标 Odoo 服务，例如：

```text
http://127.0.0.1:8070
```

> 说明：
> - 上面的后端地址是当前本地验证版样例。
> - 正式测试环境里应替换为真实 Odoo 服务地址与端口。

## 3. 代理层必须满足的要求

### 3.1 `Host` 头必须透传

反向代理必须把请求的 `Host` 原样透传给 Odoo。

原因：

- 当前方案 A 依赖 `Host + dbfilter` 命中数据库。
- 如果代理层改写了 `Host`，则可能导致 `tenant_kebi` 无法命中，或落到错误数据库。

### 3.2 上传能力要满足 Odoo 使用要求

至少要考虑：

- 上传大小限制
- 请求超时
- 响应超时
- 长连接保持

原因：

- 当前系统内存在证据上传、图片包导入、导出等场景。
- 如果代理层默认限制过紧，可能会在正式入口下出现登录能打开、业务导入却失败的情况。

### 3.3 禁止通过该入口暴露数据库管理能力

在正式入口下应确保：

- `/web/database/selector` 不作为对外可选库入口暴露
- `/web/database/manager` 不可用
- `/web/database/list` 不可用

## 4. 建议代理行为

### 4.1 正常业务请求

访问：

```text
https://kebi.tianshu.cn/web/login
```

应当：

- 进入 `tenant_kebi` 的登录页
- 不允许用户手工切到其他数据库

### 4.2 非法或非登记入口

对未登记的子域名，应由代理层或 Odoo 层统一返回：

- 不命中业务库
- 不进入任意租户库
- 不暴露数据库选择器

## 5. 建议配置项清单

正式代理配置至少要明确下面这些项：

- 监听域名：`kebi.tianshu.cn`
- 上游 Odoo 地址与端口
- `Host` 透传方式
- `X-Forwarded-For`
- `X-Forwarded-Proto`
- 上传大小限制
- 连接超时
- 读取超时
- HTTPS 证书挂载方式（如需要）

## 6. Nginx 参考示意

> 下面是说明性示意，不是最终生产配置原文。

```nginx
server {
    listen 80;
    server_name kebi.tianshu.cn;

    client_max_body_size 100m;

    location / {
        proxy_pass http://127.0.0.1:8070;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300;
        proxy_connect_timeout 60;
        proxy_send_timeout 300;
    }
}
```

## 7. 与正式 `dbfilter` 的配合口径

代理层与 Odoo 运行配置必须同时成立：

- 代理层透传 `Host = kebi.tianshu.cn`
- Odoo 运行配置下的 `dbfilter` 只允许该 `Host` 命中 `tenant_kebi`

如果两边口径不一致，就算登录页能打开，也不应视为 `P0` 正式通过。

## 8. 交付给运维时最少要带的话

给运维的最少信息应包括：

- 租户编码：`kebi`
- 数据库名：`tenant_kebi`
- 正式测试子域名：`kebi.tianshu.cn`
- 当前采用方案：方案 A
- 代理要求：透传 `Host`
- 验收要求：
  - 正确命中 `tenant_kebi`
  - 不暴露数据库选择页
  - `/web/database/manager` 不可用
  - `/web/database/list` 不可用

## 9. 一句话收口

当前 `P0` 方案 A 的正式反向代理核心不是“把域名转到 Odoo 就行”，而是**让 `kebi.tianshu.cn` 在正式入口下稳定命中 `tenant_kebi`，并且不暴露数据库入口**。
