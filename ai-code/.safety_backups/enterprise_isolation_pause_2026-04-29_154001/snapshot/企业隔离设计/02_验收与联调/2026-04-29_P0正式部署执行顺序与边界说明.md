# 2026-04-29 `P0` 正式部署执行顺序与边界说明

## 1. 文档定位

- 本文用于把当前 `P0` 剩余工作从“剩余事项列表”进一步收成“可执行顺序”。
- 本文默认继续采用 **方案 A：子域名 -> dbfilter -> 数据库**。
- 本文不重复已经完成的本地验证结论，只回答接下来正式环境里先做什么、后做什么、哪些工作依赖外部条件。

## 2. 当前起点

当前已经完成的 `P0` 本地验证基线包括：

- `tenant_kebi` 独立数据库与独立 `filestore`
- 本地 `dbfilter` 命中验证
- 本地数据库入口收口验证
- 本地备份恢复验证
- 本地测试域名与本地反向代理验证

因此，当前 `P0` 已经不再处于“验证能不能隔离”的阶段，而是进入“正式环境如何落地与如何验收”的阶段。

## 3. 当前 `P0` 执行边界

### 3.1 当前可以立即推进的内容

- 正式子域名方案登记
- 正式反向代理配置稿准备
- 正式 `dbfilter` 参数准备
- 正式验收表单与回填口径准备
- 正式入口、正式权限、正式备份恢复的验收项预排

### 3.2 当前需要正式环境或运维配合的内容

- DNS 解析生效
- 正式网关 / Nginx / 代理发布
- 正式 HTTPS 证书申请与挂载
- 准生产或正式测试环境上的真实访问验证
- 正式环境备份恢复演练

### 3.3 当前不再属于 `P0` 主线的内容

- `P1` 业务主链增强开发
- 图片包增强能力
- 平台库、套餐、授权、跨租户控制面

## 4. 正式部署建议顺序

### 4.1 第一步：确认正式租户入口信息

目标：

- 把 `kebi` 的正式测试入口信息先定死，避免后面一边配环境一边改口径。

需要明确：

- `tenant_code`：`kebi`
- 数据库名：`tenant_kebi`
- 正式测试子域名：`kebi.tianshu.cn`
- 所在环境名称
- 对应负责人

完成标准：

- 可以把“哪个域名对应哪个数据库”写成一行确定映射，而不是口头约定。

### 4.2 第二步：准备正式反向代理配置

目标：

- 在正式测试环境或准生产环境里，把子域名请求稳定转到目标 Odoo 服务。

至少要明确：

- 代理监听域名
- 后端 Odoo 地址与端口
- `Host` 头透传方式
- 上传大小限制
- 超时参数
- 长连接或流式访问限制

完成标准：

- 形成一份可交给运维直接照着配的代理配置说明。

### 4.3 第三步：准备正式 `dbfilter`

目标：

- 确保正式运行配置下，`kebi` 子域名只会命中 `tenant_kebi`。

至少要确认：

- 正式配置文件位置
- `dbfilter` 实际写法
- 是否关闭数据库列表
- 是否关闭数据库管理入口

完成标准：

- 配置项已准备好，且和正式代理口径不冲突。

### 4.4 第四步：做正式入口联通验证

目标：

- 证明正式域名已经能稳定进入正确租户库。

至少要验证：

- 正式子域名访问登录页成功
- 落库正确
- 不暴露数据库选择页
- `/web/database/manager` 不可用
- `/web/database/list` 不可用

完成标准：

- 形成一份正式入口验证记录。

### 4.5 第五步：做正式最小业务链验证

目标：

- 证明企业隔离正式入口成立后，当前 `P1` 主业务链在该入口上仍然成立。

至少要验证：

- 运单页可打开
- 留痕主链可用
- 证据主链可用
- 异常主链可用
- 导入中心入口可用

完成标准：

- 可以给出“正式入口不破坏当前 `P1` 主链”的结论。

### 4.6 第六步：做正式权限与备份恢复验收

目标：

- 证明正式入口不只是能访问，而且权限边界和运维恢复链也成立。

至少要验证：

- 只读账号边界
- 图片导入 / 现场人员边界
- 调度 / 管理边界
- 正式备份机制
- 正式恢复机制
- 如条件允许，一轮恢复演练

完成标准：

- 形成正式权限验收记录与正式备份恢复验收记录。

### 4.7 第七步：回填正式验收结论

目标：

- 最终给出 `P0` 是否允许正式认定通过的结论。

至少要回填：

- 环境名称
- 域名
- 数据库
- 代理方式
- 通过项
- 未通过项
- 风险项
- 最终结论

完成标准：

- 形成完整正式验收材料，而不是只有零散截图或口头结论。

## 5. 当前最值得先推进的动作

如果正式环境资源还没完全到位，当前最值得先推进的是这 3 件事：

1. `kebi` 的正式测试子域名已定为 `kebi.tianshu.cn`
2. 正式反向代理配置说明已准备
3. 正式 `dbfilter` 配置项和正式验收表头已准备好

当前最值得继续推进的动作已经变成：

1. 完成 `kebi.tianshu.cn` 的正式 DNS
2. 按说明稿完成正式反向代理发布
3. 把正式 `dbfilter` 写入正式运行配置并开始正式验收回填

## 6. 一句话收口

当前 `P0` 的正确推进方式，不是继续在本地重复验证，而是**先把正式入口、正式代理、正式 `dbfilter`、正式验收表头准备好，再在正式测试环境上完成一次完整验证与回填**。
