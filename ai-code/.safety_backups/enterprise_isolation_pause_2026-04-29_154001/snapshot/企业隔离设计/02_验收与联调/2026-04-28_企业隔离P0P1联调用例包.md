# 2026-04-28 企业隔离 `P0 / P1` 联调用例包

## 1. 文档定位

- 本文用于把现有验收清单进一步压成更接近测试执行稿的联调用例包。
- 本文服务对象是开发、联调和验收，不替代正式设计细稿。
- 本文首轮以人工执行和页面联调为主，不展开自动化测试脚本设计。

本文主要回答：

- 联调前需要准备什么测试数据
- 按什么标准路径走联调
- 每一步期望看到什么结果
- 出现偏差时优先回扫哪一层

## 2. 前置基线

- 企业之间：数据库级隔离
- 当前 `P1` 主阅读入口：`waybill`
- 页面主阅读链：`waybill -> order_line`
- 图片阅读链：`waybill -> 图片预览 / 留痕 / 证据`
- 正式追溯链：`waybill -> trace_event -> evidence -> exception`
- 联调顺序固定为：
  1. `trace_core`
  2. `evidence`
  3. `exception`
  4. 三层联动回归

## 3. 测试数据准备

### 3.1 环境准备

- 1 个基础域名
- 至少 2 个租户子域名
- 至少 2 个租户数据库
- 每个租户库安装相同一套 `P1` 模块

### 3.2 租户样例

| 租户 | `tenant_code` | 数据库名 | 域名 | 用途 |
| --- | --- | --- | --- | --- |
| 租户 A | `alpha` | `tenant_alpha` | `alpha.example.com` | 主联调租户 |
| 租户 B | `beta` | `tenant_beta` | `beta.example.com` | 串库验证租户 |

### 3.3 主链样例数据

主联调租户至少准备：

- 1 个 `wave`
- 1 个 `batch`
- 3 个 `waybill`
- 每个 `waybill` 至少 2 条 `order_line`
- 每个 `order_line` 至少 1 条 `goods_line`

建议把 3 个运单分成：

- 运单 A：正常路径样例
- 运单 B：图片命中 / 补链样例
- 运单 C：异常流转样例

### 3.4 留痕样例数据

建议至少准备以下 `trace_event`：

- 仓侧到场
- 装车完成
- 发车
- 在途
- 到店
- 签收
- 异常上报

### 3.5 图片样例数据

至少准备 3 组图片包：

1. 正常命中包
- 能完整命中 `waybill_no + customer_line_no`

2. 候选命中包
- 仅命中 `waybill_no`
- 需要进入待补链或人工复核

3. 错误包
- 无法命中
- 应进入失败 / 待处理结果

### 3.6 异常样例数据

至少准备：

- 1 条 `open` 异常
- 1 条 `processing` 异常
- 1 条可关闭的 `resolved` 异常

### 3.7 角色样例用户

至少准备：

- 租户管理员
- 调度 / 客服
- 图片导入 / 现场工作人员
- 只读查看员

## 4. 联调总顺序

1. `P0` 多数据库与路由联调
2. 租户初始化与模块安装联调
3. `trace_core` 联调
4. `evidence` 联调
5. `exception` 联调
6. 主阅读页三层联动回归
7. 权限回归

## 5. `P0` 联调用例

### 用例 P0-01：子域名命中正确数据库

- 前置：
  - 已配置 `alpha.example.com`
  - 已配置 `beta.example.com`
- 操作：
  - 分别访问两个域名
- 期望：
  - `alpha` 只能进入 `tenant_alpha`
  - `beta` 只能进入 `tenant_beta`
  - 不出现数据库选择页

### 用例 P0-02：租户间数据不串库

- 前置：
  - `tenant_alpha` 与 `tenant_beta` 各有不同运单样例
- 操作：
  - 在两个租户内分别打开主链页面
- 期望：
  - A 租户看不到 B 租户运单
  - B 租户看不到 A 租户运单

### 用例 P0-03：租户库初始化成功

- 操作：
  - 按 SOP 创建新租户库
  - 安装主模块
- 期望：
  - 模块安装成功
  - 能进入 `waybill` 页面
  - `trace / evidence / exception` 可正常读到菜单或入口

## 6. `trace_core` 联调用例

### 用例 T-01：`waybill` 留痕摘要可读

- 前置：
  - 运单 A 已有多条 `trace_event`
- 操作：
  - 打开运单 A 详情页
- 期望：
  - 能看到留痕数量
  - 能看到最近留痕时间
  - 能看到最近留痕类型 / 摘要

### 用例 T-02：从 `waybill` 进入留痕列表

- 操作：
  - 点击查看留痕入口
- 期望：
  - 仅看到当前 `waybill_id` 的留痕
  - 可进入单条 `trace_event` 详情

### 用例 T-03：留痕提交权限正确

- 操作：
  - 用图片导入 / 现场工作人员提交留痕
  - 用只读查看员尝试提交留痕
- 期望：
  - 前者提交成功
  - 后者在页面层或模型层被拦截

## 7. `evidence` 联调用例

### 用例 E-01：正常图片包自动命中

- 前置：
  - 正常命中包已准备
- 操作：
  - 导入图片包
- 期望：
  - 结果进入已命中 / 已补链
  - 正式证据能关联到目标 `trace_event`
  - `waybill` 页证据数量更新

### 用例 E-02：候选命中包进入待处理

- 前置：
  - 候选命中包已准备
- 操作：
  - 导入图片包
- 期望：
  - 不直接错误挂到正式证据
  - 进入待补链或人工复核状态

### 用例 E-03：失败包进入失败结果

- 操作：
  - 导入错误包
- 期望：
  - 能看到失败结果
  - 能看到失败原因
  - 不污染正式证据统计

### 用例 E-04：证据权限正确

- 操作：
  - 只读查看员查看证据
  - 非导出授权角色尝试导出
- 期望：
  - 可按授权查看
  - 越权导出被拦截

## 8. `exception` 联调用例

### 用例 X-01：异常创建成功

- 前置：
  - 运单 C 已有相关留痕
- 操作：
  - 创建异常
- 期望：
  - 异常主挂在 `waybill / batch / trace_event`
  - 自动写入创建日志

### 用例 X-02：合法状态迁移成功

- 操作：
  - `open -> processing -> resolved -> closed`
- 期望：
  - 每次迁移成功
  - 生成对应 `state_change` 日志

### 用例 X-03：非法状态迁移被拦截

- 操作：
  - 直接从 `open` 改 `closed`
  - 或已 `closed` 再回改
- 期望：
  - 模型层直接报错

### 用例 X-04：最终态要求生效

- 操作：
  - 不填 `close_summary` 直接关闭
- 期望：
  - 关闭失败
  - 补齐说明后才允许关闭

### 用例 X-05：异常详情能反读上下文

- 操作：
  - 打开异常详情页
- 期望：
  - 可回跳 `waybill`
  - 可查看相关 `trace_event`
  - 可查看相关证据
  - 可查看处理日志

## 9. 三层联动回归用例

### 用例 R-01：主阅读页三块摘要同时稳定

- 操作：
  - 打开运单 B 或 C 详情页
- 期望：
  - 留痕摘要正常
  - 证据摘要正常
  - 异常摘要正常

### 用例 R-02：从 `waybill` 逐层回跳稳定

- 操作：
  - 从 `waybill` 进入留痕
  - 从留痕进入证据
  - 从异常进入证据 / 留痕
- 期望：
  - 每一跳都只看到当前运单相关对象

### 用例 R-03：图片补链后主阅读页摘要更新

- 操作：
  - 补链成功后回到运单页
- 期望：
  - 证据统计变化正确
  - 相关入口可打开最新内容

## 10. 权限回归用例

### 用例 P-01：只读查看员

- 可做：
  - 查看 `waybill`
  - 查看留痕 / 证据 / 异常详情
- 不可做：
  - 提交留痕
  - 导入图片包
  - 关闭异常
  - 导出证据

### 用例 P-02：图片导入 / 现场工作人员

- 可做：
  - 上传图片包
  - 查看本人导入结果
  - 提交留痕
- 不可做：
  - 关闭异常
  - 重试高风险补链
  - 导出证据

### 用例 P-03：调度 / 客服

- 可做：
  - 查看主阅读页
  - 跟进异常
  - 查看证据与留痕
- 受限：
  - 若无专项授权，不导出证据

### 用例 P-04：租户管理员

- 可做：
  - 全链路查看
  - 高风险动作处理
  - 权限与入口全量联调

## 11. 偏差定位建议

当联调失败时，优先按这条顺序排查：

1. 先看是不是路由或租户环境问题
2. 再看是不是模型层对象锚点问题
3. 再看是不是摘要字段未更新
4. 再看是不是页面入口 domain 错误
5. 最后看是不是权限层或按钮显隐误判

## 12. 一句话收口

这份联调用例包的目的，是把“验收知道要看什么”进一步压成“联调时具体准备什么、怎么走、每一步应该看到什么”，让 `P0 / P1` 联调不再停留在抽象清单层。
