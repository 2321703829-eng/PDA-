# 企业隔离 P1 本轮剩余待办项

## 1. 当前口径更新

- `image_package` 不再作为当前 `P1` 的主缺口。
- 当前版本已经满足：
  - 图片包导入
  - 命中运单
  - 补链到正式 `trace_event -> evidence`
  - 失败记录
  - 基本重试
  - 导入中心接入
- 后续如业务量提升，再把 `image_package` 作为可选增强项继续展开。

## 2. 当前真正剩余的重点

### 2.1 `P0` 真实环境实施

当前设计、规范、SOP、样例稿都已经齐备，但还需要把真实环境实施跑实并沉淀记录：

- 真实 `tenant_code`
- 真实数据库名
- 真实域名
- 真实 `dbfilter`
- 真实访问验证结果
- 真实备份恢复记录

这部分是当前最优先的剩余项，因为它直接决定企业隔离底盘是否真正落地。

### 2.2 权限实账号回归

当前结构性权限和首轮人工回归已经完成，但仍建议用真实业务账号把下列角色再回扫一轮并留痕：

- 只读用户
- 图片导入 / 现场人员
- 调度 / 管理
- 图片审计

重点确认：

- 菜单显隐
- 按钮显隐
- 越权拦截
- 提示文案
- 页面与模型层权限是否一致

### 2.3 交付收口

这轮编码和人工回归已经基本跑通，下一步要把交付材料收成正式版本：

- 回归检查表回填
- 真实环境参数登记单回填
- 阶段验收记录沉淀
- 本轮完成能力与剩余待办项定稿

## 3. 不再作为本轮主缺口的内容

以下内容不再列为当前 `P1` 主推进项：

- `image_package` 的人工复核台账增强
- `image_package` 的批量人工改挂
- `image_package` 的更细任务看板
- `image_package` 的更复杂批量重试策略

这些能力后续如业务需要，可作为增强项单独排期。

## 4. 建议的下一步顺序

1. 先做 `P0` 真实环境实施与记录沉淀
2. 再做权限实账号回归并留痕
3. 最后做本轮交付收口

## 5. 一句话结论

当前 `P1` 主链能力已经基本完成，后续重点不再是继续深挖图片包，而是把企业隔离的真实环境落地、权限实账号验证和交付材料收口做扎实。

## 6. 定版收口说明

- 从本轮起，当前 `P1` 不再按“待补主链功能”理解。
- 当前剩余事项统一按“回归材料回填 + 交付材料收口 + 与 `P0` 联动后续项”理解。
- 当前 `P1` 主链能力已经可以视为本轮完成版本。
- 后续若继续推进，也不应再轻易重开本轮 `P1` 主边界。
