# doc-sync-review

## 通用协作约束

1. 完成编码工作后，默认需要向用户提供详细的人工复核操作流程，除非用户已明确说明“不需要核实”或“不需要复核”。
2. 开启设计文档编写工作前，默认需要先与用户讨论编写思路；未得到用户确认前，不开始正式编写，除非用户已明确说明“不需要讨论”或直接要求开始编写。
3. 每次完成文档编写或编码后，默认需要回扫当前所处阶段对应的设计文档，并对其中已过期、已冲突或已不再符合当前实现/方案的内容进行同步修正，除非用户已明确说明“不需要更改”。
4. 若无法明确当前工作属于哪一期或哪个阶段，在进行上述设计文档回扫和修改前，默认需要先询问用户确认；只有在用户已明确说明无需询问或无需更改时，才可以跳过。

## 目的

在改代码或改结构后，扫描哪些文档需要同步更新。

## 使用场景

- 改模型
- 改目录
- 改边界
- 改运行方式

## 检查步骤

1. 列出本轮改动的文件
2. 判断改动属于模型、结构、边界、运行方式中的哪一类
3. 对照 `docs/review/doc_sync.md` 确定受影响文档
4. 若需要更新文档，立即补齐
5. 生成或更新 `docs/change_notes/` 记录

## 检查项

- `AGENTS.md` 是否需要同步
- `docs/ai/` 是否需要同步
- `docs/context/` 是否需要同步
- `ARCHITECTURE.md` 是否需要同步
- `upgrade_and_verify.md` 是否需要同步
- `change_notes` 是否已补写
