# phase3-frontend-delivery

## 通用协作约束

1. 完成编码工作后，默认需要向用户提供详细的人工复核操作流程，除非用户已明确说明“不需要核实”或“不需要复核”。
2. 开启设计文档编写工作前，默认需要先与用户讨论编写思路；未得到用户确认前，不开始正式编写，除非用户已明确说明“不需要讨论”或直接要求开始编写。
3. 每次完成文档编写或编码后，默认需要回扫当前所处阶段对应的设计文档，并对其中已过期、已冲突或已不再符合当前实现/方案的内容进行同步修正，除非用户已明确说明“不需要更改”。
4. 若无法明确当前工作属于哪一期或哪个阶段，在进行上述设计文档回扫和修改前，默认需要先询问用户确认；只有在用户已明确说明无需询问或无需更改时，才可以跳过。

## 目的

为“三期前端优化设计”相关任务提供统一入口，减少新对话重新建立上下文的成本，让 Codex 能更快进入：

- 文档阅读
- 范围判断
- 代码落位
- 验收回扫

## 使用场景

- 用户要求实现三期前端优化中的页面、接口接线或页面动作
- 用户要求继续三期中的 `司机管理`
- 用户要求继续三期中的 `统计图表`
- 用户要求继续三期中的 `导入结果页页面化`
- 用户要求判断某个需求是否属于三期范围
- 用户要求从新对话直接接手三期实现

## 不适用场景

下面这些不应由本 skill 直接承接，应先回到专项方案或另起主题：

- 企业分离功能的完整实现
- 多数据库底盘、`dbfilter`、域名路由、平台控制面
- 套餐能力层、跨租户能力层、跨租户汇总
- 非运单对象导入中心化扩建
- 固定需求 + 临时需求体系

如用户转向企业分离主题，先读：

- `ai-code/企业分离功能文件夹/00_导航与总纲/企业隔离方案可行性与分期落地调整说明.md`

并默认按：

- `P0` 多数据库底盘验证
- `P1` 现有物流模块租户化
- `P2` 平台控制基础版
- `P3` 商用运营增强版

理解优先级，不要一开始就把三期前端任务误切到平台控制面。

## 三期范围冻结口径

当前三期主线固定为：

1. `司机管理`
2. `统计图表`
3. `界面系统化美化`

并承接一小组二期收尾项：

- 导入结果页页面化
- 三期新增接口与二期存量接口的命名/口径统一
- 与当前前端主路径直接相关的少量技术债清理

当前明确不并入：

- 企业分离方案中的套餐能力层与跨租户能力设计
- 非运单对象导入中心化扩建
- 独立客户明细 / 货物明细标准模板
- 固定需求 + 临时需求体系

## 默认工作方式

1. 先锁 `Outcome / Behavior / Boundary`
2. 先比对现有代码，再决定是否能直接改
3. 如果当前任务有完整专题稿、接口稿、交互稿、验收稿，默认直接进入实现
4. 如果当前任务落在文档待补区，先补文档再编码
5. 实现后按对应验收清单回扫
6. 同步更新 `ai-code/docs/change_notes/`

## 默认实现顺序

当用户只说“继续三期”而没有指定子线时，默认优先级为：

1. `司机管理`
2. `统计图表`
3. `导入结果页页面化`
4. `界面系统化美化`

原因：

- 前 3 条线已具备更完整的方案、接口、交互、验收链
- `界面系统化美化` 目前仍缺更细的交互稿和验收稿

## 何时先补文档再编码

遇到下面任一情况，默认先补文档：

- 任务属于 `界面系统化美化`
- 需要拆后端字段级接口契约
- 需要给新对话稳定交接复杂实现
- 需要新增聚合字段、复杂 controller 响应或跨页统一口径

优先补这些文档：

- `三期界面系统化美化交互与组件说明.md`
- `三期界面系统化美化联调与验收清单.md`
- `三期接口路线决策文档.md`
- `三期前后端接口字段级契约清单.md`
- `三期 controller 示例响应.md`
- `三期聚合字段实现策略文档.md`

## 实现边界提醒

1. 页面隐藏和按钮禁用只作为体验层，不是最终安全边界
2. 关键动作仍要依赖后端权限或能力校验
3. 不要把企业隔离层、套餐能力层混入三期页面权限说明
4. 不要为导入结果页重开第二套接口体系
5. 不要把统计页和司机画像页做成图表职责重叠

## 最低验证清单

三期实现完成后，至少做下面 5 件事：

1. 对照对应专题验收清单逐项回扫
2. 检查菜单、action、路由、模板和样式是否都已接入
3. 检查是否误越出三期边界
4. 检查是否需要同步更新相关设计文档
5. 记录或新增 `docs/change_notes/`
