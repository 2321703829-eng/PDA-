# kebi 企业入口收口设计

## 设计原则

1. 保留已有功能，不删除底层模型、视图和动作。
2. 只调整菜单组织方式，把原生 Odoo 能力挂到企业业务工作区。
3. 业务入口按实际工作流组织，而不是按 Odoo 原生应用组织。
4. 留痕证据属于配送履约链路，归入 `配送调度 TMS`，避免成为独立顶层入口。

## 实现范围

### 企业菜单

文件：`custom_addons/logistics_web/views/logistics_web_enterprise_menus.xml`

该文件定义企业统一入口：

- 基础资料
- 订单经营 ERP
- 仓库作业 WMS
- 配送调度 TMS
- 数据看板 BI

其中 `留痕证据` 被放入 `配送调度 TMS` 下，作为配送链路中的证据查看与追溯入口。

### 原生菜单隐藏

文件：`custom_addons/logistics_web/data/logistics_web_native_menu_cleanup.xml`

该文件通过 `active=False` 隐藏容易造成混淆的原生顶层菜单。隐藏菜单不代表删除功能，企业菜单仍可通过 action 调用对应能力。

### 模块加载

文件：`custom_addons/logistics_web/__manifest__.py`

在 `data` 中加载：

- `views/logistics_web_enterprise_menus.xml`
- `data/logistics_web_native_menu_cleanup.xml`

确保模块升级后菜单结构和隐藏规则能够自动生效。

## 验收点

1. `https://kebi.tianshuchain.cn/web` 能正常登录。
2. 顶层只保留企业系统主入口和管理员设置入口。
3. `配送调度 TMS > 留痕证据` 下能进入仓库证据、司机证据、证据汇总。
4. 原有图片查看、图片下载、批量导出、小程序上传链路不受菜单调整影响。
5. `设置` 仍可供管理员维护用户、权限和系统参数。

## 回退方式

如需回退，恢复以下文件到调整前版本并升级 `logistics_web`：

- `custom_addons/logistics_web/__manifest__.py`
- `custom_addons/logistics_web/views/logistics_web_enterprise_menus.xml`
- `custom_addons/logistics_web/data/logistics_web_native_menu_cleanup.xml`

生产执行前应先备份当前模块目录和数据库。
