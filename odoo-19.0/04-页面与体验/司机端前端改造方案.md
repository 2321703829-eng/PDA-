# 司机端小程序前端改造方案 (v1.0)
负责人：涂子麟

## 1. 模块目标
为物流现场操作人员提供最快、最顺手的“订单现场留痕闭环”入口。保障司机能单手完成：扫码识别 -> 查看任务 -> 动作打卡 -> 拍照留痕 -> 明确反馈。

## 2. 模块边界
负责：司机端页面布局、操作流程控制（前端状态机）、交互反馈、调用 Odoo 业务接口与图片服务。
不负责：订单主控数据生成、批次调度逻辑、底层图片存储与压缩。

## 3. 页面信息架构与清单（小程序/H5 页面清单）
本期司机端保持极致轻量，聚焦单页核心闭环：    
pages/index/index (现场作业工作台)
1. 搜索区：输入框 + 扫码按钮
2. 全局指示区：横向地铁图路线（标明已完成、当前目标、待解锁）  
3. 上下文区：当前店铺联系人、详细地址、配送物品摘要
4. 作业操作区：根据状态流转的动态按钮组 + 留痕上传框

## 4. 司机端关键流程设计 (前端状态机)
为了防止司机误操作，前端实现了严格的状态机阻断：
1. PENDING (未解锁)：前置站点未完成，当前站点操作区锁死，提示“需按顺序完成上一站打卡”。
2. WAIT_DEPART (待出发)：展示“确认已出发”按钮，点击后记录时间，进入下一状态。
3. IN_TRANSIT (前往中)：展示“确认已到达”按钮，点击后解锁拍照区。
4. WAIT_UPLOAD (待传图)：展示拍照/选图框，未选图时“上传并打卡”按钮置灰。
5. COMPLETED (已完成)：展示图片凭证（image_access_key），自动切至下一站点。

## 5. 页面核心字段清单

| 字段区域 | 字段名 | 来源/说明 |
|---|---|---|
| 顶部进度 | 站点列表 (nodes) | 包含各节点 node_id, store_name, status |
| 订单详情 | 运单号 (waybill_no) | 业务唯一标识 |
| 订单详情 | 联系人及电话 | contact_name, contact_phone |
| 订单详情 | 详细地址 | address (支持一键拉起地图导航) |
| 订单详情 | 配送物品 | goods_info (重点高亮展示) |
| 留痕作业 | 图片凭证 (image_access_key) | 留痕凭证主键，关联 trace_record_evidence |

## 6. 前端接口消费清单 (与开发协同最新确认版)
前端一期闭环需要消费以下接口（按调用时序）：
1. 调度中心接口：
   - 查询当前任务路线与上下文：`GET /api/mini/routes/{waybill_no}` (待调度负责人提供)
2. 图片服务接口：
   - 上传图片：调用 `upload_image_object` 获取 `image_access_key`。
3. 留痕与证据中心组合接口：
   - 第一步：调用 `create_trace_event` (创建事件，如：到店留痕/装车留痕)
   - 第二步：调用 `create_trace_evidence` (为事件创建证据对象)
   - 第三步：调用 `attach_image_to_evidence` (将 upload 得到的 key 挂靠到证据对象上)

## 7. 弱网、重试与异常反馈规则
1. 扫码失败/查无订单：弹出清晰 Modal 提示“未找到该运单，请核对后手动输入”。
2. 弱网上传失败：图片上传失败时，保留用户已选取的本地图片 tempImagePath，按钮恢复可点击状态，并 Toast 提示“网络不佳，请点击重试”。
3. 操作防抖：所有“出发/到达/上传”按钮点击后立即触发 wx.showLoading 并禁用按钮，防止多次重复提交。
4. 成功反馈：打卡成功后，提供 1.5s 的 Success Toast，并伴随自动向右滚动解锁下一站的视觉动画。
