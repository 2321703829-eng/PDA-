# image-main-4b 文件夹说明

## 一、这个文件夹是干什么的

`image-main-4b` 不是图片上传子线，也不是对 `feat-image-4a` 的重复拷贝。

它的定位是：

**后续主业务链补全工作目录。**

对应的是项目下半部分要继续推进的正式主链能力，而不是继续把所有代码都堆在图片模块里。

按当前仓库设计基线，后续要补齐的主链是：

`波次 -> 批次 -> 运单号 -> 运单下订单 -> 留痕事件 -> 图片证据`

`image-main-4b` 主要就是围绕这条主链往前推进。

## 二、为什么要单独建 `image-main-4b`

这样拆的原因有 3 个：

1. `feat-image-4a` 已经承接了图片、留痕、证据、小程序上传这条稳定线  
2. 下半部分开始接的是正式主链模块，边界已经变了  
3. 单独拆目录后，后续代码、文档、验收边界更清楚，不会把已跑通的图片链搅乱

也就是说：

- `feat-image-4a`：偏“已跑通的图片/留痕子线”
- `image-main-4b`：偏“正式主链补全子线”

## 三、这个文件夹现在放了什么

当前结构是：

```text
image-main-4b/
  addons/
    logistics_base/
    logistics_dispatch/
  docs/
```

### 1. `logistics_base`

负责基础主数据扩展。

当前主要方向是：

- 门店 / 客户基础字段扩展
- 员工 / 司机基础字段扩展
- 仓库基础字段扩展

它的作用不是直接跑业务，而是给后续主链模块提供共享底座。

### 2. `logistics_dispatch`

这是 `image-main-4b` 当前最核心的模块。

它承接的是正式主业务对象：

- `logistics.dispatch.wave`
- `logistics.dispatch.batch`
- `logistics.dispatch.waybill`
- `logistics.dispatch.waybill.order.line`
- `logistics.dispatch.waybill.stop`

它负责的业务方向包括：

- 波次组织
- 批次执行
- 运单主对象
- 运单下订单明细
- 运单站点定义
- 批次 / 运单聚合统计

## 四、它和 `feat-image-4a` 的关系

可以这样理解：

### `feat-image-4a`

负责：

- `logistics_trace_core`
- `logistics_trace_evidence`
- 图片上传
- 图片预览 / 下载
- 小程序联调接口
- 留痕、证据、图片链

### `image-main-4b`

负责：

- `logistics_base`
- `logistics_dispatch`
- `wave`
- `batch`
- `waybill`
- `waybill_order_line`
- `waybill_stop`

一句话：

**4a 是证据链子线，4b 是主链补全子线。**

## 五、现在做到哪一步了

当前 `image-main-4b` 已完成：

1. 目录和文档骨架已建立  
2. `logistics_base`、`logistics_dispatch` 已整理进目录  
3. Odoo 18 兼容性已修正  
4. 在服务器临时库里做过真实安装验证  
5. 主链层新增了 `waybill_stop` 正式子对象  

也就是说：

**它已经不是空目录，而是可以继续往正式主链上推进的工作基础。**

## 六、后续主要做什么

后续 `image-main-4b` 主要继续承接这些工作：

1. 把正式主对象层补稳  
2. 让 `wave / batch / waybill / waybill_order_line / waybill_stop` 真正落到主业务库  
3. 把 `feat-image-4a` 已跑通的小程序 / 图片能力按正式主链口径并回正式模块  
4. 和前端 `logistics_web` 对齐正式字段口径  
5. 做正式主库联装和整链联调

## 七、同事怎么看这个目录最合适

同事理解这个目录时，可以直接按下面这句：

**`image-main-4b` 是下半部分正式主链补全目录，不是图片线；它主要负责波次、批次、运单、运单订单、运单站点这些正式主对象。**

如果同事只看一眼想知道“这里是干嘛的”，就看这一点就够了。
