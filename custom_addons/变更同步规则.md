# custom_addons 变更同步规则

文档类型：
- 模块治理规范

当前状态：
- active

当前角色：
- `custom_addons/` 代码变更的最小文档同步规则

主文档：
- [README.md](./README.md)

## 1. Objective

明确 `custom_addons/` 下代码目录发生变化时，哪些文档必须一起同步，避免代码、模块入口、架构口径和专题设计长期漂移。

## 2. 适用范围

适用于以下目录的真实变更：

- `models/`
- `controllers/`
- `services/`
- `views/`
- `static/`
- `security/`
- `data/`
- `__manifest__.py`

不适用于：

- `__pycache__`
- 临时运行产物
- 不进入仓库的本地调试文件

## 3. 每次都要检查的基础文档

无论改的是哪一层，至少都要检查：

1. [custom_addons/README.md](./README.md)
2. [模块职责矩阵.md](./模块职责矩阵.md)
3. 当前模块自己的 `README.md`
4. `ai-code/docs/change_notes/`

如果本轮变更不会影响其中某份文档，也应在 `change_notes` 里说明为什么不需要同步。

## 4. 按目录类型的同步规则

### 4.1 改 `models/`

重点关注：

- 主对象是否变化
- 字段、状态、关系、聚合口径是否变化
- 模块职责边界是否变化

至少同步：

1. 当前模块 `README.md`
2. [模块职责矩阵.md](./模块职责矩阵.md)
3. `ai-code/docs/architecture/ARCHITECTURE.md`
4. 对应专题设计主文档
5. `ai-code/docs/change_notes/`

常见对应专题：

- `logistics_dispatch` -> `ai-code/专题设计/前端设计/`、`ai-code/专题设计/企业隔离设计/`
- `logistics_trace_*` -> `ai-code/专题设计/企业隔离设计/`、`ai-code/专题设计/前端设计/`
- `logistics_base` -> `ai-code/专题设计/仓管设计/`、`ai-code/专题设计/前端设计/`

### 4.2 改 `controllers/`

重点关注：

- API 路径、入参、出参是否变化
- 后台 / mini / open 接口边界是否变化
- 控制器是否越过了既有模块职责边界

至少同步：

1. 当前模块 `README.md`
2. [模块职责矩阵.md](./模块职责矩阵.md)
3. 相关目录级 `controllers/README.md`
4. 对应专题设计里的接口文档
5. `ai-code/docs/change_notes/`

如接口前缀、接口职责或系统边界变化明显，再同步：

6. `ai-code/docs/architecture/ARCHITECTURE.md`
7. `ai-code/docs/review/checklists/doc_sync.md`

### 4.3 改 `services/`

重点关注：

- 服务职责是否变化
- 聚合读取、导入导出、图片存储或任务编排是否变化
- 服务层是否把职责吸走到错误模块

至少同步：

1. 当前模块 `README.md`
2. 相关目录级 `services/README.md`
3. [模块职责矩阵.md](./模块职责矩阵.md)
4. 对应专题设计主文档
5. `ai-code/docs/change_notes/`

如果服务变化已经影响模块边界或执行链，再同步：

6. `ai-code/docs/architecture/ARCHITECTURE.md`

### 4.4 改 `views/`

重点关注：

- 后台页面入口、菜单、视图结构是否变化
- 页面信息架构是否变化
- 是否影响当前阅读链或操作入口

至少同步：

1. 当前模块 `README.md`
2. 相关目录级 `views/README.md`
3. 对应前端专题设计文档
4. `ai-code/docs/change_notes/`

如果页面结构变化已经影响系统级口径，再同步：

5. [模块职责矩阵.md](./模块职责矩阵.md)
6. `ai-code/docs/architecture/ARCHITECTURE.md`

### 4.5 改 `static/`

重点关注：

- 前端动作、组件、模板、样式、部件职责是否变化
- 页面承接层是否变化
- 是否影响导入中心、统计、追溯、司机/车辆、异常或证据阅读

至少同步：

1. 当前模块 `README.md`
2. 相关目录级 `static/README.md` 及下级 `README.md`
3. [模块职责矩阵.md](./模块职责矩阵.md)
4. `ai-code/专题设计/前端设计/` 下相关阶段主文档
5. `ai-code/docs/change_notes/`

如前端承接边界或模块归属变化明显，再同步：

6. `ai-code/docs/architecture/ARCHITECTURE.md`

### 4.6 改 `security/`

至少同步：

1. 当前模块 `README.md`
2. 相关目录级 `security/README.md`
3. `ai-code/docs/change_notes/`

如果权限模型影响角色矩阵或专题规则，再同步对应专题设计。

### 4.7 改 `data/`

至少同步：

1. 当前模块 `README.md`
2. 相关目录级 `data/README.md`
3. `ai-code/docs/change_notes/`

如果初始化数据影响对象口径、标签同步或导入映射，再同步相关专题设计和矩阵文档。

### 4.8 改 `__manifest__.py`

重点关注：

- 模块依赖是否变化
- 数据加载项是否变化
- `assets`、`post_init_hook`、`application` 状态是否变化

至少同步：

1. 当前模块 `README.md`
2. [模块职责矩阵.md](./模块职责矩阵.md)
3. `ai-code/docs/architecture/ARCHITECTURE.md`
4. `ai-code/docs/change_notes/`

## 5. 最小输出要求

每轮涉及 `custom_addons/` 真实代码改动时，`change_notes` 至少要写清：

1. 改了哪个模块
2. 改了哪个目录层
3. 哪些文档已经同步
4. 哪些文档暂未同步以及原因
5. 本轮是否影响模块职责矩阵

## 6. 推荐执行顺序

1. 先确认变更落在哪个模块、哪个目录层
2. 再对照本规则找必须同步的文档
3. 先改代码，再补 README / 架构 / 专题 / change_notes
4. 最后在提交前回看本规则，避免漏同步
